# 신청서코드와 순차결재 로컬 검증

2026-11-18. [승인 명세](../superpowers/specs/2026-11-18-request-form-approval-routing-design.md)와 [구현 계획](../superpowers/plans/2026-11-18-request-form-routing.md)에 따라 로컬 전용 PostgreSQL과 Chrome을 사용했다. PC 1440×900, 모바일 390×844 터치 에뮬레이션에 서로 다른 합성 직원을 배정했다.

| 업무 | 팀장 승인 직후 | 실장 최종 승인 후 |
| --- | --- | --- |
| 휴가 1일 | 대기, 현재 결재자 실장, 잔여 3일 | 승인, 잔여 2일 |
| 원휴가 취소 | 취소 신청 대기, 원휴가 유효, 잔여 2일 | 원휴가 ‘승인 · 취소됨’, 잔여 3일 |
| 누락된 퇴근 정정 | 정정 대기, 유효 퇴근 미기록 | 정정 승인, 유효 퇴근 18:00, 원천 퇴근 미기록 |

담당자는 신청서 세 종류에서 대상 사원의 팀장→실장을 미리 보고 설정을 저장·재조회했다. 직원은 휴가·취소·정정을 신청했고 각 결재자는 자기 차례에 결재함에서 승인했다. 두 직원의 DB 기록에는 신청 6건, 건별 단계 승인 2회, 직원별 휴가 차감 1회·복원 1회가 남았다. 원천 출근은 각 1건, 원천 퇴근은 각 0건이었다.

실제 브라우저에서 취소 및 정정 화면에 결재선이 표시되지 않는 문제를 발견했다. 서버 화면 응답의 허용 필드에 해당 미리보기를 추가하고 두 화면 폭에서 취소와 정정의 신청·승인을 다시 수행했다. HTTP 화면 응답 회귀 테스트에는 결재선 확인값과 결재선 변경 후 취소 사유 보존도 포함했다.

최종 JAR(`6cbd0bcafc064770f79d5055f6b51d8b0b7b982b9638c0ad294672eeca1e3298`)에서는 같은 합성 DB를 사용해 화면 폭별로 7개 항목을 다시 읽었다. 관리자 신청서 3종 미리보기, 완료된 신청 3종의 처리 이력·효력, 직원 내 정보의 ‘기존 배정 기준’ 펼치기를 확인했다. 이 마지막 확인에서 추가 쓰기, JavaScript 예외, 가로 넘침은 각각 0건이었다.
