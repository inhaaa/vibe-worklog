## 검증 환경

[일일 근태 자동화 결과](daily-attendance-20261126.md#검증-환경)와 같다. JDK 25는 테스트 명령에만 쓰고, 테스트 DB는 고정 기반 이미지로 띄운 전용 컨테이너(`127.0.0.1:25432`)를 전체 회귀 전에 새로 만들었다. 실제 메일 서버로는 보내지 않았다. 메일은 로컬 메모리 메일함과 시험용 가짜 SMTP로만 확인했다.

## 코드 검토에서 고친 점

독립 검토에서 다음을 찾아 고쳤다(`623b3bf`).

- 메일 한 건이 예상 밖 오류를 내면 그 회사의 나머지 메일이 계속 막히던 문제
- 결재자를 바꾸면 이전 결재자에게 지울 수 없는 안 읽은 알림이 남던 문제
- 안 읽은 알림이 목록 밖에만 있을 때 '모두 읽음'이 사라지던 문제
- 화면 낭독기가 100건 이상을 '100건'으로 읽던 문제
- 메일 발송 작업이 새벽 일괄 작업을 늦출 수 있던 문제(예약 작업 스레드 2개)

## 브라우저 확인

빈 테스트 DB에 로컬 데모 회사를 만들고(`local-demo-bootstrap`) 앱(`local,local-demo` 프로필)을 앱 내장 브라우저로 조작했다. 데모 준비 명령은 지정 날짜와 DB 이름만 받으므로, 결재자 합성 계정(사번 20001)과 결재 관계는 이 일회용 시험 DB에 SQL로 넣었다.

| 흐름 | 결과 |
| --- | --- |
| 담당자(99999)가 출퇴근 정정 신청 | 결재자에게 '결재 요청' 알림 1건, 1분 안에 메일 상태 `SENT`(로컬 메모리 메일함) |
| 결재자로 전환 | 상단 종에 빨간 배지 1, 종을 누르면 알림 화면에 '결재 요청 · 담당자 · 출퇴근 정정 11-26 · 안 읽음' |
| 알림에서 상세 열기 | DB에서 읽음 처리됨 |
| 결재자 승인 | 신청자에게 '승인' 알림, 1분 안에 메일 상태 `SENT` |
| 신청자로 전환 | 홈 종 배지 1 → 알림 화면 → 상세 창을 열면 종 배지가 바로 사라짐 → 창을 닫으면 목록이 '읽음'으로 바뀌고 '모두 읽음' 버튼이 사라짐 |
| 모바일 390×844 | 페이지 가로 넘침 없음, 종은 상단 바에 표시, 목록은 시트 안 가로 스크롤 |

브라우저 확인 중에 다음 문제를 발견해 고쳤다(`ef70521`). 결재 상세가 알림 화면 위에 창으로 열리면, 상단 종과 목록에 읽기 전 값이 남아 있었다. 이제 상단 종은 가장 최근 응답의 건수를 쓰고, 알림 화면 위의 상세 창을 닫으면 목록을 다시 불러온다.

## 남은 점

- **실제 메일 발송**: 현재 단계 규칙상 실제 SMTP 서버로는 보내지 않았다. 메일 본문은 통합 테스트의 가짜 SMTP와 메모리 메일함으로 확인했다.
- **실행하지 못한 검증**
  - 서버 여러 대에서의 발송 잠금(단일 DB 잠금 시험으로만 확인)
  - 고정 이미지 위의 테스트와 개통 브라우저 시나리오
  - 공개 데모 배포
- **반려·결재자 변경의 브라우저 확인**: 통합 테스트로만 확인했다.
- **한 번 더 가는 메일**: 발송 직후 서버가 멈추면 같은 메일이 한 번 더 갈 수 있다(설계상 최소 1회 전달).
- **알림 보관**: 알림은 삭제하지 않고 화면에는 최근 100건만 보인다.
