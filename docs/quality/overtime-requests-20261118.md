# 연장근무 신청·결재·실적 대조 로컬 검증

[업무 명세](../superpowers/specs/2026-11-18-overtime-requests.md)와 [구현 계획](../superpowers/plans/2026-11-18-overtime-requests.md)을 기준으로 전용 PostgreSQL과 합성 자료를 사용했다. PC Chrome과 모바일 터치 에뮬레이션에서 서로 다른 사원으로 각각 아래 흐름을 확인했다.

| 시점 | 원신청 효력 | 담당자 목록의 유효 승인 | 실제 퇴근 |
| --- | --- | --- | --- |
| O01 신청 후 팀장 승인 | 대기, 실장 결재 중 | 0분 | 20:00 |
| 실장 최종 승인 | 승인 유효 | 135분 | 20:00 |
| O02 취소 신청 후 팀장 승인 | 원승인 유효 | 135분 | 20:00 |
| 취소 최종 승인 | 원신청 취소됨 | 0분 | 20:00 |

직원은 18:30~21:00 구간을 선택해 20:00~20:15 예정 휴게를 뺀 135분을 확인하고 제출했다. 담당자는 신청서별 결재선과 사원·기간·상태 조회를 확인했다. 각 화면 크기에서 9개 동작을 확인했고 7개 화면을 캡처했다. 검사한 화면의 페이지 오류와 가로 넘침은 0건이었다.

DB에서도 신청·취소 네 건의 결재 8단계, 원신청의 취소 효력과 취소 신청의 승인 효력을 확인했다. 합성 직원 두 명의 출퇴근은 각각 09:00·20:00 두 건, 휴가 원장 행은 0건이었다.

최종 JAR에서 PC 1440px, 모바일 390px로 원신청과 담당자 목록을 다시 조회했다. 입력 필터 보완 후 두 화면 크기에서 각각 3개 화면의 가로 넘침과 페이지 오류가 없었다. 검증 완료 후 로컬 앱 두 개와 전용 DB를 종료했다.
