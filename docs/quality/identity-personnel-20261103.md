# 사번 로그인·권한 선택·내정보 확장 검증

> 후속 실제 공개 반영: 2026-11-03 `aab37e6`·V17의 백업/독립 복원·사번 전환·자료/권한 보존·공개 HTTP·PC/모바일 검증을 완료했다. [최종 배포 결과](public-identity-personnel-deploy-20261103.md)를 따른다. 아래는 개발/통합 당시의 검증 이력이다.

2026-11-03 Asia/Seoul. [승인 설계](../superpowers/specs/2026-11-03-identity-personnel-design.md)와 [구현 계획](../superpowers/plans/2026-11-03-identity-personnel.md)의 개발 결과다. 공개 소스 보안 통합과 실제 배포 결과는 별도로 기록한다.

## 구현

- 회사 범위를 확인한 사번 로그인과 기존 이메일 이행 호환. 한 계정의 보유 권한만 선택하고 공통 직원 메뉴에 선택 역할 메뉴를 추가한다. 선택은 로그인 신원이나 서버 권한을 바꾸지 않는다.
- 기존 `/admin/access`에서 사번별 복수 권한을 관리한다. 역할 회수·마지막 관리자·독립 승인·자기 승인 차단은 유지한다.
- 담당자 `99999`/이름 `담당자`. 다른 신규 사원은 회사 입사일의 `YY`+`001~999`를 단건/일괄 저장 시 자동 발급한다. 기존 수동 사번은 호환하며 일반 수정에서 사번을 바꾸지 않는다. 퇴사 번호·예약 `99999`를 자동 재사용하지 않는다.
- 합성 계정 전환은 별도 `demo-identity-setup worklog-demo-identities-20261103 2026-11-03` 명령이다. 고정 회사·5개 사원/계정 UUID·DB명·제한 migration 역할·현재 해시/역할·bootstrap 감사를 검증하고 충돌은 전체 롤백한다. 기존 DB에서 bootstrap/sample-data를 재실행하지 않는다.
- 내정보 7탭(기본/발령/가족/학력/자격/어학/주소·연락처), 실제 인사 항목과 미등록 구분, 담당자 상세 편집 및 최소 이력 추가. 발령은 실제 소속 이력을 읽는다. 주민등록번호 원문 입력/저장은 제공하지 않는다.
- V17의 두 전용 표에 복합 FK·FORCE RLS·최소 UPDATE 열 권한을 적용한다. 본인 상세는 본인 ID로만 읽고 새 개인정보를 공통 헤더·회사 목록·감사 원문에 추가하지 않는다.

| --- | --- | --- |
| 기존 담당자 | 99999 | 직원·담당자 |
| 기존 가상 사원 하나 | 26001 | 직원·승인자 |

위 사번은 현재 합성 자료의 입사일을 기준으로 한 값이다. 명령은 기존 사원의 실제 입사일과 회사 내 예약 번호를 읽고 배정한다. 기존 UUID·계정·신청·연차·일정·사진·인사 이력은 보존하며 변경 전후 사번과 담당자 이름 변경을 감사로 남긴다. 전용 합성 DB에서 실제 준비를 검증했으며 위 표를 공개 배포 완료 사실로 확대하지 않는다.

## 직접 실행한 검증

- 기준선: Java 단위132개·프론트262개 통과.
- 사번·CLI 단위별 RED→GREEN: 단위3+실제 PostgreSQL56개, 프론트23개 통과. 단건/일괄·동시 생성·회사 격리·비활성 사번 미재사용·동일 명령 재시도·연도/예약/한도·기존 bootstrap/독립 승인 준비 회귀와 새 CLI의 실제 전환·충돌 롤백·재실행 무변경을 포함한다.
- 인사 단위별 RED→GREEN: 실제 PostgreSQL 관련28개와 사진 단위3개, 본인 조회·현재 권한 회수·타 회사/RLS·동시 저장·버전 충돌·멱등성·감사 원문 제외·V16→17 자료 보존을 확인했다.
- 전체 Java: `mvnw.cmd -B -Dfrontend.skip=true verify`에서 단위138개 통과, PostgreSQL584개 중583개 통과·기대 목록1건 실패. 새 두 표가 실제 FORCE RLS 목록에 추가된 결과였고 보안 완화 없이 정확한 기대 목록에 두 표를 추가했다. `DatabaseFoundationIT`11개 재검증은 실패/오류/건너뜀0·BUILD SUCCESS다.
- 최종 프론트: `npm.cmd test -- --maxWorkers=2`의20파일285개 통과. 기존 50행 테스트의 부하 경합에 의한5초 초과와 비동기 초점 검증의 즉시 단언 실패는 원래 로그에 보존했다. 초점 단언을 실제 효과 완료를 기다리는 `waitFor`로 수정하고 작업자2개로 실행했다. 타입·Vite 빌드도 통과했다. 기존500kB 청크 안내는 의존성/설정 변경으로 숨기지 않는다.
- 최종 프론트 자산을 포함한 `mvnw.cmd -B -Dfrontend.skip=true -DskipTests package`가 성공했다. 이 추가 패키징은 테스트를 생략했으며 앞선 단위/통합 검증을 대신하지 않는다.
- 독립 사양 검토에서 누락 없음. 독립 품질 검토가 발견한 P2 두 건(세 폼 간 입력 유실, 이력409 재시도 불가)은13개 실패 테스트 후 수정했다. 다른 dirty 폼 제출 차단·영역별 취소·세 폼 이동/새로고침 확인·현재 이력 비교와 최신 버전 승인 재시도·503 동일 명령 보존을 관련37개 테스트와 재검토로 확인했다. 미해결 P1/P2 없음은 해당 정적 검토 범위의 결과다.

개발 작업트리 ignored `target/`에 `final-java-verify.log`, `final-rls-verify.log`, `final-frontend-tests-bounded.log`, 단위별 RED/GREEN 로그를 보존한다. 실패 로그를 지우거나 처음부터 통과한 것으로 기록하지 않는다.

## 합성 HTTP와 실제 화면

전용 `worklog_demo` 임시 DB와 loopback `18099` 앱에서 실제 HTTP110항목을 통과했다. 5사번 정상 인증·정확 역할·세션 회전/로그아웃·사진·실제 다른 고객사/권한/CSRF/오래된 버전·겸임자의 자기 승인403/자기 지정422·거부 시46개 업무표 무변경을 확인했다. 담당자의 정상 상세 수정과 동일 명령 재시도는 상세정보/감사 두 표만 바꾸고 본인 조회에 반영됐다. 실제 고객 자료·식별번호는 사용하지 않았다.

CUA에서 26002/99999/25001을 로그인하고 기본사항·실제 발령·가족/학력/자격/어학/주소 자료, 담당자 이름·사번, 직원/담당자/승인자 메뉴와 같은 사원 유지, 별도 권한 관리5명 목록, 탭 Home/End 이동을 확인했다. PC1280/모바일390의 페이지 가로 넘침은0이었다. 처음 실제 CSS 검증에서 선택 탭 배경이 전역 일반 버튼 규칙에 덮이는 문제를 발견해 공통 `t-btn`과 해당 컴포넌트 선택자로 수정했다. 같은 화면의 최종 배경은 `rgb(238,242,255)`·글자 `rgb(67,56,202)`·터치 높이44px이며 관련37개·타입/빌드를 통과했다.

`target/identity-personnel-ui-20261103/`에 HTTP/준비/인증/자기 승인/탭 대비 RED·GREEN·브라우저 관측과 화면을 보존한다. CSS 보완 전의 HTTP 자산 증거와 최종 빌드 자산 증거를 구분한다. 검증 세션은 정상 로그아웃했고 소유 앱/DB 종료·18099 해제를 확인했다. 초기 `main-class-manifest`는 자산도 포함하므로 종료의 전체 디렉터리 일치 값은 false다. 별도 대조에서 변경이 `static/react/app.js`/`app.css` 두 개뿐이고 Java class/SQL/설정은 전부 같음을 확인했다. 최종 두 자산의 실제 HTTP SHA도 빌드 결과와 같다. 최초 false 증거는 보존했다.

## 주요 변경 파일과 한계

인증 `AuthStore`/`CompanyAuthenticationProvider`/`LocalDemoLogin`, 메뉴 `App`/`navigation`, 자동 발급 `EmployeeNumbers`/`EmployeeService`/`OrgBulkService`, 합성 전환 `LocalDemoIdentitySetup`, 인사 `EmployeePersonalDetails*`/V17, 화면 `PersonalDetails`/`PersonnelPage`와 관련 테스트를 변경했다. 과거 V1~V16·라이브러리/빌드 버전은 수정하지 않았다.

공개 보안 통합·백업/독립 복원·V17 배포는 별도 결과로 기록한다. 현재 문서만으로 공개 배포·장시간 부하·전체 취약점 재검사·실제 개인정보 처리·상용 운영 수용 완료를 주장하지 않는다. 새 가족/학력/자격/어학 항목은 원본을 덮어쓰지 않는 추가 이력 방식이며 별도 복잡한 HR 코드/승인 체계는 구현하지 않았다.
