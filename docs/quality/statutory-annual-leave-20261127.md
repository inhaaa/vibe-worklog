# 법정 연차 자동 산정 검증 (D 묶음)

2026-11-27 서울 기준으로 로컬 합성 자료에서 다음을 확인했다. [설계](../superpowers/specs/2026-11-27-statutory-annual-leave-design.md) · [구현 계획](../superpowers/plans/2026-11-27-statutory-annual-leave.md) · [이전 결과](overtime-payroll-20261126.md)

- 회사가 연차 부여 기준(회계연도 기준·입사일 기준)을 고른다.
- 근로기준법 제60조의 근속 일수와 회계연도 첫해 비례 일수를 계산한다.
- 직전 기간 출근율과 입사 첫해 월 개근을 일일 근태로 판정한다.
- 담당자가 미리 본 뒤 일괄 반영하고, '확인 필요' 사원은 골라서 법정 일수로 반영한다.

[일일 근태 자동화 결과](daily-attendance-20261126.md#검증-환경)와 같다. 테스트 DB는 고정 기반 이미지로 띄운 전용 컨테이너(`127.0.0.1:25432`)이며, 전체 회귀 전에 새로 만들었다. 브라우저 확인은 같은 컨테이너 안의 일회용 DB(`tna_demo_d`, `tna_demo_d2`)에 로컬 데모 회사를 만들어 했다.

## 코드 검토에서 고친 점

작업 단위마다 독립 검토를 했고 다음을 고쳤다(`39dfa21`, `d3937a3`, `9906db1`).

- **기초 잔여 이중 부여**: 월 연차 일괄 반영이 기초 잔여에 이미 들어 있는 달까지 개근으로 반영할 수 있었다. 그런 달은 '확인 필요(기초 잔여 확인 필요)'로 빼서 사원별 화면에서 판정한다.
- **이월 시험 복원**: 다음 해 반영의 이월·보류 시험이 미리보기만 확인하도록 줄어 있었다. 담당자 선택 반영으로 다시 끝까지 반영해 확인한다.
- **판정 불가 문구**: 근무 일정이 없는 날도 세므로 '근태 확정 전'을 '판정 불가 n일'로 바꿨다.
- **퇴사자와 미래 월**: 기념일 뒤에 퇴사해 비활성인 사원이 지난달 반영에서 빠지던 것을 고쳤다. 이번 달보다 뒤의 월은 미리보기·반영을 거절한다.
- **월 연차 일괄 화면**: 반영은 됐는데 다시 불러오기에 실패하면 결과를 잃던 것을 고쳤다. 응답을 잃으면 같은 명령으로 결과를 확인한다.

## 남은 점

- **'부여 대상'과 월 개근의 실제 흐름**
  - 출근율 80% 이상으로 바로 부여되는 행과, 월 연차의 개근·미개근 반영은 통합 테스트로만 확인했다.
  - 브라우저에서는 1년치 근무조·출퇴근 자료를 만들지 않아 모두 '확인 필요'였다.
- **입사일 기준 이월·소멸**: 통합 테스트로만 확인했다. 브라우저 DB에는 직전 기념일 묶음이 없었다.
- **도입 전 근태가 없는 사원**: 도입 첫해에는 거의 모두 '확인 필요'다. 담당자가 사정을 확인하고 골라 반영하는 것이 정상 흐름이다.
- **고정 이미지 브라우저 시나리오**: `verify-annual-leave-cycle.cjs`와 `AnnualLeaveCycleBrowser`는 고친 뒤 컴파일만 확인했다. 고정 DB 이미지를 이 PC에서 만들 수 없어 실행하지 못했다.
- **알려진 한계**
  - 이번 달 미리보기는 날짜가 바뀌면 토큰이 달라져 다시 미리 봐야 한다.
  - 반영 뒤 입사일을 고치면 직전 묶음이 이월 대상에서 빠질 수 있다.
  - 큰 회사에서는 미리보기·반영이 사원마다 1년치 근태를 읽는다. 속도는 재지 않았다.
- **범위 밖**
  - 연차 사용촉진(제61조)
  - 법보다 더 주는 회사별 표
  - 출근율 80% 미만 사원의 월 단위 자동 부여
  - 단시간 근로자 비례
  - 퇴사 정산 규칙 변경
