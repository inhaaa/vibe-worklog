# 공통 업무 그리드 적용·검증

> 상시 입력 박스를 없애는 후속 변경과 실제 최신 검증·공개 배포 준비는 [셀 직접 편집 보고서](sheet-cell-editing.md)를 따른다. 아래207개·618개·62개는 최초 공통 시트 단위의 검증 이력이다.

기준일: 2026-10-29, `Asia/Seoul`. 사용자가 [설계](../superpowers/specs/2026-10-29-common-sheet-design.md)를 승인하고 적용 가능한 표의 순차 전환·작은 단위 커밋·일반 Push를 위임했다. [실행 계획](../superpowers/plans/2026-10-29-common-sheet.md)과 [ADR-0005](../adr/0005-common-worklog-sheet.md)를 따른다. 공개 배포와 로컬 구현 결과는 구분한다.

## 적용과 보존

AG Grid Community/React **36.2.0**을 동일 버전으로 고정하고, MIT·React19 peer·TypeScript 요구를 공식 문서와 registry에서 확인했다. 페이지는 기존 제어형 입력·draft·업무 규칙·서버 Form을 유지하며 `WorklogSheet`에 typed 열·안정적인 행 ID·선택·변경·오류를 전달한다. 별도 그리드 엔진이나 DB/API를 만들지 않았다.

| 대상 | 적용 |
| --- | --- |
| 공통·근태코드 | 그룹·상세·근태코드 편집과 불변 정책 이력 |
| 조직·사원 | 조직/사원 편집, 조직장 이력, 선택 조직 직원 |
| 결재선 | 정의 편집, 버전, 사원/조직별 배정 이력 |
| 관리·회사 현황 | 기존 단건 화면의 직원/조직/소속/승인자/일정 버전·배정 조회, 계정별 권한, 회사 대상 사원·일별 현황·신청 |
| 개인·근태 검토 | 홈 최근 신청, 신청 목록, 연차 원장, 일 결과, 당시/현재 출퇴근, 감사 목록 |

기존 표를 사용하는 7개 페이지 파일의 해당 표를 전환했다. 남은 native table은 `AdminPages.ScheduleFields`의 7요일 시간·휴게 입력 행렬 한 곳이다. Spring의 field name/index 바인딩을 보존한다. 달력·계층 조직도·홈 카드와 표가 아닌 폼/목록은 목적에 맞는 구조를 유지한다. 원래 `codex/annual-requests`의 미커밋 연간 신청·V15는 이번 커밋에 포함하거나 수정하지 않았다.

현재 페이지 정렬/필터와 불러온 전체 이력을 구분해서 안내한다. 필터로 숨은 행도 변경·선택·저장·취소 범위에 남는다. 저장된 행의 `비활성화`는 기존 이력을 보존하고, 미저장 신규 행만 화면에서 제거한다. `commandId`, `expectedVersion`, 사유, 50행 한도, 409/422 편집 보존과 503 결과 미확정 재시도는 기존 계약을 유지한다.

## 검증 결과

| 실행 | 실제 결과 |
| --- | --- |
| `npm --prefix frontend test` | 15파일 **207개 통과**. AG Grid 비동기 행/셀 준비를 기다리는 실제 jsdom DOM 검사 |
| TypeScript·Vite production build | 통과. Community만 설치, Enterprise 미설치 |
| 최종 JAR 패키징 | 통과. 빌드한 프론트8개 파일과 JAR 내 해당 경로의 바이트 불일치0 |
| Maven `verify` | 단위105 + 전용 PostgreSQL 통합513 = **618개**, 실패/오류/skip0, BUILD SUCCESS |
| Python 도구 회귀 | 프로젝트 JDK25를 자식 프로세스에 지정해 **62개 통과** |
| npm audit | runtime 및 개발 의존성 포함 전체 모두 취약점 매치0 |
| 스타일·HTTP 공급 | CSS·폰트/SVG 자산 계약3개와 기존 proxy5개를 프론트207개에 포함. HTML shell Java9개는 Java105개에 포함 |
| production 검증 프록시 | 별도 ignored Node 표준 라이브러리 fixture 자체 검사4개, 실제 JS/CSS·SVG4개·WOFF2 1개 정상 응답·MIME·nosniff 확인 |

Java 검증은 프로젝트 전용 JDK25와 Docker/Testcontainers 경로에서 실행했고 호스트 JDK8·전역 신뢰·기본 DB·Compose 설정은 바꾸지 않았다. Python 첫 실행은 전역 JDK8의 javac 때문에 truststore fixture 준비가 실패했으며 프로젝트 JDK25를 지정한 재실행62개가 최종 결과다. 새 Flyway 파일은 없다.

첫 전체 프론트 실행의 기존 결재선 포커스 검사와, 전환 뒤 fragment 링크 검사/중첩 빈 그리드 준비 검사를 실제 비동기 DOM 기준으로 보완했다. 그리드가 있는 다수 jsdom 파일의 과도한 동시 실행을 피하도록 worker2·개별 제한15초를 사용한다. 테스트를 생략하거나 가짜 그리드로 대체하지 않았다.

버튼 문구 통일 뒤 관련64개와 최종 전체207개를 다시 통과했다. 이후 CSS의 모바일 버튼 한 줄 표시·읽기 전용/변경 셀 강조는 스타일 공급3개·production build·실제390px 화면으로 추가 검증했다. 이 문서 작업은 링크·범위 검증으로 확인하며 코드 테스트를 다시 실행한 것으로 표시하지 않는다.

## 실제 브라우저 확인

기존 로컬 합성 데모 백엔드를 이용했다. Vite `127.0.0.1:5175`에서 편집·취소·포커스를 확인하고, 최종 빌드 파일과 실제 로컬 백엔드를 연결한 `127.0.0.1:18100`의 읽기 검증 프록시에서 strict CSP를 확인했다. 프록시는 HTML에 검증된 `sheet.css` 링크를 넣으며 일반 업무 쓰기를405로 차단한다. 이 결과를 새 JAR 실행·외부 배포나 실제 DB 저장 검증으로 확대하지 않는다.

- production PC1280px: 근태코드와 그 이력, 사원, 조직, 결재선, 권한, 회사 일별 현황, 회사 신청의 빈 상태, 전체 신청, 월 일 결과, 감사 목록을 확인했다. 마지막9개 경로의 가로 넘침0·인라인 style 태그0, 콘솔 error/warn0이었다.
- production390px: 사원·근태코드·결재선·회사 일별 현황·월 일 결과·감사의6개 경로 모두 문서 가로 넘침0이었다. 시트는 내부 가로 스크롤을 제공한다.
- 열 크기160→200px 조절을 실제 드래그로 확인했다.390px 내부 스크롤의 scrollLeft0→813과 선택 열 유지,600px 미만 식별 열 고정 해제·desktop 복귀 복원을 확인했다.
- 저장하지 않은 새 행을 추가·편집한 뒤 Tab과 방향키 이동, 필터로 숨은 선택/변경 건수, 취소 복원을 확인했다. 기본 DB에 이 편집을 저장하지 않았다. 실제 저장 payload·409/422/503·미저장 이동은 프론트 회귀에서 검증했다.
- 사원 배정 문맥은 초기160px 내용이111px 셀에서 잘리는 것을 측정했다. 공통 line-height를 수정한 뒤75.78px 내용과 모든 상세/근무/계정 링크가111px 셀 안에 들어왔다.
- 최종 모바일의 입력/비활성화/저장/취소 버튼은 모두44px 높이·한 줄 문구로 표시했다. 읽기 전용 값은 별도 배경으로 구분한다.
- 월 계산 근거에 줄바꿈·자동 높이를 적용했다. 현재 합성 데모의 미산정31행에서 내용 잘림0을 측정했다. 모든 장문·실사용 자료 조합을 브라우저로 검증했다는 의미는 아니다.

리뷰에서 마지막/첫 경계 행과 로컬 필터의 Enter가 암시적 저장을 일으키는 문제, 한글 조합 확정이 행 이동으로 처리되는 문제를 발견했다. 실패 테스트를 먼저 확인하고 수정했으며 공통17개 테스트는 Enter 경계·조합 입력·키보드·선택·오류·모바일 복원을 포함한다.

증거는 ignored `target/sheet-*.log/json`과 `target/common-sheet/`의 production proxy probe, PC/mobile DOM proof, 스크린샷에 보존했다. 브라우저 viewport 임시 설정은 원복했다.

## 커밋과 작업트리

시작점은 `ed96992`, 분리한 브랜치는 `codex/common-sheet`다. 설계·스타일/CSP·공통 모듈·코드·조직/사원·결재선·권한/회사 조회·근태 조회·키보드/모바일·문구·표시 보완을 작은 단위로 커밋하고 각각 일반 Push했다. 문서 직전 구현 커밋은 `15b8ebc`이며 최종 문서 커밋은 Git 이력을 따른다. 원본 연간 신청 작업트리와 공개 전용 작업트리는 그대로 보존한다.

## 보안·남은 범위

`script-src 'self'; style-src 'self'; img-src 'self'`를 유지했다. legacy Quartz CSS의 data URL 글꼴1개·SVG4개를 같은 출처 파일로 빌드하므로 unsafe-inline·unsafe-eval·data:·CDN 허용을 추가하지 않았다. 실제 strict CSP 브라우저에서 오류 없이 표시했다.

내장 XLSX·Excel형 clipboard·셀 범위 선택은 유료 범위여서 도입하지 않았다. 기존 서버의 검토용 Excel을 유지한다. 새 전체 데이터 정렬 API도 없으며 현재 불러온 행만 정렬한다. 번들은 JS 약1.59MB/gzip438KB·CSS269KB/gzip34KB이며 Vite500KB 경고가 남는다. 새 이미지의 장시간 부하·OS/컨테이너 취약점 전수 검사는 이번에 실행하지 않았다.

최초 공통 시트 단위 당시 공개 `worklog.inhaaa.com` 배포는 **미실행**이었다. 이후 클릭 편집·모바일 표시 보완과 `12f0f78`·V14 공개 반영은 [후속 실제 배포 결과](public-sheet-deploy-20261029.md)를 따른다. 아래는 당시 연결 준비 이력이다. 마지막 공개 문서 기록은 `efd13ea`·V13이며, 이번에는 health200/UP만 확인했고 현재 서버 내부 SHA·스키마·자원은 조회하지 못했다. 전용 공개 worktree는 clean(`2ac6ea5`)이었다. 정상 SSH 자격·연결이 준비되어 있지 않고 기존 Hostinger Webconsole도 이번 연결 표면에 없어 서버 변경을 실행하지 않았다. 사용자 승인이 부족해서 멈춘 것은 아니다.

개발본에는 공개 문서 기준 아직 반영하지 않은 V14가 포함되어 있으므로 [공개 갱신 절차](../development/worklog-public-updates.md)에 따른 보안 통합·전용 백업·독립 복원·자료 보존 검증을 먼저 해야 한다. 개발본을 현재 공개 소스로 덮어쓰거나 UI만 무마이그레이션 경로로 교체하지 않았다. PriceSys·기존 demo·portfolio와 전역 Docker/DNS/Caddy는 변경하지 않았다.
