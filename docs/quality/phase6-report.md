# Phase 6 로컬 품질 검증 보고서

이 문서는 첫 Phase 6 실행 당시 기록이다. 이후 전체396개 회귀·보안 패치·전체 의존성/이미지 검사와 HTTP 지속 부하의 최신 결과·한계는 [후속 보고서](http-soak-vulnerability.md)를 따른다. 아래383개와 당시 미실시 항목을 후속 결과로 덮어쓰지 않는다.

## 기준과 판정

검증일: **2026-10-25, Asia/Seoul**. [PRD](../prd.md)의 고정 근무 MVP와 [실행 계획](../superpowers/plans/2026-10-25-phase6-quality.md)을 기준으로 합성 데이터만 사용했다. 범위는 로컬 기능 연결·회귀·권한·격리·동시성·탐색적 부하·논리 복원이다. 실제 고객에 대한 법적 적용·운영 출시 판정은 별도다.

**로컬 검증 통과:** 전체383개(단위39·실제 PostgreSQL 통합344), 실패·오류·건너뜀0. 초기368개에 새15개 회귀/연결 테스트를 추가했다. 최종 Linux app/migrate 이미지 빌드·로컬 Compose 기동, V10 유지·FORCE RLS34개·최소4역할·고객사/계정/운영자0·loopback·uid10001·read-only·운영자 비활성·관리 자격 미주입을 재확인했다. 새 이미지의 실제 HTTP 보안24개와 프록시 환경변수 우회 검사도 통과했다.

MVP S01~S10과 SEC-01~12의 아래 **명시된 자동 검증 범위**를 점검했다. 남은 외부 프록시·실사용·운영 부하·전체 취약점/침투 검증은 미완료로 유지한다. 이번 범위에서 재현한 Q01~Q03은 모두 수정·검증했다.

## 백업·논리 복원

전용 새 Testcontainers의 A/B 합성 데이터만 사용했다. 같은 클러스터의 별도 새 DB에 custom dump를 단일 트랜잭션으로 복원했다. 원본 DB명으로 다시 연결하는 `--create`와 기존 객체를 삭제하는 `--clean`을 사용하지 않는다. 소유자·ACL을 생략하지 않는다. [pg_dump](https://www.postgresql.org/docs/18/app-pgdump.html), [pg_restore](https://www.postgresql.org/docs/18/app-pgrestore.html)의 공식 동작을 기준으로 삼았다.

복원 성공: dump262ms·restore299ms. 원본 불변, 전체 업무표/Flyway 행 수·원천/결과/XLSX/감사 SHA14개·계산 입력/파일 바이트·소유자·SECURITY DEFINER·정책·FORCE RLS34개를 대조했다. 실제 앱 역할의 A/B 격리·컨텍스트 해제와 auth/operator의 업무 SELECT 거부, 초대/RESET 목적 범위를 확인했다. 자료는2고객사·2사원·4토큰·4원천·2계산실행·2일결과·2XLSX·2감사다.

dump/restore가 동일한 고정 문자열 배열을 배열 전체 cast와 원소별 cast로 다르게 표현한3개 인증 정책은 정확한 두 상수·타입 변환 형태만 비교 정규화했다. 원본/복원 raw manifest를 모두 보존하고 실제 인증 역할의 목적/고객사 접근도 검사했다. 이 결과는 기존 글로벌 역할이 있는 동일 클러스터의 소규모 논리 복원이다. 클러스터 유실·역할 재구축·다른 서버·대용량·백업 암호화/오프사이트·운영 RPO/RTO는 검증하지 않았다.

```powershell
python scripts/verify-local-http.py --port 18080
```

로컬 네트워크용 Maven 설정이 필요하면 [개발 안내](../development/local.md)의 ignored 설정을 사용한다. 부하 도구도 기본 새 컨테이너로 실행하고, 수동 테스트 JDBC 설정 시 기존 loopback·전용 DB 제한을 따른다. 복원 도구는 외부 지정 DB를 시작 전에 거부한다. HTTP 도구는 proxy/redirect를 해제한127.0.0.1 직결만 사용하며 기본 운영자 비활성 구성을 전제로 한다.

산출물은 ignored `target/phase6-*`의 실행 로그·부하/복원/HTTP JSON·덤프·raw manifest다. 비밀값·실제 개인정보는 커밋하지 않는다. 각 도구는 샘플/격리/중복/불변성 assert가 실패하면 비정상 종료한다.

## 남은 운영 수용 조건

- 실제 고객의 법 적용·휴게/연차 근거·데이터 처리·보존/파기·국내 리전·개인정보 고지 검토.
- 실제 메일 초대/복구 전달·배송 실패와 abuse 대응, Caddy/HTTPS·인프라 방화벽·비밀 회전·모니터링.
- 실제 파일럿 브라우저/모바일·접근성·Excel 데스크톱 대조와 사용자 평가.
- 운영 사양의 HTTP 혼합 부하·로그인 폭주·장시간 soak·300명 전체 일괄 집계·이력 누적·장애/리소스 고갈 실험.
- 전체 의존성·이미지 취약점 검사, 독립 침투 점검·사고 대응과 오프사이트 복구 훈련.

외부 서버 접속·배포·실제 메일·실고객 자료 사용은 하지 않았다. 다음은 위 조건을 구체화하는 파일럿 준비이며 실제 고객 연결이나 배포는 별도 승인 범위다.
