# React 권한·메뉴·내 정보 구현 검증

기준일: **2026-10-27, Asia/Seoul**. 사용자가 승인한 [업무 확장 1단계](../superpowers/specs/2026-10-26-worklog-service-design.md)와 [실행 계획](../superpowers/plans/2026-10-27-react-identity-access.md)을 구현하고 로컬 검증·V11 반영을 완료했다. Java515개·React113개·실제 HTTP51개·PC/모바일9회 관측과 기존 DB 보존을 확인했다. 운영 공개 완료를 뜻하지 않는다.

## 구현 범위

- 대표 `COMPANY_REPRESENTATIVE`를 기존 공통·관리자·결재 기능과 독립적으로 부여/회수한다. 역할 변경의 기존 세션 회수·감사·마지막 관리자 보호를 유지한다.
- React 공통 메뉴와 상단 이름에 **내 정보**를 추가한다. 본인 계정의 이름·사번·회사·이메일·재직·현재 소속/근무/지정 결재자·역할을 읽기 전용으로 제공한다. 미배정·결재자 재지정 필요를 구분한다.
- **권한 관리** 목록은 관리자만 조회하고 기존 사원별 계정·역할 화면으로 연결한다. 대표 체크박스를 추가하며 기존 APPROVER 체크 상태를 함께 제출한다. 현재 단건 POST는 전체 역할 선택 계약이며 부분 역할 시트 저장은 후속이다.
- 관리자/대표의 **회사 근무현황·신청 현황**을 새 읽기 경로로 제공한다. 사원/조직·월/연도·상태와50행 페이지를 지원하고, 회사 근무는 목록과 선택 사원1명의 월 일 결과를 조회한다. 검색/조직은 서울 기준 오늘 소속이다.
- 대표 단독 계정에는 관리자 설정·재집계·원장 조정·감사·관리자 Excel을 허용하지 않는다. 실제 결재는 기존 APPROVER와 현재 배정·독립 승인 조건을 유지한다.
- 회사 목록은 자유 사유·이메일·IP·정정 원문·계산 근거·세션 정보를 제공하지 않는다. 미산정/오래된 결과의 예정·실근로·휴가는 현재 수치로 사용하지 않고 미확정으로 표시한다.

조직장·조직도·새 결재선·시트형 일괄 편집·근태/공통코드·본인 연도별 집계/모달·월간 그래프는 후속이다. 기존 종일 연차·CALC-1·원장·허용망을 변경하지 않는다.

## 권한·DB 경계

`V11__company_representative.sql`은 `role_grant` 허용값 CHECK에 대표만 추가한다. 기존 V1~V10·업무 행·DB 역할·RLS·권한은 보존한다. 일반 웹앱에는 마이그레이션 비밀번호를 넣지 않으며 별도 migrate로 적용한다.

`CompanyReadAccess`는 같은 tenant 공유 advisory 잠금과 현재 계정·재직·공통 및 관리자/대표 역할·auth_version을 조회 진입과 반환 전에 검증한다. 기존 관리자/일반 업무 쓰기 경계는 넓히지 않는다. 본인 정보는 principal 대상에 고정하고 공유 읽기 및 기존 본인 권한의 반환 전 검증을 유지한다. 새 조회에서는 업무·감사·재집계 결과를 저장하지 않는다.

새 React 데이터는 페이지 allowlist와 안전 DTO만 사용한다. 회사 URL은 GET만 허용하며 Vite 개발 프록시에도 같은 회사 경로를 추가했다. 기존 로그인·CSRF·JSON/HTML·no-store·303/409/422·다운로드 계약을 유지한다. 고정 로컬 데모의 정확한 역할 경계는 보존하며 대표 로그인 검증은 별도 합성 계정을 사용한다.

### 실패를 먼저 확인한 경로

- React 신규14개는 메뉴·화면·대표 선택의 부재로 실패한 뒤 구현했다. 개발 프록시1개도 회사 경로 부재로 실패를 확인했다.
- 새 React 페이지 allowlist 단위 테스트는 미등록 view가 null인 실패를 확인한 뒤 등록했다. 기존 바깥 모델의 비공개 필드 제외도 함께 검증한다.
- `CompanyReadAccessIT`는 회사 읽기 경계 부재를 먼저 확인하고, 이후 역할/재직/세션·타 회사·반환 전 회수·컨텍스트 해제·공유 읽기/실제 독점 변경 대기를 검증한다.
- 권한 목록/대표 역할 웹 테스트의 첫 실패는 합성 회사코드 대소문자 때문에 로그인에 실패한 fixture 결함이었다. 이를 기능 RED로 취급하지 않았다. fixture 수정 후 해당 두 동작만 기존 상태로 되돌려 목록200 기대/실제403, 대표 저장303 기대/실제422를 확인하고 신규 구현을 복원했다.
- 본인 정보 GET은 기존403/기대200을 확인했다. 새 대표의 DB 허용값이 없을 때 발생한 CHECK 실패는 별도 스키마 부재 증거로 구분한다.

### 통합 중 발견·수정

- 신규 Controller가 기존 `OrgErrorAdvice` 대상에서 누락돼404/422가 안전한 문제 화면으로 처리되지 않았다. 공통 오류 처리 대상에 추가하고 기존 실패 회귀를 유지했다.
- 프로필의 공유잠금 Mapper가 `void`를 반환해 MyBatis가 PostgreSQL 반환값을 매핑하지 못했다. 직접 Mapper 회귀에서 `No constructor found in void matching [java.lang.String]`를 확인하고 기존 패턴과 같은 `Object`로 수정했다.
- 독립 리뷰에서 선택 사원 B의 월 변경 시 첫 사원 A로 바뀌는 문제를 발견했다. 신규3개 행동 회귀로 실패를 확인한 뒤 월 변경은 사원을 유지하고 조직/검색 변경만 선택을 초기화했다. 회사 검색 상한도 서버와100자로 맞췄다.
- Python 첫 기준 실행은 호스트 Java8로 합성 인증서 도구를 컴파일해 실패했다. 코드/호스트 설정을 바꾸지 않고 기존 프로젝트 전용 JDK25의 자식 환경으로 재실행해62개를 통과했다.

독립 명세/보안 리뷰와 P2 재검토에서 추가 P1/P2는 발견하지 못했다. 리뷰는 실제 테스트/브라우저 결과를 대신하지 않는다.

## 로컬 DB 보존과 적용

기본 DB의 변경 전 컨테이너·이미지·볼륨, 업무34개 테이블의 전체 행 SHA256·행 수·RLS/ACL과 Flyway V10을 기록하고 custom-format 백업을 보존했다. 기존 보고서의35개는 업무34개와 public Flyway 이력1개를 합한 전체 테이블 수다. 백업 첫 검사에서 업무 테이블만35개로 기대한 검증 오류를 바로잡고 실제34+1 범위를 확인했다.

새 app/migrate 빌드는 성공했고 기본 DB의 V10에 V11 한 건을 추가해 migrate 종료0을 확인했다. 기본 app은 새 이미지로 running이다. DB 컨테이너/이미지/볼륨·기존 업무34개 테이블 전체 행·RLS/ACL은 전후 동일하며, 데모 계정의 역할은 EMPLOYEE·ATTENDANCE_ADMIN으로 보존했다. 새 앱은 UID10001·읽기 전용 root·cap drop ALL·NNP·loopback18080을 유지한다.

실행 JAR의 `BOOT-INF/classes/`234개 항목은 검증 JAR과 바이트가 같다. 앱 image는 `sha256:ec5b3dc6bec9abb9cecfc7008609db63b53a70550336f30f437d399f99b59660`이다. 이번 새 이미지에 이전33분 부하·보안 검사 성적을 옮기지 않는다.

### 실제 HTTP·화면과 임시 자원

기본 데모에서 새 네 조회 경로를 확인했다. 별도 fixture의 관리자 로그인→기존 역할 POST로 대표 부여→옛 세션401→새 대표 로그인→회사 조회200·타 회사404·관리/미지정 결재403을 확인했다. 실제 신청 목록에서도 자유 사유·개인 이메일·정정/계산 증빙을 노출하지 않는다. 이는 새로운 합성 전용 DB이며 기본 서비스 자료에 대표 테스트 계정을 추가하지 않았다.

브라우저에서는 내 정보·권한 목록·대표 체크박스 진입과 관리자/대표 회사 조회, 대표 메뉴의 관리자·결재 링크0개, 선택 사원의 월 변경 유지, PC·390px viewport의 표/빈 상태를 확인했다.390px에서 스크롤바를 제외한 본문 clientWidth는375/390px다.9회 관측의 가로 넘침·콘솔 오류는0이며 임시 viewport는 복원했다.

fixture 첫 시작은 분리 작업 폴더의 출력 target 디렉터리 누락으로 종료됐다. 출력 폴더 생성 후 새 owned DB로 재시작했으며 첫 실패 로그도 보존했다. 최종 fixture는 정상 종료했고 원천55,800건·대기3건·승인0·재생 중복0을 확인했다. 기본 서비스는 유지한다.

## 근거·미실시 범위

원본은 Git 제외 `target/identity-access-20261027/`의 baseline·RED/GREEN·프런트·최종 Java 로그와 DB 전후 JSON·백업·로컬 빌드/HTTP/화면 기록에 보존한다. 비밀값·토큰·백업·원본 데이터·dist·target은 커밋하지 않는다.

이번 단위는 신규33분 부하·전체 이미지 취약점 재검사·외부 서버 접속·운영 배포·실고객/실제 메일 검증을 포함하지 않는다. 기존 [no-XML 부하](no-xml-soak.md)·[보안/공급](react-residual-impact.md)의 수행 이력과 잔여 조건을 유지하며 이번 이미지의 동일 검증으로 확대하지 않는다. 공개 서비스 수용은 별도다.
