공개 브라우저는 정상 데모 로그인·업무 메뉴로 진입했다. 사용 가능12DAY와 실제 서버 미리보기1DAY, 결재 담당 미지정을 확인했고 최종 제출은 비활성으로 유지됐다. 미리보기에서 내용 수정으로 돌아가도 입력이 보존됐다. 깨끗한 작성 창은 Escape로 닫히고 신청 버튼으로 초점이 복귀했다. 공개 공유 자료에는 검증 신청을 추가하지 않았다.

실제 접수 성공은 **독립 승인자가 있는 전용 합성 로컬 환경**에서 검증했다. 유형 → 내용 → 서버 미리보기 → 최종 제출 → 접수 완료 → 생성 신청 상세를 실제 화면으로 수행했다. 미리보기는 DB 무변경, 제출은 본인 PENDING 신청/이벤트/감사가 정확1건 증가하고 원장·20DAY 잔여는 그대로였다. 상세는 실제 저장된 승인자·처리 이력만 표시했다. [로컬 결과](request-workspace-20261103.md)의 증거·한계를 함께 따른다.

## 준비 중 발견과 증거

첫 전송 묶음은 순수 가드가 import하는 `prepare-package.py`가 빠져 서버 가드17개 중1개가 오류였다. 앱 교체/빌드/자료 조회 단계에 진입하기 전 멈췄다. 누락을 로컬 재현하고 전송 의존성 확인을 추가한 뒤 수정 묶음의 전체 파일/바이트/SHA를 확인하고 서버17개를 다시 통과했다. 최초 묶음과 서버 디렉터리는 삭제하지 않고 별도 보존했다. 제품 소스는 이 수정으로 바뀌지 않았다.

수정 전송은30파일189,835바이트, SHA `30c5711d97283e627cf5886e1ad10ede878ac7e204075d852638033b1ca8aab4`다. 서버 단계는 package → before → source → build → artifact → app → final 순으로 실제 통과했다. runtime/migrate JAR 동일성과 공개 보호 클래스·11자산·16마이그레이션을 앱 반영 전에 확인했다.

서버 증거는 `/srv/worklog/.local/request-workspace-20261103`에, 비밀값/원본 행을 포함하지 않는 수집 요약과 공개 검증/화면은 공개 작업트리 ignored `target/request-workspace-deploy-20261103/`에 보존했다. 대표 파일은 `server-deployment-summary.json`, `browser-proof.json`, `verify-public-demo-result.json`, `network-proof-result.json`, `photo-proof.json`, `assets-result.json`, `public-overview-desktop.jpg`, `public-{type,content,review}-{desktop,mobile}.jpg`다. 실제 접수 화면은 개발 작업트리의 `target/request-workspace-ui-20261103/`에 있다.

로컬 검증 앱·전용 합성 DB/볼륨·Ryuk 종료와18097 포트 해제를 확인했다. 검증용 뷰포트는 복구했다. Docker Desktop은 실행 상태로 두며 기존 도구/컨테이너를 정리하지 않았다.

새 Java 전체·기존 Python74개 전체·장시간 부하·전체 취약점 스캔은 다시 실행하지 않았다. 과거 작업의 Java728/Python74 통과를 이번 실행으로 합산하지 않는다. 공개 Vite의 기존 큰 chunk 경고는 남고 임계값을 완화하지 않았다. 미저장 native 확인창의 실제 승인/취소는 CUA에 창이 노출되지 않아 수동 UI 검증 완료로 계산하지 않으며 관련 단위 테스트는 통과했다. 공개 공유 계정에서 승인자 미지정을 우회하지 않았다. 실제 고객/개인정보/메일·상용 수용은 범위 밖이다.
