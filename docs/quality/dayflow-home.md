# 흰색·파란 업무 테마의 하루 흐름 홈 (2026-10-26)

사용자의 후속 결정에 따라 기존 흰 배경·파란 포인트와 공통 메뉴를 유지하고 **홈의 배치만 하루의 흐름으로 변경**했다. [실행 계획](../superpowers/plans/2026-10-26-dayflow-home.md)과 [화면 계약](../design/screens.md)을 따른다. 소개·개인 달력·직원 목록의 기존 A안과 입력 없는 데모 입장은 유지한다. 이전 [A안 결과](workspace-ui.md)의 이미지 검사·성적은 당시 이력으로 보존한다.

## 적용 내용

- 큰 서울 날짜와 실제 본인 이름 아래에 시간순 일정·기록, 출퇴근·확인할 일, 주간7일, 최근 신청을 배치했다. 원천/현재 반영 비교와 실제 근로 확인·환경 정보는 접이식으로 제공한다.
- `DayView.timeline()`은 근무일의 존재하는 예정 근무·휴게 시각과 현재 반영 출퇴근을 서울 시각으로 정렬한다. 예정/현재 반영을 문구와 색으로 구분하며 동일 시각·중복 사건을 보존한다. 원천·승인 정정·실제 근로 확인을 변경하거나 근로시간·지각·연장을 판정하지 않는다.
- 미배정·미등록·미확인과 실제0을 구분한다. 시안의 이름·예시 시각·연차/시간 수치는 하드코딩하지 않았다. 기본 합성 DB에는 일정·연차·출퇴근을 추가하지 않아 실제 홈은 빈 상태다.
- 확인할 일의 실제 근로·휴게 확인 링크는 현재 반영 IN·OUT이 모두 있고 현재 확인이 없을 때 제공한다. 한쪽 기록이나 빈 기록을 완료/누락으로 판정하지 않는다. 링크는 기존 확인 폼의 검토 진입이며 저장 조건을 보장하지 않는다.
- 출퇴근 POST·CSRF·명령 ID·확인 버전/fingerprint·정상 데모 인증·본인 tenant 읽기·현재 권한 검증과 환경 상태 htmx 갱신을 보존했다. CSS는 `.t-home-flow` 아래에만 추가했다. DB 스키마·의존성·설정·공통 fragment·JavaScript는 변경하지 않았다.

단위 테스트는 예정/반영 정렬·서울 연도 경계·동시간/중복 보존·시각 누락·미배정/비근로일을 확인한다. 신규 WebIT는 독립 합성 tenant에서 실제 시각의 정렬·원천=반영 비교·OUT만 있는 중간 상태·확인 미저장·실제 주간7일 링크를 확인한다. IN만 있는 경우와 승인 정정으로 양쪽 비교값이 달라지는 홈 SSR은 이번 신규 WebIT의 직접 사례가 아니다. 기존 전체 회귀의 정정 효력 검증과 홈의 직접 관측 범위를 구분한다.

Java 통합은 Testcontainers 전용 PostgreSQL을 사용했고 기본 DB를 테스트 fixture로 사용하지 않았다. JDK25는 자식 프로세스에만 주입했으며 호스트 전역 JDK를 변경하지 않았다. 문서 상대 링크·변경 범위·UTF-8·`git diff --check`와 별도 읽기 검토도 확인했다.
