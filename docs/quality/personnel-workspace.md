# 업무 메뉴·인사정보·신청 화면 검증

기준일: 2026-11-02, Asia/Seoul. [승인 설계](../superpowers/specs/2026-11-01-workspace-navigation-employee-header-design.md)와 [구현 계약](../design/personnel-workspace.md)의 로컬 구현 결과다. 개발 브랜치는 `codex/annual-requests`이며 이전 미커밋 연간 신청/V15를 보존해 이 UI의 선행 기능으로 함께 검증했다. 별도 공통 그리드 검토안은 이번 변경에 포함하지 않는다.

## 구현

- 역할별 5개 대표메뉴·업무 묶음·26개 화면 링크의 3단계 트리, 현재 조상 펼침·상세 문맥·브레드크럼·모바일 메뉴를 구현했다. 공유 상세의 뒤로가기 문맥도 복원한다.
- 홈 메뉴를 없애고 첫 진입은 내 정보로 연결했다. 기존 오늘 URL은 출퇴근 화면으로 안내하며 오늘/과거일의 출퇴근 명령과 근로 확인을 구분했다.
- 공통 EmployeeHeader와 본인/관리자 사원별 탭, 선택 인사정보·사진·재직 상태 적용일/이력 등록 화면을 구현했다. 현재 로그인 사용자와 업무 대상 사원을 구분하고 전사/결재 조회에 민감 헤더를 추가하지 않았다.
- V16 인사정보·상태 이력과 별도 버전, 현재 권한·tenant SQL/FORCE RLS·명령 재시도·충돌 비교·감사를 연결했다. 계정 활성/인증·근태 계산은 인사 표시 상태와 독립적으로 유지한다.
- PNG/JPEG 128KiB·2048px·400만 픽셀 제한, 실제 디코딩/재인코딩과 인증 사진 조회를 구현했다. `photo?v=인사버전`으로 교체와 이전 로드 실패 후 갱신을 보장한다. 전역 multipart를 켜지 않았다.
- 신청 요약/검색·목록/모바일 카드, 유형→내용→확인 모달, 휴게 행 편집을 적용했다. 유형별 날짜·미리보기/오류 입력·중복 제출·초점·미저장 보호와 기존 연간 수치 계약을 유지한다.

## 자동 검증

| 검증 | 실제 결과 |
| --- | --- |
| 프로젝트 JDK25 전체 Maven verify | 단위116 + 실제 PostgreSQL 통합555 = **671개**, 실패/오류/skip0, 종료0 |
| 최종 React/Vitest | 19파일 **237개**, 실패0, 종료0 |
| TypeScript·Vite production build | 종료0, app.js/app.css 생성 |
| 보조 Python 도구 | 프로젝트 JDK25에서 **62개**, 실패/오류0 |
| 최종 JAR 패키징 | 종료0, React JS/CSS가 최종 dist와 바이트 일치, V16 포함 |
| 실제 loopback HTTP | **54요청·50검증**, 경고0 |
| 합성 논리 복원 | 종료0, 원본 불변, 인사/사진/상태 SHA256 4개 일치, FORCE RLS46개 |

Maven은 `mvnw.cmd -B -o -s target/local-maven-settings.xml -Dfrontend.skip=true verify`, React는 `npm.cmd test -- --maxWorkers=2`, 빌드는 `npm.cmd run build`를 실행했다. Java/DB 검증 후 프론트의 날짜/단계 회귀를 보완해 최종 프론트 전체를 재실행했고, 최신 프론트를 포함하도록 JAR을 다시 패키징했다. 재패키징 자체를 Java 전체 회귀 재실행으로 표현하지 않는다.

처음 보조 도구 실행은 호스트 기본 JDK8을 선택해 Java 문법 컴파일에서 실패했다. 전역 설정을 바꾸지 않고 해당 검증 프로세스에 프로젝트 JDK25를 지정해62개를 통과했다. 프론트51행 테스트는 화면 렌더 약0.3초 뒤 버튼의 전역 접근성 탐색에 약4.8초가 걸려5초 제한을 넘었다. 제한 시간을 늘리지 않고 동일 저장 버튼을 직접 찾도록 테스트 탐색을 줄인 뒤 전체237개를 통과했다.

## 경계·실제 화면

- 인사 조회/수정의 비관리자403·다른 테넌트404, 직접 SQL의 무컨텍스트/타 tenant 조회·쓰기 차단, 연결 재사용, 권한 회수와 현재 권한 재확인, CSRF403을 검증했다.
- 별도 인사 버전·같은 버전의 동시 저장1성공/1충돌·동일 명령 재시도·409 최신값 비교와 제출값/사진 보존, 미래 생년월일422, 상태 적용일·동일일 후속·입퇴사 경계를 확인했다.
- 사진 교체/유지/해제·PNG/JPEG 형식/크기/픽셀 제한·실제 이미지 반환·no-store/nosniff와 버전 URL 갱신을 확인했다. 독립 검토에서 발견한 같은 URL의 이전 사진 유지 문제는 RED 재현 후 수정했다.
- 전용 fixture-owned 앱 `127.0.0.1:18092`와 합성 사원만 사용했다. HTTP 검증은 새 합성 사원을 대상으로 진행했고 기존 로컬18080 앱/DB에는 변경 명령·마이그레이션을 실행하지 않았다.
- PC에서 실제 로그인→본인 헤더·업무 트리→인사 등록→저장 후 직급 헤더 갱신, 신청 유형·내용 단계·휴게 행 입력을 확인했다. 390px에서는 본인 헤더·탭·메뉴와 신청 모달의 가로 넘침이 없음을 관측했다. 라디오 크기·모바일 닫기 배치와 미래 연차→정정의 날짜/단계 이동을 보완했다.
- 브라우저의 미저장 닫기 확인창 이후 첫 검증 탭의 자동화 연결이 멈춰 해당 확인창 이후의 추가 브라우저 조작은 완료로 세지 않는다. 모달 닫기/확인·입력 보존·직렬화·Escape·초점은 자동 회귀를 별도로 통과했다.

원시 근거는 Git 제외 `target/personnel-ui/`의 frontend-final.log/frontend-build.log/python-jdk25-final.log/java-final.log/package-proof.json/http-proof.json과 캡처에 있다. 사진 회귀와 복원 근거는 `target/personnel-photo-version-{red,green}.log`, `target/personnel-recovery.log`, `target/phase6-recovery-result.json`이다. 실제 개인정보·메일·실고객 자료는 사용하지 않았다.

## 공개 반영 경계

이번 로컬 결과를 공개 반영으로 표현하지 않는다. 조사 시 최신 공개 작업트리는 `fd183b3`, 배포 기록의 실제 소스는 `3529a25`·V14이며 최신 공통 그리드/직접 편집을 포함한다. 개발본 전체로 대체하면 이 기능을 잃으므로 독립 통합이 필요하다. 새 인사 POST의 공유 계정 보호도 공개 경로·서비스 양쪽에 추가하고 V14→V16의 전용 백업/독립 복원·기존 자료 보존을 검증해야 한다.

이번 실행 환경에서 정상 SSH의22번 연결은 실제로 시간 초과했다. 이를 과거 기록만으로 추정하지 않았다. 서버·전역 Docker·DNS·Caddy·다른 프로젝트는 변경하지 않았다. 새 공개 배포·새 Linux 앱 이미지·33분 부하·전체 취약점 검사·실제 운영/법률 수용은 이번 로컬 완료 범위에 포함하지 않는다. 공개 연결과 통합을 마친 뒤 [후속 절차](../development/worklog-public-updates.md)의 별도 결과로 기록한다.
