# 선택근무제 로컬 인수 검증

2026년 11월 20일 · [업무 명세](../superpowers/specs/2026-11-20-selective-work.md) · [구현 계획](../superpowers/plans/2026-11-20-selective-work.md)

## 실제 브라우저에서 확인한 흐름

Chrome 157에서 전용 PostgreSQL의 합성 회사로 로그인했다. PC는 1440×900, 모바일은 390×844 터치 뷰포트를 사용했다. 서로 다른 사원으로 근무시간코드 생성과 개정, 근무조 요일 편성, 적용일 배정, 직원 캘린더 조회, 출퇴근, 실제 휴게 확인, 오전 반차 신청과 별도 결재자의 승인을 수행했다. 직원의 개인 근무현황과 담당자의 월 마감 화면에서 동일한 사원·기간을 재조회했다.

| 기간 목표 | 77시간 | 19시간 30분 |

실근로는 자동화가 실제 출근과 퇴근 버튼을 차례로 누른 시간 차이다. 예정 점심시간이 이 구간 밖에 있어 직원은 휴게 없음으로 확인했다. 선택 시간대·코어 이탈은 화면에 표시됐고 기록한 실근로도 합계에 포함됐다. 두 정산기간 모두 진행 중이어서 확정 차이는 유보됐다. 모바일에서 11월 30일~12월 6일에 걸친 한 주가 이어서 표시됐다. 두 너비 모두 가로 넘침과 JavaScript 페이지 오류는 0건이었다.

모바일 첫 실행에서는 근무조 저장 직후 사원 배정 탭으로 전환을 기다리다 시간이 초과됐다. 당시 화면에는 근무조 선택 목록이 열려 있었다. 같은 흐름을 다시 실행해 배정부터 승인·정산 대조까지 통과했다. 별도 합성 근무조 네 건은 저장 직후 첫 터치에 모두 정상 전환됐고 실제 터치 좌표도 사원 배정 버튼과 일치했다. 최초 실행은 터치 좌표를 남기지 않아 원인을 특정하지 못했다.

## 계산과 데이터 검증

- 윤일을 포함한 월경계 주에서 휴일·휴무일의 확인 근로, 입사·퇴사일, 근무조 전환, 홀수 표준분의 반차를 대조했다. 421분 기준의 반차는 210분 30초로 보존됐다.
- 실제 휴게 미확인·오래된 계산·정정 대기에는 잠정 합계를 표시했다. 종일 휴가와 실근로가 겹치면 회사 점검에서 미확정으로 남았다. 취소 승인과 재집계 후에는 목표 부족이나 코어 경고가 남아도 마감할 수 있었다.
- 마감 당시 정책과 근로·휴가 근거를 고정한 뒤 인사·근무조 기준이 달라져도 마감한 기간의 결과가 보존되는지 확인했다. 직원의 본인 조회와 담당자의 회사 내 사원 조회 결과가 일치했고 권한이 없는 계정과 타사 자료는 차단됐다.
- 기존 고정 근무 확인의 지문을 V31 형식과 대조했다. 선택근무에서 예정 휴게가 12~13시이고 12시 30분에 출근하면 확인 대상은 30분, 13시에 출근하면 0분이었다.
- 달력이 없는 날에도 정정 승인으로 실근로 1시간을 확인할 수 있었다. 이 상태의 마감은 거절됐고, 달력 등록과 재확인·재집계 후 마감됐다.
- 정산 카드에서 실제 휴게 미확인, 정정 결재 대기, 달력 미등록, 미산정과 재집계 필요를 구별했다. 사유가 같은 날짜가 여러 개여도 안내는 한 번만 표시된다.
- 이미 이틀을 집계한 사원의 퇴사일을 마감 전에 첫날로 소급했다. 마감 직전과 직후에 모두 1일·420분이었고 마감 후 인사 변경에도 보존됐다. 재개 후 대상이 이틀인 사원을 재집계해 다시 마감하자 2일·840분이 반영됐다.
- V31 합성 회사 두 곳에서 기존 시간코드 네 버전과 휴게 네 건이 V32에서도 고정근무로 보존됐다. V31에서 저장했던 고정 템플릿 등록·개정을 적용일 이틀 후 동일하게 재전송하면 최초 결과를 돌려줬다. 같은 명령 ID로 시간을 변경한 요청은 409, 새 명령으로 과거 날짜를 지정한 요청은 422였다.
- V32에서 V33으로 이관하면서 전체월, 재직 범위를 확인할 수 있는 부분월, 재직 범위가 불확실한 부분월, 해당 월 제외자를 대조했다. 불확실한 사원에게만 재개·재마감을 안내했고 기존 마감 Excel 행은 보존됐다. PostgreSQL에서 다른 회사의 정산 근거 읽기·쓰기와 일반 앱 역할의 마감 근거 수정·삭제가 차단됐다.

## 검증 환경과 빌드

Java 25와 전용 PostgreSQL 18.6 환경에서 최종 소스로 `mvn verify`를 실행했다. 서버 단위 테스트 222건과 통합 테스트 816건이 모두 통과했고 실패·오류·건너뜀은 0건이었다. TypeScript 검사와 Vite 빌드를 완료했으며, 화면 테스트 62개 파일의 696건도 모두 통과했다. 브라우저 검증이 끝난 뒤 전용 앱과 PostgreSQL 컨테이너를 종료하고 두 포트의 리스너가 해제된 것을 확인했다.

브라우저에서 실행한 JAR의 SHA-256은 `6be9645b4465e946d03134d76524bab28a64da44799eb8d5e8164387ddc3f645`다. 마지막 전체 회귀용 JAR과 대조한 내부 파일 907개의 내용이 모두 일치했다. 이 가운데 프런트 자산 101개는 Vite 빌드 출력과, 마이그레이션 33개는 저장소의 SQL과 바이트 단위로 일치했다.

실제 모바일 기기, 고객사 데이터와 공개 데모 배포는 이번 로컬 검증 범위 밖이다.
