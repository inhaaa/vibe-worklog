# 일일 근태 자동화 검증 (B 묶음)

2026-11-26 서울 기준. 다음 기능을 로컬 합성 자료로 확인했다. [설계](../superpowers/specs/2026-11-25-daily-attendance-automation-design.md) · [구현 계획](../superpowers/plans/2026-11-25-daily-attendance-automation.md) · [이전 결과](holiday-management-20261124.md)

- 퇴근하면 예정 휴게를 자동 적용하고 바로 집계한다.
- 근무시간코드를 기준으로 지각·조퇴를 판정한다.
- 날이 지난 무기록 근로일을 결근으로 판정한다.
- 결재를 처리하면 바로 재계산한다.
- 매일 새벽 일괄 작업으로 자동 확인하고 집계한다.

## 검증 환경

[계정 자동 생성 결과](account-provisioning-20261124.md#검증-환경)와 같다. JDK 25는 테스트 명령에만 쓴다. 테스트 DB는 고정 기반 이미지 `postgres:18.6-bookworm@sha256:bbf8…20fc`로 띄운 전용 컨테이너(`127.0.0.1:25432`)이며, 전체 회귀 전마다 새로 만들었다.

## 브라우저 확인

빈 테스트 DB에 로컬 데모 회사를 만들고(`local-demo-bootstrap`), 앱(`local,local-demo` 프로필)을 앱 내장 브라우저로 조작했다. 데모 관리자로 아래 기준을 화면에서 등록했다.

- 허용 네트워크: 127.0.0.1/32
- 2026년 공휴일
- 근무시간코드 `W01`: 09:00~18:00, 휴게 12:00~13:00
- 근무조 `G01`: 월~금 W01
- 사원 배정: 오늘부터

| 흐름 | 화면 | 결과 |
| --- | --- | --- |

브라우저 확인 중에 실제 홈(위젯 홈 `WorkspaceHome`)에 근태 표시가 빠진 것을 발견했다. 서버는 값을 보내고 있었고, 앞서 고친 곳은 다른 홈 컴포넌트였다. 위젯 홈에 표시를 추가하고 테스트를 넣었다(`d016416`).

## 남은 점

- **결근의 브라우저 확인**: 지난 날짜가 필요해 브라우저로는 확인하지 못했다. 통합 테스트(결근 판정, 연차 승인 뒤 해소, 새벽 일괄)로만 확인했다.
- **실행하지 못한 검증**
  - 새벽 00:10 스케줄러의 실제 실행
  - 서버 여러 대에서의 잠금
  - 고정 이미지 위의 테스트와 개통 브라우저 시나리오
  - 공개 데모 배포
- **설계와 다른 점**: 설계 §5의 '월말 점검 목록에 결근·지각·조퇴 행 표시'는 구현하지 않았다. 대신 담당자 '지각·조퇴·결근' 탭이 같은 역할을 한다. 월말 점검 목록은 결근을 더 이상 '확인 필요'로 세지 않는다.
- **홈·월 일정의 반차일**: 반차일에는 '확인 필요'를 표시하지 않는다(종일 휴가와 같게 처리).
- **퇴사자 처리**: 새벽 일괄 작업은 비활성(`active=false`)으로 바뀐 퇴사자를 건너뛴다.
