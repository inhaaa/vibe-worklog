# A안 워크스페이스 실제 적용 (2026-10-26)

> 이후 사용자 결정으로 흰색·파란 테마와 공통 메뉴를 유지하고 홈만 하루 흐름으로 변경했다. 최신 실행·검증은 [하루 흐름 홈 보고](dayflow-home.md)를 따르며 이 문서의 테스트 수·이미지/SBOM은 A안 적용 당시 이력이다.

사용자가 소개·홈·일정·직원 목록 시안을 승인하고 실제 화면 적용·검증·커밋·일반 Push를 요청한 단위다. [적용 계획](../superpowers/plans/2026-10-26-workspace-ui.md)과 [디자인 결정](../design/ui-redesign-proposal.md)을 따른다. 외부 배포는 하지 않는다.

## 적용한 화면과 동작

- 밝은 회색 배경·흰 카드·블루 강조의 A안을 실제 Thymeleaf 화면에 적용했다. 고객사 업무 화면은 공통 sidebar/header와 모바일 접이식 메뉴를 사용한다. 운영자·일반 로그인·토큰 수락의 별도 경계는 유지한다.
- `local,local-demo`에서 첫 주소와 `/login`은 소개 `/demo`로 안내한다. **데모로 입장** 버튼은 공개 합성 `admin / admin`을 숨김 필드와 CSRF로 기존 POST `/login`에 전달한다. 사용자는 회사코드·아이디·비밀번호를 입력하지 않는다.
- 실제 DB 해시·활성/재직·현재 역할·세션 ID 교체·세션 회수·속도 제한·CSRF·RLS는 유지한다. 일반 프로필의 회사코드·이메일 인증도 유지한다. 데모에 승인자·운영자 권한을 추가하지 않는다.
- 홈은 실제 사용 가능 연차·본인 대상 대기 신청·오늘 일정·반영 출퇴근·주간 일정·최근 신청을 표시한다. 기존 원천/실제 근로 확인 폼과 환경 상태 fragment는 접이식 영역에서 제공한다.
- `/me/schedule?month=YYYY-MM&date=YYYY-MM-DD`는 본인 월 달력과 날짜 상세를 조회한다. 기존 snapshot·신청/효력 조회를 같은 인증된 tenant 읽기 트랜잭션에서 조합하며 새 집계·자동 저장을 하지 않는다. 서울 날짜·월/연도 경계와 조회 월 밖 날짜 거부를 유지한다.
- 직원 목록은 실제 검색·소속/활성 필터·50명 페이지·선택 상세를 제공한다. 현재 소속만 조회하며 통계는 **현재 검색·필터·페이지**의 수치다. 활성 상태는 재직 기간과 구분한다. 등록·수정·소속/계정 관리의 기존 CSRF·commandId·version 계약을 보존한다.
- 기존 신청·조직·근무 설정·근태/계산·감사 화면도 같은 틀로 연결했다. 상세의 사원/월 복귀 링크와 서울 ISO 날짜의 `<time>` 표시를 보존했다.

현재 기본 DB의 합성 직원은1명이며 일정·기초 연차·원천 기록은 등록되지 않았다. 따라서 실제 화면은 `미배정`·`미등록`·`미기록`·`미확인`을 표시한다. 시안의8명·잔여8일·32시간을 실제 자료로 넣지 않았다. 승인 연차·취소 검토·0일·정정 효력과 실제 근로 확인은 구분한다.

## 검증 방법

신규 경로·모델·메뉴에 관한 테스트를 먼저 작성해 미구현으로 인한 실패를 확인한 뒤 구현했다. 별도 검토에서 발견한 달력 오류 advice 연결, POST 전용 메뉴 링크, 사원/월 상세 복귀 링크를 보완했다. 실제 통합에서 확인한 날짜 의미 요소와 테스트 공유 자료 간섭도 수정했다.

Java 검증은 전용 Testcontainers PostgreSQL에서 수행한다. 기본 DB와 다른 기존 컨테이너는 테스트 저장소로 사용하지 않는다. Python은 이 프로젝트의 JDK25를 자식 프로세스에만 주입해 실행한다. 기본 호스트 JDK 설정은 변경하지 않았다.
