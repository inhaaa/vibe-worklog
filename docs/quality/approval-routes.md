# React 결재선 관리·조직장 결재 검증

검증일은 2026-10-28 `Asia/Seoul`이다. 기준 커밋 `1f9d943` 위에서 사용자가 승인한 확장 3단계를 구현했다. [상세 계약](../design/approval-routes.md)과 [실행 계획](../superpowers/plans/2026-10-28-react-approval-routes.md)을 따른다. 아래 결과는 이번 단위의 실제 실행 근거로 갱신하며 이전 이미지의 부하·보안 검사와 구분한다.

## 변경 범위

- 관리자 React 결재선 정의 시트의 검색·입력·삭제 예정·저장·취소. 변경1~50행 원자 저장, 불변 버전, 코드 고정,409/422 편집·최신값·명령 보존.
- 사원/조직별 적용일 배정·교체·종료 이력. 서울 오늘 이후 구간, 이후 예약 보존, 대상 aggregate version 충돌과 명시적 재확인.
- 신규 신청은 사원 명시 결재선 → 기존 지정 승인자 → 오늘 소속 조직 결재선 순서다. 상위 경로 부적격 시 차단하며 조직장·대표의 관리/결재 기능을 자동 부여하지 않는다.
- 연차·정정·취소 모두 같은 resolver로 실제 담당을 결정하고 새 경로만 신청당 불변 스냅샷을 저장한다. 기존 배정·대기 담당·승인 결과·효력·원장·CALC-1은 보존한다. 재할당은 기존 명시 경로와 전후 이력을 유지한다.
- 지정 대기함과 본인 승인/반려 이력, 프로필의 실제 경로/차단 이유, 상세의 최초 결재선과 현재 담당을 구분한다. 조직·사원 이름은 고정된 당시 ID의 현재 표시 이름이며 과거 이름 복원은 제공하지 않는다.
- V13에 네 테이블·tenant 복합 FK·FORCE RLS·기간 중첩 차단과 신청 참조 XOR/지연 FK를 추가한다. 버전/스냅샷 UPDATE/DELETE와 최초 legacy 참조 두 열 UPDATE를 허용하지 않는다.

## 테스트와 발견 사항

변경 전 Java101+447=548개, React136개를 통과했다. 신규 서버 관리15개·신청14개와 React 초기6개는 신규 경로/테이블/화면 부재로 RED를 확인했다. React는 확정된 서버 page/model 계약으로도 실패를 재확인했다. 새 allowlist·감사 안전 요약2개도 먼저 실패시킨 뒤 구현했다.

첫 서버 선택 검증96개에서95개를 통과했다. 유일 실패는 회수된 역할의 옛 HTTP 세션이401인데 테스트가403을 기대한 경우다. 기존 현재 세션 검사에 맞춰401로 바로잡고 서비스 직접 재전송403을 추가했다. 보안 처리를 완화하지 않았다. 이후 감사 실패 원자 롤백과 실제 FK/XOR·불변 권한·채워진 snapshot RLS 검증을 보강했다.

화면 검토에서 입력 버튼이 작성 내용을 초기화하는 문제와 현재 배정 기본값을 미저장으로 판단하는 문제를 각각 RED로 재현했다. 입력은 초점 이동으로 바꾸고, 현재 배정과 실패 draft를 구분해 취소·이동 경고를 수정했다. 실제 화면 검증 결과와 최종 전체 수치는 아래 실행 결과에 기록한다.

실제 브라우저에서 완료 결재의 공통 메뉴·이름 누락을 발견했다. `WorkspaceWebConfiguration`에 새 경로 등록이 빠진 것이 원인이었다. 실제 로그인 세션의 HTML/JSON 회귀를 추가해 역할 `[]` RED를 확인하고 정확한 경로를 등록했다. 현재 권한 검사를 그대로 재사용하며, 보완 후 전체 Java586개와 새 이미지·새 합성 HTTP·화면을 다시 검증했다. 독립 재검토에서도 추가 P1/P2를 찾지 못했다.

로컬 DB 보존 도구의 최초 식별자 검사는 숫자가 들어간 기존 `over_8h_millis` 열을 거부했다. 기존 열명을 확인해 식별자 허용식을 바로잡고 백업/manifest를 다시 생성했다. 이 도구 오류는 제품 테스트 실패나 DB 자료 변경으로 집계하지 않는다.

추가 복원 도구는 최초에 기본 DB의 `postgres` 역할을 합성 fixture에 사용해 접속에 실패했다. fixture의 실제 `tna_test_admin`으로 수정한 뒤, 원본/복원의 enum CHECK4개에서 동일 값의 varchar 배열→text 캐스트 표현 차이를 확인했다. 해당 네 제약의 정확한 두 표현만 정규화했고 다른 FK·지연 속성·제약과 원시 manifest는 보존했다. 마지막 별도 작업 폴더의 fixture 준비 중 Dockerfile·출력 target 경로 누락도 확인해 기존 Dockerfile 복사와 출력 폴더 생성 후 재실행했다. 준비 실패는 성공 결과에 포함하지 않는다.

최종 앱 이미지는 `sha256:e60163fb4faab8e3db179e9340cb96f5c07b968a22a06eb4bf5212c60553b6fb`다. 보완 전 Java585개·첫 이미지의 실제 HTTP123건은 이력이며 최종 재실행 수에 더하지 않는다. 단위/통합 수는 Maven 실행 단계별 집계이며 과거 선택 실행으로 남은 Surefire XML을 디렉터리 전체 합산하지 않는다.
