# 회사 연차 부여와 직원 원장 검증

로컬 PostgreSQL의 가상 회사에서 서울 기준 2026년 1월 5일에 2026년 연차를 부여했다. 결재일과 1월 6일 오전 반차의 사용일을 구분해 확인했다. [업무 명세](../superpowers/plans/2026-11-21-annual-leave-ledger.md) · [재현 방법](../development/local.md#회사-연차-부여와-반차-승인-및-취소-검증)

## 담당자가 반영한 수량

담당자가 회사의 회계 시작월을 1월, 연간 부여량을 12일, 이월 한도를 3일로 저장했다. 아래 일수는 이 회사의 합성 기준이다. 두 번 미리 보며 사원별 기간과 수량을 대조했고 직원의 사용 가능 잔여는 확정 전까지 0일이었다.

| 대상 사원 | 전년도 확정 잔여 | 다음 연도로 이월 | 소멸 | 신규 부여 | 새 묶음 잔여 |
| --- | ---: | ---: | ---: | ---: | ---: |
| L101 | 4.5일 | 3일 | 1.5일 | 12일 | 15일 |
| L202 | 0일 | 0일 | 0일 | 12일 | 12일 |

첫 확정이 서버에서 성공한 뒤 브라우저로 오는 응답을 끊었다. 담당자가 화면에서 같은 명령으로 결과를 다시 요청하자 처음과 같은 적용 ID를 받았다. 사원별 부여가 늘어나지 않았고 2025년 묶음에서 전기 기초 4.5일과 이월 차감 3일·소멸 1.5일을 다시 조회했다.

## 직원과 결재자의 업무

직원과 결재자는 각각의 계정으로 로그인했다. 매 단계에서 L101의 신청 화면에 표시된 오늘 사용 가능 잔여를 개인 원장과 비교했다.

| 처리 시점 | 직원의 사용 가능 잔여 | 원장·신청에서 확인한 변화 |
| --- | ---: | --- |
| 연도 부여 확정 | 15일 | 12일 신규 부여와 전년도에서 이월한 3일 |
| 오전 반차 신청 | 15일 | 결재 대기 0.5일 |
| 반차 최종 승인 | 14.5일 | 사용 예정 0.5일, 원장 사용 −0.5일 |
| 취소 신청 | 14.5일 | 취소 대기 중 원승인 효력과 차감 유지 |
| 취소 최종 승인 | 15일 | 같은 사용에 +0.5일 복원, 사용 예정 0일 |

비교 사원 L202의 잔여는 첫 부여 직후와 L101의 취소 완료 후에 모두 12일이었다. L101의 2026년 원장에는 부여·이월·소멸 4행, 사용 1행, 복원 1행이 남았다. 직원 본인 조회·담당자 미리보기·결재 상세는 실제 WorkLog 화면을 사용했다. [브라우저 시나리오](../../scripts/verify-annual-leave-cycle.cjs)

최종 V37 앱과 같은 번들에서 Chrome 157.0.8103.52 데스크톱 1440×900 및 모바일 터치 에뮬레이션 390×844를 각각 실행했다. 각 환경에서 8단계가 통과했다. 두 결과 JSON의 미리보기·잔여·원장 6종이 일치했고, 화면 캡처는 각각 10장이었다. 최종 실행에서 조회 재시도와 브라우저 JavaScript 오류는 0건이었다.

## 연도 경계와 원장 보존

- 여러 전기 묶음은 사원별 이월 한도를 공유한다. 미분류·종료일 없는 묶음, 이미 당해 기초를 등록한 사원, 후속 연도를 먼저 처리한 사원을 구분한다. 다른 담당자가 추가 부여할 때에도 그 연도 첫 반영 기준을 사용한다.
- 전기 묶음에 차감형 휴가나 원휴가 취소가 대기 중인 직원은 해당 결재를 마친 후 다시 미리 본다. 다른 사원은 먼저 처리할 수 있다. 만료 이후 복원된 양은 원천 묶음에 검토 근거로 남는다.
- 전용 PostgreSQL에서 V36→V37 적용 후 기존 행과 권한을 대조했다. 이미 존재하던 원장 행에 부여 참조가 추가된 사례는 0건, 마이그레이션 재실행 시 적용 건수도 0건이었다. 회사 기준·회계연도·사원별 부여는 추가 전용으로 저장하고 회사 범위와 현재 권한을 확인한다. [도메인 검증](../../src/test/java/kr/tna/AnnualLeaveCycleIT.java) · [기존 데이터 업그레이드 검증](../../src/test/java/kr/tna/CodeMigrationUpgradeIT.java)
- 처음 계산한 회계연도는 시작월 개정에 맞춰 갱신된다. 직원이나 담당자가 지정한 조회 연도는 유지된다. 다른 담당자가 정책을 개정한 뒤 원래 저장 명령을 재전송하면 최초 개정의 일수를 돌려준다. 정수 입력란에 소수 연도·월·버전이 들어오면 HTTP 400으로 요청 전체를 거절한다. [화면 권한·입력·재시도 검증](../../src/test/java/kr/tna/AnnualLeaveCycleWebIT.java)

## 회귀 실행 결과

| 범위 | 최종 실행 결과 |
| --- | --- |
| Java 25 단위·통합 | 단위 255건, 통합 861건 통과. 실패·오류·건너뜀 각 0건 |

전체 화면 테스트 중 기존 코드관리 시트의 접근성 이름이 렌더링 후 1.206~1.297초에 준비되는 경우를 재현했다. 해당 테스트의 최대 대기를 5초로 조정한 후 코드관리 28건과 전체 737건이 통과했다. 연장근무 화면 테스트에는 중복 날짜 키 경고, 빌드에는 번들 크기 경고가 남았다. 최종 빌드의 `app.js` SHA-256은 브라우저에서 검증한 `807cb3c9fa64ae77c73520c39e406fb2ccd8b9fc167c23787063f8da9cd60cad`와 일치했다.
