# 공통코드·근태코드 관리 검증

기준일: 2026-10-28, Asia/Seoul. [4단계 계약](../design/code-management.md)과 [실행 계획](../superpowers/plans/2026-10-28-react-codes.md)을 기준으로 React 화면·신청 정책 연결·로컬 V14를 검증했다. 이전 3단계 수치와 중복 합산하지 않는다. 실제 고객 운영·새 휴가 계산·법적 적합성 수용을 뜻하지 않는다.

## 구현 범위

- 관리자 전용 공통코드 그룹/상세 시트와 별도 근태코드 시트·메뉴. 조회·입력·삭제 예정·저장·취소, 검색·50행 페이지, 코드 불변·시스템 코드 보호를 제공한다.
- 한 시트의 변경분1~50행 원자 저장, commandId 재전송·현재 관리자·tenant 잠금·행/루트 감사·전체 rollback을 유지한다.409/422에는 편집/삭제 예정/사유/명령·행 ID와 검색 밖 최신 원본·정책 이력도 보존한다. 다른 시트 편집을 버리는 저장·미저장 이동은 확인한다.
- 근태코드의 불변 버전·적용일·동일일 revision·등록자/사유/근거를 표시한다. 관리 시트는 예약을 포함한 최신 등록본이고 실제 신청은 대상일 기준이다. 이후 예약 정책은 유지한다.
- 종일 연차·출퇴근/휴게 정정만 기존 서버 처리에 연결한다. 신규 병가·경조·반차·시간차 등은 초안이며 신청 활성화·임의 시스템 핸들러 연결을 차단한다. 유급 구분은 메타데이터, 근무 인정시간은 산정 미지원이다.
- 신청의 근태정책 버전을 고정하고 승인에서 그 버전의 capability·기존 업무 규칙을 검증한다. 취소는 원신청 버전을 승계한다. 이후 비활성·새 정책을 기존 대기·승인·차감/복원·정정 효력에 소급하지 않는다. 정책이 갈리는 기간은 분리 신청422다. CALC-1은 변경하지 않았다.

## 로컬 V14·자료 보존

- V13 custom-format 백업과 기존39개 업무 테이블의 모든 기존 열·행수·행 SHA256, RLS/정책·테이블/컬럼 권한, DB 컨테이너/이미지/볼륨을 기록했다. 기본 앱만 중지한 뒤 별도 migrate로 V14 한 건 적용·종료0, 새 app 기동·health200을 확인했다.
- V14 이후 업무43개 + Flyway1개 총44개 테이블이다. 기존39개 자료·RLS/정책·테이블 권한과 기존 컬럼 권한·DB 컨테이너/이미지/볼륨은 보존됐다. 신규 `approval_request.attendance_type_version_id` INSERT 권한만 의도적으로 추가했고 UPDATE는 허용하지 않았다.
- 기본 DB에는 tenant1개, 기존 신청/원장/결재 스냅샷0건이므로 이 대조만으로 과거 신청 호환을 주장하지 않는다. 별도 업그레이드 IT는 V13에 합성2tenant의 신청8건(기존 직접 지정과 V13 경로)·스냅샷2건·승인 이벤트·정정·차감/복원을 넣고 V14 후 모든 원래 열/행·ACL/RLS와 정확한 기초 정책 연결·NOT NULL·컨텍스트 복원을 확인했다.
- 기존 및 신규 tenant의 초기화는 고정 시스템 메타데이터만 생성한다. seed 함수는 고정 search_path·PUBLIC EXECUTE 회수·tenant 컨텍스트 저장/복원을 적용한다. 신청 선택·계산 규칙은 Java 계층에 둔다. 앱은 시스템 소유/유형/seed 표시를 임의 삽입할 권한과 정책 버전 UPDATE/DELETE 권한이 없다.
- 앱 이미지 `sha256:bc3ac9b1c55e8b194e3b5c6c31f5a9f3c6ce8922313d325e187fdcba5e4dc90b`. 실제 실행 JAR의 `BOOT-INF/classes`305개 항목이 검증 JAR과 바이트 일치한다. 비루트·읽기 전용 rootfs·cap drop ALL·no-new-privileges·loopback 게시·별도 migrator 계약을 통과했다.

기본 보존 helper의 첫 실행은 이전 단계의 신규 컬럼 권한 금지 기대값 때문에 중단됐다. 이번에 허용한 단 한 개 INSERT 권한을 정확히 비교하도록 기대값을 보완한 재실행에서 위 자료·권한 보존을 확인했다. 합성 검증 자료는 기본 DB에 넣지 않았다.

## 합성 논리 복원

같은 owned 클러스터의 새 전용 DB에44개 테이블을 custom dump·single-transaction restore하고 행수/해시·RLS flags·테이블/컬럼 권한·제약을 대조했다. 근태정책 버전14행을 포함해 자료와 권한을 보존했으며 원본은 변하지 않았다. 복원된 앱 역할에서 컨텍스트 없음0, A회사10, A의 다른 회사 조건0, B회사2 정책 버전을 확인했다.

첫 제약 대조는 PostgreSQL dump/restore의 표현 차이를 그대로 차이로 보고했다. 원시 manifest를 보존하고 이름을 지정한21개 enum CHECK의 동등한 varchar-array/text cast와2개 정렬/version CHECK의 정확한 AND 결합 표현만 정규화했다. 나머지 정의·이름·타입·FK·deferral은 원문을 비교한 새 복원을 통과했다. 기존 global role이 있는 같은 클러스터 검증이며 클러스터 유실·외부 백업·RPO/RTO 검증은 아니다.

## 공개 배포·남은 범위

공개 후속 절차의 현재 접속 조건을 확인하는 동안 별도 공개 작업트리에 V13 통합 merge가 진행 중인 사실을 확인했다. 그 작업의 실행 계획은 V14를 명시 제외한다. 이번 작업에서 해당 작업트리·서버·기존 사이트를 변경하거나 V14 공개 배포를 수행하지 않았다. 정상 Hostinger 인증 세션을 확인했지만 서버 명령은 실행하지 않았다. 공개 서버의 실제 현재 SHA/스키마를 이번 결과로 확정하지 않는다. 검증된 이번 커밋의 공개 통합은 별도 진행 작업과 순서를 조율해야 한다.
