# 선택근무 미확정 날짜 처리 검증

2026년 11월 20일 로컬 합성 회사에서 [미확정 날짜 처리 명세](../superpowers/specs/2026-11-20-selective-unconfirmed-days.md)와 [구현 계획](../superpowers/plans/2026-11-20-selective-unconfirmed-days.md)을 검증했다. 브라우저에서 실행한 JAR의 SHA-256은 `19681dc1916dea0a9203b1f8dd014fc70868880a5e440fe811638b7743517401`이다. 화면 자산 101개를 빌드 출력과 대조했다. DB 스키마는 V33이다.

## 직원 확인과 담당자 재조회

10월 조회에서 9월 28일~10월 4일 주를 열었다. PC와 모바일에 서로 다른 사원을 배정하고, 각 사원과 근태 담당자는 별도 세션으로 로그인했다. 담당자는 처음에 다른 사원이 선택된 상태에서 대상 사원을 조회했다.

| --- | --- | --- |
| 처리 전 미확정 | 직원·담당자 모두 2일 | 직원·담당자 모두 2일 |

| 저장 후 남은 날짜 | 두 화면 모두 10월 1일 퇴근 누락 1일 | 두 화면 모두 10월 1일 퇴근 누락 1일 |

근무 확인 화면에서 브라우저 뒤로 가기와 새로고침을 수행했다. 담당자 화면에서는 9월 30일의 집계 근거 상세까지 열고 원래 정산으로 돌아왔다. 저장 후 직원과 담당자가 각각 다시 읽은 일수와 날짜를 대조했다.

## 재집계와 정정 신청

두 화면 너비에서 추가 사원별로 담당자가 9월 30일을 눌러 대상 사원·날짜를 확인하고 재집계를 저장했다. 미확정은 2일에서 1일로 줄었다. 이어 직원이 10월 1일을 눌러 퇴근 정정을 제출했다. 해당 날짜는 미확정 1일에 남았고 상태는 결재 대기로 바뀌었다. 직원과 담당자가 같은 신청 상세를 열고 다시 원래 사원과 주로 돌아왔다.

Chrome 157에서 PC·모바일 각각 8개의 화면을 확인했다. 업무 요청 오류, JavaScript 예외, 가로 넘침은 0건이었다. 기존 파비콘 요청은 두 환경에서 각각 HTTP 403이 29회 기록됐다. PC 첫 검증은 로그인 페이지를 여는 45초 대기에서 종료됐으며, 같은 제한으로 단독 재실행해 전 과정을 통과했다.

## 자동 회귀와 실행 환경

- `mvn verify`에서 서버 단위 테스트 228건과 전용 PostgreSQL 통합 테스트 825건이 통과했다. 실패·오류·건너뜀은 0건이다. 전체 회귀가 끝난 JAR와 브라우저에서 실행한 JAR의 SHA-256이 일치했다.
- TypeScript 검사와 Vite 빌드를 통과했다. 전체 프런트 회귀는 62개 파일의 702건이 통과했다. 첫 병렬 실행에서 비동기 화면을 기다리는 테스트가 시간 초과됐고, 최종 실행은 프로젝트 기본 대기 시간을 유지하고 작업자 한 개로 수행했다.
- 날짜 합계와 예정일 분리, 중복 사유, 정정 제출·철회, 확정 후 복귀, 실제 근무조와 다른 정산기간, 다른 사원·회사 접근, 마감 당시 자료와 재개 후의 적용일을 회귀 사례에 포함했다. 마감 테스트는 V33 트리거가 저장한 일집계 ID를 읽고 비교한다.
- 브라우저 검증이 끝난 뒤 전용 앱과 PostgreSQL 컨테이너를 종료했고, 사용한 로컬 포트 4개의 리스너가 해제됐다.
