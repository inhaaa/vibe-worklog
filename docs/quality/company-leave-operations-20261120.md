# 회사별 휴가 운영 검증

2026-11-20에 가상 회사 한 곳의 담당자, 직원 두 명, 팀장과 실장 계정으로 확인했다. 합성 근무일은 2026-09-30이다. 두 직원은 하루 표준시간이 8시간인 선택근무조에 배정했고 연차 잔여 묶음은 부여하지 않았다. 공개 데모 배포는 보류했다.

재집계 전에도 직원의 월 요약과 담당자의 사원 일별 근무현황에서 승인 직후 1일, 취소 직후 0일이 일치했다. 유급 인정시간은 경조휴가 승인 시 8시간, 개인휴가 승인 시 0시간이었다. 두 직원의 연간 신청에서 회사 휴가를 취소한 행은 각각 해당 휴가 이름과 ‘휴가 취소’로 표시됐다.

9월 마감 v1의 회사 전체 파일과 고객팀 파일을 두 기기에서 각각 내려받았다. 합계와 사원 명세를 대조했고 동일 범위 파일은 모든 셀과 SHA-256이 일치했다.

## 회귀 검증

근태코드 적용일과 정책 변경, 회사 간 격리, 미차감 휴가의 잔여 묶음 생략, 연차·반차 차감과 취소 복원, 중복 처리, 예전 마감 결과 보존을 검증했다. 최종 Maven 전체 검증은 단위 232건과 격리된 PostgreSQL을 포함한 통합 835건이 모두 통과했고, 건너뛴 테스트는 0건이었다. 프런트엔드는 62개 파일의 테스트 708건과 TypeScript·Vite 프로덕션 빌드를 통과했다. 완성된 JAR에서 브라우저 번들, 월 조회 클래스와 V34·V35 마이그레이션도 대조했다.

V33에서 V35로 올린 뒤 기존 데이터와 DB 권한이 보존되고 재실행 시 추가 마이그레이션이 0건인지 확인했다. 과거 V18→V30 이관 도구의 테스트는 해당 두 버전 사이의 테이블·권한과 V31 입력 거부를 확인하도록 고쳤다. Python 도구 회귀 94건이 통과했다.

부하가 겹칠 때 직원 월 조회가 동시성 테스트의 제한 시간을 넘기는 현상을 재현했다. 42일을 포함하는 달의 원천 데이터를 한 번에 읽도록 바꿔 MyBatis가 준비한 SQL을 427회에서 5회로 줄였다. 동일한 로컬 계측에서 수정 후 6회 조회에 0.143~0.384초가 걸렸다. 두 조회가 공유 잠금을 가진 동안 실제 사원 수정이 기다리는 것도 세 번 확인했다.
