# 계정 자동 생성과 사번·생년월일 최초 접속 검증

2026-11-24 서울 기준. 담당자 초대 메일 없이 등록·입사 확정 때 계정을 만들고, 직원이 사번과 생년월일로 첫 비밀번호를 정하는 경로를 로컬 합성 자료로 확인했다. [구현 계획](../superpowers/plans/2026-11-24-account-provisioning.md) · [결정 기록](../adr/0008-employee-account-provisioning.md)

## 검증 환경

- JDK 25가 없어 Eclipse Temurin 25.0.5.1을 사용자 폴더에 풀어 테스트 명령에서만 썼다. 시스템 `JAVA_HOME`은 바꾸지 않았다. Docker Desktop은 레지스트리 설치 정보가 없어 시작되지 않아 공식 설치 파일로 사용자 단위 재설치(4.96.3)를 했다.
- 테스트 DB 이미지(`infra/postgres/Dockerfile`)는 빌드되지 않는다. 고정한 `postgresql-common-dev=293.pgdg12+1`이 PGDG 색인에서 빠졌다(현재 294·295·297만 있음). 그래서 같은 기반 이미지 `postgres:18.6-bookworm@sha256:bbf8…20fc`를 `127.0.0.1:25432` 전용 컨테이너로 띄우고 [외부 테스트 DB 절차](../development/local.md#docker가-없는-환경의-전용-native-postgresql)대로 `TNA_TEST_JDBC_URL`로 연결했다. 프로젝트 이미지와 달리 XML·LLVM 기능을 제거하지 않은 PostgreSQL이다.
- 이 DB는 실행 사이에 상태가 남는다. 전체 회귀는 매번 새 컨테이너에서 돌렸다.

## 브라우저 확인

앱(`local` 프로필)을 위 테스트 DB에 붙이고 앱 내장 브라우저로 조작했다. 커밋 `f0c518a` 기준이다. 담당자 계정 하나를 최초 접속 대기로 바꾼 뒤 시작했다.

| 흐름 | 화면 | 결과 |
| --- | --- | --- |
| 담당자 최초 접속 | PC 1366×900 | 로그인 화면에 비밀번호로 사번 입력 → 최초 접속 화면(회사 코드·사번 채워짐). 틀린 생년월일은 공통 문구, 맞으면 `/login?activated` → 새 비밀번호로 로그인 |
| 입사 예정 등록·확정 | PC | 생년월일 입력 범위 1900-01-01~입사 전날. 확정 후 사번 26001, "최초 접속 대기". DB에서 입사 예정 행 생년월일 삭제, 인사정보 생년월일 저장, 계정은 비활성·비밀번호·이메일 없음, 기한 7일, EMPLOYEE 역할. 감사에 생년월일 없음 |
| 5회 잠금 | 모바일 390×844 | 사번/사번 → 최초 접속. 틀린 생년월일 5회 모두 같은 문구, 이후 맞는 생년월일도 거부. 감사는 실패 4건과 잠김 1건 |
| 담당자 초기화 | PC | 계정·권한 화면에 "잠김(5회 실패)". 확인 문구 "비밀번호를 초기화하면 직원은 7일 안에 사번으로 다시 첫 로그인해야 합니다." 후 "최초 접속 대기". 본인 계정에는 초기화 대신 "본인 계정은 초기화할 수 없습니다." |

이 확인에서 이메일 없는 대기 계정의 계정·권한 화면이 500 오류를 냈다. 화면 모델을 null을 받지 않는 `Map.of`로 만들었기 때문이다. 재현 테스트를 먼저 쓰고 고쳤다(`f0c518a`).

그 뒤 바뀐 대기 계정 역할 편집 표시(`164a823`)와 직원 등록·일괄 등록 계정 생성, "계정 만들기"(`4ac32a5`)는 통합·React 테스트로만 확인했다.

## 실행하지 못한 검증

- 프로젝트 고정 이미지(XML·LLVM 제거판) 위의 테스트와 개통 브라우저 시나리오. 이미지 고정 버전을 갱신해야 한다.
- 공개 데모 배포, 실제 메일 발송, 외부 서버. 이번 범위에 넣지 않았다.
- 알려진 한계(타인의 5회 잠금, 담당자 초기화를 통한 대리 접속, 최초 접속 전 결재자의 결재선 제외 등)는 [ADR 0008](../adr/0008-employee-account-provisioning.md#결과와-한계)에 있다.
