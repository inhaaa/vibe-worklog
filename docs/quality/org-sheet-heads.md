# React 조직·사원 시트와 조직장 구현 검증

작업 시작: **2026-10-27**, 최종 검증: **2026-10-28, Asia/Seoul**. 사용자 승인한 [업무 확장 2단계](../superpowers/specs/2026-10-26-worklog-service-design.md)와 [실행 계획](../superpowers/plans/2026-10-27-react-org-sheet.md)을 구현하고 로컬 반영·검증을 마쳤다. Java548개·React136개·실제 HTTP80개·PC/390px18회 관측, V12와 기존 DB 보존을 확인했다. 운영 공개 완료를 뜻하지 않는다.

## 구현 범위

- React 조직·사원 시트에 조회·입력·복수 선택 삭제·저장·취소를 제공한다. 저장 후 조직코드/사번은 불변이고 기존 행 삭제는 비활성 예정이다. 새 행은 저장 전 화면에서 제거하며 현재 소속·조직장·근무는 조회와 기존 배정 링크로 제공한다.
- 변경분1~50행만 각 업무의 한 트랜잭션으로 저장한다. 단건 API의 반복 호출을 사용하지 않는다. 모든 대상/기대 버전·최종 조직 그래프·최종 재직 집합을 검증하고 한 행 실패 시 업무·세션 회수·감사까지 롤백한다.
- 고객사 독점 잠금과 현재 관리자 검증 뒤 명령을 재전송 검사한다. 정규화한 행 순서·clientRowId·대상 ID·예상 버전·업무 값·사유를 해시하고 루트 감사에 배치 ID·행별 ID/버전 매핑을 저장해 성공 결과를 복원한다. 행 감사는 별도 명령 ID와 동일 배치 추적 ID로 연결한다.
- 409/422에서 전체 편집·삭제 예정·commandId/clientRowId와 최신 원본을 유지한다. 검색/페이지에서 사라진 편집 대상도 최신값 비교에 포함한다. 최신값 확인과 새 저장은 새 commandId를 사용하고, 503/네트워크 오류의 같은 내용 재시도는 원래 명령을 유지한다.
- 미저장 이동·조회·뒤로가기에는 손실 확인을 제공한다. 이동 취소가 브라우저 이전 기록을 지우지 않게 위치를 복원한다. POST 처리 중 모든 폼의 활성 입력·버튼을 잠그고 실패 후 원래 활성 상태를 복구한다. 전송 데이터는 잠그기 전에 생성한다.
- 조직장 배정/교체/종료는 적용일별 원본을 보존한다. 서울 오늘 이후, 현재 및 적용일 재직 조건을 검사하며 다른 조직의 사원·계정 없는 사원도 조직장이 될 수 있다. 관리/APPROVER 역할을 자동 부여하지 않는다.
- 같은 시작일 교체·종료는 superseded 이력으로 보존하고 해당 날짜를 포함한 구간만 분할한다. 이후 예약과 미배정 공백은 유지한다. 조직 aggregate version으로 동시 변경을 차단한다.
- 관리자·대표에게 전사 조직 트리와 선택 조직의 오늘 소속 직원50명·검색/페이지를 제공한다. 일반 직원의 전사 조회를 추가 허용하지 않는다. 조직장 재직 적격성과 결재 자격을 구분하고 본인 프로필에도 현재 조직장 상태를 제공한다.

기존 단건 관리·적용일 소속 이동·계정 초대·지정 승인자·신청/원장/CALC-1은 보존한다. 조직장 변경으로 대기 신청의 결재자를 이동하지 않는다. 새 결재선·권한 시트·공통/근태코드·본인 연도별 현황/모달·월간 그래프는 후속이다.

## DB·보안 경계

V1~V11은 편집하지 않고 `V12__organization_heads.sql`로 `organization_head_assignment`를 추가한다. tenant/id 복합 PK/FK, `[valid_from,valid_to)`, nonsuperseded 기간 exclusion, 버전·사유·처리자를 둔다. FORCE RLS·명시 tenant 조건·최소 SELECT/INSERT/닫기 열 UPDATE를 사용하고 DELETE를 허용하지 않는다.

조직장 관리·시트 문맥 조회는 관리자 권한과 공유 읽기 및 반환 전 재검증을 사용한다. 회사 조직도는 기존 `CompanyReadAccess`를 사용한다. 본인 프로필은 principal 대상에 고정한다. 회사 DTO에는 이메일·자유 사유·계정/세션·감사 원문을 제공하지 않는다. 운영자 권한·관리용 DB 자격을 업무 조회에 사용하지 않는다.

배치 입력은 top-level/행 필드 allowlist, 중복 파라미터/JSON 키, UUID 행 식별자, 작업/대상 중복과 범위 검증을 적용한다. 오류에도 타 회사 대상은404다. 감사 화면은 배치의 허용된 UUID·버전 매핑만 해석한다.

### 실패를 먼저 확인한 경로

- 기존 bulk POST는405여서 정상303/422/409의 신규11개가 실패했다. 조직장 신규13개는 경로403·스키마 부재로, 프로필은 새3필드 부재로 실패했다. 스키마 부재와 기능 부재를 구분했다.
- React 시트10개, 조직장/조직도·오류6개, 프로필1개, 현재 배정·저장 중 이동2개와 검색 길이/뒤로가기/POST 잠금 회귀에서 실패를 먼저 확인했다.
- 새 페이지 allowlist·감사 배치 요약2개와 조직 aggregate 버전 요약1개를 실패 확인한 뒤 명시 필드만 추가했다. 조직/사원 시트의 현재 조직장·근무 문맥2개도 모델 부재를 확인했다.
- 실제 업무·auth_version·행 감사 뒤 루트 감사 저장을 합성 tenant 전용 CHECK로 실패시켰다. 전체 롤백과 같은 명령의 이후 성공을 검증한다.

### 리뷰·통합에서 보완한 항목

- 충돌 대상이 검색에서 사라지면 최신 원본이 누락됐다. 사원/조직 각각 최신 원본1개 기대/실제0을 확인하고 현재 페이지와 편집 대상 ID의 최신값을 합쳤다. 오류 조회는 최대100명이고50명 단위 SQL로 제한한다.
- 코드/사번 중복 오류가 무관한 첫 행을 지목했다. 유효한 첫 행과 기존 마스터에 중복되는 둘째 행을 제출해 잘못된 clientRowId를 확인한 뒤 실제 충돌한 변경 행을 표시하도록 수정했다.
- 뒤로가기 취소 후 같은 이동을 재시도하면 이전 기록을 건너뛰었다. 별도 이전 페이지를 둔 회귀에서 재현하고 브라우저 위치 복원으로 수정했다.
- POST 대기 중 새 편집이 응답에 덮였다. 독립 JSDOM 재현과 신규 회귀로 확인하고 입력 잠금·실패 복구를 추가했다. 독립 재검토에서 성공·503·네트워크 실패3경로를 확인했다.
- 초기 조직장 React 테스트2개는 같은 URL의 GET 폼을 잡는 selector 결함이어서 POST로 한정했다. 50회 클릭 테스트의 시간 초과는49행 fixture+1회 입력으로 동일 경계를 검증했다. disabled 버튼에 직접 fireEvent를 보내는 모사 오류는 실제 브라우저와 같은 native click으로 교정했다.
- 첫 전체 Java 실행의 유일한 실패는 V12 테이블이 기존 `DatabaseFoundationIT`의 FORCE RLS 기대 목록에 없는 것이었다. 검사 범위를 줄이지 않고 새 테이블을 목록에 추가했다. 새 조직장 RLS/권한·동시성 검증은 같은 실행에서 통과했다.
- 실제 모바일 사원 시트에서 본문375px에 scrollWidth553px인 실패를 확인했다. 숨김 레이블의 absolute 배치 기준이 표 스크롤 영역 밖이었으며 `.t-sheet-scroll`에 relative 배치 기준을 두어375/375px로 수정했다. 조직장 배정 링크도 별도 줄로 표시했다. Java/React 행동 코드를 바꾸지 않은 CSS 보완이며 관련 Java12개·재패키지·이미지 재빌드·실제 모바일/HTTP/기본 DB 보존을 다시 확인했다. 스타일 문자열만 대조하는 모사 테스트로 대신하지 않았다.

조직장·bulk·프런트의 독립 명세/보안/품질 리뷰에서 위 보완 사항을 재검토했으며 추가 P1/P2는 발견하지 못했다. 리뷰는 실제 실행 검증을 대신하지 않는다.

## 로컬 적용·실행 기록

기본 DB의 V11·업무34개 테이블 전체 행 SHA256/행 수·RLS/ACL·열 권한·컨테이너/이미지/볼륨을 먼저 기록하고 custom-format 백업을 보존했다. 새 app/migrate 빌드 후 별도 migrate로 V12 한 건을 적용해 종료0을 확인했다. CSS 보완 뒤 새 이미지의 migrate는 V12 no-op·종료0이고 app은 running이다.

기존34개 업무 테이블 전체 행·테이블/열 권한·RLS와 DB 컨테이너/이미지/볼륨은 전후 동일하다. 조직장 테이블1개를 추가해 현재 업무35개·Flyway 포함36개 테이블이다. 기본 데모에 조직·사원·조직장·대표 테스트 자료를 추가하지 않았으며 데모의 공통·관리자 역할도 유지했다. 계정 초대·출퇴근·원장 자료를 테스트 용도로 변경하지 않았다.

최종 앱은 UID10001·읽기 전용 root·cap drop ALL·NNP·loopback18080을 유지한다. 실행 JAR의 `BOOT-INF/classes/`267개 항목은 검증 JAR과 바이트가 같다. 최종 image는 `sha256:b64090b983bb1c2fbea33ea825313c9dce9e59753e5b25a0bd1f9beeaff7ab18`이다.

### 실제 HTTP·브라우저와 임시 자원

기본 앱의 새 조회와 기존 보안24개를 확인했다. 별도 합성 fixture에서 조직·사원 일괄 생성/수정·재전송·최종 순환·마지막 오류의 무효과·409/422 편집 및 최신값 유지·조직장 배정·본인 프로필·대표 조직도/관리403·실제 타 회사 조직404·CSRF·unknown 필드 거부를 검증했다. 신규56개와 공통24개를 합해80개다. 공통 검사 첫 호출의 CLI 인자 오류는 `--port`로 바로잡았으며 미성공 호출을 통과 수치에 넣지 않았다.

실제 React에서는 조직 다중 행 입력·중복 오류의 정확한 행/초점·전체 편집 보존·오류 수정 후 저장·비활성 예정 취소/저장, 사원 두 행 저장, 조직장 당일 배정/종료/재배정·과거 이력 보존, 조직도 접기/키보드 펼치기·직원 조회, 대표 메뉴와 본인 조직장 표시를 확인했다. 모바일 본문은 viewport390px에서 스크롤바를 뺀375px이며 긴 표만 내부 스크롤한다.18회 관측은 가로 넘침0이고 관리자 합성 탭·최종 기본 앱의 콘솔 오류는0이다. 대표 탭은 콘솔 수치의 표본에 포함하지 않았다. 임시 viewport를 복원하고 검증 탭을 닫았다.

합성 fixture는 정상 종료0과 owned 컨테이너 제거를 확인했다. 원천55,800건·대기3건·승인0·재생 중복0이며 기본 서비스는 유지한다. 논리 복원도 별도 owned 컨테이너/DB를 사용했다. 이는 같은 클러스터·기존 전역 역할의 복원이고 외부 백업·서버 유실 복구를 검증한 것이 아니다.

## 근거·미실시 범위

원본은 Git 제외 `target/org-sheet-20261027/`의 기준·RED/GREEN·최종 Java/React 로그, DB 전후 JSON·백업과 실제 실행 기록에 보존한다. 비밀값·토큰·백업·원본 자료·target/dist는 커밋하지 않는다.

검증 근거 JSON을 읽는 첫 도구 호출의 Windows 기본 인코딩 오류는 UTF-8을 명시해 수정했다. 원본 로그·검증 대상은 바꾸지 않았고 최종 집계·문서 수치는 실제 완료 결과만 사용한다. Git 게시 결과는 완료 보고의 원격 SHA로 확인한다.

새 장시간 부하·전체 이미지 취약점 재검사·실제 메일·실고객·외부 서버 접속·운영 배포는 이번 단위에 포함하지 않는다. Python 도구 소스는 변경하지 않았으며 기존62개 결과를 이번 재실행으로 표시하지 않는다. 이전 이미지의 [부하](no-xml-soak.md)·[보안](react-residual-impact.md) 이력과 잔여 조건을 이번 새 이미지의 동일 검증으로 확대하지 않는다.
