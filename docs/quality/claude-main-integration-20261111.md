## 충돌 해결과 기존 개발본 보존

- 원본 변경 63파일 중 개발본에 없는 `DemoAccountSwitcher.css`, `DemoLanding.css`의 부재를 유지하고 `cssLayers.test.js` 목록에서 두 항목을 제외했다. 통합 직후 61파일이며 요청 범위 밖 변경은 없었다.
- `App.tsx`에는 디자인 CSS import 3개만 추가했다. 기존 개발본의 인증·로그인·사원 전환·권한 동작을 보존했다. Java, DB 마이그레이션, 런타임 설정, 배포 파일과 `AGENTS.md`는 변경하지 않았다. 프런트 패키지 파일의 Pretendard 추가는 원본 25개 범위다.
- 공통 시트는 초기 레이어 분리를 개발본에 적용한 뒤 `d37dcc1`의 전체 CSS 개편을 반영했다. 자산 검증도 새 디자인 토큰을 검사하도록 통합했다.
- `design.md`에는 새 규칙과 기존 개발본의 홈·업무 화면 링크를 함께 보존했다. 개발본에 없는 공개 랜딩 문서 링크는 추가하지 않았다.

## 검토에서 발견한 문제와 수정

외부 폼에 연결된 `SheetSaveDialog` 사유 칸이 처리 중에도 편집 가능했다. 사유 수정으로 `commandId`가 바뀌면 응답 유실 후 재시도에서 자동 사번 신규 사원이 중복 생성될 수 있었다. `e547089`에서 `disabled={busy}`를 추가하고 폼 연결·재시도 경로를 독립 재검토했다. 요청 본문은 비활성화 전에 수집되어 사유 송신이 유지된다.

## 로컬 실행 이미지와 앱 반영

- JAR 소스: `e547089`.
- 최종·실행 JAR SHA-256: `662075a72363f54d6fa65fa30c1e9111e966de26cc187257ae333479ee198716`.
- 이미지: `vibe-attendance-main-integration:20261111`.
- 확인한 이미지 식별자: `sha256:99e7a2b49d11ecd5d45dfa7383ece78f49a8df678d4b57fe7b2f045fa4069b0f`.
- 기존 로컬 런타임 이미지를 바탕으로 새 JAR만 교체했다. 저장소 전체 Docker 빌드를 새로 수행한 결과와 구분한다.
- 후보 포트 `18082`에서 검증한 뒤 같은 이미지로 기본 `18080` 앱만 교체했다. 읽기 전용 루트 파일시스템과 loopback 게시를 유지하고 실제 HTTP 24개를 다시 확인했다. DB 컨테이너는 계속 실행 중이며 확인 당시 약 16시간의 가동 시간과 healthy 상태를 유지했다.
- 이전 앱 이미지는 `vibe-attendance-local-app:before-main-20261111` 태그로 보존했다. 새 DB 마이그레이션·초기화·샘플 데이터 재적재는 수행하지 않았다.
- 임시 `18082` 컨테이너는 검증 후 중지했으며 삭제하지 않았다. 기본 `18080` 앱은 유지한다.
