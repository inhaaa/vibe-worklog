# 결재 화면·데모 승인 구현 계획

**목표:** [설계](../specs/2026-11-03-approval-workspace-design.md)에 따라 결재 화면을 정리하고 공개 가상 데모에서 신청→승인을 직접 체험한다.

**구조:** 기존 React 페이지/Java 인증·신청 서비스·PostgreSQL V16을 재사용한다. 개발 브랜치와 기존 공개 전용 작업트리를 사용하고 서로 독립적인 UI·데모 인증/자료·검증을 병렬 담당한다. 의존성/스키마 확대는 필요성 검증 없이 하지 않는다.

- [x] README/kickoff/PRD·결재/데모 계약·현재 파일/테스트·공개 차이를 읽고 인터페이스/보존 범위를 정한다.
- [x] UI: 대기/완료·한글 유형/상태·페이지 범위 건수·빈 상태·기존 링크/전송/권한 테스트를 먼저 실패시킨 뒤 결재 목록/상세와 반응형 CSS를 구현한다.
- [x] 데모: 고정 승인자 정상 인증/비정상 역할·신원/프로필 거부·CSRF/세션/공유 보호 테스트를 먼저 실패시킨 뒤 두 persona의 진입/전환을 구현한다.
- [x] 자료 준비: 기존 가상 자료/해시/감사/버전의 엄격한 확인·트랜잭션·최소 추가·재실행 무변경·충돌 롤백을 PostgreSQL 테스트로 확인하고 전용 후속 명령을 구현한다.
- [x] 공개본에 필요한 파일만 이식하고 시트/공유 보호를 보존한다. 관련 Java/DB와 프론트 전체·타입/빌드·배포 계약을 실행하고 독립 코드 검토로 발견한 문제를 수정한다.
- [x] 전용 합성 앱에서 CUA로 실제 신청→전환→승인→완료/신청자 잔여를 확인한다. PC1440/모바일390·오류/넘침·승인 전후 정확 원장/이벤트·중복 차감을 확인하고 화면을 보존한다.
- [x] 문서/검증과 필요한 파일만 커밋·일반 Push하고 공개 최신 상태/자료·권한·서비스를 다시 읽는다. 전용 백업·독립 복원·명시 자료 보완 후 WorkLog 앱만 반영하고 모든 기존 자료 보존/허용된 추가/스키마/공개 보안·정적 파일·실제 흐름을 검증한다.
- [x] README/개발 안내/품질 문서에 실제 결과·미실시 범위/배포 SHA·이미지/V16을 기록하고 최종 diff/status·임시 앱/DB/연결 종료·뷰포트 복구를 확인한다.

최종 결과: [로컬 검증](../../quality/approval-workspace-20261103.md)·[공개 배포/실제 신청→승인](../../quality/public-approval-workspace-deploy-20261103.md). 실제 배포 소스는 `3e6e99c`이며 이후 결과 문서 커밋과 구분한다.
