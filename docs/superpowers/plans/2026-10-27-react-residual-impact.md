# React 잔여 취약점 영향 확인·안전한 보완 계획

**Goal:** 7종 이미지 원시 매치의 현재 서비스 영향과 공식 수정 공급을 확인하고, 적용 가능한 보완을 검증한다.

**Architecture:** 기존 app/migrate·공유 PostgreSQL·별도 빌드/테스트 경계를 유지한다. OS와 도구 조사는 병렬로 수행하고 이미지 변경·DB 실행·최종 검증은 순서대로 관리한다. 원시 경고를 숨기거나 권한·TLS·RLS를 완화하지 않는다.

**Tech Stack:** 기존 Python 표준 라이브러리·Java/Maven·Docker·Syft/Grype와 공식 공급자 자료. 근거 경로는 `target/react-residual-impact-20261027/`다.

## 판정 계약

- 이전 2,035행·7종 이미지 원장은 보존한다. 현재 설치판·공식 공급 상태·현재 HTTP/SQL/빌드 호출 경로·잔여 조건을 별도 기록한다.
- `영향 없음`은 구성요소 부재나 OS/호출 조건의 명확한 불일치에만 사용한다. 경로 미발견·기능 미사용·loopback·비루트는 각각 제한 조건으로 기록한다.
- 기본 DB 데이터·권한은 보존한다. 전용 합성 DB와 네트워크로 재현하며 기본 DB에는 읽기 전용 확인만 수행한다. 로컬 반영이 필요하면 기존 백업·전체 행 해시 절차를 재사용한다.
- 공급자 서명/체크섬·버전·라이선스·지원 조합을 확인한다. 취약점 수를 줄이기 위한 임의 번들 내부 교체·다른 배포판 패키지 혼합·테스트 자동 정리 비활성화를 하지 않는다.
- 현재 요청과 기존 승인 범위에서 필요한 로컬 설정·컨테이너·DB 검증을 진행한다. 외부 배포·Push·전역 환경 변경은 포함하지 않는다.
