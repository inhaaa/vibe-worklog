# 신청서코드와 단계별 결재 구현 계획

기준 커밋 `ab8c87a`. [승인 명세](../specs/2026-11-18-request-form-approval-routing-design.md)의 세 신청서를 기존 Java·MyBatis·PostgreSQL·React 경로에 연결한다. 로컬 합성 데이터로 검증한다.

1. **설정 모델과 관리자 화면**. 신청서 마스터·적용 버전, 초기 코드 L01/L02/A01, 결재 단위와 팀장까지·실장까지 결재선 버전을 정의한다. 기존 자료 전환·코드 교체·권한·기간 및 중복에 대한 테스트를 먼저 추가한다. 관리 메뉴의 검색/편집/미리보기에 연결한다.
2. **신청자별 결재선 생성**. 제출일·주 소속·조직장 유효기간·자격으로 결재선을 생성한다. 미지정·공석·자기 결재·겸임·직속·대리 신청을 테스트하고, 미리보기와 제출에서 같은 해석기를 사용한다. 최초 단계와 실제 담당을 구분해 저장한다.
3. **단계 전이와 실제 업무**. 팀장 승인 후 대기·다음 담당 전환, 최종 승인 후 휴가 차감·취소 복원·정정 효력을 검증한다. 반려·철회·재할당·중복 제출과 기존 단일 결재의 회귀를 확인한다. 담당자 현황, 결재함, 상세에 현재 단계와 결정 이력을 표시한다.
4. **브라우저 검증**. 로컬 전용 앱에서 PC와 모바일 화면 폭으로 관리자 설정·미리보기, 직원 제출, 두 결재자의 결정, 직원 및 담당자의 결과 재조회를 수행한다. 단계별 잔여·취소 효력·정정 결과를 대조하고 실행 결과를 기록한다.

분담은 설정 서비스·관리 UI, 결재선 해석·단계 처리 서비스, 신청 및 결재 UI, 브라우저·서비스 통합 검증으로 구분한다. 스키마 변경은 후속 Flyway로 관리한다. 각 담당자는 기존 파일을 읽고 회귀 사례를 먼저 실행한 뒤 해당 기능을 연결한다.
