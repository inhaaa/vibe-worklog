# 간결한 표 디자인 구현 계획

**목표:** 제공된 참고의 정돈된 정보 밀도를 WorkLog의 표·정보 영역·모달에 적용한다.

**구조:** 기존 DOM·업무 인터페이스를 유지하고 담당 CSS와 공통 토큰을 수정한다. 구현과 검증은 파일 범위를 나눠 병렬 진행한다.

**기술:** 기존 React/Vite/CSS, 기존 합성 UI 검사 도구. 새 의존성 없음.

1. 기존 관련 계약 테스트와 현재 배포 자산의 화면을 먼저 확인한다.
2. 공통 토큰/표는 root, 내정보/요약은 별도 담당, 신청/상세/모달은 별도 담당이 수정한다.
3. 전체 React 테스트·타입·빌드 후 두 테마/1440·390·320px에서 정보 보존·넘침·키보드·대비를 검증한다. CSS만 수정하는 만큼 구현을 복제한 테스트는 추가하지 않는다.
4. Hallmark render 검사와 독립 시각 검토를 진행하고 발견된 문제를 한 번에 보완한다.
5. 공개 전용 브랜치의 보안·AG Grid를 보존해 통합하고 해당 빌드/테스트/화면 검사를 수행한다.
6. 기존 승인된 콘솔 배포 경로로 WorkLog 앱만 반영한다. SQL 변경 없이 기존 자료·서비스·Caddy·실행 기반과 공개 자산을 전후 비교한다.
7. 실제 결과와 제한을 문서화하고 단위별 커밋·일반 Push한다.
