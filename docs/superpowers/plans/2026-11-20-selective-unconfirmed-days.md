# 선택근무 미확정 날짜 처리 구현 계획

기준은 선택근무 개발 브랜치의 `f8e9127`이며 [업무 명세](../specs/2026-11-20-selective-unconfirmed-days.md)를 따른다. 기존 조회와 처리 명령을 사용하며 DB 스키마 변경은 필요하지 않다.

| 작업 단위 | 구현 범위 | 테스트 우선 검증 |
| --- | --- | --- |
| 날짜별 사유와 처리 권한 | `SelectiveSettlement`, `WorktimeService`에서 동일한 미확정 판정으로 현재 목록·예정 수·역할별 조치를 반환 | 미래일, 중복 사유, 월경계, 정정 대기와 마감, 근무 확인 후 두 역할의 2→1을 JUnit과 전용 PostgreSQL로 대조 |
| 기간 카드와 날짜 목록 | `SelectiveSettlements.tsx`에서 기간 선택과 역할별 링크, 예정·빈 목록·재조회 표시. `selectiveNavigation.ts`에서 정산 주소와 업무 링크 조립 | Vitest로 날짜·건수·역할별 버튼·이전 사원의 응답 폐기·선택 기간 복원을 확인 |
| 기존 업무 화면 연결 | 근무 확인, 정정, 신청 상세, 회사 달력, 일자 재집계에 제한된 정산 복귀 문맥을 전달한다. 성공·입력 오류와 취소로 돌아갈 때 원래 조건을 보존한다 | MVC와 React 테스트에서 기존 진입점, 원래 조회 월과 다른 날짜, 사원·역할 불일치, 변형 주소를 대조 |
| 실제 브라우저와 회귀 | 로컬 Chrome PC·모바일에서 합성 사원마다 두 미확정일을 준비하고 직원 처리와 담당자 재조회를 수행한다 | 최초 2일·처리 후 1일, 남은 날짜·이유·사원·선택 기간을 화면과 응답에서 대조한다. 프런트 전체 테스트·빌드와 Maven 전체 회귀 후 작업별 일반 푸시 |

각 기능 단위는 관련 테스트가 먼저 실패하는 것을 확인하고 구현한 뒤 다시 실행한다. 브라우저 검증 결과는 품질 보고서에 남긴다.
