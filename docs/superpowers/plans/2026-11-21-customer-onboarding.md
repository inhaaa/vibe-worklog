# 고객사 개통부터 직원의 첫 출근까지

2026-11-21 · 첫 이용을 검수할 단위는 새 회사, 첫 담당자, 결재자와 직원이다. 플랫폼 운영자만 먼저 준비하고 고객사 업무 데이터는 사용자가 화면에서 등록한다.

## 인수 기준

| 사용자 | 실제 업무 | 완료 확인 |
| --- | --- | --- |
| 운영자·첫 담당자 | 관계 확인 후 회사 코드·회사명과 첫 담당자의 사번·업무 이메일을 등록한다. 담당자가 초대 메일에 적힌 회사의 수락 화면을 열어 코드를 입력하고 비밀번호를 정한다. | 수락 전에는 로그인할 수 없다. 수락 뒤 회사 코드와 자신의 계정으로 로그인해 회사 설정을 찾을 수 있다. 운영자 로그인과 고객사 로그인은 별도다. |
| 담당자 | 사용할 조직과 근무시간코드·근무조를 만들고 근무일, 휴게시간과 출퇴근 허용망을 정한다. 입사일에 맞춰 결재자와 직원의 입사를 확정하고 배정·초대를 확인한다. | 첫 이용 안내에서 필요한 메뉴로 이동한다. 입사 확정 때 빠진 조직이나 유효한 근무조를 확인하고 해당 설정을 열 수 있다. |
| 담당자·결재자 | 초대를 수락한 결재자에게 승인자 권한을 주고 직원에게 적용할 결재선을 정한다. | 직원·기준일·신청서로 미리 본 결재자가 실제 지정과 같다. |
| 직원 | 최신 초대를 수락하고 처음 로그인한다. 홈에서 오늘 배정된 근무를 확인한 뒤 허용된 네트워크에서 출근한다. 로그인 화면에서 비밀번호를 복구한다. | 재발급 전 초대 및 만료·소비한 코드는 거부된다. 새 비밀번호로 로그인해 같은 사원의 첫 출근 시각을 다시 볼 수 있다. |

## 메일·접근 계약

- 기존 계정·역할·토큰과 사원별 적용일 데이터를 사용한다. 운영자·업무·인증 DB 역할 및 회사별 권한 검사를 유지한다. 업무 메일을 보내려면 전달 모드, SMTP 서버, 발신 주소와 사용자용 서비스 주소를 설정한다.
- 회사 등록, 초기 초대 재발급, 직원 초대·재발급은 저장이 커밋된 뒤 전달한다. 재발급은 등록된 이메일로만 가능하며 이전 초대는 취소된다. 동일한 명령 재시도는 새 코드를 만들지 않는다. 전달에 실패한 미수락 계정은 재발급할 수 있다.
- 초대 메일에는 회사 코드, 수락 폼 주소, 24시간용 일회성 코드를 싣는다. 복구 메일에는 회사 코드, 재설정 폼 주소, 30분용 일회성 코드를 싣는다. 주소는 설정한 서비스 주소에서 생성하고 코드는 폼의 POST 본문으로 제출한다. 비밀번호 복구 안내는 계정 존재 여부와 관계없이 같다.
- 직원·결재자 계정은 수락 후에만 활성화한다. 비밀번호를 변경하면 이전 로그인 세션은 회수한다. 사원·근무 배정·출근 기록은 같은 계정에 이어진다.

## 구현 및 검증 순서

1. 초대와 복구를 구분하는 전달 계약과 테스트 SMTP 수신, 실패·재발급·코드 만료·재사용 검증을 먼저 작성한다. 공통 전달 경로를 기존 운영자·담당자·복구 기능에 연결한다.
2. 첫 담당자의 설정 진입점, 입사 확정의 선행 조건, 초대 수락·재발급·복구 화면을 실제 역할과 다음 행동에 맞춘다. 기존 화면·검증 로직을 재사용한다.
3. PC와 모바일 크기의 터치 브라우저에서 별도 가상 회사를 만든다. 각각 테스트 메일함에 도착한 메시지로 계정을 활성화하고, 담당자 설정·결재선 확인·첫 출근·비밀번호 복구와 기록 재조회를 수행한다. 단위·통합 테스트 결과와 브라우저 검증 조건을 기록한다.
