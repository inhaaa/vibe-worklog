# Phase 6 로컬 품질 검증 계획

**목표:** 고정 근무 MVP의 전체 업무 연결, 테넌트 격리·동시성·보안·성능을 실제 로컬 PostgreSQL에서 확인한다. 상용 출시·법률 적정성·외부 배포 완료를 의미하지 않는다.

**구조:** 기존 서비스·권한·RLS·트랜잭션 계약을 기준으로 검토하고 재현된 결함에만 최소 수정을 적용한다. 신규 의존성 없이 기존 JUnit·Testcontainers와 JDK를 사용한다. 합성 데이터만 사용하며 기존 로컬 Compose의 빈 업무 DB는 부하 대상으로 사용하지 않는다.

**진행 승인:** 2026-10-25 사용자가 질문 없는 수정·문서 반영·검증·작업 단위별 커밋·일반 Push를 요청했다. 기존 로컬 DB·설정 작업 승인은 같은 범위에서 유지한다. 외부 서버 접속·배포는 제외한다.

- [x] 고객사 3곳, 각 사원 300명·31일 원천을 준비한다. 준비 시간과 워밍업은 지연 시간에서 제외하고 샘플 수·동시 작업 수·p50/p95/max·실패 수를 기록한다.
- [x] 사원 목록·월 결과·계산 상세·감사 페이지·출퇴근·재집계·XLSX를 한 고객사/여러 고객사에서 측정한다. 동일 명령 재시도에서 사건/감사 중복이 없는지도 확인한다.

- [x] 최종 Linux 이미지 빌드·로컬 Compose 기동·DB 경계·HTTP 보안 확인. 외부 서버와 기존 타 서비스는 변경하지 않는다.
- [x] 전용 합성 DB의 백업·복구를 별도 임시 DB에 실행하고 행 수·불변 근거·RLS·역할 경계 보존을 확인한다. 실제 운영 복구 목표는 별도다.
