# React 재점검 3건 수정 실행 계획

> **For agentic workers:** 독립된 프론트 탐색·개발 프록시·운영자 서비스 파일을 병렬로 담당하고 TDD로 각 재현을 정식 회귀 테스트로 전환한다.

**Goal:** 사용자 승인에 따라 재점검에서 발견한3건을 수정하고 전체 테스트·실제 동작을 다시 검증한다.

**Architecture:** 기존 HTTP·화면 데이터·명령/버전·세션·DB 스키마 계약을 유지한다. 실패한 popstate의 주소를 현재 화면에 맞게 복구하고, 다운로드 응답은 프록시를 통과시키며, 운영자 읽기 반환 전 현재 권한을 재검증한다.

**Tech Stack:** 기존 React·TypeScript·Vite·Vitest·Java25·Spring·PostgreSQL 조합. 새 라이브러리를 추가하지 않는다.

## 수정 계약

1. **탐색 실패:** `/admin/employees`→직원 상세→뒤로 가기에서503 또는 네트워크 오류가 발생하면 기존 상세 화면의 GET 주소로 복구한다. 편집 값과 명령 ID를 보존한다. 지연된 history 조회를 기존 화면의 링크/POST가 대체하면 표시 주소를 먼저 복구하고, 표시 주소로 왕복하면 이전 GET을 무효화한다. 일반 링크의 실패에는 새 history를 추가하지 않으며,401/403·세션 파기503의 정보 제거·POST 대기 잠금·최신 요청 우선·fragment 처리는 유지한다.
2. **개발 다운로드:** `/admin/reports/exports/{id}/download`의 HTML GET은 Vite index로 치환하지 않고 loopback 백엔드로 전달한다. query가 있어도 첨부 헤더와 본문을 보존한다. 일반 페이지 HTML·JSON·POST·CSS의 기존 처리와 프록시 허용 경로는 유지한다.
3. **운영자 조회:** 회사·감사 조회가 끝난 뒤 현재 운영자 계정/권한 개정을 다시 확인하고 회수되었으면403으로 결과를 차단한다. 고객사 세션과 독립성을 유지하며 초대·상태 변경 등 쓰기 명령의 계약은 변경하지 않는다. 조회에서 쓰기·잠금 승격을 추가하지 않는다.

- [x] `frontend/src/App.tsx`의 실패 복구를 최소 수정하고 관련 테스트를 GREEN으로 확인한다.
- [x] 실제 Vite 설정·합성 백엔드 응답으로 직접 다운로드와 query·일반 페이지 동작의 RED→GREEN을 확인한다.
- [x] 운영자 회사·감사 조회 중 권한 회수의 정식 Java 테스트를 RED→GREEN으로 확인한다. 전용 PostgreSQL 동시성도 검증한다.
- [x] 프론트 전체 테스트·타입/빌드, Java 전체 단위/전용 PostgreSQL 통합, Python 도구 테스트를 실행한다.
- [x] 패키지·로컬 실행·HTTP/브라우저의 영향을 확인한다. 컨테이너 갱신은 `--no-deps`로 DB를 보존한다.
- [x] 문서·결과와 git status/diff·새 파일을 검증하고 실제 통과 범위 및 실행하지 못한 검증을 보고한다.

설정 변경·전용 로컬 DB 검증은 현재 세션의 기존 승인과3건 수정 요청 범위다. 파일 삭제·전역 설정·Git Push·외부 배포는 하지 않는다. 샌드박스 실행 제약은 실제 결과와 구분해 기록한다.
