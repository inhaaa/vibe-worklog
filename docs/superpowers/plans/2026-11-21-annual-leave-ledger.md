# 회사별 연차 부여·이월·소멸과 직원 원장

2026-11-21. 담당자가 회사의 연차 기준으로 한 회계연도를 열고, 직원과 결재자가 같은 연차 잔여로 신청과 취소를 처리한다. 기존의 기초 이관·조정과 연차 신청·결재를 이어서 사용한다. [기초 이관](../specs/2026-11-18-leave-balance-batch.md) · [신청·승인 규칙](../../rules/workflow.md)

## 담당자와 직원의 작업

1. 담당자는 **휴가관리 → 신청·연차 → 연차 관리 → 연차 부여·이월·소멸**에서 회사의 회계 시작월, 사원당 연간 부여 일수, 사원당 이월 한도와 변경 사유를 저장한다. 시작일은 선택한 달의 1일이다. 수량은 0.5일 단위이고 회사가 정한 값을 입력한다.
2. 적용할 회계연도의 시작 연도를 선택해 미리 본다. 활성 사원 중 회계 시작일에 재직한 대상의 사번·이름, 전기 잔여, 신규 부여, 이월, 소멸과 새 묶음의 합계를 확인한다. 본인 잔여는 다른 담당자가 처리한다. 이미 반영한 사원과 당해 귀속의 기초를 등록한 사원을 구분한다. 미리보기만으로 잔여는 바뀌지 않는다.
3. 이월 원천은 직전 귀속연도가 확정됐고 사용 종료일이 새 회계연도 시작 전날인 묶음이다. 여러 원천의 남은 양을 합산해 사원별 한도를 한 번 적용한다. 원천에는 다음 연도로 이월한 양과 한도 초과로 소멸한 양을 남기고, 새 묶음에 부여량과 전년도에서 받은 이월량을 적는다. 미분류 기초·종료일 없는 기초와 만료 후 복원분은 보존한다. 전기 묶음에 미결 연차 사용·취소가 있는 사원은 결재 처리 후에 다시 미리 본다. 이미 후속 연도에 부여한 직원은 과거 연도의 신규 부여 대상에서 제외하고 그 인원을 표시한다.
4. 담당자가 적용 사유를 남겨 확정하면 해당 회사의 대상 사원을 한 트랜잭션에서 처리한다. 미래 시작분은 미리 볼 수 있다. 상태가 달라졌으면 미리보기를 다시 요구하고, 같은 확정의 재시도는 한 번만 반영한다. 첫 반영 시 회계 시작월을 고정해 기간 중복을 막는다. 부여 일수와 이월 한도는 다음 미반영 연도에 바꿀 수 있다. 기존 연도에 다른 담당자가 추가 반영할 때는 그 연도의 처음 기준을 사용한다.
5. 직원은 **내 업무 → 휴가·신청 → 내 신청 이력 → 내 연차 원장**에서 오늘 사용 가능한 잔여, 연도별 내역과 수량을 확인한다. 신청·취소 대기 중 잔여는 유지한다. 최종 승인 때 선택한 묶음에 사용을 쓰고, 취소 최종 승인 때 같은 사용을 참조하는 복원을 기록한다. 과거 사용기간이 끝난 묶음에 뒤늦게 복원된 양은 검토할 이력으로 보존한다.

회사가 확인한 수량과 사유를 반영하는 기능이다. 근속·출근율별 법정 발생량, 사용촉진 절차와 미사용수당 정산은 회사의 개별 사실관계를 검토해야 한다. 화면상의 소멸은 이월하지 않은 수량을 회사 원장에 기록하는 동작이다. [근로기준법 제60조·제61조](https://www.law.go.kr/LSW/lsInfoP.do?ancNo=21857&ancYd=20260804&efYd=20261002&lsiSeq=290781)

## 데이터와 화면 계약

- V37은 회사별 규칙, 적용 연도·사원의 부여 근거와 원장 종류를 추가한다. 기존 묶음·귀속 및 사용 효력 관계를 재사용한다. 서버가 세션의 회사와 권한을 확인하고 업무 SQL·RLS로 격리한다.
- 담당자 화면은 `GET /admin/leave-balances/annual-cycle`이다. 같은 경로 아래 `POST /policy`는 개정과 변경 사유, `POST /preview`는 연도, `POST /apply`는 연도·미리보기 식별값·사유·명령 ID를 받는다. 저장에는 CSRF·최신 권한·버전을 확인한다. 미리본 양과 현재 자료를 서버에서 다시 대조한다.
- 직원 화면은 `GET /me/leave-ledger?year=…`다. 직원 식별자는 세션에서 가져오며, 선택 연도의 내역과 조회일 기준 현재 잔여를 따로 표시한다. 표시량은 기존 신청 화면·원장 합계와 같아야 한다.

## 구현 순서와 인수 테스트

1. 부여·이월·소멸, 동일 연도 중복 방지, 기초 자료 보존, 반일 수량과 승인·취소 정합성의 실패 테스트를 먼저 작성한다. Flyway·MyBatis·서비스를 연결하고 독립 PostgreSQL로 권한·동시 변경을 확인한다.
2. 담당자 정책·미리보기·확정과 직원 원장을 기존 메뉴에 연결한다. 첫 진입, 미설정, 빈 대상, 입력 오류, 미리보기 후 변경·재시도의 화면과 HTTP 계약을 확인한다.
3. PC와 모바일 터치 화면에서 각각 같은 합성 사례를 실행한다. 전기 4.5일, 신규 12일, 한도 3일이면 원천 3일 이월·1.5일 소멸, 신규 잔여 15일이다. 오전 반차 신청·승인·취소 신청·취소 승인 후 잔여는 각 15일·14.5일·14.5일·15일이다. 전기 잔여 없는 동료와도 비교한다.
4. 회귀·브라우저 결과와 재현 방법을 남기고 작업별로 커밋·푸시한다. 이번 기능은 별도 개발 브랜치에서 검증하며 공개 배포는 보류한다.
