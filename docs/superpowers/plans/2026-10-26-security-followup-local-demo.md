# 문서·최종 이미지 보안·Ryuk·로컬 데모 로그인 실행 계획

> 작업은 `subagent-driven-development`와 완료 전 검증을 적용한다. 사용자 요청의 로컬 설정·DB·검증·커밋·일반 Push 승인 범위이며 외부 배포는 하지 않는다.

**목표:** 문서의 현재 상태를 동기화하고 회사코드 없는 로컬 `admin / admin` 로그인 적용 후, 실제 최종 이미지와 Ryuk 경계를 검사한다.

**설계:** [로컬 데모 계약](../../design/local-demo-login.md)의 두 프로필·서버 고정 테넌트·실제 DB 인증을 사용한다. 스키마·일반 비밀번호 정책·고객사 권한을 바꾸지 않는다. 보안 검사는 공식 checksum을 대조한 Syft/Grype와 고정한 DB로 로컬 실행하고 원시 매치와 공급자 판정을 구분한다.

- [x] README·PRD의 현재/과거 상태를 분리하고 최신 402개 회귀·최종 Linux 측정 근거를 연결한다.
- [x] 데모 프로필·인증/UI와 명시 CLI 준비를 테스트 먼저 작성해 RED→GREEN으로 구현한다. 담당 파일을 분리하고 독립 리뷰한다.
- [x] 새 전용 DB에서 전체 회귀와 일반/데모 인증·RLS·회수 경계를 검증한다. 기존 로컬 DB는 사전 식별/집계를 기록한 후 예약 데모 자료만 명시 CLI로 추가한다.
- [x] app/migrate를 빌드하고 실제 loopback 실행·로그인을 확인한다. 새 image ID·빌드/실행 권한·일반 프로필 경계를 기록한다.
- [x] 그 최종 app/migrate·builder·현재 PostgreSQL 이미지의 SBOM과 취약점을 검사한다. 공식 도구/DB 버전·checksum·범위·전체/원시/제외 내역을 기록하고 기존 원장을 보존한다.
- [x] Ryuk의 실제 게시 주소·권한·socket·filter/cleanup 경계를 공식 소스와 대조한다. 가능한 최소 보완을 TDD로 검증하고 새 컨테이너에서 실제 재확인한다. 전역 daemon 변경·임의 shaded patch·단순 정리기 비활성화는 하지 않는다.
- [x] 결과·남은 P1/P2/P3·기능/운영 경계를 문서에 반영하고 링크/diff/status·비밀정보 범위를 확인한다.

마무리 단계는 관련 파일만 커밋·일반 Push한 뒤 원격 HEAD·작업 트리를 확인하는 것이다. 실제 커밋과 원격 확인 결과는 완료 답변으로 전달한다.

검사 DB가 이전 frozen DB와 다르면 검출 차이를 코드 수정 효과로 단정하지 않는다. 로그인 변경 후 기존 33분 성적을 새 이미지의 재측정으로 표시하지 않는다. 새 sustained 부하는 이번 필수 범위가 아니며 실제 수행 여부를 보고한다.

최종 결과는 [검증 보고서](../../quality/security-runtime-recheck.md)를 따른다. 전체 Java433개·Python35개, 실제 HTTP16+24개, 이미지4종 원시1,289행·제외0, Ryuk loopback·자동 정리/범위 밖 보존을 확인했다. 기존 P1과 새 공급자 평가 대기3개 CVE, Ryuk 관리자 소켓 권한은 미해결로 유지한다.
