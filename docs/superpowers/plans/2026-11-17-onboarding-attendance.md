# 인사기본·최초 발령과 출퇴근 기간 조회 구현 계획

> 작업은 담당 파일을 분리해 병렬로 실행한다. 각 단위에서 실패하는 업무 테스트를 먼저 확인한다.

**목표.** 담당자가 인사기본 시트에서 입사 예정 등록, 확정, 최초 발령, 계정 초대 동선을 끝낼 수 있게 한다. 직원은 출퇴근 기록을 기간으로 찾고 일자 상세와 정정 화면을 열 수 있다.

**기준.** 개발 소스 `036f614`의 격리 작업 폴더에서 구현한다. 승인 명세의 현재 DB·HTTP·React 계약을 확장하고 기존 경로를 보존한다. 서버 페이지 JSON과 기존 양식의 CSRF, 변경 감사, 고객사 격리를 재사용한다.

- [인사 명세](../specs/2026-11-17-personnel-onboarding-design.md)
- [출퇴근·메뉴 명세](../specs/2026-11-17-attendance-history-navigation-design.md)

## 담당 1. 입사 예정과 최초 발령

- [x] `EmployeeOnboardingIT` 또는 기존 조직 통합 테스트에 예정 등록·수정·철회, 단일 확정·재시도, 실패 시 두 배정과 사번까지 롤백, 날짜·타사·권한 반례를 추가한다.
- [x] Flyway V18과 `org/EmployeeOnboarding*`에 예정·확정 참조, 복합 FK, FORCE RLS, 제한된 열 권한, HTTP 명령을 구현한다. 명령은 `OrgCommands` 하나 안에서 사번·사원·소속·근무 및 감사를 처리한다.
- [x] `EmployeeService`, `OrgBulkService`에서 이 경로로 확정한 입사일의 수정만 제한한다. 신원과 초대는 기존 계정 경로를 사용한다.
- [x] 화면 담당에게 `org/onboarding` 페이지 모델, 폼 명령 필드, 사원별 발령 연결 값을 전달하고 서버 회귀를 실행한다.

## 담당 2. 인사기본 시트, Excel과 입사 화면

- [x] 시트에서 인사 열과 입사 예정 진입, 확정 검토·결과·미래 초대 안내, 미저장 중 다운로드 차단의 React 사용자 테스트를 작성한다. Excel은 유형·사용자 문자열·권한과 범위에 대한 서버 테스트를 작성한다.
- [x] `OrgAdminController`, `EmployeeAdminMapper`와 조직 시트의 기존 조회에 인사 필드를 투영한다. 등록된 사번을 읽기 전용으로 표시하고 승인된 입사일은 편집 대상에서 제외한다.
- [x] `org/PersonnelExport*`에서 선택 및 전 필터 내보내기, 1,000행 상한, XLSX 고정 열, 현재 권한과 감사 경계를 구현한다. 기본 시트는 `OrgSheetPages`, 예정과 발령은 별도 페이지 컴포넌트에 둔다.
- [x] 담당 1의 모델로 예정·확정·철회 양식과 사원 상세·계정 초대 경로를 연결한다. 공통 React 모델·보안 경로 충돌은 통합 담당에 알린다.

## 담당 3. 출퇴근 기간 조회

- [x] `AttendanceHistoryTest`와 기간 조회 React 테스트에 이번 달·지난달, 3개월 경계, 오늘 진행 중, 누락 필터, 상세·정정 링크를 작성한다.
- [x] `clock/AttendanceController`의 기존 날짜 경로에 기간 모드를 분기한다. 본인 조회만 허용하고 `ClockService`·`WorktimeService`의 유효 기록과 최신성 판단을 재사용한다. 계산과 Excel의 31일 제약은 각 현재 경로에서 유지한다.
- [x] 기간 결과만 담은 읽기용 모델과 컴포넌트를 연결한다. 실제 근무 값이 없으면 공란 표기를 쓰고 기간 조건을 URL에 보존한다. 오늘의 홈 버튼과 기록·확인 메서드 계약은 그대로 연결한다.

## 통합. 업무 메뉴, 신청 범위, 최종 검증

- [x] `navigation.ts` 및 관련 React 테스트에서 직원·담당자·대표·승인자와 겸임 메뉴, 상세/페이지 복귀 URL을 고정한다.
- [x] `RequestController`, `LeaveWorkflowService/Mapper`, `ProfileCompanyController/Queries/Mapper`에 대상 유형 조건을 추가한다. 휴가 목록은 종일 연차와 취소, 정정 목록은 출퇴근 정정만 보여 준다. 회사 목록은 페이지 제한 전 조건을 적용한다.
- [x] 담당자 입사 예정 등록 → 확정 → 발령 확인 → 계정 초대와 직원 기간 조회 → 누락 선택 → 정정 화면을 합성 자료로 검증한다. 역할별 읽기와 변경 범위, 둘 이상의 고객사와 세션 회수를 포함한다.
- [x] 프런트 전체 테스트, 타입 검사, 빌드, Java 단위 및 전용 PostgreSQL 통합 테스트를 실행한다. 도구 제약으로 실행하지 못한 단계는 결과에 기록한다. 검증 기록과 변경 범위를 함께 확인한다.

## 검증 결과

- 프런트 전체 회귀 44파일 544건, TypeScript 검사와 Vite 빌드 통과. 기간 바로가기에서 누락 필터 유지, 관리자 정정 상세 모달의 메뉴 경로 유지, 입사 예정 목록의 독립 페이지 진입을 회귀에 포함했다.
- Java 단위 163건과 관련 PostgreSQL 통합 10클래스 97건 통과. 전용 합성 PostgreSQL 18.6에서 Flyway V1~V18을 적용했다.
- 담당자 흐름에서 입사 예정 등록·철회, 입사 확정과 재시도, 최초 조직·근무 배정, 중복 확정 차단, 실패 후 원자적 롤백을 확인했다. Excel은 선택 범위와 52행 필터 범위, 권한·CSRF 차단, 성공 감사와 파일 내용을 대조했다.
- 직원 흐름에서 합성 초대 수락, 발급 사번 로그인, 최초 발령과 근무 확인, 허용 네트워크 첫 출근을 연결했다. 출퇴근 조회는 92일 허용, 하루 초과 거부, 다른 고객사·사원 자료 범위 차단과 기존 하루 조회를 확인했다. 대표·담당자 신청 유형 목록과 권한도 확인했다.
- 2026-11-17 격리 V18의 최신 JAR로 실제 Chrome 브라우저를 추가 검증했다. PC 1440×900 및 터치 모바일 에뮬레이션 390×844 각각에서 담당자 입사 예정 등록·확정·최초 발령·사원 상세, 직원 3개월 조회·누락 필터·단일 날짜 조회·뒤로 가기·정정 신청 제출을 확인했다.
- 두 환경 모두 12개 화면 관측 기준 문서 가로 넘침과 브라우저 실행 오류가 없었다. 날짜는 PC 2026-10-06 및 모바일 2026-11-03 합성 원천이며 정정은 독립 승인자에게 대기로 제출했다. 모바일 실기기 대신 Chrome의 모바일 에뮬레이션을 사용했다.
