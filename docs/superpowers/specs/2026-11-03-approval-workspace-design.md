# 결재 작업공간·데모 승인 흐름 설계

2026-11-03, Asia/Seoul. 사용자는 현재 신청/헤더/메뉴 디자인에 맞는 결재 화면과 공개 데모의 승인자 배정, 신청부터 승인까지 직접 체험하는 흐름을 요청했다. 승인된 공개 후속 배포 범위에서 진행한다.

## 화면·기존 인터페이스

기존 `ListModel {title, requests, completed?, page?, hasNext?}`와 `RequestDetailModel`을 사용한다. 결재 대기/본인 처리 완료를 현재 인디고 카드·상태 배지·44px 동작 영역으로 표시하고 신청자/유형/기간/연차 DAY/현재 효력을 읽기 쉽게 배치한다. 건수는 조회한 페이지 범위임을 명시하고 전체 건수나 제출 시각을 추정하지 않는다. 빈 목록·미지 코드·다음/이전 페이지를 보존한다. `completed` 없는 관리 목록은 별도 기존 계약을 유지한다.

상세의 승인/반려 영역은 검토 안내·분명한 제목·사유/처리 버튼으로 정리하고 대기함으로 돌아갈 수 있게 한다. 기존 서버 canDecide·버전·commandId·CSRF·정확한 action을 보존한다. 신청자에게 결재 버튼을 노출하거나 프론트에서 승인 권한을 추정하지 않는다. 날짜별 산정·제출 당시 정책/결재선·현재 담당·실제 저장 이력을 유지한다. 사원 헤더에 탭을 추가하지 않는다.

## 데모 신원과 배정

기존 공유 admin의 EMPLOYEE+ATTENDANCE_ADMIN 역할/신원을 유지하고, 같은 합성 고객사의 별도 재직 가상 사원에 EMPLOYEE+APPROVER 계정을 연결한다. 소개에서 신청자/승인자 진입을 선택하고 업무 화면에서 데모 계정 선택으로 돌아갈 수 있게 한다. 전환은 기존 CSRF POST `/login`·DB 암호 해시·현재 계정/역할·세션 교체를 사용한다. GET이나 파라미터만으로 principal을 만들어 인증하지 않는다. 일반 프로필 인증은 변경하지 않는다. 데모는 고정 tenant/account/employee 및 정확 역할 allowlist로 제한하고 두 공유 신원 변경/회수 경로를 보호한다.

기존 사원/사진·계정·원장·일정·신청은 보존한다. 신청자에게 새 신청부터 적용되는 독립 승인자를 전용 후속 준비 명령으로 배정한다. 조사 결과 기존 신청자에 일정·합성 달력·12DAY 묶음이 있어 새로 생성하지 않는다. 묶음의 미분류 귀속도 추정 확정하지 않는다. 기초잔여나 기존 완료/대기 신청을 덮어쓰지 않고, 기존 대기를 자동 재할당하지 않는다. 재실행은 감사 근거와 고정 식별자를 검증해 같은 상태에서 추가 변경이 없어야 한다. bootstrap/sample-data/과거 인사 CLI는 재실행하지 않는다. 스키마를 바꾸지 않는 최소 구현을 우선한다.

## 실제 흐름·안전 경계

정상 신청자 로그인 → 미래 소정근로일의 종일 연차 미리보기 → 제출 → 승인자 정상 로그인 → 지정 대기함 → 검토 사유/승인 → 본인 처리 완료/상세 → 신청자로 전환 → 승인 상태·실제 잔여 차감을 확인한다. 처리 완료는 서버 응답/저장 상태만 표시한다. 반려/철회·동시 처리·중복 재전송·다른 테넌트/자기 승인 차단은 기존 업무 서비스가 검증한다. 실제 개인정보/메일/운영자 접근은 추가하지 않는다.

UI TDD와 인증/공유 보호/준비 명령의 실패 테스트 후 구현한다. 전용 합성 PostgreSQL에서 실제 상태/이벤트/원장/감사의 정확한 변화와 재실행을 검증한다. 공개 최신 소스/이미지/V16·전체 자료/권한·기존 서비스 기준을 새로 읽고 전용 백업/독립 복원 및 필요한 자료 보완·앱 반영·공개 보안/PC/모바일/실제 신청→승인을 검증한다. 예상된 추가 행과 기존 자료 보존을 구분하며 실행하지 않은 검증은 별도로 남긴다.
