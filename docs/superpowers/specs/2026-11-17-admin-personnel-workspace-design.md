# 담당자 인사기본과 인사정보 일괄관리 상세 명세

기준일은 2026-11-17이다. 담당자가 사원 한 명의 인사정보를 관리하는 화면과 여러 사원의 공통 항목을 한 번에 관리하는 시트를 제공한다. 이번 문서는 구현 전 명세다. [입사·최초 발령 계약](2026-11-17-personnel-onboarding-design.md) · [인사정보와 이력 계약](../../design/personnel-workspace.md)

## 1. 메뉴와 담당자 동선

| 메뉴 | 담당자 업무 |
| --- | --- |
| 인사관리 > 사원 > 인사기본 | 인사 헤더에서 사원 선택 → 탭 조회 → 입력·저장 → 같은 탭 재조회 또는 다운로드 |
| 인사관리 > 사원 > 인사정보 일괄관리 | 사번·이름·소속·상태로 조회 → 기존 시트의 여러 행 편집·비활성화 → 변경 확인·저장 → 선택 또는 조회 조건 Excel |
| 인사관리 > 사원 > 입사 예정 관리 | 입사 예정 등록 → 사번과 최초 소속·근무 배정 → 입사 확정 → 확정 사원의 인사기본으로 이동 |
| 내 업무 > 인사정보 > 내 정보 | 로그인한 사원 본인의 헤더와 7개 탭 조회 |

- 인사기본 첫 진입에는 사원 검색과 선택 안내를 표시한다. 로그인 담당자의 이름이 있던 헤더 자리에 `사원 검색`을 표시한다. 상단 로그인 사용자 표시는 기존 공통 화면에서 관리한다.
- 검색 결과에는 사번·이름·소속·재직 상태만 표시한다. 담당자는 인증된 회사 내의 확정 사원 전체를 사번 또는 이름으로 검색할 수 있다. 휴직·퇴사·비활성 사원도 결과에 포함하고, 미확정 입사 예정은 입사 예정 관리에서 조회한다. 동명이인은 사번과 소속으로 구분한다.
- 선택하면 헤더의 사진·사번·이름·소속·재직 상태·생년월일·직급·직책·직무·입사일과 7개 탭 전체가 선택 사원 기준으로 표시된다. 사원 변경 시 기본사항 탭으로 돌아가고 같은 사원의 저장 뒤에는 현재 탭을 다시 연다. PC에서는 헤더에 검색을 배치하고 모바일에서는 선택 전과 선택 후 모두 헤더 위쪽에서 검색할 수 있게 한다. 검색과 탭 전환은 키보드로도 가능해야 한다. 결과가 없으면 검색어와 결과 0건을 표시한다.
- 일괄관리 시트 행의 인사정보 링크는 해당 사원의 인사기본을 연다. 기존 편집 범위인 이름·입사일·마지막 재직일·활성 상태와 사번 불변 계약, 서버 검색·페이지, 일괄 취소·원자 저장·Excel 필터 범위를 유지한다. 재직 표시 상태와 직급·직책·직무는 현재와 같이 시트에서 조회한다.

## 2. 탭별 입력·저장·다운로드

기본사항과 주소·연락처에는 `입력·수정`, 이력 탭에는 `이력 추가`, 발령내역에는 `소속 발령 등록`을 제공한다. 입력 중에는 `저장`과 `취소`를 표시한다. 다운로드는 선택한 사원의 현재 탭에 저장된 값으로 생성한다. 공통 식별 열은 사번과 한글 이름이다.

| 탭 | 담당자 입력 항목 | 저장 방식 | Excel 허용 열 |
| --- | --- | --- | --- |
| 기본사항 | 한글·영문 이름, 회사 입사일·마지막 재직일, 입사구분, 인정경력, 그룹입사일, 생년월일, 사진, 직급·직책·직무, 재직 상태와 적용일, 결혼 여부·일자, 보훈·장애 여부, 병역 상태·군별 | 사원·인사·상세정보의 기존 원본과 검증을 사용한다. 사번은 조회만 한다. 재직 상태는 적용일 이력으로 남긴다. 휴대전화 수정은 주소·연락처에 둔다. | 입사일, 마지막 재직일, 입사구분, 인정경력, 그룹입사일, 소속, 재직 표시 상태, 직급·직책·직무 |
| 발령내역 | 배정할 활성 조직, 소속 적용 시작일, 변경 사유 | 기존 소속 배정 서비스에 새 발령을 저장한다. 기존 미종료 소속 종료일은 새 발령 시작일로 계산한다. 입사 확정 시 기록한 최초 발령은 입사로 표시한다. | 발령 구분(입사·소속 배정), 조직명, 적용 시작일, 적용 종료일(미포함) |
| 가족사항 | 관계, 해당 인원, 적용 시작일, 선택 종료일, 변경 사유 | 관계·인원 단위로 새 개정을 추가한다. 저장된 과거 이력은 행으로 조회한다. 관계는 배우자·자녀·부모·기타, 인원은 1 이상의 정수로 입력한다. | 관계, 인원, 시작일, 종료일. 기존 자유입력 이력은 관계·인원을 확정된 형식으로 읽을 수 있는 경우에만 해당 열에 기록한다. |
| 학력사항 | 학교명, 전공·졸업 구분, 시작일, 선택 종료일, 변경 사유 | 기존 학력 분류에 새 이력을 추가한다. | 학교명, 전공·졸업 구분, 시작일, 종료일 |
| 자격사항 | 자격명, 발급기관, 취득일, 선택 만료일, 변경 사유 | 기존 자격 분류에 새 이력을 추가한다. | 자격명, 발급기관, 취득일, 만료일 |
| 어학사항 | 언어·시험명, 등급 또는 점수, 취득일, 선택 만료일, 변경 사유 | 기존 어학 분류에 새 이력을 추가한다. | 언어·시험명, 등급 또는 점수, 취득일, 만료일 |
| 주소·연락처 | 우편번호, 기본주소, 상세주소, 휴대전화, 연락 이메일, 변경 사유 | 상세정보에 현재값을 저장한다. 계정 로그인 이메일은 계정 관리에서 관리한다. | 우편번호, 기본주소, 끝 4자리만 보이는 휴대전화, 아이디를 마스킹한 연락 이메일 |

### 발령내역

- 기존 소속 배정의 적용일 규칙을 사용한다. 서울 기준 오늘 이후이면서 사원의 재직 기간 안이고, 마지막 소속 시작일보다 늦은 날짜를 받는다. 같은 시작일, 과거일, 종료된 재직 기간, 비활성 조직은 저장 단계에서 거부한다.
- 적용 구간은 시작일 포함·종료일 미포함이다. 종료일이 없는 구간은 시작일과 서울 오늘을 비교해 현재 또는 예정으로 표시한다. 기존 기록 중 종료된 구간은 종료일을 표시한다.
- 화면에 발령 시작일·종료일·소속·입사 표식을 표시한다. 초기 발령의 구분은 기존 입사 확정 기록에서 가져온다. 변경 사유는 기존 감사 흐름에 남긴다. 이번 등록 범위는 소속 발령이다.

### 가족사항과 다른 추가 이력

- 가족 입력에는 관계와 인원만 받는다. 가족 이름·주민등록번호·생년월일·연락처를 수집하는 필드는 두지 않는다. 기존 형식의 이력은 입력 이전 자료로 구분해 조회하며, Excel에서는 자유입력 원문과 변경 사유를 제외한다.
- 네 이력 탭의 종류는 현재 탭으로 결정한다. 시작일은 필수, 종료일은 선택이며 시작일보다 빠른 종료일은 검증 오류로 표시한다. 저장마다 새 개정을 추가하고 기존 이력은 읽기 전용으로 제공한다. 각 탭은 해당 분류의 이력만 표시하고 다운로드한다.
- 기존 항목명·상세·날짜 저장 계약을 재사용한다. 새 입력은 탭별 필드를 항목명·상세에 정해진 형식으로 전달한다. 기존 형식으로 저장한 학력·자격·어학 행은 안전하게 구분할 수 있는 항목과 날짜를 내보내고 구분을 확인할 수 없는 상세 원문은 다운로드에서 제외한다.

## 3. 조회·저장·다운로드 계약

| 경로 | 계약 |
| --- | --- |
| `GET /admin/employees` | 인사기본 검색 대기 화면. 기존 `employeeId` 단독 링크는 선택 사원의 인사기본으로, 기존 시트 조회 조건 링크는 일괄관리로 연결한다. |
| `GET /admin/employees/personnel/search?q=…&page=…` | 담당자 전용 검색. 행에 사원 ID·사번·이름·소속·재직 상태를 제공한다. 50건 단위로 페이지를 조회한다. |
| `GET /admin/employees/{id}/personnel?tab=…` | 선택 사원의 인사기본. 기존 사원별 인사정보 링크를 사용한다. 탭 값은 7개 고정 식별자로 검증한다. |
| `GET /admin/employees/bulk-edit` | 기존 사원 시트. `q`, `organizationId`, `status`, `page`를 사용한다. |
| 기존 `POST /admin/employees/bulk`, `POST /admin/employees/exports` | 일괄관리 저장과 Excel의 기존 입력·검증·지원 범위를 유지한다. 입사 예정과 최초 발령 API도 기존 경로를 사용한다. |
| `POST /admin/employees/{id}/personnel/tabs/{tab}` | 현재 탭의 변경 필드, 변경 사유, 명령 ID, 해당 원본 버전을 받는다. 기존 사원·인사·상세 저장과 발령 규칙을 공통으로 사용한다. |
| `POST /admin/employees/{id}/personnel/tabs/{tab}/export` | 권한 검증 후 한 사원·한 탭의 XLSX를 제공한다. 현재 탭이 비어 있으면 열 제목이 있는 파일을 제공한다. |

- 저장은 해당 사원과 변경 탭에 한해 서버에서 필드를 검증한다. 기본사항의 여러 원본 저장은 같은 고객사 잠금·트랜잭션에서 처리해 함께 반영한다. 주소·연락처와 기본사항이 상세정보 버전을 공유하므로, 서버는 현재 탭의 변경 필드만 반영하고 낡은 버전은 409로 반환한다.
- 사원·탭 전환, 일괄관리 이동, 뒤로 가기와 페이지 이탈 전에 미저장 입력을 확인한다. 저장 대기 중에는 중복 제출과 사원 전환을 막는다. 검증 실패나 충돌 때는 현재 사원·탭과 입력을 유지하고, 충돌 시 최신 저장값을 비교해 다시 저장할 수 있게 한다. 저장 후 같은 탭을 재조회하고 헤더에 반영할 값도 갱신한다.
- 검색·상세·저장·파일·사진 요청마다 서버에서 현재 담당자 역할과 인증된 고객사를 확인한다. 고객사 또는 대상 사원 ID는 검색 결과의 화면 상태에만 의존하지 않는다. 타사 또는 존재하지 않는 사원은 같은 404로 처리한다. 일반 직원의 본인 정보는 기존 본인 조회 경로를 사용한다.
- XLSX는 탭별 허용 목록으로 생성한다. 기본사항의 생년월일·사진·결혼·보훈·장애·병역, 상세주소·연락처 원문, 변경 사유·처리자는 파일에서 제외한다. 사용자 입력은 문자열 셀로 기록한다. 캐시는 `no-store`를 사용하고, 성공한 다운로드에는 요청자·대상 사원·탭·시각·행 수를 남긴다. 파일과 내용 원문은 감사에 저장하지 않는다.
- 공개 데모의 공유 사원은 검색·조회에 표시하고 변경 제한을 함께 안내한다. 공개 데모의 기존 인사정보 다운로드 차단을 새 탭별 다운로드에서도 적용한다. 보호 대상은 UI와 직접 요청 모두에서 확인한다.

## 4. 순차 구현과 수용 기준

| 순서 | 작업 | 수용 기준 |
| --- | --- | --- |
| 1 | 인사정보 일괄관리 이동 | 기존 검색과 필터로 여러 사원을 찾고 행 두 개를 저장한다. 조회 상태를 유지하고 시트에서 기존 사원 상세 경로로 이동한다. 2단계에서 같은 경로에 새 화면을 연결한다. |
| 2 | 인사기본 헤더와 검색·조회 | 동명이인 두 명을 사번·소속으로 구분한다. 선택한 사원과 헤더·7개 탭이 일치하고, 다른 사원 전환 시 이전 사원 데이터가 남지 않는다. 휴직·퇴사 사원도 검색된다. |
| 3 | 탭 편집과 발령 연결 | 기본사항 저장 후 헤더가 갱신된다. 소속 발령으로 현재·예정 구간이 맞게 표시된다. 가족·학력·자격·어학 추가 후 기존 이력과 새 개정이 보인다. 주소 변경은 다른 탭의 값을 보존한다. |
| 4 | 탭별 XLSX | 저장 후 받은 각 파일의 열과 값이 명세와 일치한다. 다른 사원 정보, 미저장 입력, 가족 자유입력 원문과 상세 연락처가 포함되지 않는다. 다운로드 감사를 확인한다. |
| 5 | 담당자·직원 흐름과 보안 회귀 | PC·모바일에서 검색→선택→입력→저장→재조회→파일을 확인한다. 미저장 이동, 동시 저장 충돌, 일반 직원과 타사 요청, 공개 공유 사원 보호, 기존 입사 확정·최초 발령과 내 정보 회귀를 검증한다. |
