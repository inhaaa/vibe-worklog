# 회사 근무현황의 퇴근 누락·정정 반영 명세

- 작성일 2026-11-18
- 대상 메뉴 [근태 운영 > 회사 근무현황]
- 대상 사용자 근태 담당자, 직원, 지정 결재자

## 1. 업무 목표

담당자는 사원을 한 명씩 열지 않고 특정 근무일의 퇴근 누락을 찾는다. 직원이 본인 기록에서 정정을 신청하면 지정 결재자가 심사한다. 담당자는 같은 날짜의 목록으로 돌아와 승인된 유효 퇴근 시각과 최신 실근로시간이 각각 반영됐는지 확인한다.

현재 회사 근무현황은 사원을 선택한 뒤 월별 일자·집계 정보를 보는 화면이다. 이번 개선으로 그 화면에 `퇴근 누락` 탭을 추가한다. 첫 진입에는 기존 월별 화면을 열고, 퇴근 누락 탭의 첫 조회는 서울 기준 어제로 설정한다. 담당자는 지난 근무일을 선택해 여러 조직·사원의 누락을 한 번에 확인한다.

## 2. 사용자 흐름

| 순서 | 사용자와 화면 | 동작과 확인 결과 |
| --- | --- | --- |
| 1 | 담당자 · 회사 근무현황 > 퇴근 누락 | 날짜를 선택한다. 필요하면 해당 근무일 당시 소속, 사번·이름, 정정 상태로 좁힌다. 행을 열어 원천 출근, 누락된 원천 퇴근, 예정 퇴근, 현재 유효 기록을 확인한다. 확인이 필요한 사원에게 해당 근무일을 안내한다. |
| 2 | 직원 · 내 업무 > 출퇴근 > 기간 조회 | 최대 3개월 범위에서 해당 근무일을 찾아 상세를 연다. `정정 신청`에서 기존 출근 시각 유지, 실제 퇴근 시각, 사유를 입력한다. 실제 근로와 휴게를 확인할 수 있으면 같은 신청서에 기록한다. 제출하면 직원에게 결재 대기 상태가 표시되고 담당자 목록에도 대기로 나타난다. |
| 3 | 지정 결재자 · 결재함 | 출퇴근 정정 신청 상세에 원천·현재 유효·제안 시각 비교를 추가한다. 결재자는 대상일과 제안 퇴근 시각, 사유, 근무·휴게 확인 내용을 검토하고 기존 1단계 지정 결재로 승인하거나 반려한다. 자기 승인 및 원천 기록이 바뀐 오래된 신청의 승인 제한을 적용한다. |
| 4 | 담당자 · 회사 근무현황 > 퇴근 누락 | 같은 날짜와 검색 조건에서 `정정 반영` 행을 열면 결재 결과와 유효 퇴근 시각이 보인다. `정정 상세`로 신청·결재 이력을, `근태 집계·Excel`로 해당 사원·월의 집계 상세를 연다. 재집계가 필요한 경우 기존 재집계 기능을 사용하고, 돌아와서 그 날짜의 최신 집계 시각과 실근로시간을 확인한다. |

회사 근무현황은 누락을 찾고 반영을 확인하는 업무 진입점이다. 출퇴근 정정 현황은 제출된 신청과 결재 이력을 보여 준다. 회사 근무현황에서 아직 신청이 없는 날짜도 발견할 수 있고, 신청이 생기면 같은 행에서 상세로 이동할 수 있다.

직원이 본인 기록에서 출근을 유지하고 누락된 퇴근만 정정하는 경우, 신청서에 대상일과 기존 출근 시각을 보여 주고 퇴근 시각과 사유부터 입력할 수 있게 한다. 근무·휴게는 직원이 실제로 확인한 값을 받아 저장한다. 같은 날 대기 신청이 있으면 해당 신청을 보여 준다.

## 3. 퇴근 누락 탭

### 조회와 표시

- 필터는 `근무일`, `소속`, `사번 또는 이름`, `정정 상태` 순서로 둔다. 날짜는 서울 기준 어제까지 선택할 수 있다. 오늘 출근만 있고 퇴근이 없는 경우 직원의 오늘 기록에서는 기존 규칙에 따라 `근무 중`으로 표시한다.
- `근무일 당시 소속`은 그 날짜에 유효한 주 소속을 사용한다. 전보 이후에도 이전 날짜의 기록은 당시 소속에서 검색된다. 소속 미등록 행은 전체 조회에 남기고 `소속 미등록`으로 표시한다.
- 상태 필터는 `전체`, `퇴근 누락`, `결재 대기`, `정정 반영`이다. 기본값 `전체`에는 반영 후 행도 남긴다. 누락, 대기, 반영 순으로 보여 주고 상태 내에서는 사번과 내부 사원 ID로 정렬한다.
- PC 목록에는 사번·이름, 소속, 원천 출근·퇴근, 유효 퇴근, 정정 상태, 집계 상태를 표시한다. 상세에서 근무일, 예정 퇴근, 유효 출근, 결재 결과와 이동 버튼을 확인한다. 모바일에서는 사원·상태·유효 퇴근을 먼저 보여 주고 같은 상세를 펼칠 수 있게 한다.
- `정정 상세`나 `근태 집계·Excel`로 이동하고 돌아올 때 근무일·소속·검색어·상태·페이지를 복원한다. 결과가 0건이면 조회한 근무일과 조건을 표시한다. 날짜나 검색 조건을 바꾸면 첫 페이지에서 다시 조회한다.

### 누락 후보와 상태 전이

누락 후보는 재직 기간 중 확정된 근무일에 **원천 출근 1건, 원천 퇴근 0건**이 있는 사원과 근무일의 조합이다. 근무일 기준으로 일정과 캘린더가 확인돼야 한다. 휴일·비근무일·승인 종일 휴가일, 출근 누락, 기록 중복·순서 오류 등 별도 판단이 필요한 경우는 퇴근 누락 목록에서 제외한다. 유효 기록과 승인 휴가가 충돌하면 기존 근무현황·집계에서 확인한다.

| 정정 상태 | 표시 조건과 다음 동작 |
| --- | --- |
| 퇴근 누락 | 현재 유효 퇴근이 없고 같은 날짜의 대기 정정이 없다. 반려·철회 후에도 유효 퇴근이 없으면 이 상태로 돌아온다. 처리 이력이 있으면 상세에서 최근 결과와 링크를 표시한다. |
| 결재 대기 | 같은 날짜의 정정 신청이 심사 중이다. 현재 유효 시각은 승인 전 값으로 유지하고 대기 중인 신청을 연결한다. 다른 내용을 수정하는 정정이면 실제 제안 항목을 상세에서 확인할 수 있다. 기존 중복 신청 제한을 적용한다. |
| 정정 반영 | 현재 효력이 있는 승인 정정으로 유효 퇴근이 생겼다. 원천 퇴근은 `미기록`, 유효 퇴근은 승인 시각으로 따로 표시한다. 후속 정정이 대기 중이면 `결재 대기` 상태로 보여 주면서 현재 유효 퇴근은 계속 표시한다. |

승인 이력이 있어도 현재 유효 퇴근이 없으면 `정정 반영`으로 표시하지 않는다. 대체 정정의 적용 시점에는 현재 유효값과 연결되는 상세가 함께 갱신된다. 원천 출퇴근 기록과 이전 신청·결재·집계 이력은 기존 방식으로 보존한다.

## 4. 승인 이후 집계 확인

정정 승인 시 유효 출퇴근과 승인 결과가 적용되고 이전 집계는 최신성을 잃는다. 확인 근거가 갖춰진 날짜는 `재집계 필요`, 근거가 부족한 날짜는 `근무 확인 필요`로 표시한다. 화면 조회에서는 산정을 실행하지 않는다.

| 집계 상태 | 담당자에게 표시할 내용 |
| --- | --- |
| 근무 확인 필요 | 승인된 유효 출퇴근이 있어도 실제 근로·휴게 확인이 부족하면 실근로시간은 `미확정`이다. 직원이 기존 기준을 충족하면 본인 근무 확인을 하고, 이 확인 저장 뒤 해당 주의 산정이 실행된다. 일정·기록 조건이 기존 확인 조건을 충족하지 않으면 상세에서 해당 사유를 안내한다. |
| 재집계 필요 | 필요한 확인 근거는 있으나 최신 입력을 반영한 집계가 없다. `근태 집계·Excel`에서 기존 기간 지정·사유 입력으로 재집계한다. 영향받은 주를 재산정한 뒤 해당 날짜에서 결과를 확인한다. |
| 집계 확인 필요 | 중복·순서·일정·휴가 충돌 등 재집계 결과에 검토가 필요하다. 집계 상세에서 이유를 보고, 현재 집계에서 확정된 값만 표시한다. |
| 집계 반영 | 해당 날짜의 결과가 현재 사실·검토 개정과 원천 지문에 일치하고 실근로시간이 확정됐다. 실근로시간과 집계 시각을 표시한다. |

지난 집계 결과는 기존 결과 이력에서 확인할 수 있다. 현재 집계 칸은 이전 수치나 확인되지 않은 `0시간`을 표시하지 않는다. 예정 휴게는 실제 휴게 확인을 대신하지 않는다. 승인 휴가와 유효 기록이 충돌하면 기존 검토 상태를 적용하고 휴가 효력과 원장 이력을 보존한다.

## 5. 조회 인터페이스와 권한

- 신규 조회는 `GET /company/attendance?view=checkout&date=YYYY-MM-DD&organizationId=&q=&status=ALL&page=0`으로 한다. 상태 값은 `ALL`, `MISSING`, `PENDING`, `CORRECTED`다. 날짜 생략 시 어제, 상태 생략 시 전체를 적용한다. 잘못된 날짜, 오늘 또는 미래 날짜, 알 수 없는 상태는 검증 오류로 안내한다. 페이지당 50건을 조회한다. 기존 월 조회의 URL과 파라미터를 계속 지원한다.
- 날짜별 행은 사원 ID·사번·이름·조회일 당시 주 소속, 근무일·예정 퇴근, 원천/유효 출퇴근 시각, 표시할 정정의 ID·상태, 집계 상태·현재 확정 실근로시간·집계 시각을 반환한다. 원천과 유효 시각은 각각 누락값을 표현할 수 있고, 현재 값이 없으면 시간 필드는 비운다. 정정 사유는 권한을 확인하는 기존 신청 상세에서 조회한다.
- 누락 판정, 승인 효과, 결과 최신성은 각각 기존 출퇴근·정정·집계의 서버 판정을 사용한다. 당시 소속으로 범위를 좁히고 상태를 판정한 뒤 페이지를 자른다. 한 화면 조회 중 정정 상태와 유효 기록이 서로 다른 시점의 값을 표시하지 않도록 같은 일관된 읽기 범위에서 가져온다.
- 근태 담당자(`ATTENDANCE_ADMIN`)가 소속 테넌트의 새 탭과 기존 담당자 상세를 조회한다. 대표 권한으로는 기존 회사 월별 근무현황을 조회한다. 직원은 본인 기록·신청, 지정 결재자는 자신에게 배정된 신청을 기존 권한 범위에서 다룬다. URL의 조직·사원·신청 ID를 바꿔도 다른 테넌트나 권한 밖 데이터에 접근할 수 없어야 한다.
- 정정에는 기존 `/me/requests/correction?date=…`, `/approvals`, `/requests/{id}`를 사용한다. 집계에는 기존 `/admin/attendance?employeeId=…&month=…`를 사용하고 해당 날짜 행으로 연결한다. 돌아가기에는 이 화면의 검증된 조회 조건만 사용한다. 별도 저장 경로나 신규 테이블 없이 기존 승인·감사·재집계 경로를 사용한다.

## 6. 수용 기준

| 시나리오 | 기대 결과 |
| --- | --- |
| PC·모바일에서 역할별 전체 흐름 | 같은 가상 사원·날짜에 원천 출근 09:00, 원천 퇴근 없음으로 시작한다. 담당자 발견 → 직원이 퇴근 18:00·실제 휴게 12:00~13:00과 근로 확인을 담아 제출 → 지정 결재자 승인 → 담당자가 원천 미기록·유효 퇴근 18:00·재집계 필요 확인 순서로 진행한다. 유효한 일정·캘린더와 그 밖의 계산 조건이 갖춰진 사례에서 재집계 후 해당 날짜가 `집계 반영`, 실근로 8시간으로 표시된다. |
| 승인에 실제 근로·휴게 확인이 없는 경우 | 유효 퇴근은 표시되고 집계는 `근무 확인 필요` 또는 확인 사유가 표시된다. 실제 확인 전에는 실근로가 미확정이다. |
| 반려·철회·연속 정정 | 여전히 유효 퇴근이 없으면 누락으로 돌아간다. 승인 뒤 대체 신청이 대기인 동안 종전 유효값을 유지하고, 대체 정정이 승인되면 새 값과 링크로 갱신한다. 요청 이력과 원천은 보존된다. |
| 날짜·소속 경계 | 오늘 진행 중, 휴일·비근무일, 승인 종일 휴가일, 출근 누락, 중복·순서 오류는 누락으로 잘못 표시하지 않는다. 전보 이전 날짜는 당시 소속으로 조회된다. |
| 권한과 동시 처리 | 담당자만 새 탭에 진입한다. 타 테넌트의 사원·조직·신청과 자기 승인, 이중 제출·중복 승인, 변경된 원천 기준으로 제출한 오래된 화면의 승인이 각각 기존 규칙에서 차단된다. |
| 탐색과 현재 결과 | 다른 상태로 전환돼도 전체 목록에서 대상 행을 다시 찾을 수 있다. 상세·집계에서 돌아오면 조회 조건이 복원된다. 재조회 이전 결과가 최신 실근로로 보이지 않는다. |
