# 연차 기초 잔여 이관과 반일 단위 조정

담당자는 휴가관리 > 연차 관리에서 개인별 등록·조정 또는 사원별 일괄 입력을 선택한다. 예전에 쓰던 원장의 사번과 근거를 확인해 기초 7.5일을 등록하고 직원 잔여와 대조한다. 직원 반차의 최종 승인으로 7일, 취소 최종 승인으로 7.5일이 된다.

- 기초는 0 이상, 조정은 0을 제외한 양수·음수이며 기존 한도와 날짜·사유·근거 규칙을 적용한다. 정수와 정확한 0.5일 단위를 허용한다. 0.25, 음수 기초, 음수가 되는 조정은 해당 행에 오류를 표시한다.
- 일괄 시트는 행별로 기초/조정, 사번, 기준일, 일수, 근거, 사유를 받는다. 기초에는 사용 가능 기간을, 조정에는 해당 사원의 기존 연차 묶음을 지정한다. 한 번에 1~50행을 입력하며 여러 사원의 행을 추가·제거한다. 적용 전 미리보기에서 사원·행별 오류 및 대상 잔여의 전후값을 확인한다. 미리보기는 원장을 변경하지 않는다.
- 저장은 현재 테넌트와 담당자 권한, 본인 변경 금지, 중복 행, 대상과 버전, 입력 규칙을 다시 확인한다. 오류나 동시 변경이 있으면 전체를 되돌린다. 동일 명령 재전송은 한 번만 반영한다. 같은 사원의 동일 기초 행 또는 동일 묶음에 대한 중복 조정을 한 저장에서 차단한다. 저장 후 직원별 원장과 이력에서 확인한다.
- 저장 수량은 PostgreSQL numeric으로 정확히 보존한다. 기존 기초·조정·반차 원장과 정수 명령의 재시도를 유지한다. 연간 귀속 기초 합계에도 반일을 보존한다. 회사가 확인한 기초를 옮기는 업무로 연차 자동 발생 계산은 별도다.

## 화면·서버 인터페이스

사번에 해당하는 조정용 묶음은 담당자의 고객사 범위에서 `GET /admin/leave-balances/bulk/options?employeeNo=...`로 가져온다. 일괄 입력의 `preview`와 `save`는 `/admin/leave-balances/bulk/` 아래의 POST 요청이며 CSRF를 확인한다. 입력에는 명령 ID와 행 식별자, 업무 구분(OPENING/ADJUSTMENT), 사번·효력일·수량·근거·사유를 전송한다. 기초 등록은 사용 가능 기간을 사용하고 조정은 묶음 ID와 저장 전 확인한 버전을 사용한다. 미리보기에서 각 묶음 잔여 전후와 오류를, 저장 후에는 실제 원장 링크를 제공한다.

기존 [반차 승인·취소](2026-11-18-attendance-codes-half-day.md)의 정수 기초·조정 제한을 이 명세로 확장한다.
