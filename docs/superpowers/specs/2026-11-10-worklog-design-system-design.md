# WorkLog 공통 디자인 시스템 설계 — 시트·모달·화면 틀

- 기준일: 2026-11-10 `Asia/Seoul`
- 상태: 사용자 방향 승인(시안 v1과 아래 결정). 구현 전.
- 기준: `codex/demo-entry-public-20261109` `8cab191` → 작업 브랜치 `claude/worklog-design-system-20261110`, 작업트리 `target/worklog-design-20261110`
- 시안: [디자인 보드](../../design/mockups/2026-11-10-worklog-design-board.html). 합성 자료만 사용한다. 보드는 문서용이라 CDN 글꼴을 쓰고, 앱은 글꼴을 자체 포함한다.

## 1. 요청과 결정

사용자는 현재 WorkLog가 낡고 AI가 만든 것처럼 보인다며 전반적인 디자인 정리를 요청했다. 필요한 것은 공통 시트, 공통 모달, 공통 화면 틀이다. 2026-11-10 시안 v1을 검토한 뒤 다음을 선택했다.

| 항목 | 결정 |
| --- | --- |
| 밀도 | 기본: 컨트롤 34px, 표 행 38px, 표 머리 36px. 모바일·터치는 44px |
| 사이드바 | 밝은 사이드바 |
| 테마 | 차콜·블루 전환 유지, 두 테마 색 재조정 |

| 구현 | A안: 기존 CSS를 legacy 층으로 낮추고 새 디자인 층을 올린 뒤 5단계로 이전 |
| 동작 변경 | ① 일괄 변경 사유를 저장 확인 모달에서 입력 ② 화면 설명 문장을 도움말(?)로 이동 ③ 내 업무 화면의 사원 헤더를 한 줄 맥락 줄로 축소 ④ 캘린더 오른쪽 요약 패널 |

사용자가 준 참고 화면에서는 조회 조건 바, 문서형 표, 결재란, 날짜 메뉴, 요약 줄 같은 일반적인 업무 화면 패턴만 가져온다. 특정 제품의 모양·문구·자산은 재현하지 않는다(AGENTS.md 독립 개발 원칙).

## 2. 현재 문제

- 글꼴은 `Noto Sans KR`로 지정돼 있지만 글꼴 파일을 싣지 않는다. 그래서 Windows에서는 맑은 고딕으로 표시된다.
- React 화면은 CSS 세 개를 차례로 불러온다: `/app.css`(백엔드 정적 파일, 62KB), `/react/app.css`, `/react/sheet.css`.
- 덮어쓰기가 많이 쌓였다. `#tna-app` 선택자가 2,000곳, `!important`가 11곳이다.
- 모서리 값은 20가지 이상, 글자 크기는 25가지 이상이 섞여 있다.
- 화면마다 설명 문장이 붙고, 버튼은 모두 같은 무게이며, 표는 가운데 정렬이다. 입력창은 크고 둥글다.
- 버그: 조직 시트의 조직장 칸에서 "조직장 미배정"과 "조직장 배정" 링크가 붙어 보인다.

## 3. 목표와 범위

1. 공통 시트, 공통 모달, 화면 틀 5종을 하나의 토큰·컴포넌트 규칙으로 통일한다.
2. 화면을 옮긴 뒤 쓰지 않게 된 legacy CSS를 삭제한다.
3. 업무 동작, 서버 계약, 권한, CSP, 접근성 동작은 유지한다. 바꾸는 동작은 1절의 네 가지뿐이다.

범위 밖:

- 로그인 전 소개·로그인·초대·비밀번호 재설정 화면(2026-11-07 재설계분)
- 운영자 콘솔과 Thymeleaf 템플릿
- 새 업무 기능, API, DB
- 메뉴 항목과 권한별 노출
- 다크 모드, 다중 화면 탭
- 공개 데모 배포

## 4. 디자인 원칙

- 채운 버튼은 영역마다 하나만 둔다. 시트 머리에서는 [저장], 모달에서는 주 동작, 화면 머리에서는 화면 주 동작이다. 조회 조건 바의 [조회]는 진한 중립색이다.
- 화면 머리에는 제목, 도움말(?), 화면 동작만 둔다. 설명 문장은 도움말로 옮기며 내용은 지우지 않는다.
- 표는 2px 윗선과 1px 칸선을 쓴다. 정렬은 글자 왼쪽, 숫자 오른쪽, 날짜·체크·상태 가운데이며, 머리 정렬은 내용 정렬을 따른다.
- 다음은 쓰지 않는다: 그라디언트, 장식 그림자, 큰 둥근 카드, 카드 안 카드, 이모지. 배경은 흰색으로 두고 선과 간격으로 구획한다.
- 숫자는 `tabular-nums`로 폭을 맞춘다. 버튼 문구는 "3건 저장", "신청"처럼 동사로 구체적으로 쓴다.
- 상태는 색만으로 구분하지 않고 문구와 함께 표시한다. 필요하면 아이콘도 더한다.
- 아이콘은 1.7px 선으로 된 인라인 SVG 한 세트만 쓴다.

## 6. CSS 구조

- **우선순위:** `@layer vendor, legacy;`를 쓴다. 새 디자인 CSS는 층 없이 두므로 legacy보다 항상 우선한다. 따라서 `#tna-app` 선택자를 새로 쓰지 않는다.
- **`src/main/resources/static/app.css`:** 첫 줄에 층 순서를 선언하고, 나머지 전체를 `@layer legacy { … }`로 감싼다. Thymeleaf 화면은 이 파일만 쓰므로 표시가 같다.
- **기존 React CSS:** WorkspacePolish·컴포넌트·페이지 CSS를 파일마다 `@layer legacy { … }`로 감싼다. `@import`에는 `layer(legacy)`를 붙인다.
- **AG Grid CSS:** `@import … layer(vendor)`로 불러온다.
- **legacy 안의 `!important`:** 새 규칙과 겹치는 곳만 지운다.
- **새 파일:**
  - `frontend/src/design/tokens.css`: 토큰, 호환 별칭, Pretendard 동적 분할 CSS import
  - `frontend/src/design/ui.css`: 셸, 화면 머리, 버튼·입력·칩, 조건 바, 구역 머리, 문서형 표, 정보 격자, 안내, 팝오버
- **다시 쓰는 기존 파일:** `components/worklog-sheet.css`(`sheet.css` 자산 이름 유지)와 `components/Modal.css`.
- **클래스 이름:** 새 클래스는 `wl-`로 시작한다. 옮긴 화면에서는 옛 `t-` 클래스를 지워 legacy 규칙이 닿지 않게 한다. 클래스 이름을 확인하는 테스트는 함께 고친다.
- **1단계 확인:** legacy 감싸기만 적용한 빌드와 이전 빌드의 합성 화면을 픽셀 단위로 비교해 차이가 0이어야 한다. 차이가 있으면 원인을 확인한 뒤 진행한다.

## 7. 공통 부품

### 7.1 셸

- **사이드바:** 너비 232px, 흰 바탕, 오른쪽 1px 선.
  - 위에서부터 로고·WorkLog·데모 표시, 회사·역할 블록, 메뉴 그룹 이름(12/600 g600), 메뉴를 둔다. 메뉴 높이는 34px이고 아이콘 16px, 글자 14px이다.
  - 하위 메뉴는 들여 쓰고 세로 안내선을 둔다.
  - 선택한 메뉴는 brand-tint 바탕에 brand-ink 700 글자로 표시한다.
- **그대로 두는 것:** `WorkspaceNavigation`의 메뉴 구조, 권한별 노출, 펼침, 모바일 접힘, 키보드 동작은 바꾸지 않는다. 마크업 클래스와 CSS만 교체한다.
- **상단바:** 높이 56px.
  - 왼쪽에는 위치(breadcrumb)를 둔다.
  - 오른쪽에는 화면 테마·업무 권한 선택, 사용자, 사번 변경, 로그아웃을 둔다. 아이콘만 있는 버튼에는 `aria-label`을 붙인다.

### 7.2 화면 머리 `PageHeader`

- props: `title`, `help?: ReactNode`, `actions?: ReactNode`. 제목은 22/700이다.
- `help`가 있으면 제목 옆에 `?` 버튼을 둔다(`aria-label="도움말"`, `aria-expanded`). 누르면 팝오버가 열리며, Esc나 바깥을 누르면 닫히고 초점은 `?` 버튼으로 돌아간다.
- 설명 문장은 팝오버 안으로 옮긴다. 문장은 DOM에 그대로 남는다.

### 7.3 조회 조건 바 `.wl-querybar`

- 기존 GET form에 클래스만 붙인다.
- 모양: g50 바탕, g200 선, 6px 모서리.
- 배치: 라벨·컨트롤 쌍을 한 줄에 놓고, 오른쪽 끝에 [초기화](선 없는 버튼)와 [조회](진한 중립색)를 둔다.
- 모바일에서는 세로로 쌓고 버튼은 전체 폭으로 늘린다.

### 7.4 구역 머리 `SectionHeader`

- props: `title`, `count?`, `actions?`. 제목 15/700과 "총 N건"을 표시하며 N은 brand-ink 색이다.
- 시트, 목록, 폼 구역에 공통으로 쓴다.

### 7.5 공통 시트 `WorklogSheet`

- **구조:** 위에서부터 차례로 둔다.
  1. 구역 머리: 제목·총 건수 | 현재 페이지 찾기(200px) · 저장 전 변경 N건 · 편집 동작
  2. 오류 안내
  3. 그리드
  4. 하단: 표시 n/m행 · 선택 · 변경 | 페이지 이동
- **props:** 기존 props는 그대로 두고 `title?`(기본은 `label`), `count?`(기본은 `rows.length`), `actions?`, `pagination?`만 더한다.
- **그리드:**
  - 머리: 36px, g50 바탕, 13/600 g700 글자
  - 행: 38px, 13px 글자, 칸선 g150, 윗선 2px g800
  - 마우스를 올린 행 `#fbfbfc`, 선택한 행 brand-tint
  - 정렬·필터 아이콘은 활성일 때와 마우스를 올렸을 때만 진하게 표시
- **행 상태:**
  - 신규 행: 왼쪽에 3px ok 색 띠
  - 비활성 예정 행: 왼쪽에 3px danger 색 띠 + 취소선. 상태 칸과 선택 칸은 취소선에서 뺀다.
  - 수정한 칸: 칸 왼쪽 위에 7px info 색 삼각형. `cellClassRules`로 `data-changed` 값을 보고 표시한다.
  - 오류 칸: 1.5px danger 색 테두리 + danger-bg 바탕
- **상태 칸:** 공통 `SheetState`로 신규·수정·비활성 예정만 표시한다. "저장됨"은 표시하지 않는다.
- **편집:** 편집 가능한 칸은 마우스를 올리면 1px g300 테두리, 편집 중에는 2px brand 테두리를 보인다. 읽기 전용 칸은 g600 글자로 쓴다.
- **AG Grid 설정:** CSP 때문에 Theming API의 `<style>` 주입을 쓸 수 없다. 따라서 `legacy` 테마와 CSS 변수 방식을 유지한다.
- **오류 안내:** 시트 아래에 "n행 · 열: 메시지 [해당 칸으로 이동]" 형식으로 보인다. 이동은 기존 `focusCell` 동작을 쓴다.
- **모바일:** 가로 스크롤은 그리드 안에서만 생기고, 고정 열은 해제하며, 머리줄은 줄바꿈한다.

### 7.6 저장 확인 모달 (일괄 변경 사유)

- [저장]을 누르면 `Modal size="s"` "변경 내용 저장"이 열린다.
- 모달 내용: 신규·수정·비활성화 건수 칩, 변경 사유 입력(필수, 500자, 글자 수 표시), [취소] [N건 저장].
- 사유 입력과 확인 버튼은 HTML `form` 속성으로 기존 시트 form에 연결한다. 그래서 제출 필드, 검증, `commandId`, 50행 제한, 충돌 차단, 미저장 보호가 그대로 유지된다.
- 서버 422 응답의 오류 필드가 `reason`이면, 화면을 다시 그릴 때 모달을 자동으로 열고 사유 칸에 초점을 둔다.
- 대상: 현재 `t-sheet-reason`을 쓰는 일괄 저장 시트 세 곳이다.
  - `OrgSheetPages`: 조직·사원
  - `CodePages`: 공통코드·근태코드
  - `ApprovalRoutePages`: 결재선 정의
- 결재선 배정, `AdminPages`의 `Reason`, 조직장 배정처럼 한 건씩 처리하는 폼은 사유 입력을 폼 안에 그대로 둔다.

### 7.7 공통 모달 `Modal`

- **크기:** `size?: 's' | 'm' | 'l' | 'xl'`은 각각 440/720/920/1200px이다(`min(크기, 100% - 48px)`). 기본값은 `l`이다.
- **머리:** 높이 56px, 제목 18/700, 닫기 버튼 32px.
- **본문:** 여백 24px.
- **하단:** 오른쪽에 [취소][주 동작]을 고정한다. 왼쪽은 필수 표시 같은 보조 정보 자리다.
- **그대로 두는 동작:**
  - `showModal`, 초점 이동·가두기·복귀
  - Esc로 닫기(처리 중에는 막음), `aria-busy`
  - 배경 화면 보존
- **모바일(≤600px):** 전체 높이 시트로 바뀌고 위쪽 모서리 12px, 하단은 safe-area만큼 띄운다. 문서형 표는 항목명이 위, 값이 아래가 되도록 쌓는다.
- 넓게 보기 버튼은 넣지 않는다.

### 7.8 문서형 표 · 정보 격자 · 결재란 · 안내

- **`.wl-form-table`:**
  - 2px 윗선을 긋는다. 항목명 칸은 116px 너비에 g50 바탕, 13/600 g700 글자이고, 행 사이는 1px g200 선이다.
  - 필수 항목은 항목명 뒤에 5px danger 색 점과 스크린리더용 "필수"를 붙인다.
  - 빨간 테두리와 문구는 오류일 때만 보인다.
- **`.wl-info-grid`:** 읽기 전용 `dl`이다. 항목명(12px g600)을 위에, 값(14/600)을 아래에 두고 2~4열로 배치한다.
- **`ApprovalStamps({ steps })`:** 결재란이다.
  - 칸 하나는 128px이며, 위에서부터 역할(기안·결재), 이름 14/700과 소속·직책, 상태 칩을 둔다.
  - 기존 결재선 미리보기 자료만 쓴다.
  - 모바일에서는 세로 목록으로 바뀐다.
- **`.wl-notice`:** g50 바탕에 아이콘과 한 문장을 둔다.

### 7.9 팝오버 (날짜 메뉴·도움말)

- 너비 232px, 모서리 6px, 팝오버 그림자.
- 머리에는 날짜·보조 문구·닫기를 둔다.

### 7.10 사원 맥락 줄 (`EmployeeHeader` compact)

- **내 업무 화면:** 아바타 34px, 이름 14/700, 재직 상태 칩 | 사번·소속·직급·직책·직무·입사일. 한 줄로 두고, 넘치면 줄바꿈한다.
- **인사정보 화면:** 내 정보 7탭과 사원 인사정보는 상세 카드를 유지하고 새 토큰으로 다시 꾸민다.

### 7.11 요약 줄 · 캘린더 · 오른쪽 패널

- **요약 줄 `.wl-summary`:** g50 바탕이고 항목 사이를 세로선으로 나눈다. 값은 700 굵기에 `tabular-nums`로 쓰며, 경고성 값만 warn·danger 색을 쓴다.
- **캘린더 머리:** [이전] 2026년 11월 [다음] [오늘] | 범례.
- **캘린더 본문:**
  - 2px 윗선 아래에 요일 머리를 둔다. 토요일은 파랑, 일요일은 빨강이다.
  - 날짜 칸은 최소 98px이다.
  - 오늘 날짜는 brand 원, 선택한 날짜는 brand-tint 바탕에 1.5px brand 안쪽 선이다.
- **막대:** 높이 22px, 12/600 글자이며 종류별로 아이콘을 붙인다.
  - 근무 예정: 시계
  - 비근로일·휴일: 깃발
  - 승인 연차: 체크
  - 검토 중: 모래시계 + 테두리
  - 미배정·미확인: 빗금
- **⋯ 버튼:** 마우스를 올렸을 때, 선택한 날짜, 키보드 초점이 있을 때만 보인다. 터치 기기에서는 항상 보인다.
- **오른쪽 패널:** 1200px 이상에서는 캘린더 오른쪽에, 그보다 좁으면 캘린더 아래에 둔다.
  - "주간 근무": 선택한 날짜(기본은 오늘)가 속한 주의 예정 근무 일수·시간, 승인 연차, 비근로일. 해당 주의 `WorkspaceDay`(`schedule`, `requests`, `dayKind`)로 계산한다.
  - "처리할 일": 이번 달의 검토 중 신청과 미배정·미확인 날짜.
  - 새 API는 쓰지 않는다. 계산할 자료가 없으면 해당 블록을 숨긴다.

## 10. 검증

- **자동:**
  - `npm --prefix frontend test`와 `npm --prefix frontend run build`(tsc + vite)를 실행한다.
  - 클래스 이름과 CSS 자산 계약을 확인하는 테스트(`sheetAssets.test.ts` 등)는 새 이름·값으로 고친다.
- **Java:** Java 코드를 바꾸지 않은 단계에서는 Java 테스트를 실행하지 않고, 결과 문서에 실행하지 않았다고 적는다. `app.css` 변경은 5단계에서 `mvnw.cmd test`로 프런트 빌드 연동을 한 번 확인한다.
- **화면:**
  - 합성 미리보기로 확인한다. 빌드 결과와 합성 envelope만 쓰며 DB와 업무 POST는 없다.
  - 단계별 대상 화면을 1440·390px, 차콜·블루로 캡처한다.
  - 확인 항목: JS 오류 0, 390px에서 페이지 가로 넘침 0, 초점 표시.
- **접근성:**
  - 글자 대비 4.5:1 이상인지 토큰 계산값으로 기록한다.
  - 키보드로 시트 칸 이동, 모달 초점 가두기·복귀, 팝오버 Esc를 확인한다.
  - 축소 모션 설정에서 움직임이 없는지 확인한다.
- 실제 DB, 공개 서버, 실기기 검증은 실행하지 않으면 결과 문서에 미실행으로 적는다.

## 11. 위험과 대응

- **Vite의 `@import … layer()` 처리:** 빌드 결과에서 `@layer vendor`가 붙었는지 확인한다. 처리되지 않으면 AG Grid CSS는 층 없이 두고, 새 시트 규칙은 `.w-sheet` 범위로 우선순위를 확보한다.
- **Pretendard 용량:** 동적 분할 woff2 약 92개로 dist가 약 3MB 늘어날 것으로 추정한다. 화면마다 필요한 조각만 내려받는다. 작은 조각이 `data:`로 인라인되면 기존 `sheetAssets` 플러그인이 파일로 추출한다. `font-display: swap`을 쓴다.
- **문구·클래스 의존 테스트:** 설명 문장은 DOM에 남기므로 `getByText`는 유지된다. 클래스 이름 의존은 테스트를 함께 고친다.
- **사원 헤더 축소:** 사진 등 상세 정보는 내 업무 화면에서 빠진다. 대신 인사정보 화면의 상세 카드에서 계속 제공한다.
- **기준 브랜치 후속 변경:** `target/demo-entry-public-20261109`의 후속 커밋과 충돌할 수 있다. 각 단계를 시작할 때 기준 브랜치 변경을 확인하고, 병합이 필요하면 사용자 확인 후 진행한다.
