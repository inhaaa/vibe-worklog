# 선택근무 정산의 미확정 날짜와 처리

직원과 근태 담당자는 주간 또는 월간 정산에서 **미확정 2일**을 눌러 어느 날짜의 무엇을 처리할지 확인한다. 직원이 한 날짜의 근로·휴게를 확인하거나 담당자가 필요한 날짜를 재집계하면 두 사람이 같은 정산을 다시 열었을 때 남은 한 날짜와 사유가 일치해야 한다.

## 날짜와 권한

- 기존 [선택근무 정산](2026-11-20-selective-work.md)의 합계와 날짜별 미확정 판정을 함께 계산한다. 같은 날에 사유가 여러 개여도 한 행으로 표시한다. 코어·선택 시간대 경고만 있는 확정일은 처리 목록에 넣지 않는다.
- 서울 기준 오늘까지의 미확정 날짜를 오래된 순서로 보여준다. 앞으로 올 미확정 근무일은 예정 일수로 따로 표시한다. 주가 달을 넘으면 조회한 달 양쪽의 해당 주를 포함한다. 재직·배정·마감 당시 근거와 회사·사원 권한은 기존 정산과 같다.
- 두 정산 조회 API의 기간 응답에 `unconfirmedDates`와 `upcomingDays`를 추가한다. 기존 `unconfirmedDays`는 두 수의 합이다. 날짜 행은 `workDate`, `reasons`, `employeeAction`, `adminAction`, `requestId`를 담는다. 링크를 만드는 데 필요한 대기 정정 ID만 반환한다.
- 직원은 근로·휴게를 직접 확인할 수 있는 날에 **근무 확인**, 출퇴근이 누락되어 정정할 수 있는 날에 **정정 신청**, 이미 정정 결재 중이면 **신청 진행 확인**을 사용한다. 달력 미등록이나 재집계 필요처럼 담당자가 처리할 사유는 안내한다. 오늘 아직 퇴근하지 않은 정상 근무를 정정 대상으로 안내하지 않는다.
- 담당자는 신청 상세, 대상일이 입력된 회사 달력, 해당 사원의 일자별 집계 검토·재집계에 접근한다. 직원의 근무 확인을 대신 처리하지 않는다. 마감표의 날짜는 읽기 전용이다. 기존 쓰기 명령의 권한과 마감 검사를 유지한다.

## 처리와 복귀

기간 선택을 주소에 기록한다. 직원은 `/me/worktime?month=…&settlementPeriod=…&settlementFrom=…`, 담당자는 `/admin/attendance?employeeId=…&month=…&settlementPeriod=…&settlementFrom=…`을 사용한다. 처리 화면에는 이 주소를 `settlementReturn`으로 전달한다. 서버는 정해진 두 내부 경로, 역할·대상 사원, 달과 실제 정산기간 및 대상 날짜의 일치를 검사한다. 복귀 정보가 부적절하면 기존 화면 흐름을 따른다.

조회 화면의 **선택근무 정산으로** 링크, 근무 확인·정정 제출·대상일 재집계 후의 복귀, 브라우저 뒤로 가기·새로고침 모두 같은 사원·원래 조회 월·펼친 정산기간을 복원한다. 처리 후 서버에서 다시 읽고 마지막 건까지 처리하면 열린 목록에 남은 건이 없다고 표시한다. 정정 제출 직후에는 결재 대기를 표시하고 기존 신청 상세로 연결한다.

## 인수 기준

서로 다른 직원·담당자 세션에서 같은 기간에 미확정 날짜 두 개를 확인한다. 직원이 한 날짜의 실제 근로·휴게를 확인한 뒤 두 세션 모두 1일과 같은 남은 날짜·사유를 보여야 한다. 담당자 화면에서는 다른 사원을 기본으로 선택한 상태에서도 처리 대상 사원과 원래 정산기간이 복원돼야 한다. PC와 터치 모바일 크기의 실제 브라우저에서 각각 검증한다. 미래일, 월경계 주, 취소·결재 대기, 마감, 잘못된 복귀 주소, 직원·다른 회사의 접근도 회귀 대상으로 둔다.
