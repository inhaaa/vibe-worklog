# 선택근무제 설정과 정산 조회

담당자는 근무시간코드의 선택 가능 시간대와 정산 기준을 정하고, 근무조에 사원을 적용일 기준으로 배정한다. 직원은 출퇴근과 실제 휴게를 기록·확인한 뒤 본인의 정산 진행 상황을 본다. 담당자는 회사 근무현황의 월 마감에서 해당 사원의 같은 수치를 대조한다.

## 정책과 적용일

- 하루 한 구간, 서울 기준 당일 근무를 지원한다. 선택 가능 시작·종료, 선택 사항인 의무 근무시간대(코어타임), 하루 표준근로시간, 예정 휴게를 불변 코드 버전에 저장한다. 표준시간은 선택 가능 구간에서 예정 휴게를 제외한 시간 이내여야 한다. 코어의 양 끝은 함께 입력하며 선택 가능 구간 안에 있어야 한다.
- 정산기간은 달력의 한 달 또는 월요일부터 일요일까지 한 주다. 한 근무조 개정의 근로 요일은 같은 근무 방식과 정산기간을 쓴다. 요일별 선택 가능 시간과 표준분은 다를 수 있다. 배정·전입·개정·퇴사 경계에는 근무일 당시의 정책을 적용한다. 정책이 바뀐 기간은 해당 기준에 속하는 날짜만 계산한다.
- 회사가 합의한 기간 총시간을 해당 기간의 대상 근로일별 표준시간 합으로 운영하는 경우를 지원한다. 휴일·비근로일 목표는 0이다. 정산 목표와 법정 한도는 서로 다른 값이다. 1개월 초과 연구개발 특례, 야간을 넘기는 근무, 임금·가산수당 산정은 향후 별도 범위다.
- 근로기준법 제52조는 근로자가 업무 시작·종료 시각을 정하도록 하고 근로자대표 서면합의에 대상, 정산기간과 총 근로시간 등을 정하도록 한다. 사업장의 합의와 적용 대상 확인은 담당자 업무다. 이 화면은 합의된 설정과 실적을 기록한다. [국가법령정보센터, 2026년 10월 8일 시행 제52조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1029728219) · [고용노동부 선택적 근로시간제](https://www.moel.go.kr/policy/policybbs/workinghour/detailList.do?tpi_seq=15)

## 화면과 정산

1. 담당자는 근무 설정에서 시간코드를 선택근무로 등록하고 근무조 요일에 연결한다. 미리보기의 소정시간은 표준분으로 계산한다. 조를 개정하면 적용일부터 소속 사원에게 자동 반영한다.
2. 직원은 일정에서 선택 시간대와 코어를 확인하고 실제 시각으로 출퇴근한다. 창 밖의 기록도 보존한다. 근무 확인에는 실제 출퇴근 구간과 겹치는 예정 휴게만 제시한다. 직원이 실제로 쉰 구간이 일치한다고 확인하면 이를 반영하고, 다르면 휴게 정정을 신청한다. 코어와 시간대 이탈은 검토용으로 표시하며 확인된 실근로를 보존한다.
3. 직원의 월별 근무현황과 담당자의 사원별 조회는 같은 기간 목표, 확인 실근로, 승인 유급휴가, 미확정 일수, 차이를 표시한다. 차이는 확인 실근로와 휴가 인정시간의 합에서 목표를 뺀 값이다. 승인된 종일 연차는 당일 표준분, 반차는 절반을 인정하고 취소 승인분은 제외한다. 미산정·휴게 미확인·대기 정정·진행 중 기간은 확정 차이를 표시하지 않는다. 해당 월에 걸친 주는 월·연도 경계 양쪽을 포함한다.
4. 진행 중에는 확인된 실근로와 승인 휴가를 목표에서 뺀 남은 시간을 0 이상으로 표시한다. 마감 달의 적용 정책·실근로·휴가는 당시 계산 근거에서 읽고, 열린 달은 최신 자료로 계산한다. 월경계에 걸친 주는 두 달의 근거를 이어서 조회한다. 종일 휴가와 출근 기록이 겹치면 담당자가 충돌을 해소한 뒤 마감한다. 시간대·코어 이탈과 목표 대비 차이는 검토용으로 표시한다.

## 저장 및 조회 계약

`work_time_code_version`에 `work_mode`, `core_start`, `core_end`, `standard_minutes`, `settlement_period`를 추가한다. 기존 버전과 이전 형식의 등록 요청은 고정 근무로 해석한다. 선택 정책의 날짜별 근거는 기존 조 배정, 불변 코드 버전과 주간 일정 개정에서 찾는다.

| 경로 | 입력·결과 |
| --- | --- |
| `/admin/schedules/workgroups/codes` | 기존 코드 명령에 `workMode`, `coreStart`, `coreEnd`, `standardMinutes`, `settlementPeriod` 추가. 시각은 기존 `startTime`, `endTime` 사용 |
| `GET /worktime/selective-settlements` | `month`로 인증된 직원 본인의 정산 조회 |
| `GET /admin/attendance/month-close/selective-settlements` | `month`, `employeeId`로 담당자 소속 회사의 사원 조회 |

기간 목록은 양끝 날짜, 적용 근로일, 목표 분, 확인 근로·휴가·차이 밀리초, 미확정 일수와 확인 사유를 돌려준다. 적용 구간이 없으면 빈 목록을 반환한다. 서버가 세션과 현재 권한을 확인하고 테넌트 조건과 RLS를 적용한다.

## 수용 예시

| 사례 | 기대 |
| --- | --- |
| 07~21시 선택, 10~15시 코어, 표준 480분, 예정 휴게 12~13시 | 09~18시 출퇴근과 실제 휴게 한 시간 확인 시 실근로 8시간. 가능 구간 14시간을 목표로 사용하지 않는다. |
| 예정 휴게 12~13시, 12시 30분 또는 13시 출근 | 근무 확인 화면에 각각 12시 30분~13시 또는 휴게 없음이 표시된다. 실제 휴게가 다르면 직원이 정정을 신청한다. |
| 이틀 목표 16시간, 첫날 실근로 9시간, 둘째 날 3시간과 승인 반차 | 실근로 12시간·휴가 4시간·기간 차이 0시간. 하루 9시간 근무만으로 법정 연장을 확정하지 않는다. |
| 늦은 출근 또는 창 밖 퇴근, 실제 휴게 미확인 | 사실과 확인 사유를 표시한다. 실제 근로가 미확정이면 기간 차이를 유보한다. |
| 월경계 주·중도 입사·전환·휴일 | 같은 날을 두 번 계산하지 않고 두 화면의 같은 기간 수치가 일치한다. |
| 기존 고정 근무·이전 마감·타사 사원 | 기존 결과를 재현하며 사원 접근은 각 회사와 권한 범위를 따른다. |
