# WorkLog 공통 업무 그리드 설계 검토안

- 기준일: 2026-10-29 `Asia/Seoul`
- 상태: 사용자 검토 전 제안. 라이브러리 설치·구현·배포는 수행하지 않았다.
- 요구: 목록·정렬·필터·셀 편집·일괄 저장을 제공하는 업무용 그리드. 사용자가 이번 대화에서 해당 범위를 선택했다.

## 현재 문제와 선택

조직·사원, 결재선, 공통·근태코드는 각 페이지에서 HTML table과 입력 필드를 직접 구성한다. `table-scroll`, `t-table`, `t-sheet-table`의 스타일과 화면별 최소 너비·셀 폭 규칙이 섞여 있다. 그리드 패키지만 추가하면 해결되지 않으며 공통 테마·툴바·열 규칙도 함께 적용해야 한다.

| 접근 | 장점 | 부담 | 제안 |
| --- | --- | --- | --- |
| 기존 native table 공통화 | 새 의존성 없음, 현재 폼 재사용 | 열 조절·고정·키보드 탐색을 직접 구현·검증 | 디자인 정리만 할 경우 대안 |
| AG Grid Community + WorklogSheet | 기본 테마와 업무용 그리드 동작을 함께 재사용 | 새 의존성, 기존 입력·오류·포커스 연결 검증 필요 | 권장 |
| TanStack Table + 자체 UI | 디자인 자유도와 headless 상태 관리 | 편집 UI·시각 규칙·키보드 연결을 직접 구성 | 이번 목적에서는 보류 |

AG Grid는 조회한 공식 문서 기준 36.2.0을 도입 후보로 둔다. Community는 MIT이고 무료 상업 사용이 가능하다. 현재 프로젝트의 React 19.3.1·TypeScript 6.0.3과 공식 호환 안내를 대조했으나 실제 설치·타입 검사·브라우저 검증은 아직 하지 않았다. 패키지 버전은 실제 도입 시 registry와 peer dependency를 다시 확인하고 React 어댑터와 core를 같은 버전으로 고정한다.

## 첫 적용 범위와 화면 규칙

첫 구현은 공통코드 그룹·상세 두 시트다. 기존 `CodePages.tsx`의 열 정의와 시스템 코드 보호·원자적 저장 경로를 그대로 연결할 수 있어 적합하다. 검증 뒤 근태코드 → 조직·사원 → 결재선 → 조회 표 순으로 확장하며 첫 단위에서 모든 화면을 일괄 교체하지 않는다.

- 하나의 WorkLog 테마를 사용한다. 기존 색상·글꼴을 이어받고 헤더·행 높이·테두리·포커스·입력 여백을 공통으로 정한다. 기본안은 헤더 40px, 행 40px이며 오류는 셀 표시와 별도 요약으로 제공한다.
- 검색·필터 영역, 시트 툴바, 그리드, 건수·페이지 영역 순서를 고정한다. `조회 / 입력 / 비활성화 / 저장 / 취소`의 위치와 강조를 통일한다. 업무에 없는 동작은 표시하지 않는다.
- 행 선택·변경 상태 열과 식별 코드 열을 왼쪽에 두고, 긴 설명 열은 남는 폭을 사용한다. 열 크기 조절과 식별 열 고정을 제공한다. 화면별 nth-child 폭 규칙을 새 모듈에 적용하지 않는다.
- 텍스트는 왼쪽, 수량은 오른쪽, 체크·상태는 가운데에 정렬한다. 읽기 전용·신규·수정·비활성 예정·오류는 문구와 시각 표시를 함께 제공한다.
- 셀 편집, Tab·방향키 이동, 행 선택, 빈 결과·로딩·오류 안내를 공통화한다. 작은 화면은 그리드 내부 가로 스크롤과 최소 열 너비를 사용하며 페이지 전체가 가로로 넘치지 않게 한다.

## 모듈 인터페이스와 책임

별도의 범용 시트 엔진·수식 엔진·독립 패키지를 만들지 않고 `frontend/src/components/WorklogSheet.tsx`를 제안한다. AG Grid의 `ColDef<T>`를 재사용하여 두 번째 열 스키마를 만들지 않는다.

| 입력·이벤트 | 계약 |
| --- | --- |
| 행 데이터·열 정의 | 페이지가 보유한 제어형 행 상태와 typed AG Grid 열 정의 |
| 행 ID | 기존 `clientRowId`로 선택·편집·오류를 연결. 정렬 뒤에도 행 인덱스에 의존하지 않음 |
| 편집 요청 | `rowId`, `field`, `value`를 페이지로 전달. 서버 저장 없이 draft만 변경 |
| 편집 가능 여부 | 시스템 소유·고정 코드·비활성 예정 행의 기존 업무 규칙을 페이지가 결정 |
| 선택·변경·오류 | 선택 행 ID와 기존 행/필드별 오류·변경 상태를 표시 |
| 툴바·페이지 | 페이지가 제공한 동작·활성 조건·건수·이전/다음 링크를 공통 위치에 표시 |
| 저장 | 열린 셀 편집을 확정하고 최신 draft가 기존 Form 직렬화에 반영된 뒤 제출 |

`commandId`, `expectedVersion`, 변경 사유, 최대 50행, 시스템 코드 보호, 기존 행의 비활성화, 409 최신값 비교, 422 필드 오류, 불명확한 재시도, 미저장 이동 보호는 기존 페이지와 서버 계약을 따른다. 공통 그리드는 업무 권한·저장 API·DB 접근을 새로 만들지 않는다. 취소는 페이지의 기준 자료로 draft를 복원한다.

편집 중인 셀의 변경값이 아직 draft에 확정되지 않았더라도 미저장 보호 대상으로 취급한다. 검색·링크·페이지·그룹 이동은 편집 중 값까지 포함해 확인하고, 저장 시에는 편집 확정 → 최신 draft 직렬화 → 제출 순서를 보장한다. 취소 시에는 진행 중 셀 편집도 폐기한다.

필터는 표시만 바꾸며 현재 페이지의 draft·선택을 제거하지 않는다. 저장은 숨은 행을 포함한 현재 페이지 전체 변경 행, 비활성화는 숨은 행을 포함한 선택 행을 대상으로 하고, 툴바에 전체 선택·변경 건수와 숨은 선택·변경 건수를 표시한다. 취소는 현재 페이지 전체 편집을 복원한다. 오류 요약에서 필드를 선택하면 해당 행을 가리는 필터를 해제하고, 행·열을 화면 안으로 스크롤한 뒤 해당 셀 또는 편집기로 포커스를 옮긴다.

현재 서버가 페이지별 최대 50행을 반환하므로 첫 단위의 그리드 정렬·필터는 **불러온 현재 페이지**에 적용하고 이를 화면에 표시한다. 전체 검색과 이전/다음 페이지는 기존 서버 조회를 사용한다. 페이지 이동 시 미저장 변경 확인을 유지하며 전체 결과 정렬로 오인하게 표시하지 않는다.

## 무료 범위와 제외

Community의 기본 편집·정렬·필터·열 조절·열 고정·키보드 탐색을 사용한다. 내장 XLSX 내보내기, 셀 범위 선택과 Excel형 클립보드 기능은 Enterprise 경계이므로 첫 단위에 포함하지 않는다. 기존 서버 검토용 Excel 다운로드는 기존 경로를 사용한다. 그리드 내부 자동 저장, 수식·셀 병합·다중 워크시트, 서버 검색 API 확장, 권한·DB 변경도 첫 단위에서 제외한다.

## 구현 전·후 검증

1. 먼저 공통 그리드의 선택·셀 편집·읽기 전용·빈 상태·오류 연결 테스트와 공통코드 회귀 기대 결과를 작성한다.
2. 파일럿 구현 뒤 기존 공통코드의 시스템 값 보호, 저장 직전 셀 값 확정, 취소, 50행 제한, 409/422 편집 보존, 명령 ID/재시도, 페이지·그룹 이동의 미저장 보호를 검증한다.
3. 정렬·필터 후에도 stable ID 기준으로 올바른 행만 편집·선택·저장하는지 검증한다. 숨은 변경/선택 건수와 저장·취소 범위, 편집 중 셀의 이동 보호, 오류 행 노출·포커스, 공통코드 그룹·상세 사이 편집 보존도 포함한다.
4. React 테스트·TypeScript·production build를 실행하고 PC·390px 브라우저에서 열 조절·고정·키보드·내부 스크롤·오류 포커스와 화면 배치를 확인한다.
5. 변경 파일·의존성 검사 결과를 기록한 뒤 후속 화면 확대 여부를 판단한다. 공개 배포는 기존 WorkLog 전용 통합·보안·회귀·배포 절차를 별도 실행한 경우에만 완료로 보고한다.

진행 중인 연간 신청·V15와 기타 기존 작업은 이 단위에 포함하지 않는다. 현재 검토안 작성에서는 문서 검증만 수행하며 테스트·빌드·DB·공개 배포 검증은 미실시다.
