# 근태코드 간소화와 오전·오후 반차

2026-11-18 · 기준 커밋 `0cd27b3` · 업무 기준 시간대 Asia/Seoul

## 담당자가 근태코드를 조회하고 관리한다

담당자는 **근태 운영 > 근무 기준 > 근태코드 관리**에서 짧은 코드나 한글 이름으로 검색하고, 선택한 유형의 적용일별 정책 이력을 확인한다. 기본 표시코드는 연차 `A01`, 출퇴근·휴게 정정 `A02`이다. 신청서 관리의 `L01`(휴가 신청), `L02`(휴가 취소)는 각각의 결재선을 정한다. 종일·오전·오후 연차는 같은 연차 정책과 신청서를 쓴다.

기존 고객사 자료를 전환할 때 고객사 등록 코드, 정책·버전 식별자, 신청·결재·원장을 보존한다. 기본 코드가 이미 사용 중이면 다른 기본 코드까지 먼저 확보한 뒤 `A03`부터 사용 가능한 번호를 배정한다. 새 고객사에서도 동일한 기본 코드가 제공된다. 기존 긴 기본코드 검색과 해당 코드가 들어 있는 휴가 조회 링크는 계속 해당 유형으로 연결한다. 담당자는 신규 코드를 영문 대문자와 숫자 1~8자로 등록한다. 기존 긴 사용자 코드의 이력 조회 및 정책 개정은 계속 가능하다.

## 직원이 반차를 신청한다

직원은 연차 신청에서 **종일 / 오전 반차 / 오후 반차**를 선택한다. 반차는 대상일 한 날과 사용할 연차 묶음, 사유를 입력한다. 미리보기에서 대상일, 구분, 예상 차감 **0.5일**, 선택 묶음의 잔여, 결재 순서를 확인한다. 단위나 대상일을 바꾸면 다시 미리본다. 휴일·비근로일·미배정·캘린더 미확인 또는 반차에 여러 날짜를 지정한 경우에는 사유를 표시한다. 종일 신청의 기간 계산과 기존 신청·취소 허용 시점 규칙을 따른다. 직원의 일반 취소는 첫 실제 차감일의 예정 출근 시각 전까지 가능하다. 오후 반차에도 같은 기준을 적용하고 이후에는 담당자의 예외 취소 절차를 따른다.

기존 신청·미리보기 계약에 `leavePart`를 추가하며 값은 `FULL`, `AM`, `PM`이다. 생략한 기존 요청과 기존 연차는 종일이다. 같은 사원·날짜의 대기 또는 유효한 종일 연차는 양쪽 반차와 겹친다. 같은 반일끼리도 겹친다. 오전과 오후는 각각 신청할 수 있다. 반려·철회·취소 완료한 구간은 다시 신청할 수 있다. 취소 신청이 대기 중인 원신청은 유효하다.

## 결재자가 승인하고 담당자가 확인한다

| 처리 | 직원·담당자에게 보이는 결과 | 잔여 예시 |
| --- | --- | --- |
| 기초 잔여 2일에서 오전 반차 접수 | 대기 0.5일 | 2일 |
| 팀장 중간 승인 | 실장 결재 대기 | 2일 |
| 실장 최종 승인 | 원신청 승인, 사용 또는 예정 0.5일 | 1.5일 |
| 취소 접수 및 중간 승인 | 원승인 유효, 해당 오전 구간은 계속 점유 | 1.5일 |
| 취소 최종 승인 | 원신청 취소됨, 사용분 0.5일 복원 | 2일 |

대상일 정책과 묶음 유효기간, 최종 승인 시 가용 잔여를 재검증한다. 동일 명령 재전송·동시 승인으로 중복 차감·복원되지 않는다. 승인·취소 권한, 테넌트 격리, 제출 당시 결재선과 정책 버전은 기존 계약을 따른다. 원장과 날짜별 사용량은 정확한 반일 단위를 보존하고, 기초 등록·수동 조정 입력은 기존 정수 계약을 유지한다.

직원 연간·홈·캘린더, 결재함·상세, 담당자 휴가 신청 현황·원장, 회사·근태 집계에서 반일을 반올림하지 않는다. 원신청과 취소에서 오전·오후를 구분한다. 양쪽 반차가 모두 유효하면 그날 합계는 1일이다. 반차 승인으로 출퇴근 시각이나 실근로 시간을 만들지 않는다. 반차 하루의 나머지 근무 기록이 없으면 확인 대상으로 남기며 검토용 Excel의 휴가량에도 0.5일을 보존한다.

## 검증 사례

- 기존 고객사의 기본코드 충돌·기존 사용자 코드와 신청 보존, 신규 고객사, 이전 코드 링크와 한글 검색.
- 오전/오후 선택, 단일 날짜 강제, 휴일, 겹침, 잔여 부족, 중간·최종 승인, 반려·철회·재신청, 신청 및 취소의 반복 처리.
- PC 및 모바일에서 담당자 검색 후 직원 신청, 결재, 잔여·목록 재조회, 취소 복원. 승인 전후 출퇴근 및 원장 대조.
