# 연장근무 사전신청·순차결재·실적 대조 명세

2026-11-18 · 기준 커밋 `70b4a9a` · 업무 시간대 Asia/Seoul

## 직원 신청

내 업무 > 근태관리 > 연장근무 신청에서 본인 근무일을 선택한다. 그날 유효한 사원 배정, 근무조 개정, 근무시간코드 버전과 회사 휴일 캘린더로 신청 가능 여부를 판정한다. 근로일의 출근 전 또는 퇴근 후 허용 구간 하나 안에서 시작·종료 시각과 사유를 입력한다. 허용 구간이 없는 기존 고정배정, 미배정, 비근로일, 휴일, 캘린더 미확인은 원인을 안내한다.

| 입력 사례 | 서버와 화면의 결과 |
| --- | --- |
| 정규 퇴근 18:00, 연장 허용 18:30~21:00, 연장 휴게 20:00~20:15 | 전 구간 신청은 135분, 19:50~20:10 신청은 겹치는 휴게 10분을 빼고 10분 |
| 18:15 시작, 휴게로만 구성된 신청, 자정 통과, 종료가 시작과 같거나 앞섬 | 제출을 막고 원인을 표시 |
| 같은 사원·근무일의 대기 또는 유효 승인 건과 시간 중첩 | 제출 차단. 끝과 시작이 맞닿은 별도 구간은 허용 |
| 시작 시각이 도래한 뒤 제출 | 사전신청 마감 표시 |

서버가 적용 버전과 순신청 분을 계산한다. 제출 전 결재 순서를 확인하고 제출 시 신청서 버전, 결재자, 신청 구간·분과 근무 기준을 보존한다. 미리보기 뒤 근무 기준 또는 결재선이 달라지면 재확인을 안내한다.

## 결재와 취소

연장근무 신청서와 승인 취소 신청서를 별도 코드로 관리한다. 기본 코드 예시는 O01·O02다. 고객사 담당자가 기존 결재선 관리에서 각 신청서의 결재 단계를 지정한다. 이미 접수된 건은 제출 당시 결재선을 따른다.

| 처리 | 신청과 효력 |
| --- | --- |
| 팀장 중간 승인 | 대기 상태와 현재 결재 단계만 갱신. 승인 분은 아직 발생하지 않음 |
| 실장 최종 승인 | 대상일의 근무조·시간코드·캘린더와 시간 근거를 재검증. 기준이 달라졌으면 철회·재신청 안내. 유효한 건은 승인 효력을 1회 생성 |
| 반려·본인 철회 | 승인 효력 없음. 원신청·결재 이력 보존 |
| 승인된 연장 취소 | 직원이 원신청에서 시작 전 전체 취소를 신청. 한 건에 대기 취소 한 개. 취소 결재 중에는 원승인 유효. 취소 최종 승인 때 원신청에 ‘취소됨’을 표시. 반려·철회 시 원승인 유지 |

결재 지연으로 시작 시각이 지나도 기한 안에 접수한 신청과 취소는 처리할 수 있다. 중복 명령·동시 결재로 이중 승인되거나 순서가 뒤바뀌지 않아야 한다.

## 담당자 대조와 접근 범위

근태 운영 > 연장근무 신청현황에서 대상일과 처리 상태로 조회하고 사원별 신청 구간·신청 분·승인 상태와 실제 출퇴근 시각을 대조한다. 21시까지 승인받고 20시에 퇴근했다면 두 시각을 각각 표시한다. 정정이 승인된 출퇴근은 현재 반영 기록을 사용하고 미기록은 미기록으로 표시한다. 신청 승인과 취소는 원천 출퇴근·실제 근로시간·급여 가산·휴가 원장을 수정하지 않는다. 휴가·출퇴근 정정 전용 목록에 연장 신청을 섞지 않는다.

담당자는 자기 고객사, 직원은 본인, 결재자는 배정된 결재 건에만 접근한다. 인증 정보에서 고객사를 결정하고 DB의 고객사 제약·RLS와 서버 권한 및 CSRF를 적용한다. 신규 및 기존 고객사에서 신청서코드와 결재선이 작동해야 한다.

## 수용 확인

담당자가 결재선을 연결한 후 직원이 135분을 신청하고, 팀장 승인 직후 대기, 실장 승인 후 135분 유효, 담당자 실적 대조, 취소 결재 및 원신청 효력 해제를 확인한다. 근무 기준 개정·중복·휴일·경계 휴게·권한·동시/반복 처리와 PC·모바일 화면을 검증한다.
