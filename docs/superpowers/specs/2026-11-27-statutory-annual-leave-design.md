# 법정 연차 자동 산정 설계 (D 묶음)

작성일 2026-11-27 · 사용자 승인 설계 · 업무 시간대 `Asia/Seoul` · 기준 브랜치 `claude/opening-prep-20261123`

개통 점검에서 "근속에 따른 연차 발생이 없다"가 판매 차단 요인으로 나왔다. [개통 점검 결과](2026-11-23-opening-prep-design.md)

지금 연차는 다음과 같이 동작한다.

- 회계연도 시작일에 회사가 정한 일수를 회계연도 시작일 이전에 입사한 모든 사원에게 똑같이 준다.
- 입사 첫해 월 연차는 담당자가 사원·월마다 개근 여부를 직접 판정해 하나씩 반영한다.
- 입사 다음 해 비례 부여, 근속 가산, 출근율 80% 판정이 없다.

[연차 원장 계획](../plans/2026-11-21-annual-leave-ledger.md) · [입사·퇴사 연차 계획](../plans/2026-11-22-employment-leave.md) · [일일 근태 자동화](2026-11-25-daily-attendance-automation-design.md)

## 1. 사용자 결정

| 질문 | 결정 |
| --- | --- |
| 부여 기준 | 회사가 '회계연도 기준'과 '입사일 기준' 중에서 고른다. |
| 근속 가산 | 법정대로 자동으로 계산한다. 3년 이상 근속하면 2년마다 1일을 더하고, 최대 25일이다(근로기준법 제60조). |
| 출근율·월 개근 | 일일 근태의 결근 판정으로 자동 판정한다. 판정할 수 없거나 80% 미만이면 '확인 필요'로 표시한다. 연간 부여의 확인 필요 행은 담당자가 골라 법정 일수로 함께 반영할 수 있고, 고르지 않은 행은 뺀다. 월 연차의 확인 필요는 일괄 반영에서 빼고 사원별 화면에서 처리한다. |
| 반영 방식 | 담당자가 미리보기를 확인하고 일괄 반영한다. 자동 반영은 하지 않는다. |

## 2. 회사 기준

- 연차 규칙에 `basis`를 추가한다. 값은 `FISCAL`(회계연도 기준)과 `HIRE_DATE`(입사일 기준)이고, 기존 회사는 `FISCAL`이다.
- 회계 시작월과 이월 한도는 지금처럼 회사가 정한다. 입사일 기준이면 회계 시작월은 쓰지 않는다.
- 부여 일수 입력칸을 없앤다. 새 규칙 버전의 `grant_days`는 법정 기본 15일로 저장하고, 실제 부여 일수는 사원별로 §3에 따라 계산한다.
- 연간 부여나 월 연차를 한 번이라도 반영한 회사는 기준을 바꿀 수 없다. 회계 시작월 변경을 막는 지금 규칙과 같다.
  - 안내: "연간 부여나 월별 연차를 기록한 회사는 연차 기준을 바꿀 수 없습니다. 이월 한도는 변경할 수 있습니다."

## 3. 부여 일수

- **근속 가산**: 근속 n년차의 일수는 `min(15 + floor((n − 1) / 2), 25)`이다(n ≥ 1).
  - 예: 1·2년차 15일, 3·4년차 16일, 5·6년차 17일, 21년차 이후 25일
- **입사일 기준**: 입사 n주년 기념일에 n년차 일수를 준다. 사용 기간은 기념일부터 다음 기념일 전날까지다.
  - 2월 29일 입사자의 기념일은 평년이면 3월 1일이다(`plusYears`가 2월 28일을 돌려주면 그 다음 날로 본다).
- **회계연도 기준**
  - 근속 n년차는 '그 회계연도 시작일이 입사한 회계연도의 시작일로부터 몇 년 뒤인가'로 센다.
  - n = 1(입사 다음 회계연도)에는 비례 일수를 준다.
    - 비례 일수 = `15 × (입사일부터 입사 회계연도 말일까지 일수) / 365`를 0.5일 단위로 올린다.
    - 예: 1월 시작 회사에 2024-07-01 입사 → 184일 → 7.56 → 2025-01-01에 8일
  - n ≥ 2에는 근속 가산 일수를 준다.
    - 같은 예: 2026-01-01 15일, 2027-01-01 16일, 2029-01-01 17일
  - 입사 회계연도 시작일은 입사일보다 빠르거나 같으므로 근속 가산이 입사일 기준보다 늦지 않다. 같은 예에서 입사일 기준은 2027-07-01에 16일이다. 퇴사할 때 입사일 기준과의 차이는 기존 퇴사 정산 화면에서 대조한다.
  - 회계연도 시작일에 입사한 사람은 그해 회계연도의 대상이 아니다. 월 연차만 발생한다.
- **1년 미만 월 연차**: 두 기준 모두 지금처럼 입사 후 매월 개근하면 1일씩, 최대 11일이다. 사용 기한은 지금 규칙을 따른다.
- 부여 일수는 0.5일 단위다. 원장 검사 조건과 같다.

## 4. 출근율 자동 판정

일일 근태 결과(`day_result`)의 B 묶음 판정을 쓴다.

- **소정근로일**: 그날 배정된 근무조가 근무일이고 휴일이 아닌 날
- **결근**: `absence = 'FULL'`이면 1일, `absence = 'HALF'`이면 0.5일
- 휴가·출장 등 승인된 근태가 있는 날은 결근이 아니다. B 묶음이 이미 이렇게 판정한다.
- **판정 불가**: 지난 소정근로일 중 최신 결과가 없거나 최신이 아닌 날

### 4.1 연간 부여의 80% 판정

- **산정기간**
  - 입사일 기준: 직전 1년(직전 기념일부터 이번 기념일 전날까지)
  - 회계연도 기준: 직전 회계연도. 비례 부여는 입사일부터 입사 회계연도 말일까지
- **출근율** = (소정근로일 − 결근 일수) / 소정근로일
- 출근율이 80% 이상이고 판정 불가인 날이 없으면 '부여 대상'이다.
- 다음 경우는 '확인 필요'다.
  - 판정 불가인 날이 있다: "근태 확정 전 n일"
  - 소정근로일이 0일이다
  - 출근율이 80% 미만이다: "출근율 76.4%"
- 확인 필요인 사원은 담당자가 다음 중 하나를 고른다.
  - 근태를 확정한 뒤 미리보기를 다시 한다.
  - 사정을 확인하고 그 행을 골라 함께 반영한다. 부여 일수는 부여 대상과 같은 법정 일수(비례 첫해·근속 가산)다. 도입 전 근태가 없는 기존 사원도 이렇게 처리한다.
  - 고르지 않고 빼 둔다. 80% 미만이라 법정 일수를 주지 않을 사원(법상 개근한 달마다 1일)은 기존 '잔여 조정'으로 처리한다. 이번 묶음에서는 자동 계산하지 않는다.
- 담당자가 고른 행은 계산한 판정 근거(소정·결근 일수)를 그대로 저장하고 '담당자 확인'으로 표시한다.

### 4.2 월 연차의 개근 판정

- 그 달 산정기간에 결근이 없고 판정 불가인 날이 없으면 '개근'(1일)이다.
- 결근이 있으면 '미개근'(0일)이다.
- 판정 불가인 날이 있으면 '확인 필요'이고 일괄 반영에서 빠진다.

## 5. 반영 흐름

모두 담당자(`ATTENDANCE_ADMIN`)의 '연차 관리 > 연차 부여·이월·소멸' 화면에서 미리보기를 확인한 뒤 일괄 반영한다. 미리보기 토큰, 명령 중복 방지, 반영 사유, 감사 기록은 지금 방식을 그대로 쓴다.

- **회계연도 기준 연간 부여**
  - 지금처럼 연도를 골라 미리보기 → 일괄 반영한다.
  - 대상 행에는 사번, 이름, 입사일, 근속년차, 출근율, 부여 일수, 전기 잔여, 이월, 소멸, 판정(부여 대상/확인 필요와 사유)을 보인다.
  - 확인 필요 행에는 '법정 일수 부여' 선택칸을 둔다. 일괄 반영은 부여 대상 행 전부와 담당자가 고른 확인 필요 행을 반영한다.
  - 고른 사원 목록은 반영 명령에 포함된다. 다시 계산한 미리보기에서 그 사원이 확인 필요 행이 아니면 거절하고 미리보기를 다시 요구한다.
  - 입사일 기준 연간 부여도 같다.
- **입사일 기준 연간 부여**
  - 월을 골라 미리보기를 한다. 그 달 1일부터 오늘(지난달이면 말일)까지 입사기념일이 지난 미반영 사원이 대상이다.
  - 일괄 반영하면 사원마다 기념일을 시작일로 하는 연차 묶음을 만든다.
  - 직전 묶음의 이월·소멸도 같은 날 처리한다. 이월 한도는 회사 규칙을 쓴다.
  - 지난 달의 미반영 기념일도 그 달을 골라 반영할 수 있다.
- **월 연차 일괄 반영**
  - 발생일이 오늘까지 지났지만 아직 판정하지 않은 전 사원의 월 연차를 한 표에서 보인다.
  - 표에는 사번, 이름, 입사일, 몇 번째 달, 산정기간, 소정·결근·판정 불가 일수, 자동 판정을 보인다.
  - 개근·미개근 행만 일괄 반영한다. 판정 근거 문구는 "자동 판정: 소정 22일, 결근 0일"처럼 저장하고, 담당자가 입력한 반영 사유를 함께 남긴다.
  - 기존 사원별 월 연차 화면은 남긴다. '기초 잔여에 이미 포함' 판정과 개별 확정은 거기서 한다.
- **개인 원장**: 입사일 기준 회사의 '내 연차 원장'은 연도 대신 입사기념일 기준 1년 기간으로 보인다.

## 6. 저장

- V47
  - `annual_leave_rule.basis`(`FISCAL`/`HIRE_DATE`, 기본 `FISCAL`)
  - `annual_leave_award`에 판정 근거 열을 추가한다. 기존 행은 비어 있다.
    - `service_year`
    - `period_start`, `period_end`
    - `scheduled_days`, `absence_days`
    - `granted_days`
    - `reviewed_by_admin`(담당자가 고른 확인 필요 행이면 참, 기본·기존 행은 거짓)
  - 입사일 기준 회사의 연간 부여도 `annual_leave_cycle`(회사·연도)과 `annual_leave_award`(회사·연도·사원)를 쓴다. 연도는 기념일이 속한 해다. 한 사원은 한 해에 기념일이 한 번이다.
- 월 연차 일괄 반영은 기존 `leave_monthly_review`와 `MONTHLY_ACCRUAL` 원장을 그대로 쓴다.

## 7. 오류와 경계

- 미리보기 뒤 근태·잔여·규칙이 바뀌면 지금처럼 토큰 불일치로 거절하고 다시 미리보기를 요구한다.
- 대기 중인 휴가·취소 신청이 있는 직전 묶음은 지금처럼 이월하지 않고 '대기 중'으로 센다.
- 퇴사 정산을 마친 사원과 퇴사일이 부여일보다 앞선 사원은 대상이 아니다.
- 담당자 본인은 대상에서 빠진다. 자기 처리 금지는 지금 규칙과 같다.
- 한 번에 반영하는 사원 수에는 별도 상한을 두지 않는다. 미리보기 표는 시트 안에서 스크롤한다.

## 8. 검증 기준

- **단위**
  - 근속년차별 일수(1·2·3·4·5·21·30년차)
  - 회계연도 비례(월초·월말·윤년·회계연도 시작일 입사)
  - 2월 29일 기념일
  - 출근율 경계(정확히 80%, 79.9%, 반일 결근)
- **통합**
  - 기준 선택 저장과 변경 금지
  - 회계연도 기준 미리보기·반영(비례 첫해, 근속 가산, 확인 필요 제외)
  - 담당자가 고른 확인 필요 행은 법정 일수와 담당자 확인 표시로 반영하고, 고르지 않은 행은 빠지며, 확인 필요가 아니거나 다른 회사의 사원 ID는 거절
  - 입사일 기준 월별 반영과 이월·소멸
  - 월 연차 일괄 반영(개근·미개근·확인 필요)
  - 토큰 불일치, 회사 격리, 권한
  - V47 스키마
- **React**: 기준 선택, 판정 열과 확인 필요 표시·선택, 월 연차 일괄 반영 표
- **브라우저**: 회계연도 기준과 입사일 기준 각각 미리보기 → 반영 → 직원 원장 확인, 월 연차 일괄 반영, 모바일

## 9. 범위 밖

- 연차 사용촉진(제61조) 통보와 미사용 보상 면제
- 법보다 더 주는 회사별 근속 표
- 출근율 80% 미만 사원의 월 단위 자동 부여
- 단시간 근로자 비례 부여
- 퇴사 정산 규칙 변경
