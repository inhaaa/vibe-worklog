# 사번 로그인·업무 권한 전환·내정보 확장

2026-11-03 Asia/Seoul. 사용자는 단일 사번 로그인, 보유 권한 전환, 별도 권한 관리, 인사정보 7개 탭을 요청했다. 후속 답변에서 입사연도 2자리+순번 3자리와 담당자 예외 `99999`를 승인했다. 기존 UUID PK·계정·신청·원장 연결은 유지한다.

## 계정과 사번

- 담당자 사번 `99999`, 이름 `담당자`. 다른 합성 사원은 회사 입사일의 연도 두 자리와 해당 연도 001~999 순번으로 발급한다. 담당자 예약 번호는 자동 발급에서 제외한다. 퇴사 번호도 재사용하지 않고 이미 발급한 번호는 일반 수정에서 바꾸지 않는다.
- 일반 로그인은 검증한 회사 범위+사번+비밀번호. 기존 이메일 로그인은 이행 호환을 유지하며 새 화면은 사번을 안내한다. 회사 간 같은 사번은 독립 계정이다. 공개/로컬 데모는 서버 고정 합성 회사와 명시적으로 준비한 계정만 허용한다.
- 사번 일괄 전환은 합성 데모 전용 명시적 후속 명령이다. 기존 UUID·입사일·계정·권한·신청·일정·연차·사진을 보존하고 전후 사번/변경 사유를 감사로 남긴다. bootstrap/sample-data는 기존 DB에서 재실행하지 않는다. 명령은 충돌 시 전체 롤백하고 같은 입력 재실행은 무변경이다.
- 테스트 계정은 일반·승인·담당·겸임·대표 권한을 확인할 수 있도록 구성한다. `99999`는 기존 담당자 신원에 연결한다. 각 합성 사원의 실제 입사연도에 맞춰 번호를 부여한다.

## 권한 전환

한 사원에 EMPLOYEE/APPROVER/ATTENDANCE_ADMIN/COMPANY_REPRESENTATIVE를 복수 부여한다. 기존 `/admin/access`와 역할 변경 경로를 재사용한다. 상단 선택은 테마 선택처럼 보유 역할의 업무 메뉴를 전환하며 로그인 사번·tenant/account/employee·실제 서버 권한은 바꾸지 않는다. 권한 회수 후 옛 세션, 마지막 관리자 보호, 지정 범위와 자기 승인 차단을 유지한다. 데모의 다른 사원 로그인은 권한 전환과 명확히 구분한다.

## 인사정보

`/me/profile`의 공통 사원 헤더 아래 기본사항/발령내역/가족사항/학력사항/자격사항/어학사항/주소·연락처 탭을 둔다. 본인 조회, 같은 고객사 담당자 등록·수정이며 다른 사원의 상세가 공통 헤더나 회사 목록으로 확산되지 않는다.

기본사항은 입사구분·인정경력(개월)·입사일·그룹입사일·한글성명·영문성명·결혼여부·결혼일자·보훈여부·장애여부·병역여부·군별·주민등록번호 표시 항목·생년월일·휴대전화다. 현재 명세의 비수집 원칙에 따라 주민등록번호 원문 입력/저장은 제공하지 않는다. 데모는 마스킹된 안내만 표시하고 나머지는 가상 자료만 사용한다. 미등록과 해당 없음을 구분한다.

발령은 기존 실제 소속 이력에서 안전한 필드를 조회한다. 나머지 이력은 필요한 최소 항목과 적용일/별도 버전으로 저장한다. 새 Flyway만 추가하며 tenant SQL·복합 FK·FORCE RLS·허용 열 권한·현재 관리자 재검증·명령 멱등성·버전 충돌·감사를 유지한다. 민감한 상세 원문을 감사 JSON에 복제하지 않는다.

## 검증과 배포

TDD로 사번/인증·격리·재시도·동시 생성·권한 회수·본인 상세 경계와 탭/키보드/빈 값 테스트를 먼저 실패시킨 뒤 구현한다. Java/프론트 기본 회귀·타입/빌드를 직접 실행한다. 공개 반영은 최신 공개 브랜치의 공유 계정 보호와 통합하고 전용 백업·독립 복원·자료 보존·기존 서비스/공개 HTTP를 검증한 결과만 완료로 보고한다.
