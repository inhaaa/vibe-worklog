# 신청 작업공간 디자인 후속

2026-11-03, Asia/Seoul. 사용자는 현재 탭 없는 사원 헤더·업무 메뉴와 같은 디자인으로 신청 화면을 다듬고 실제 신청 흐름을 보여 달라고 요청했다.

## 표시와 흐름

- 기존 native dialog의 유형 선택 → 내용 작성 → 제출 전 확인을 유지한다. 넓은 화면에서는 왼쪽 작성·오른쪽 신청 요약, 좁은 화면에서는 한 열로 표시한다. 인디고 강조·흰 카드·부드러운 테두리·44px 동작 영역으로 현재 메뉴/헤더와 맞춘다. 별도 헤더 탭은 추가하지 않는다.
- 요약은 현재 선택 유형/기간과 서버 제공 현재 사용 가능량·결재 담당만 표시한다. 유형/기준일 조회가 필요한 동안에는 이전 담당자를 새 유형의 확정 정보처럼 표시하지 않는다. 예상 차감은 서버 preview 이후만 표시한다.
- 기본 화면은 신청 버튼을 제목 옆에 두고 현재 사용 가능·사용/예정/대기를 먼저 보여준다. 기초/귀속 근거·대리 작성·유형별 집계는 기존 의미와 값을 보존해 보조 정보로 구분한다. 자료 없음과 귀속 미확인을 0으로 바꾸지 않는다.
- 확인 화면은 입력 기간·사유·정정 내용과 서버 예상량·실제 결재 담당을 읽기 쉬운 카드로 정리한다. 성공은 실제 createdId가 있을 때만 접수 완료로 표시하고 생성 건 상세로 연결한다.
- 신청 상세도 같은 카드/상태 배지/처리 이력 형태로 맞춘다. 기존 서버 허용 동작만 제공하며 신청 유형/상태의 내부 코드는 한글 표시명과 분리한다.

## 보존할 인터페이스

기존 AnnualModel/AnnualView/ComposeView/RequestDetailModel과 API·Form 필드/액션을 그대로 사용한다. TYPE/CONTENT/REVIEW 상태·preview 무쓰기·서버 eligible/conflict·최종 재검증·CSRF·명령/버전/fingerprint·503 동일 명령·409/422 입력 보존·중복 잠금·일반 PAGE·미저장 확인/Escape/초점 복귀를 유지한다. 잔여 부족만으로 클라이언트가 신청을 새로 차단하지 않는다. 정책 계산·원장·승인권한·DB/의존성/설정은 바꾸지 않는다.

## 검증과 공개

표시 기능의 실패 테스트를 먼저 확인한 뒤 구현한다. 기존 신청/정정/상세 회귀·프론트 전체/타입/빌드를 실행한다. 전용 로컬 합성 DB의 독립 승인자·일정·연차묶음을 사용해 실제 브라우저로 선택 → 입력 → 무쓰기 preview → 최종 POST → 접수 → 상세를 확인하고 화면을 보존한다. 공개 demo의 승인자 미배정을 우회하거나 공유 자료에 검증 신청을 추가하지 않는다.

최신 공개 브랜치에 필요한 UI 파일만 통합하고 공개 보안과 V16·기존 자료/서비스를 보존해 앱만 반영한다. 과거 날짜용 인사 등록 CLI/seed/migration을 재실행하지 않는다. 실제 배포·미실시 검증은 별도 결과로 기록한다.
