# 휴가 종류별 신청 현황 명세

- 작성일 2026-11-18
- 대상 메뉴 [휴가관리 > 신청·연차 > 휴가 신청 현황], [근태 운영 > 회사 현황 > 출퇴근 정정 현황]
- 기준 소스 공개 앱 `9a0e35a`와 배포 기록 `2649681`

## 1. 목적과 메뉴

담당자는 휴가 종류별 대기 건을 찾아 현재 결재자를 확인한다. 같은 종류의 승인·반려 이력을 조회하고, 신청 상세에서 처리 사유와 휴가의 현재 효력을 확인한다. 현재 두 메뉴는 분리돼 있고 각각의 서버 조회 범위도 정해져 있다. 담당자 메뉴와 즐겨찾기에서 휴가 전용 목록으로 일관되게 들어갈 수 있도록 정리하고 기존 휴가 목록에 검색과 상태별 조회를 추가한다.

| 대상 | 진입과 조회 범위 |
| --- | --- |
| 휴가 신청 현황 | [휴가관리 > 신청·연차]의 기존 `/admin/requests?scope=LEAVE`를 사용한다. 휴가 신청과 그 휴가의 취소 신청을 조회한다. |
| 출퇴근 정정 현황 | [근태 운영 > 회사 현황]의 기존 `/admin/requests?scope=CORRECTION`을 사용한다. 출퇴근·실제 휴게 정정을 조회하며 회사 근무현황의 퇴근 누락 동선도 계속 연결된다. |
| 기존 담당자 통합 주소 | `/admin/requests`에 조회 유형 없이 들어오면 휴가 신청 현황으로 이동시킨다. 업무 메뉴와 상세의 돌아가기에서도 이 통합 목록을 거치지 않는다. 알 수 없는 조회 유형은 기존 입력 오류로 응답한다. |

대표는 기존 [회사 휴가 신청 현황]에서 회사 단위 목록을 조회한다. 직원은 [내 신청]에서 본인 신청을 확인하고, 지정 결재자는 기존 결재함에서 배정된 신청을 처리한다.

## 2. 담당자 화면과 조회 흐름

1. **대기 건 찾기**
   [휴가 신청 현황]을 처음 열면 `대기` 상태와 `전체 휴가 종류`가 선택된다. 기간은 비어 있어 이미 접수된 과거 대기 건과 휴가 대상일이 아직 오지 않은 대기 건을 함께 찾을 수 있다. 대기 건은 접수 오래된 순으로 보여 준다.
2. **휴가 종류와 필요한 조건 선택**
   `휴가 종류`, `신청 구분`(전체·휴가 신청·취소 신청), `휴가 대상 기간`, `현재 소속`, `사번 또는 이름`으로 좁힌다. 기간은 시작일부터 종료일까지 신청의 대상 기간과 하루라도 겹치는 건을 조회한다. 현재 소속은 화면의 조회 기준일에 해당하는 주 소속이다. 전체 소속에는 소속 미등록 사원도 포함한다. 필터를 바꾸면 첫 페이지에서 시작한다.
3. **같은 조건으로 처리 이력 확인**
   `대기` · `승인` · `반려` · `전체`를 전환해도 휴가 종류와 나머지 조건을 유지한다. 상태별 건수는 해당 검색 조건에 맞는 전체 페이지 기준이다. 승인·반려는 최근 결재 처리 순이며 전체는 최근 접수 순이다. 전체에서 철회 건도 `철회` 상태로 확인할 수 있다.
4. **상세에서 확인하고 목록으로 복귀**
   대기 건은 현재 지정 결재자와 접수 시각을, 승인·반려 건은 실제 처리자·처리 시각과 처리 사유를 확인한다. 취소 신청은 원래 휴가 신청으로 이동할 수 있다. 목록으로 돌아가면 휴가 종류·신청 구분·기간·소속·검색어·상태·페이지를 복원하고 최신 상태로 조회한다.

PC 목록에는 사번·이름, 소속, 휴가 종류, 신청 구분, 대상 기간, 일수, 요청 상태와 휴가 효력, 결재자 또는 처리자, 접수·처리 시각을 보여 준다. 일수는 선택한 검색 구간과 무관하게 신청 전체의 일수다. 모바일은 사원, 휴가 종류, 기간, 상태를 먼저 표시하고 같은 행을 열면 나머지 정보와 상세 이동을 제공한다. 접수·처리 시각은 서울 기준으로 표시한다. 조회 결과가 없으면 선택한 상태와 조건에 맞는 휴가 신청이 0건임을 표시하고 초기화할 수 있게 한다.

### 휴가 종류, 신청 상태, 효력

- **휴가 종류**는 신청 당시 연결된 근태코드 버전의 유형과 표시명을 사용한다. 종류 필터는 변경되지 않는 상위 코드로 조회해 이름이 바뀌기 전 신청도 같은 종류에 포함한다. 행과 상세는 각각 신청 당시 이름을 보여 준다.
- 현재 신청 가능한 휴가는 **종일 연차**다. 해당 유형이 이후 비활성화되어도 기존 신청 이력을 조회할 수 있다. 근태코드에만 있는 미지원 초안과 출퇴근 정정 코드는 휴가 종류 선택지에 올리지 않는다.
- 취소 신청은 원신청의 휴가 종류를 이어받는다. 원신청의 대상 기간과 취소 대상 일수를 읽어 표시하되, 취소 요청 자체가 새 휴가 일수를 사용한 것으로 합산하지 않는다. 상태별 건수는 휴가 사용일수가 아닌 요청 건수다.

| 사례 | 상태와 효력 |
| --- | --- |
| 휴가 신청이 대기, 반려 또는 철회됨 | 해당 신청 상태를 표시한다. 승인된 휴가 효력은 없다. |
| 휴가 승인 뒤 취소 신청 대기 또는 반려 | 원신청은 `승인 · 유효`로 보인다. 별도 취소 요청에는 그 요청의 상태를 표시한다. |
| 휴가 취소가 승인됨 | 원신청은 `승인 · 취소됨`으로 남고, 별도 취소 신청은 `승인`으로 보인다. 두 신청과 각각의 결재 이력을 연결한다. |

## 3. 조회 계약과 권한

- 담당자 휴가 목록은 `GET /admin/requests?scope=LEAVE&status=PENDING&leaveTypeCode=&requestKind=&from=&to=&organizationId=&q=&page=0`을 사용한다. 상태는 `PENDING`, `APPROVED`, `REJECTED`, `ALL`이다. 신청 구분은 전체 또는 `LEAVE_DAY`, `CANCEL_LEAVE`다. 기간을 입력할 때는 두 날짜를 `YYYY-MM-DD`로 입력한다. 날짜 누락·역전, 지원하지 않는 상태·신청 구분·휴가 코드는 해당 항목의 오류로 표시한다.
- 서버에서 휴가 유형과 인증된 테넌트 범위를 적용하고 검색 조건으로 걸러낸 뒤 페이지당 50건씩 반환한다. 상태 건수와 목록에 같은 유형·기간·조직·사원 검색 조건을 적용한다. 정렬 시각이 같으면 요청 ID로 순서를 고정한다. 신청 상태, 효력 및 결재 이력은 일관된 읽기 범위에서 확인한다.
- `approval_request`와 신청에 고정된 `attendance_type_version`, 상위 `attendance_type`을 읽는다. 현재 효력은 `request_effect`, 승인·반려 처리자와 처리 일시는 해당 `approval_event`에서 읽는다. 처리 이력이 확인되지 않는 기존 요청은 `미확인`을 표시하고 같은 상태의 처리 시각이 있는 행 다음에 둔다. 신청·처리 사유는 권한을 확인하는 기존 신청 상세에서 조회한다.
- 목록과 상세는 기존 담당자 권한과 PostgreSQL 테넌트 경계를 적용한다. 상세의 복귀 URL은 같은 앱의 휴가 목록 주소와 허용된 검색 값만 받는다. 승인·반려·재할당 등 실제 변경은 기존 상세의 권한·결재 규칙을 따른다. 이번 화면에서 사용하는 조회는 새로운 신청·승인·원장 변경을 일으키지 않는다.

## 4. 수용 기준

| 시나리오 | 기대 결과 |
| --- | --- |
| 메뉴와 직접 이동 | 휴가 메뉴와 기존 담당자 통합 주소에는 휴가와 취소 신청만 나온다. 같은 데이터에서 출퇴근 정정은 정정 현황에만 나온다. |
| 휴가 종류로 대기에서 승인·반려까지 조회 | 담당자가 종일 연차를 고르고 날짜·조직·사원 조건을 선택한 뒤 상태를 바꾸면 조건이 유지된다. 각 탭은 맞는 건수와 목록을 보이고 상세에서 같은 조건·페이지로 돌아온다. |
| 기간 경계와 이력 이름 | 시작일 또는 종료일에 걸친 신청이 누락되지 않는다. 같은 코드의 이전 버전 신청도 검색되고 당시 이름이 보인다. 비활성은 과거 조회를 막지 않는다. |
| 취소와 철회 | 원신청의 승인 기록과 현재 효력이 별도 표시된다. 취소 대기·반려에서 원효력이 유지되고 취소 승인 후 효력이 취소됨으로 보인다. 철회는 전체에서 찾을 수 있다. |
| 권한과 격리 | 일반 직원·대표는 담당자 전용 목록에 접근할 수 없다. 타 테넌트의 조직·사원·신청을 필터나 직접 주소로 조회할 수 없다. 대표의 기존 휴가 조회와 지정 결재자의 결재함은 계속 열린다. |
| PC·모바일 | 화면별로 휴가 종류 선택 → 대기·승인·반려 비교 → 처리 상세 확인 → 같은 조건 복귀를 확인한다. 검색 0건, 잘못된 날짜, 50·51건 페이지 경계도 검증한다. |
