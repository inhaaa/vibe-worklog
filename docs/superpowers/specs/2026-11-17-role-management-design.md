# 권한별 사원 조회와 부여·해제

2026-11-17 설계안. 담당자가 **시스템 설정 > 권한 관리**에서 권한을 하나 선택하면 해당 권한이 부여된 사원을 확인하고, 같은 시트에서 사원을 추가하거나 권한을 해제한다. 현재 계정별 목록과 사원 상세의 역할 저장이 사용하는 권한·세션·감사 규칙을 따른다. [계정·역할 계약](../../design/account-access.md) · [대표 권한 추가 이력](../../quality/identity-access.md)

## 담당자 흐름

1. PC에서는 권한 목록을 왼쪽에, 선택한 권한의 사원 시트를 오른쪽에 둔다. 모바일에서는 권한 선택을 시트 위에 둔다. 기존 `/admin/access`에서 처음 진입하면 **담당자**를 선택하고, 다시 열 때는 URL에 지정된 권한을 사용한다.
2. 담당자가 **결재 담당**을 선택하면 오른쪽에 해당 권한의 사원만 표시한다. 사번·이름으로 전체 대상에서 검색하고 페이지를 이동할 수 있다. 시트 열은 사번, 이름, 현재 조직, 사용 상태, 변경 예정으로 구성한다. 현재 조직은 서울 기준 오늘의 소속이며 시트에는 조회값으로 표시한다. 권한별 전체 부여 인원과 시트의 검색 결과 건수를 구분한다.
3. **사원 추가**를 누르면 선택한 권한이 없는 같은 고객사의 사원을 사번·이름으로 찾아 여러 명을 선택할 수 있다. 초대를 수락한 활성 계정이 있고 현재 재직 중인 활성 사원만 선택할 수 있다. 선택한 사원은 시트에 **부여 예정**으로 표시된다. 후보가 없으면 사원 관리로 연결해 계정 상태와 초대를 확인할 수 있게 한다.
4. 기존 행을 선택하고 **권한 해제**를 누르면 **해제 예정**으로 표시된다. 저장 전에는 예정 동작을 취소할 수 있다. 이미 부여 예정인 신규 행을 취소하면 시트에서 그 행이 빠진다. 보유 권한이 있는 사원의 계정이 비활성 또는 재직 요건을 충족하지 않으면 보유 행은 보여 주고, 행에서 현재 변경이 제한되는 사유를 안내한다.
5. **저장**에서 부여·해제 대상과 인원, 검색·정렬로 가려진 변경 건수, 변경 사유를 확인한다. 같은 권한에 대한 1~50명 변경을 한 번에 저장한다. 성공하면 같은 권한과 검색 조건에서 실제 반영 결과를 확인한다. 검색·권한 변경·페이지 이동·화면 이탈로 초안이 사라지는 경우에는 먼저 확인한다.

| 권한 | 시트 동작 |
| --- | --- |
| 공통 `EMPLOYEE` | 기본 역할의 부여 사원 조회 |
| 담당자 `ATTENDANCE_ADMIN` | 조회, 부여, 해제 |
| 대표 `COMPANY_REPRESENTATIVE` | 조회, 부여, 해제 |
| 결재 담당 `APPROVER` | 조회, 부여, 해제 |

**부여 인원**은 선택 권한 행의 `active`가 참인 사원 수다. 시트는 계정 수락·활성·재직을 반영해 **사용 가능** 또는 제한 사유를 표시한다. 검색 결과와 페이지는 서버에서 사번·사원 ID 순으로 조회한다. 공통은 기본 권한임을 표시하고, 변경 버튼은 편집 가능한 권한에서 제공한다. 사원별 상세 링크에서는 기존 계정 초대, 전체 권한 점검, 지정 승인자 관리를 이어갈 수 있다.

기존 [공통 시트](2026-10-29-common-sheet-design.md)의 50행 페이지, 현재 페이지 안 정렬·필터, 초안 보존과 미저장 확인을 재사용한다. 모바일의 가로 스크롤은 시트 안으로 제한한다. 저장 오류는 요약과 해당 행에 표시하고 요약으로 키보드 초점을 옮긴다. 요약에서 행을 선택하면 필요에 따라 해당 시트 필터를 풀고 행으로 이동한다.

## 권한 변경의 효력

- 선택한 권한 하나만 부여·해제한다. 예를 들어 결재 담당을 해제한 사원의 공통과 대표 권한은 그대로 적용된다. 해제는 기존 `role_grant.active` 효력을 끄고 감사 이력을 남긴다.
- 담당자 권한을 해제할 때 같은 고객사에 **현재 재직 중이며 종료 예정일이 없는 활성 담당자**를 남겨야 한다. 한 번의 저장에서 후임 담당자를 부여하고 전임을 해제할 수 있다. 유효 담당자 수는 저장 순서와 관계없이 전체 변경 후 상태를 기준으로 확인한다. 요건을 충족하지 못하면 저장 전체를 반려하고 해결 방법을 표시한다.
- 변경된 권한은 저장 커밋 시점부터 효력이 생긴다. 대상 계정의 `auth_version`을 올려 기존 로그인 세션을 회수한다. 자신의 역할이 변경되는 저장은 확인 단계에서 재로그인을 안내한다. 세션이 회수된 담당자에게는 저장 결과만 안내하고, 다시 로그인한 뒤 현재 권한으로 화면을 열게 한다.
- 결재 담당 권한은 실제 결재 자격 중 하나다. 부여 뒤 결재 대상은 기존 지정 승인자·결재선 설정에서 관리한다. 해제 확인 화면에서 해당 사원이 결재를 처리할 수 없게 된다는 점을 안내한다. 기존 지정과 대기·완료 신청은 보존한다. 현재 적격성을 잃은 지정은 **재지정 필요**로 표시되며, 대기 신청은 기존 수동 재할당 절차로 처리한다. [결재선·재할당 계약](../../design/approval-routes.md)

## 조회·저장 계약

| 경로 | 계약 |
| --- | --- |
| `GET /admin/access?role=…&q=…&page=…` | 기존 메뉴 URL에서 역할 목록, 선택 권한의 부여 인원, 같은 고객사의 해당 역할 사원 시트, 페이지와 검색 상태를 제공한다. |
| `GET /admin/access/roles/{role}/candidates` | 편집 가능한 역할에서 같은 고객사의 부여 가능 사원을 서버 검색·페이지로 제공한다. 이미 시트에 추가한 사원은 선택 목록에서 중복 선택할 수 없게 한다. |
| `POST /admin/access/roles/{role}/members/bulk` | 앞뒤 공백을 제거한 변경 사유 1~500자, `commandId`, 1~50개 행의 `clientRowId`, `employeeId`, `expectedVersion`, `GRANT` 또는 `REVOKE`를 받는다. 성공하면 각 행의 결과를 보여주고 같은 권한으로 돌아간다. |

- 후보 조회와 저장 경로를 담당자 전용으로 등록하고, 서버에서 현재 `ATTENDANCE_ADMIN` 역할·활성 계정·재직·세션 버전을 확인한다. 새 조회는 기존 공유 잠금과 반환 전 권한 확인을, 저장은 CSRF와 고객사 독점 잠금을 적용한다. 고객사는 인증 정보로 결정하며 SQL의 고객사 조건과 FORCE RLS를 유지한다. 권한 목록은 기존 시스템 역할을 사용한다. 서비스 운영자 권한은 별도 인증 경계에 둔다.
- 저장은 편집 가능 권한, 사원 ID 중복, 현재 계정과 재직 조건, 선택 권한의 실제 보유 여부, `employee.version`과 마지막 담당자 조건을 다시 확인한다. 요청에 담긴 선택 권한에 대해서만 현재 역할에 변경을 적용한다. 변경이 없는 행은 제출에서 제외한다. 대상의 다른 권한과 계정 상태는 보존한다. 권한 행, 사원 버전, 세션 회수와 감사는 같은 트랜잭션으로 저장한다. 감사에는 수행자, 대상 사원, 전후 권한, 시각과 사유를 남긴다. 기존 `role_grant`, `tenant_account`, `employee`, `org_audit_event`를 사용한다.
- 공개 데모에서는 이미 부여된 공유 사원 행에 **공유 데모 보호**를 표시한다. 공유 사원은 추가 후보에서 제외하고 해제 선택을 제한한다. 새 일괄 경로도 기존 공개 보호 규칙으로 직접 요청을 거절한다. 권한 시트와 후보 응답에는 사번·이름·현재 조직·권한과 상태에 필요한 데이터만 제공한다.
- 저장 전에 대상 행과 문맥을 보존한다. 버전이나 보유 상태가 바뀌어 409가 오면 최신 상태와 예정 동작을 함께 표시하고 재확인 뒤 새 명령으로 저장한다. 422의 입력·업무 오류는 관련 행과 사유에 표시하고 전체 묶음을 되돌린다. 403은 현재 접근을 차단하고, 다른 고객사의 사원 ID에는 일반 404를 반환한다. 결과 확인이 어려운 통신 오류에는 동일한 입력과 `commandId`로 재시도한다. 현재 접근 권한을 확인한 뒤 동일 수행자의 완료된 명령은 원래 결과를 돌려준다. 같은 `commandId`의 수행자나 입력이 달라지면 409를 반환한다.

## 구현 수용 기준

| 시나리오 | 확인할 결과 |
| --- | --- |
| 권한 전환과 조회 | 선택 권한의 사원만 표시하고 부여 인원·검색 결과·페이지를 구분한다. 공통과 공개 공유 계정의 관리 제한이 화면과 서버에서 일치한다. |
| 사원 추가·권한 해제 | 사원 검색과 다중 선택, 예정 상태·취소, 사유 입력, 한 번의 저장과 결과 확인이 가능하다. 선택 밖 역할은 유지하고 실제 대상의 세션만 회수한다. |
| 마지막 담당자와 결재 영향 | 마지막 유효 담당자만 해제하는 저장을 거부한다. 유효한 후임 부여를 포함한 교체는 한 번에 처리한다. 결재 대기 스냅샷을 보존하고 재지정 동선을 확인한다. |
| 충돌·재전송·원자성 | 다른 담당자의 동시 변경과 오래된 화면은 409를 반환한다. 잘못된 행이나 감사 실패가 있으면 모든 행과 세션 버전을 되돌린다. 같은 명령을 재전송해도 중복 반영이 없다. |
| 권한과 고객사 격리 | 일반 직원·대표 단독·결재 담당 단독은 접근할 수 없다. CSRF 누락·타 고객사 사원·공개 공유 사원 변경 시 역할과 감사 기록을 변경하지 않는다. |
| Chrome PC·390px 모바일 | 권한 선택부터 사원 추가·해제·저장까지 화면에서 수행한다. 키보드로 오류 요약과 해당 행을 찾아 수정하고, 모바일에서는 가로 넘침 없이 동작한다. |
