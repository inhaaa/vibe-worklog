# 일일 근태 자동화 설계 (B 묶음)

작성일 2026-11-25 · 사용자 승인 설계 · 업무 시간대 `Asia/Seoul` · 기준 브랜치 `claude/opening-prep-20261123`

개통 점검에서 나온 두 가지 문제를 해결한다. 첫째, 직원이 매일 "예정 휴게대로 쉬었다"를 확인하지 않으면 그날은 '확인 전'으로 남아 근무시간이 집계되지 않는다. 둘째, 지각·조퇴·결근을 판정하지 않는다. [개통 점검 결과](2026-11-23-opening-prep-design.md) · [계산 규칙](../../rules/calculation.md) · [근무조·근무시간코드](2026-11-18-workgroup-schedule-design.md)

## 1. 사용자 결정

| 질문 | 결정 |
| --- | --- |
| 휴게시간 처리 | 퇴근 기록 즉시 예정 휴게를 자동 적용한다. 실제와 다르면 직원이 정정 신청으로 고친다. |
| 지각·조퇴 기준 | 그날 배정된 근무시간코드의 출근·퇴근 시각을 기준으로 한다. 유예시간은 두지 않는다. 08:00 출근이면 08:00을 넘는 순간부터 지각이다. 새 설정 화면은 만들지 않는다(시간은 근무시간코드에서 한 번 정하고, 근무조 배정으로 사원 전원에게 반영된다). |
| 결근 시점 | 날이 지나면(다음 날 0시) 자동으로 결근으로 표시한다. 나중에 정정이나 휴가가 승인되면 결근 표시가 사라진다. |
| 집계 시점 | 퇴근 시 즉시 계산하고, 정정·휴가 승인 직후 다시 계산한다. 매일 새벽에 일괄 계산한다. |

## 2. 휴게 자동 적용

- 퇴근 기록을 저장하면 같은 요청 안에서 그날을 자동 확인한다. 조건은 지금의 직원 확인과 같다.
  - 출근과 퇴근이 각각 하나씩 있어야 한다.
  - 두 기록 모두 근무일 당일이어야 하고, 출근이 퇴근보다 빨라야 한다.
  - 유효한 일정과 휴일 반영분이 있어야 한다.
- 적용할 휴게는 근무시간코드의 예정 휴게 중 **출퇴근 구간 안에 들어오는 부분**이다. 구간 밖의 휴게는 빼고, 걸친 휴게는 구간에 맞게 자른다. 고정 근무에도 선택근무와 같은 방식을 쓴다.
  - 예: 오전 반차로 13:00에 출근하면 12:00~13:00 휴게는 적용하지 않는다.
  - 예: 12:30에 출근하면 12:30~13:00만 적용한다.
- 확인 기록에 방법(`EMPLOYEE` 직원 확인 / `AUTO_SCHEDULE` 자동 적용)을 남긴다. 기존 기록은 `EMPLOYEE`다.
  - 자동 적용의 `confirmed_by`는 퇴근 시에는 퇴근한 본인, 새벽 일괄에서는 `NULL`(시스템)이다.
- 자동 적용 조건을 갖추지 못한 날(퇴근 누락·중복·일정 없음 등)은 지금처럼 '확인 필요'로 남긴다. 정정이 승인되면 그 정정이 담은 실제 휴게 근거를 그대로 쓴다(기존 규칙).
- 직원 화면의 '근무 확인' 버튼과 안내는 없앤다. 실제 휴게가 다르면 기존 정정 신청에서 실제 휴게를 입력한다. 정정 신청 진입 안내 문구를 "예정 휴게가 자동 적용되었습니다. 다르면 정정을 신청해 주세요."로 바꾼다.
- 자동 적용은 근거 기록이다. 지휘·감독 아래의 대기 등 실제 근로 여부에 대한 법적 최종 판단으로 표시하지 않는다. 법정 휴게 부족 경고(`BREAK_INSUFFICIENT_REVIEW`)는 그대로 둔다.
- 계산 규칙 문서 §3.1·§4.1의 "확인 전에는 체류시간만 산출" 규칙을 이 방식으로 바꾸고, 엔진 규칙 버전을 `CALC-2`로 올린다. 기존 결과의 `CALC-1` 표시와 근거는 보존한다.

## 3. 지각·조퇴·결근 판정

계산기(`WorktimeCalculator.day`)가 일 결과와 함께 판정한다. 순수 계산이며, 날이 지났는지는 호출하는 쪽이 `dayEnded`로 넘긴다.

| 구분 | 조건 | 결과 |
| --- | --- | --- |
| 지각 | 출근 시각 > 기준 출근 시각 | `late_millis` = 차이, 사유 `LATE` |
| 조퇴 | 퇴근 시각 < 기준 퇴근 시각 | `early_leave_millis` = 차이, 사유 `EARLY_LEAVE` |
| 결근 | 근로일(`WORKDAY`, 소정시간 > 0), 종일 휴가 없음, 출퇴근 기록 없음, 대기 정정 없음, `dayEnded` | `absence` = `FULL`(반차일이면 `HALF`), 실근로 0, 사유 `ABSENT` |

- **기준 시각**
  - 종일 근무일은 근무시간코드의 출근·퇴근 시각이다.
  - 오전 반차: 기준 출근 = 정규 구간의 가운데 시각 전에 시작하는 첫 예정 휴게의 종료 시각이다. 그런 휴게가 없으면 가운데 시각이다.
  - 오후 반차: 기준 퇴근 = 같은 휴게의 시작 시각이다. 그런 휴게가 없으면 가운데 시각이다.
  - 오전·오후 반차가 모두 있으면 종일 휴가와 같게 본다.
- **판정하지 않는 날**: 종일 휴가일, 휴일·비근로일, 캘린더 미확인일, 일정 누락·충돌일, 선택근무조의 날. 이런 날의 지각·조퇴·결근 값은 `NULL`이다.
- **판정할 수 없는 경우**
  - 출근이나 퇴근 중 하나만 있으면 기록이 있는 쪽만 판정하고, 기존 누락 사유로 '확인 필요'를 유지한다.
  - 기록 순서 역전·자정 통과·중복도 기존 사유를 유지하고 지각·조퇴는 `NULL`로 둔다.
- 결근은 `ABSENT`를 정보성 사유로 두어 상태를 `CALCULATED`로 확정한다(일반 규정 적용 검토가 없는 사원은 기존처럼 `LEGAL_APPLICABILITY_UNCONFIRMED`로 확인 필요 상태가 남는다). 실근로 0이 주간·월간 합계에 들어가 '확인 전' 일수가 줄어든다. `dayEnded`가 아니면(오늘·미래) 지금처럼 기록 없음으로 둔다.
- 대기 정정이 있는 무기록일은 결근 대신 기존 `PENDING_CORRECTION` 상태를 유지한다.
- 지각·조퇴·결근은 표시와 집계를 위한 값이다. 실근로는 실제 출퇴근 기준 그대로이며 급여 공제·징계를 자동으로 판단하지 않는다. 계산 규칙 §4.2의 "참고 값" 문장을 이 판정 기준으로 바꾼다.
- **오늘의 '미출근'**: 근로일 오늘이고, 기준 출근 시각이 지났고, 출근 기록이 없으면 홈과 현황에 '미출근'으로 보인다. 화면 조회값이며 일 결과에 저장하지 않는다.

## 4. 자동 집계

| 시점 | 대상 | 방식 |
| --- | --- | --- |
| 퇴근 기록 | 그날이 속한 주 | 자동 확인 후 기존 `calculateConfirmedDay` 경로(감사 `WORKTIME_AUTO_CALCULATE`)로 같은 요청의 별도 트랜잭션에서 계산한다. 계산이 실패해도 퇴근 기록은 유지한다. |
| 정정 제출·승인·반려·철회, 휴가 승인·취소 | 해당 신청 기간 안에서 '재집계 필요'로 표시된 날짜(일 결과는 날짜별로 독립이고, 주 합계는 조회할 때 묶는다) | 승인 트랜잭션 커밋 뒤 별도 트랜잭션에서 계산한다. 실패해도 승인은 유지하고 그날은 '재집계 필요'로 남는다. 결재 자체가 업무 감사에 남으므로 계산은 `calculation_run.requested_by = 결재자`로만 추적한다. |
| 매일 00:10 서울 | 회사별: 어제 + 마감하지 않은 달의 '재집계 필요' 날 + 자동 확인 대상 날 | 아래 일괄 작업 |

**새벽 일괄 작업**

- Spring 스케줄러(`@Scheduled`, `Asia/Seoul`)로 실행한다. 여러 서버가 동시에 시작해도 DB의 `pg_try_advisory_lock`으로 한 번만 실행한다. 이미 실행 중이면 건너뛴다.
- 활성 회사 ID 목록만 로그인용 인증 계정(`tna_auth`, 회사 조회 정책 보유)으로 읽는다. 처리는 사원마다 짧은 트랜잭션과 그 회사 컨텍스트(`app.tenant_id`)에서 한다. 다른 회사의 자료를 읽거나 쓰지 않으며 RLS·권한은 바꾸지 않는다.
- 처리 순서
  1. 미확인 지난 날짜(마감 전 달)를 자동 확인한다.
  2. 사원별로 지난 7일과, 최근 62일 안에서 재집계 필요로 표시된 날짜를 계산한다(마감한 달 제외).
  3. 결과가 이미 최신이면 새로 쓰지 않는다. 그래서 다시 실행해도 결과·감사가 중복되지 않는다.
- 실행자는 시스템이다. 사람의 업무 감사(`org_audit_event`, 행위자 필수)는 쓰지 않고, 계산 실행 기록 `calculation_run`에 `requested_by = NULL`로 남겨 추적한다. `requested_by`가 NULL이면 화면에 '시스템'으로 표시한다.
- 회사 하나가 실패해도 다음 회사를 계속 처리하고 실패 건수를 로그에 남긴다. 실패한 날은 다음 실행이나 담당자 수동 재집계로 다시 계산된다.
- 재직 기간 밖 날짜, 마감한 달, 미래 날짜는 계산하지 않는다(기존 계산 창 규칙).
- `local` 프로필과 테스트에서는 설정 `tna.daily-batch.enabled`로 끌 수 있다. 기본값은 켜짐이며 테스트 설정에서는 끈다.

## 5. 저장과 화면

**마이그레이션 V42**

- `tna.day_result`에 `late_millis bigint`, `early_leave_millis bigint`, `absence varchar(10)`(`FULL`/`HALF`/NULL)을 추가한다. 값은 0 이상이다. 기존 행은 NULL이다.
- `tna.work_confirmation`에 `method varchar(20) NOT NULL DEFAULT 'EMPLOYEE'`를 추가한다. 값은 `EMPLOYEE`/`AUTO_SCHEDULE`이다. `confirmed_by`의 NOT NULL을 해제하되, `method='EMPLOYEE'`이면 NOT NULL을 유지하도록 검사 조건을 둔다.
- `tna.calculation_run.requested_by`의 NOT NULL을 해제한다(NULL = 시스템 실행). `org_audit_event.actor_account_id`는 바꾸지 않는다.
- RLS·권한·기존 행·지문(fingerprint) 서명 형식은 바꾸지 않는다. 새 열은 결과 근거 JSON과 지문 입력에 넣지 않는다.

**화면**

| 화면 | 표시 |
| --- | --- |
| 직원 출퇴근 기록·근로시간 | '근태' 열: 정상 / 지각 n분 / 조퇴 n분 / 지각 n분·조퇴 n분 / 결근 / 결근(반일) / 미출근 / 확인 필요 |
| 직원 홈 '이번 주 일정' | 같은 표시. 오늘은 '미출근'이 보일 수 있다. |
| 담당자 회사 근무현황 | 기간 내 지각·조퇴·결근 건수 요약과 '근태' 필터, 행별 근태 열 |
| 월말 점검 목록 | 결근·지각·조퇴 행 표시. 결근은 더 이상 '확인 필요'로 세지 않는다. |
| 검토용 Excel | 지각(분)·조퇴(분)·결근 열 추가. NULL은 미확정 문자열이다. |

분 표시는 밀리초를 올림한 분이다(08:00:01 출근 = 지각 1분). 저장 값은 밀리초를 유지한다.

## 6. 오류와 경계

- 근무시간코드 일정이 근무일 도중에 바뀌어도 그날의 일정 버전을 쓴다(기존 일정 해석 규칙).
- 휴일 관리에서 날짜를 휴일로 바꾸면 그날이 재집계 필요가 되고, 새벽 일괄에서 결근이 사라진다.
- 마감한 달은 자동 확인과 계산 모두 하지 않는다. 마감을 재개하면 다음 새벽 일괄부터 대상이 된다.
- 결근으로 저장된 날에 나중에 출근 기록이 정정으로 들어오면 입력 개정이 바뀌어 재계산되고, 결근이 사라진다.

## 7. 검증 기준

| 범위 | 사례 |
| --- | --- |
| 계산기 단위 | 정상, 지각 1초·7분, 조퇴, 지각+조퇴, 오전·오후 반차 기준 시각, 휴게 없는 코드의 가운데 시각, 결근(종일·반일), 오늘 무기록(결근 아님), 대기 정정 무기록, 휴일·비근로일·종일 휴가·선택근무 미판정, 출근만 있는 날 |
| 자동 확인 통합 | 퇴근 즉시 확인·집계, 휴게 자르기(오전 반차·12:30 출근), 조건 미달 날 미확인, 같은 퇴근 재전송 시 중복 없음, 정정 승인 후 재계산 |
| 일괄 작업 통합 | 회사 격리, 마감 월 제외, 두 번 실행해도 결과·감사 1회, 동시 실행 시 한 번만, 회사 하나 실패 시 다음 회사 계속, 결근 → 휴가 승인 후 해소 |
| 마이그레이션 | V41→V42 기존 행 보존, 직원 확인의 `confirmed_by` 필수 유지, RLS·권한 유지 |
| 브라우저 | PC·모바일에서 퇴근 후 근무시간 즉시 표시, 지각 표시, 다음 날 결근 표시, 담당자 근무현황 필터 |

## 8. 범위 밖

- 지각·조퇴·결근에 따른 급여 공제, 징계, 직원 알림(E 묶음).
- 연장근무 집계와 52시간 점검(C 묶음).
- 지각 유예시간 설정, 자정을 넘는 근무.
