# 홈 출퇴근 위젯 설계

승인: 2026-11-16 사용자 대화(기록 테이블·버튼 규칙·설계안 선택). 상위 작업: [운영 화면 정리](2026-11-11-ops-screen-cleanup-design.md).

## 1. 결정

| 번호 | 결정 |
| --- | --- |
| W1 | 기록은 기존 `tna.attendance_event`에 남긴다. 이 테이블이 IP(`validated_ip`)·명령 ID(`client_command_id`)·근무일(`assigned_work_date`)·시각(`occurred_at`)·출퇴근 구분(`event_kind`)을 이미 갖고, 근무 확인·자동 계산·정정이 모두 이 테이블을 읽는다. 새 테이블·마이그레이션은 만들지 않는다. |
| W2 | 같은 근무일의 출근·퇴근은 각 1회만 저장한다. 서버가 막고, 같은 명령 ID 재전송은 기존처럼 한 번만 저장한다. |
| W3 | 홈의 기존 '오늘 근무' 위젯을 출퇴근 위젯으로 바꾼다. 새 위젯을 더하지 않는다. |
| W4 | 퇴근은 출근을 누르지 않았어도 누를 수 있다. 빠진 출근은 정정 신청으로 채운다. |

## 2. 위젯

- 머리: `오늘 근무`와 오늘 날짜, 오른쪽에 기존 '기록 상세' 링크(`/me/attendance`).
- 일정 한 줄: 근무일은 `09:30 ~ 15:30`, 그 밖에는 서버 일정 문구(`소정 비근로일`, `근무 일정 미배정` 등)를 그대로 보인다. 구분자 ` ~ `는 `scheduleText`를 쓰는 모든 화면(홈 주간 띠·근태 캘린더·서버 템플릿)에 함께 적용해 형식을 맞춘다.
- 버튼 2개: `출근`, `퇴근`. 오늘 그 구분의 원래 기록(정정 반영 전 `attendance_event`)이 있으면 버튼은 비활성이고 기록 시각을 `HH:mm:ss`로 보인다. 없으면 활성 버튼이다.
- 누르면 기존 `POST /me/attendance/events`로 보낸다. 숨은 값은 `eventKind`, `commandId`(화면을 그릴 때 서버가 만든 새 UUID), `returnTo=home`이다. 성공하면 `/me/home`으로 돌아와 버튼이 비활성·시각 표시로 바뀐다.
- 실패하면 `/me/home?clockError=<상태>`로 돌아와 위젯 안에 문구를 보인다. 403은 "허용된 네트워크에서만 출퇴근을 기록할 수 있습니다.", 409는 "오늘 이미 기록했습니다.", 그 밖은 "기록하지 못했습니다. 잠시 후 다시 시도해 주세요."이다.
- 기존 '현재 반영 출근/퇴근' 줄은 버튼이 대신한다. 확인 문구와 타임라인은 유지한다.

## 3. 서버

- `ClockService.record`: 명령 실행(tenant 잠금) 안에서 같은 직원·근무일·구분의 `attendance_event`가 이미 있으면 409 "오늘 출근은 이미 기록했습니다." 또는 "오늘 퇴근은 이미 기록했습니다."로 거절한다. 같은 명령 ID 재전송은 명령 재생으로 먼저 처리되므로 이 검사에 닿지 않는다.
- `AttendanceController.event`: 선택 파라미터 `returnTo`가 `home`이면 `/me/home`으로, 아니면 기존처럼 `/me/attendance`로 돌아간다. `returnTo=home`에서 `OrgException`이 나면 `/me/home?clockError=<상태>`로 돌아간다. 다른 값은 무시한다(열린 리다이렉트 없음).
- 홈 화면 모델(`workspace/home`): 오늘 원래 출근·퇴근 시각(없으면 null)과, 아직 기록하지 않은 구분에만 새 명령 ID를 넣는다. `clockError`도 허용 키에 넣는다.
- 출퇴근 기록 화면(`/me/attendance`)의 오늘 버튼도 같은 규칙을 따른다. 이미 기록한 구분은 명령 ID를 주지 않아 비활성이 되고, 버튼에 기록 시각을 보인다.
- DB 스키마는 바꾸지 않는다. 동시 요청은 tenant 잠금 안에서 직렬화되므로 같은 날 두 건이 생기지 않는다.

## 4. 바꾸지 않는 것

허용 네트워크 검사, 근무일 배정(서울 날짜), 근무 확인·자동 계산·정정 흐름, 기존 중복 기록 자료(이미 쌓인 중복은 정정으로 처리한다).

## 5. 검증

- 서버: 같은 날 두 번째 출근 409, 퇴근은 출근 없이 성공, 같은 명령 재전송은 한 건, `returnTo=home` 리다이렉트와 오류 리다이렉트, 홈 모델의 시각·명령 ID.
- 프런트: 위젯 버튼 활성/비활성·시각 표시, 숨은 값, 오류 문구, 출퇴근 기록 화면 오늘 버튼의 비활성·시각.
- 문서: `docs/design/screens.md`의 홈·출퇴근 기록 행.
