# 근무조별 근무시간코드·휴게·연장 기준과 사원 배정 명세

작성일 2026-11-18 · 승인 명세 · 기준 소스 `c819db1` · 업무 시간대 `Asia/Seoul`

**확정한 운영 원칙**은 사원을 근무조에 배정하고, 근무조를 개정하면 **적용일부터 그 조에 소속된 사원 모두에게 자동 반영**하는 것이다. 담당자가 매번 사원을 다시 선택할 필요가 없다. 아래 표는 담당자가 등록할 값과 저장 전 확인할 결과를 예시로 든다.

## 1. 담당자가 근무 기준을 만들고 배정하는 순서

**근태 운영 > 근무 기준 > 근무 설정**에 `근무시간코드`, `근무조`, `사원 배정`을 둔다. 화면 사이에서 선택한 조와 조회 기준일을 유지한다.

| 순서 | 담당자 작업 | 저장 전에 확인하는 내용 |
| --- | --- | --- |
| 1. 근무시간코드 등록 | `W01 주간 09시`에 출근 09:00·퇴근 18:00, 예정 휴게 12:00~13:00를 등록한다. 연장 신청을 허용할 요건과 시간대도 정한다. | 정규 구간 9시간, 예정 휴게 1시간, 소정 8시간이 각각 보인다. 하루의 정규·휴게·연장 구간을 시간 순으로 비교한다. |
| 2. 근무조 편성 | `G01 운영 주간조`의 월~금에 W01을 넣고 토·일은 비근로일로 정한다. 특정 요일만 `W02 주간 10시`로 지정할 수도 있다. | 적용 시작일을 포함한 일주일을 실제 날짜로 펼쳐 요일별 출퇴근·휴게·소정시간과 주간 소정 합계를 확인한다. |
| 3. 사원 배정 | 사번·이름·소속으로 사원을 검색하고 한 명 또는 여러 명에게 G01과 적용 시작일을 지정한다. 최초 발령에서도 근무조를 선택할 수 있다. | 사원별 기존 조·새 조, 기존 배정의 마지막 날, 신규 첫날, 이미 예약된 다음 배정과 충돌 사유를 보여 준다. 저장 후 같은 기준일로 재조회한다. |
| 4. 근무조 개정 | G01의 평일을 12월 1일부터 W02로 바꾸고 변경 사유를 입력한다. | 변경 전후 시간표, 최초 영향일, 자동 반영 인원·명단을 확인한다. 저장 후 직원은 본인 근무일을 선택해 그날의 근무조와 일정을 확인한다. |

근무조는 근무시간표를 공유하는 사원 묶음이다. 같은 팀의 두 사원을 서로 다른 조에 배정하거나, 여러 조직의 사원을 한 근무조에 배정할 수 있다. 조직 이동만으로 근무조를 바꾸지 않는다.

## 2. 근무시간코드에서 관리할 항목

| 항목 | 입력·검증 규칙 |
| --- | --- |
| 기본정보 | 코드, 표시명, 사용 시작일, 사용 상태, 변경 사유. 신규 코드는 영문 대문자·숫자 2~8자리 문자열로 관리한다. 앞자리 0을 보존하며 고객사 안에서 같은 종류의 코드 재사용을 막는다. 저장한 코드의 변경은 새 코드 등록으로 처리한다. |
| 정규 근무 | 근로일 하루에 출근~퇴근 한 구간을 지정한다. 종료가 시작보다 늦어야 한다. 09:00~18:00와 10:00~19:00는 별도 코드로 만들 수 있다. 신규 입력은 분 단위다. 기존 일정의 초·밀리초는 읽기·이관 시 보존한다. |
| 예정 휴게 | 근무시간코드 상세의 별도 표에서 시작·종료를 행 단위로 추가·변경한다. 정규 휴게는 정규 구간 안에 있어야 하며 둘 이상 가능하다. 시작과 종료가 같거나 뒤집힌 구간, 중복·겹침은 저장할 수 없다. 맞닿는 구간은 허용한다. 저장 전에 예정 휴게 합계와 소정시간을 함께 보여 준다. |
| 연장근무 기준 | 회사 기준으로 `신청 허용` 또는 `미허용`을 선택한다. 허용하면 같은 근무일의 정규 출근 전·퇴근 후 중 필요한 시간대를 입력한다. 전·후 각각 최대 한 구간이며 정규 구간과 겹치지 않아야 한다. 연장 중 예정 휴게가 있으면 해당 허용 구간 안에 별도로 입력한다. |
| 연장 가능 시간 표시 | 허용 구간 길이에서 그 구간의 예정 휴게만 뺀 값을 **최대 신청 가능 시간**으로 표시한다. 구간은 시작 포함·종료 제외다. 예를 들어 퇴근 18:00, 연장 허용 18:30~21:00, 연장 중 예정 휴게 20:00~20:15라면 최대 2시간 15분이다. 18:00~18:30은 신청 허용 구간 밖이며 실제 휴게로 자동 공제하지 않는다. |

정규 예정 휴게는 **소정시간** 산출에 쓴다. **실제 근로시간**은 출퇴근·근로 확인·실제 휴게·승인된 정정으로 판정한다. 18:00 이후 퇴근했거나 회사의 연장 신청 기준을 벗어나도 원천 기록과 확인된 실제 근로를 보존한다. 근무조 설정만으로 연장 승인·급여 가산을 생성하지 않는다. 이번 단위는 당일 고정 근무와 그에 붙는 연장 기준을 다룬다. 자정 통과, 비근로일·휴일 전용 신청, 선택근무제의 정산기간과 직원별 연장 신청·결재 화면은 각각 후속 업무로 둔다.

## 3. 적용일과 자동 반영

**해당 근무일의 사원 배정 → 해당 날짜의 근무조 개정 → 해당 요일에 연결한 근무시간코드 버전** 순서로 일정을 찾는다. 실제 근무일이 조회 기준이며, 오늘 조회하는 과거 기록도 그 날짜의 설정을 사용한다.

- **코드와 근무조 개정은 구분한다.** 근무시간코드의 시각이나 휴게를 수정하면 새 버전을 만든다. 이미 발행된 근무조 개정은 연결 당시의 코드 버전을 유지한다. 코드 상세에서 사용 중인 근무조를 확인하고, 바꿀 조에서 새 코드 버전과 적용일을 지정해 발행한다. 이때부터 사원별 재배정 없이 자동 반영한다. 비활성 코드는 과거 이력과 기존 발행본에서 읽을 수 있고 신규 편성에서 제외한다.
- **적용일은 서울 달력의 날짜다.** 근무조 개정과 사원 배정의 시작일을 포함하며 다음 적용일 전날까지 유효하다. 예약된 이후 개정·조 이동은 보존한다. 같은 날짜에 겹치는 신규 등록은 어느 예약과 충돌했는지 표시한다. 예약을 정정할 때는 해당 예약을 명시적으로 선택해 새 개정과 변경 사유를 남긴다.
- **적용 첫날에 유효한 시간표가 있어야 한다.** 조 개정 첫날에는 선택한 모든 근무시간코드 버전을 사용할 수 있어야 하고, 사원 배정 첫날에는 해당 조에 발행된 유효 개정이 있어야 한다. 12월 10일에 시작하는 코드나 조를 12월 1일부터 사용하려 하면 사용 가능한 첫 날짜를 안내하고 저장을 막는다.
- **같은 날 조 이동과 개정이 있으면 새 소속 조를 먼저 결정한다.** 11월 30일까지 G01에서 09:00에 출근한 사원은 12월 1일 G01 개정 후 10:00에 출근한다. 12월 1일자로 G02 이동이 예약된 사원은 그날 G02 일정을 따른다. 12월 7일 G01에 새로 들어오는 사원은 그날 유효한 G01 개정본을 받는다.
- **이미 근무가 시작된 당일은 보호한다.** 신규·변경 적용일은 서울 오늘 이후다. 당일 기존 일정을 교체할 때는 영향 사원의 변경 전후 근무 시작 중 이른 시각이 지나거나, 해당 일자에 출퇴근·근로확인 등 업무 사실이 있으면 변경을 막고 충돌 사원·날짜를 안내한다. 최초 배정은 기존 일정이 없고 해당 일자에 업무 사실이 없을 때 가능하다. 일반 설정은 지난 날짜로 소급하지 않는다.
- **자동 반영의 범위가 보인다.** 개정 저장 전에는 적용일 현재 재직·배정이 유효한 명단, 같은 날 다른 조로 이동하는 인원, 이후 해당 조에 들어올 예약을 나누어 보여 준다. 명단 확인 뒤 배정이나 조 개정이 달라졌으면 최신 영향 범위를 다시 확인한다. 조의 이후 예약 개정 전까지 전입·전출 사원에게도 같은 날짜 규칙이 적용된다.
- **재직·휴무·미배정을 구분한다.** 한 사원은 같은 날짜에 유효한 근무조 또는 기존 고정배정을 최대 하나 갖는다. 배정은 입사일과 마지막 재직일 안에서 가능하다. 휴무일은 ‘비근로일’, 배정이 없으면 ‘근무 미배정’으로 표시한다. 요일 편성은 회사 휴일 캘린더와 함께 판정한다.

## 4. 기존 자료, 서버 계약과 권한

| 대상 | 계약 |
| --- | --- |
| 기존 고정 일정 | 기존 템플릿 코드·불변 주간 버전·사원별 명시 배정·최초 발령의 참조 ID는 보존한다. 기존 사원은 ‘기존 고정배정’으로 조회한다. 담당자가 전환일과 대상 사원을 확인해 근무조에 배정하면 그날부터 자동 개정 대상이 된다. 같은 템플릿의 서로 다른 버전을 쓰던 사원을 임의로 한 조에 편입하지 않는다. |
| 저장 모델 | 근무시간코드 마스터와 불변 버전(정규·휴게·연장 구간), 근무조 마스터와 불변 주간 개정, 사원의 기간별 근무조 배정을 구분한다. 월~일 일곱 요일을 한 번씩 지정하고 최소 한 근로일을 편성한다. 근로일에는 시간코드 버전 한 개, 비근로일에는 시각 없는 비근로 표시를 저장한다. 표시명·코드가 같은 경우에도 연결하는 값은 해당 고객사의 ID와 버전이다. |
| 일정 해석 | 새 근무조 개정도 기존 주간 일정 버전으로 표현해 실제 근무일의 일정 버전 ID를 제공한다. 조회는 사원·근무일로 한 번 해석하고 휴가·출퇴근·정정·집계·직원 캘린더·최초 발령에서 같은 결과를 쓴다. 기존 배정과 새 배정을 함께 읽을 때 기간 중복을 저장 단계에서 막는다. 화면을 열거나 날짜가 넘어갈 때마다 사원별로 재저장하지 않는다. |
| 업무 이력 | 이미 확정한 근무 결과·승인 휴가·차감 원장·정정 원천은 개정 저장으로 덮어쓰지 않는다. 새 적용 구간에서 일정에 의존한 결과가 오래됐으면 재확인 대상으로 표시한다. 대기 중인 휴가는 최종 승인 직전 대상일의 일정·캘린더·차감량을 다시 검증하고 근거가 달라졌으면 기존 절차대로 철회·재신청을 안내한다. 승인된 미래 휴가의 근로일·소정 기준에 차이가 생기면 담당자가 원신청과 변경 일정을 대조할 수 있게 표시한다. |
| 화면·명령 | 기존 `/admin/schedules`와 사원별 배정 이력 주소에서 새 설정 또는 과거 이력으로 접근한다. 저장 입력에는 조·코드·버전, 대상 사원, 적용일, 사유, 기대 버전, 명령 ID를 포함한다. 조회·미리보기는 읽기 전용이다. 일괄 배정은 변경 전후를 확인한 명단만 한 번에 저장하며 한 명이라도 충돌하면 오류 사원·원인을 보여 주고 전체를 되돌린다. 같은 명령을 재전송해도 배정·감사는 한 번만 남는다. |
| 접근 | 담당자는 자기 고객사의 설정·배정·이력을 관리한다. 직원은 본인의 근무조·대상일 시간표·예정 휴게·연장 허용 기준을 조회한다. 서버에서 현재 권한을 재검증하고 모든 참조·조회·저장에 고객사 조건과 RLS를 적용한다. 코드·조 개정·사원 배정·기존 배정 전환마다 누가 언제 무엇을 바꿨는지 기록한다. |

## 5. 구현 시 확인할 수용 사례

| 사례 | 기대 결과 |
| --- | --- |
| 담당자의 처음 설정 | PC·모바일에서 W01을 등록하고 복수 휴게를 입력한 뒤 G01의 평일에 연결한다. 저장·재조회 결과에서 소정시간, 연장 허용시간, 예정 휴게가 일치한다. 휴게 중첩·정규와 겹치는 연장·자정 통과 입력은 원인을 표시한다. |
| 배정 및 직원 조회 | 담당자가 사번으로 직원을 찾아 적용일을 예약한다. 직원 캘린더의 적용 전날과 첫날, 담당자 조회 화면, 최초 발령에서 같은 근무일의 소속 조·코드·시간이 일치한다. 미배정·휴무·회사 휴일이 서로 구별된다. |
| 자동 적용과 예약 보존 | G01 개정 한 번으로 잔류 사원 전원이 09시에서 10시로 바뀐다. 같은 날 전출할 사원과 G01 개정 전날의 일정은 그대로이고, 이후 전입자는 전입 당일의 최신 유효 개정을 받는다. 12월 31일·1월 1일 경계에도 같은 규칙을 적용한다. |
| 코드 재사용 | G01·G02가 같은 W01 버전을 사용하다 G01만 새 버전을 채택하면 G01 소속에만 자동 반영된다. 두 조의 과거 근무일은 각 날짜의 기존 버전으로 재조회된다. |
| 연장 기준과 실제 시간 | 18:30~21:00 허용·15분 예정 휴게 예시는 최대 2시간 15분이다. 18:15 퇴근한 원천 기록은 유지되고 자동 연장 승인·휴게 공제는 없다. 실제 휴게 미확인은 확인 필요 상태로 남는다. |
| 기존 자료·권한·경합 | 기존 배정 전환 전후의 원천·발령·승인·원장과 과거 일정이 보존된다. 다른 고객사 사원 배정, 일반 직원의 설정 변경, 중복·동시 배정, 당일 근무 개시 후 변경, 예약 충돌을 막는다. 반복 저장 시 이력이 한 건이다. |

구현 순서는 **① 근무시간코드와 휴게·연장 기준 → ② 근무조 요일 편성·개정 전후 미리보기 → ③ 사원별 적용일 배정과 기존 배정 전환 → ④ 직원·담당자 화면 및 계산 소비처 통합 검증**이다.

기존 규칙은 [고정 근무와 적용일 배정](../../design/fixed-schedule.md), [출퇴근·근로 확인](../../design/attendance-recording.md), [근로시간 계산](../../design/worktime-engine.md), [휴가 신청과 최종 승인](../../design/leave-workflow.md)을 따른다.
