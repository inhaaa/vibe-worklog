# 월말 퇴근 누락 보완 요청

담당자는 [월말 확인 대상](2026-11-18-month-end-review.md)에서 사원·근무일을 골라 보완을 요청한다. 직원은 홈이나 **내 업무 > 근태관리 > 내 근태 보완 요청**에서 담당자가 적은 사유와 날짜를 확인하고 그날의 기존 [출퇴근 정정](2026-11-18-checkout-correction-operations-design.md)을 제출한다. 결재자는 신청서에 정해진 순서로 처리한다.

| 시점 | 담당자와 직원이 보는 상태 | 다음 행동 |
| --- | --- | --- |
| 담당자가 사유를 입력하고 저장 | 직원 확인 대기 | 직원이 해당일의 실제 퇴근과 근무·휴게 근거를 입력 |
| 정정 제출·중간 승인 | 정정 결재 대기 | 현재 순번 결재자가 신청 상세에서 처리 |
| 반려·철회 후에도 누락 | 직원 확인 대기 | 직원이 사유를 확인하고 다시 신청 |
| 최종 승인으로 퇴근이 유효해졌지만 실제 근무·휴게 미확인 | 근무 확인 필요 | 직원이 해당 날짜에서 근무를 확인하거나 정정 |
| 잘못 찍힌 출근을 정정해 유효 기록이 없어지고, 승인 종일휴가 또는 확정 휴무의 근거가 갖춰짐 | 재집계 대기 | 담당자가 해당일을 재집계해 실근로 0시간을 확인 |
| 유효 퇴근과 근무·휴게 근거 확보 | 재집계 대기 | 담당자가 월말 행에서 해당일과 주를 재집계 |
| 최신 일 결과에서 근무시간 확정 | 해소 | 직원의 미해소 목록과 해당일 월말 예외 목록에서 제외. 해소 시각·결과 식별자로 추적 |

## 대상과 권한

서울 기준 어제까지의 재직일 중 소정근로일과 회사 캘린더가 근무일로 일치하고, 원천·유효 기록이 해당일 출근 1건뿐인 날짜가 대상이다. 승인 종일 휴가, 기신청 대기 정정, 같은 사원·날짜의 진행 중 요청은 새 요청 대상에서 제외한다. 등록 시 현재 근거를 다시 확인한다. 동일 명령 재전송은 같은 요청을 반환하고 동시 요청도 활성 건 한 개만 남긴다. 해소 뒤 새로 발생한 누락에는 새 요청을 남길 수 있다.

담당자는 자기 회사 안에서 요청을 작성한다. 사유는 1~500자로 입력한다. 직원은 본인의 미해소 요청과 담당자 사유를 홈과 페이지 단위 전체 목록에서 확인한다. 관련 정정은 고객사·사원·근무일이 모두 일치해야 한다. 새 정정이 결재 대기 중이면 최근 신청 상세를 연다. 이전에 승인된 정정을 바꾸려는 신청이 반려·철회되면 근무 확인·재집계 화면에서는 실제 적용되는 승인 건을 연다. 해소 기록은 그 승인 건과 일 결과를 함께 가리키며, 반려·철회한 대체 정정은 신청 이력에서 조회한다. 보완 요청은 앱 안에서 전달하고 원천 출퇴근, 실제 근무 확인과 결재의 권한 경계를 유지한다. 최종 승인 후에도 다른 근거가 부족한 날은 계속 점검할 수 있다. 출근 기록을 잘못 찍은 사원은 정정에서 그 기록의 효력을 해제할 수 있다. 최종 승인으로 유효 기록이 없어졌을 때는 기존 근태 계산 기준으로 종일휴가·휴무가 확인되어 실제 0시간이 확정된 경우에 해소한다. 근무일에 반차만 사용했거나 근거가 부족하면 담당자와 직원의 점검 대상으로 남는다.

## 데이터와 인터페이스

- V29에 요청 ID, 테넌트, 사원, 근무일, 담당자, 사유, 작성 시각, 해소 시각·일 결과 참조를 둔다. 테넌트 키·RLS와 활성 사원일의 유일성을 적용한다. 해소는 해당일 재집계와 함께 저장한다. 승인에 실제 근무·휴게 확인이 빠진 경우에는 직원이 근무를 확인한 뒤 기존 자동 재집계가 최신 일 결과를 만들 때도 같은 기준을 적용한다.
- 담당자의 `POST /admin/attendance/follow-ups`는 `employeeId`, `workDate`, `reason`, `commandId`를 받으며 성공 시 `id`를 반환한다. 현재 권한과 CSRF를 확인한다. 월말 조회는 행에 `checkoutFollowUpEligible`과 해당 활성 요청을 제공한다.
- `GET /me/home`에는 최근 미해소 요청 3건까지, `GET /me/attendance/follow-ups?page=0`에는 한 페이지 20건과 다음 페이지 유무를 제공한다. 사원 식별자는 로그인 정보에서 결정한다.
- 요청 요약은 `id`, `workDate`, `reason`, `status`, `approvalRequestId`, `resultId`를 제공한다. 상태는 직원 확인 대기(REQUESTED), 결재 대기(PENDING_APPROVAL), 근무 확인 필요(NEEDS_CONFIRMATION), 재집계 대기(AWAITING_CALCULATION), 해소(RESOLVED)로 구분한다.

이번 개발 단위는 퇴근 누락 한 건을 발견해 해소하는 흐름이다. 여러 대상의 일괄 재집계와 월 마감·재개는 이어지는 업무 단위다.
