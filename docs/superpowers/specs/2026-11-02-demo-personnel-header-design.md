# 데모 인사정보·탭 없는 사원 헤더·업무 메뉴 표시

기준일: 2026-11-02, Asia/Seoul. 사용자가 데모 사원들의 인사정보/사진 등록, 헤더 탭 제거와 한눈에 보이는 인사정보, 메뉴 디자인 보완을 요청했다. 이전 [인사정보 계약](../../design/personnel-workspace.md)의 헤더 아래 탭 결정을 이번 요청으로 대체한다. 새 업무 기능·스키마·근태/인증 정책을 추가하지 않는다.

## 화면 계약

- `EmployeeHeaderData`와 서버의 본인/관리자 선택 대상·사진 인증 조회 계약은 유지한다. 헤더는 사진, 회사/이름/조직/사번, 재직 상태, 생년월일·직급·직책·직무·입사일을 하나의 카드에 모두 표시한다. 비어 있는 값과 이미지 오류의 이니셜 fallback은 유지한다.
- `EmployeeHeader`는 `employee`만 받는 표시 컴포넌트로 단순화한다. `EmployeeWorkTabs` 및 App의 헤더 탭 주입을 제거한다. 개인 업무는 기존 업무 메뉴, 선택 사원의 인사/소속/근무/계정 진입은 사원 시트의 기존 링크를 사용한다. 헤더에서 다른 화면을 여는 탭이나 숨겨진 정보 패널은 제공하지 않는다.
- PC에서는 사진/신원과 인사 필드를 나란히 배치하고, 좁은 화면에서는 필드가 카드 안에서 자연스럽게 줄바꿈한다. 모바일의 탭 가로 스크롤을 없앤다. 긴 이름/직무·필드 누락·재직/휴직/정직·사진 실패를 읽을 수 있어야 한다.
- 업무 메뉴의 5대표·업무 묶음·26링크, 역할 필터·상세 문맥·조상 펼침은 유지한다. 대표별 stroke SVG, 일관된 chevron, 활성 조상과 선택 링크의 인디고 강조·여백·구분선을 적용한다. 새 아이콘 라이브러리는 넣지 않는다. 모바일44px과 기존 상단 말줄임/로그아웃 줄바꿈 방지를 유지한다.

## 가상 자료와 유지보수 계약

대상은 기존 공개 데모의 정확한 tenant와 사번 `LOCAL-DEMO`, `DEMO-001`~`DEMO-003` 4명으로 고정한다. 기존 이름·조직·입퇴사일·employee 버전/active·계정/auth_version·역할·근무·연차·기존 업무 행을 수정하지 않는다.

| 사번 | 가상 생년월일 | 직급 | 직책 | 직무 | 표시 상태 |
| --- | --- | --- | --- | --- | --- |
| LOCAL-DEMO | 1988-07-14 | 책임 | 운영팀장 | 인사 운영 | 재직 |
| DEMO-001 | 1992-03-11 | 선임 | 팀원 | 서비스 기획 | 재직 |
| DEMO-002 | 1986-09-22 | 수석 | 개발팀장 | 소프트웨어 개발 | 휴직 |
| DEMO-003 | 1996-12-05 | 사원 | 팀원 | 품질 관리 | 정직 |

사진은 built-in 이미지 생성 도구로 만든 가상 성인4명의 독립 사진이다. 실제 사원·유명인·외부 사진을 사용하지 않는다. 자산과 프롬프트는 `demo/personnel-20261102/`에 보존하고 실제 업로드와 같은 `EmployeePhoto.decode`의 크기/형식/디코딩/재인코딩을 거친다. `manifest.json`은 날짜·고정4인·버전0·고정 상대 사진 경로·원본/정규화 SHA를 명시한다.

공유 계정의 인사 수정 API 보호는 유지한다. 이 보호를 끄거나 bootstrap/sample-data를 재실행하지 않는다. 명시적으로 실행하는 유지보수 CLI만 기존 `tna_app` 권한/RLS와 tenant 독점 잠금에서 위4명의 인사4건·상태4건·감사4건/단위marker1건을 한 트랜잭션으로 추가한다. 새 테이블·DB 역할·포트·웹 엔드포인트는 없다. 정확한 기존 신원·관리자/권한·빈 인사 버전/이력을 먼저 대조하고, 하나라도 다르면 전부 거부한다. 재실행은 marker와 저장 결과가 모두 같을 때만 no-op이다. 사진이나 생년월일은 감사 요약에 넣지 않는다.

## 검증·공개 반영

탭이 남아 있으면 실패하는 App 회귀와 메뉴의 활성 조상 회귀부터 확인한다. CLI는 전용 합성 PostgreSQL에서 원자성·재실행·충돌·고정 대상/역할/DB 거부·사진 검증·기존 자료 및 다른 tenant 보존을 테스트한다. 기존 공유 계정 API403과 권한/RLS를 유지한다. 최종 프론트 전체·타입/빌드와 관련 Java/전체 회귀를 실행한다.

공개는 승인된 `/srv/worklog` 범위에서 소스/이미지를 고정하고 기존 서비스 상태·V16 권한/자료를 기록한다. 전용 백업과 복원 검증 후 단발 등록의 예상 추가 행만 대조한다. 기존 자료를 덮거나 인증 보호를 완화하지 않는다. 최종 공개 HTTP·사진4개·등록된 헤더/무탭·업무 메뉴를 PC/390px로 확인한다. 실제 결과와 미실시는 별도 품질 보고서에 기록한다.
