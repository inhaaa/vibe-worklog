# 조직코드 자동 발급과 조직도 조직장 관리

2026-11-17 설계안. 담당자가 조직을 추가할 때 코드를 자동으로 받고, 조직도에서 선택한 조직의 조직장 배정·변경·종료를 처리한다. [조직·사원 계약](../../design/org-management.md) · [업무별 메뉴](2026-11-17-attendance-history-navigation-design.md)

## 조직 생성과 기존 코드

1. 담당자가 **조직관리 > 조직 관리**에서 단건 등록을 열거나 시트에 행을 추가한다. 조직명·상위 조직 등 기존 항목을 입력한다. 코드 칸은 읽기 전용으로 **저장 시 자동 발급**을 표시한다.
2. 서버가 등록을 저장할 때 `YYYYNNNN` 형식의 8자리 문자열을 발급한다. 앞 4자리는 서울 기준 시스템 생성 연도, 뒤 4자리는 고객사·연도별 `0001`~`9999` 연번이다. 같은 서버 시각으로 생성 날짜와 코드 연도를 기록한다. 상위 조직을 옮기거나 이름을 바꾸면 기존 코드로 표시한다.
3. 성공하면 실제 코드와 조직 상세 링크를 표시한다. 현재 필터나 페이지에 새 조직이 없어도 발급 결과에서 확인할 수 있다. 일괄 저장은 제출 행 순으로 신규 코드를 부여한다. 오류 시 시트 입력을 보존하고 실패한 행이나 공통 사유를 표시한다. 해당 연도에 발급할 번호가 없으면 고객사·연도를 안내하고 요청 전체를 되돌린다.

**기존 코드는 원문 그대로 유지한다.** 예를 들어 `ROOT`, `OPS01`, `20260001`은 기존 코드로 검색·조회하고 조직명 변경이나 비활성화를 할 수 있다. 비활성 조직도 발급 번호를 계속 점유한다. 같은 고객사에 `20260001`과 `20269999`가 있으면 2026년 신규 발급은 `20260002`다. 기존 공개 데모의 가상 조직코드도 같은 정책을 따른다.

조직 계층, 사원 소속, 조직장 배정, 결재선과 최초 발령 참조는 기존 고객사별 조직 UUID로 연결한다. 기존 보고서와 Excel은 저장된 코드를 문자열로 표시한다. 최초 발령 확정 시 저장한 조직코드·이름, 결재 스냅샷과 감사의 과거 값은 당시 기록을 보존한다. [입사·최초 발령 계약](2026-11-17-personnel-onboarding-design.md)

### 코드 발급 계약

- 단건 `POST /admin/organizations`와 시트 `POST /admin/organizations/bulk`의 신규 등록이 같은 규칙을 사용한다. 신규 요청의 코드는 생략하거나 비워 보낸다. 신규 등록에 임의 코드가 들어오면 422와 화면 갱신 안내를 반환한다. 기존 행의 수정·비활성화는 저장된 코드에 적용한다. 기존 클라이언트가 코드를 함께 보내면 저장된 값과 일치해야 한다.
- 기존 고객사 쓰기 잠금 아래에서 권한과 명령 재시도를 먼저 확인한다. 신규 명령이면 서버 생성 시각을 한 번 정한다. 해당 고객사·연도의 형식과 정확히 일치하는 기존 코드, 같은 배치에서 이미 배정한 코드를 건너뛰어 가장 낮은 미사용 연번을 발급한다. 기존 테이블의 고객사·코드 유일성과 코드 수정 금지 권한을 재사용한다. 생성·유일성 검증·감사는 같은 트랜잭션으로 처리한다.
- 이미 성공한 동일 명령은 최초 조직 ID와 코드를 반환한다. 전환 전에 수동 코드로 성공한 요청도 같은 입력과 식별자로 재전송하면 원래 결과를 받는다. 시트 응답은 신규 행 식별자와 조직 ID·실제 코드를 연결한다. 저장하기 전 임시 행은 번호를 점유하지 않는다.

## 조직도에서 조직장 관리

담당자가 **조직관리 > 조직도**에서 조직을 선택하면 조직 이름·코드, 오늘의 조직장과 담당 기간, 다음 예약을 확인할 수 있다. 선택 조직의 예약·배정 이력을 날짜순으로 열 수 있고 기존 소속 직원 조회도 이용할 수 있다. 모바일에서는 선택한 조직의 배정 영역과 직원 목록을 순서대로 표시한다.

| 담당자 동작 | 입력과 저장 결과 |
| --- | --- |
| **배정** | 공석 구간에서 사번·이름으로 사원을 찾아 시작일, **종료일(마지막 담당일)**, 사유를 입력한다. 하루 배정은 시작일과 종료일이 같다. |
| **후임 변경** | 전임 배정을 선택하고 후임·시작일·종료일·사유를 입력한다. 미리보기에서 전임의 마지막 담당일을 확인하고 전임 종료와 후임 배정을 함께 저장한다. |
| **종료일 변경** | 현재 배정의 조직장과 시작일을 유지하고 마지막 담당일을 지정하거나 조정한다. 즉시 공석이 필요하면 **오늘부터 미배정**을 선택한다. |
| **예약 수정·취소** | 아직 시작하지 않은 배정의 사원·기간을 바꾸거나 예약을 취소한다. 원래 예약은 변경 이력에 남기고 생기는 공석을 미리보기에서 알려준다. |

저장 전에는 선택 조직, 변경 전후 담당자와 날짜, 다음 예약, 새 공석을 보여준다. 12월 1일부터 후임이 맡으면 전임은 11월 30일까지로 표시한다. 12월 4일에 다음 예약이 있고 12월 1~3일이 공석이면 두 기간을 함께 보여준다. 저장 후 같은 조직에서 **현재 배정**, **예정**, **종료**, **변경·취소 이력**을 확인할 수 있다. 오늘의 유효 배정이 없으면 **미배정**, 기록된 조직장이 퇴사·비활성 상태가 되면 **재지정 필요**로 표시한다.

### 적용일과 충돌

- 화면의 시작일·종료일은 모두 포함한다. V12의 내부 저장 기간 `[valid_from, valid_to)`를 사용하며, 마지막 담당일의 다음 날을 `valid_to`로 저장한다. 기존 유한 기간은 저장된 종료 경계의 전날을 종료일로 보여준다. 제한 없는 배정은 `valid_to = null`이다.
- 신규·후임·예약 수정의 시작일은 서울 기준 오늘 이후다. 종료일 공란은 무기한을 뜻한다. 다음 예약 전날, 후임 변경 대상 구간의 기존 마지막 날, 후보의 마지막 재직일 중 해당하는 제한이 있으면 가장 이른 종료일을 미리보기에서 제시하고 담당자의 저장 확인을 받는다. 담당자가 지정한 기간이 그 제한을 넘거나 이미 유효한 배정과 겹치면 충돌 날짜를 안내하고 422를 반환한다. 한 조직에 같은 날 유효한 배정은 한 건이다.
- 일반 교체는 전임의 종료 경계를 후임 시작일에 맞춘다. 같은 시작일의 교체는 전임을 대체 이력으로 남긴다. 예를 들어 전임이 11월 30일까지이고 다음 예약이 12월 4일이면, 11월 20일 후임 변경은 12월 1~3일의 공석과 다음 예약을 보존한다. 예약 취소나 후임의 단기 배정 종료로 생긴 공석에는 담당자가 별도 배정할 수 있다.
- 지난 날짜의 담당자와 종료된 기간은 조회할 수 있다. 현재 배정의 종료일은 오늘 이후의 마지막 담당일을 받는다. **오늘부터 미배정**은 종료 경계를 오늘로 저장한다. 오늘 시작한 행에는 대체 이력을 남긴다. 종료일을 연장할 때는 다음 배정과 재직 기간을 다시 확인한다. 비활성 조직에서는 기존 이력과 종료·예약 취소만 제공한다.
- 조직장은 같은 고객사의 활성 사원이고 현재와 배정 시작일에 재직 중이어야 한다. 알려진 마지막 재직일 안에서 배정한다. 겸직을 허용하고 계정·결재 자격을 별도 표시한다. 배정 후 사원의 재직 상태가 바뀌면 이력을 보존하고 조회 기준일의 적격성을 다시 평가한다.

### 화면과 서버 계약

| 경로 | 처리 |
| --- | --- |
| `GET /company/organizations?organizationId=…` | 기존 조직도와 선택 조직을 보여준다. 담당자에게 조직장 관리 버튼을 표시한다. |
| `GET /admin/organization-heads?organizationId=…` | 담당자에게 선택 조직의 이력과 후보 조회를 제공한다. 조직도에서 관리 영역을 열 때 사용하며 기존 링크의 선택 조직을 유지한다. |
| `POST /admin/organization-heads/commands` | 명령 종류, 조직 ID, 해당 시 대상 배정 ID와 사원 ID, 시작일·마지막 담당일 또는 즉시 종료 선택, 사유, 조직 버전, 명령 식별자를 받는다. 기존 배정·종료 POST는 공통 쓰기 로직으로 연결한다. 기존 종료 요청의 적용일은 그날부터 미배정이라는 의미를 유지한다. |

대표는 기존 조직도 조회 권한을 유지한다. 후보·사유·입력 모델은 담당자 권한을 확인한 뒤 반환한다. 직원은 본인 프로필의 기존 조직장 조회 범위를 사용한다. 쓰기에서 현재 권한·고객사와 CSRF를 확인한다. 다른 고객사의 조직·사원·배정 ID는 오류에서도 존재가 노출되지 않게 처리한다.

저장은 기존 고객사 쓰기 잠금, 조직의 집계 버전, 대상 배정 확인과 V12 기간 중첩 제약을 사용한다. 변경과 전후 감사는 한 트랜잭션으로 처리하고 최초 배정 사유와 종료·변경의 사유를 구분한다. 최신 버전 충돌은 409로 알리고 작성값을 보존해 최신 현황과 비교하게 한다. 동일 명령 재전송은 최초 결과를 반환한다. 저장 성공·실패 모두 선택 조직과 직원 조회 문맥을 유지한다.

### 결재 연계

조직장 배정과 관리·결재 권한 부여는 별도다. 기존 결재선이 **신청 대상자의 소속 조직장**을 사용하면 신규 신청을 제출한 서울 날짜에 유효한 조직장을 해석한다. 공석·부적격은 기존 결재선 규칙에 따라 안내한다. 기존 대기·완료 신청의 결재자와 스냅샷은 보존하고, 대기 건 재할당은 기존 명시 절차를 사용한다. 다단계 결재선과 상위 조직 자동 탐색은 후속 범위다. [조직장 결재 계약](../../design/approval-routes.md)

| 사용 흐름 | 확인할 결과 |
| --- | --- |
| 조직 단건·시트 동시 등록 | 코드 중복 없음, 행별 코드와 조직 링크 노출, 같은 요청 재시도 무중복, 실패 배치의 등록·감사 전체 롤백. |
| 같은 고객사에 기존 코드와 비활성 코드가 있음 | 기존 코드 검색, 조직명 수정·비활성화 가능. 원래 코드·UUID·최초 발령 스냅샷·Excel 값 유지. 신규 코드는 점유된 번호를 건너뜀. |
| 서울 연말·연초 등록 | 생성일과 코드 연도가 일치함. 연도·고객사별 연번 독립, 지난 연도 성공 명령의 재시도 결과 유지. |
| 조직도에서 신규·후임·종료·예약 취소 | 하루 배정, 11월 30일까지 전임·12월 1일부터 후임, 오늘부터 공석, 다음 예약과 변경 이력 표시. |
| 날짜·동시 변경·접근 권한 경계 | 기간 중첩·과거 변경·재직 범위 초과 거부. 버전 충돌 시 입력과 선택 조직 보존. 대표·직원·다른 고객사의 변경과 CSRF 없는 요청 차단. |
| 조직장 변경 전후 신청 | 변경 당시 기존 대기·완료 신청 스냅샷 보존. 적용일에 새로 제출하면 그날의 적격 조직장을 사용함. |
