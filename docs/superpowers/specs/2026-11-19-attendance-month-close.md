# 회사 근태 월 마감과 재개

근태 담당자는 회사 근무현황의 월말 확인 대상에서 한 달의 입력과 계산을 점검한 뒤 회사 전체의 근태를 마감한다. 승인된 근태를 바꾸려면 담당자가 재개 사유를 남기고 업무를 처리한 뒤 다시 점검해 마감한다. 업무 기준 시간대는 Asia/Seoul이다. 급여 연계와 급여 정산은 별도 업무다.

## 담당자 흐름

1. 조회한 달의 상태와 처리 이력을 본다. 기존 회사에는 별도 이관 없이 마감 전, 버전 0을 적용한다. 마감은 서울 기준 해당 월이 끝난 뒤부터 가능하다.
2. 회사 전체 마감 점검을 실행한다. 해당 월에 하루 이상 재직한 사원 수, 확인이 필요한 사원·날짜 수, 미산정·재집계 필요·근무 확인 필요·정정 대기 건수, 월과 겹치는 대기 신청 수, 미해소 보완 요청 수를 제공한다. 한 사원·날짜에 사유가 여럿일 수 있으며 대기 신청 수에는 휴가·취소·정정·연장 신청이 포함된다. 신청 후 대상자가 퇴사한 경우에도 현재 지정된 독립 결재자는 사유를 남겨 반려할 수 있다. 기존 자료의 보완 요청일이 재직기간 밖이면 점검에서 첫 해당 사번과 날짜를 안내한다. 담당자가 인사정보와 원천 기록을 대조하고, 실제 미해소 요청이 있으면 계속 마감을 보류한다. 조직·검색·사유·페이지는 목록 조회 조건으로만 사용한다.
3. 재직 사원이 있고 확인할 날짜·대기 신청·미해소 보완이 모두 0이면 마감 사유를 한 줄로 입력하고 확정한다. 서버는 저장 직전에 전체 조건을 다시 검사한다. 아직 남은 건이 있으면 조회·보완·결재·재집계 후 다시 점검한다.
4. 마감 완료 후에도 조회·일 결과 상세와 기존 이력을 열 수 있다. 해당 월의 출퇴근 정정·휴가와 취소·연장 신청, 근무 확인, 보완 요청과 결과 재집계는 마감 해제 후 처리한다. 열린 달의 일 계산이 주 경계 때문에 마감 날짜에 걸치면 열린 날짜만 새로 저장한다. 월 경계를 걸친 주 합계에는 양쪽 달의 실적을 함께 표시한다.
5. 마감 월을 수정할 때는 재개 사유를 입력한다. 재개와 재마감은 각각 새 이력으로 남는다. 최근 이력 20건에서 처리 당시 담당자·서울 시각·사유를 확인한다. 마감·재개 후 같은 조회 조건과 페이지의 목록을 다시 읽는다.

## 날짜와 기존 근거

- 원천 출퇴근 기록, 승인 이력, 이미 저장된 일 결과를 보존한다. 서울 당일의 출퇴근은 계속 기록한다. 기간 신청에 마감월이 포함되면 부분 저장하지 않는다.
- 마감한 날짜에 적용되는 휴일 캘린더·근로 적용 검토·주 기산점 정책, 사원 등록·수정으로 해당 월 재직일이 달라지는 변경은 재개 후 처리한다. 입사 예정자 등록과 최초 발령에는 기존의 서울 당일 이후 입사일 기준을 적용한다. 사원 이름·연락처 편집, 마감한 달의 재직일에 영향이 없는 이후 입퇴사 처리는 가능하다. 진행 중인 보완 요청일을 재직기간 밖으로 밀어내는 소급 입퇴사일 변경은 단건과 일괄관리에서 모두 차단한다. 과거 근무조·근무시간은 기존 유효일·버전 정책을 적용한다.
- 마감 시점에 최신이던 일 결과는 이후 달의 퇴직일 등록 등으로 마감월에서 재집계 대상으로 되돌아가지 않는다. 정상 휴무·승인 종일휴가로 근거가 갖춰진 무근무일의 0시간과 실근로 미확정을 구분한다. 과거 결과 상세는 계산 당시의 근거를 유지한다.

## 저장과 HTTP

테넌트별 `attendance_month_closure`에 월초 날짜·버전·상태·처리자 계정과 당시 이름·처리 시각·사유를 추가한다. 마감 시 CLOSED, 재개 시 OPEN을 기록한다. 회사·월·버전은 고유하다. 테넌트 조건과 PostgreSQL RLS를 함께 사용한다.

| 경로 | 업무 계약 |
| --- | --- |
| `GET /admin/attendance/month-close?month=YYYY-MM` | 상태·버전·지난 달 여부와 최신 처리 이력을 조회한다. |
| `POST /admin/attendance/month-close/check` | `month`로 전체 회사의 마감 조건과 사유별 건수를 읽는다. |
| `POST /admin/attendance/month-close` | `month, action, expectedVersion, reason, commandId`로 마감·재개한다. 최초 처리 결과에 월·버전·상태·처리 시각·처리자·사유를 담는다. |

담당자와 기본 사원 자격을 읽기·쓰기·재전송 때 확인한다. 두 POST는 CSRF를 검증한다. 변경 명령은 기존 테넌트 독점 잠금 안에서 현재 버전·상태와 마감 조건을 검사한다. 동일 명령과 내용의 재전송은 최초 결과를 반환한다. 오래된 버전, 다른 내용의 명령 재사용 및 마감과 충돌하는 쓰기는 409로 안내한다. 새로 점검·저장하는 동안 이전 월의 늦은 응답을 표시하지 않는다.
