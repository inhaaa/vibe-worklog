## 2. 제품 목표와 검증할 문제

### 제품 정의와 대상

국내 중소기업을 대상으로 직원의 출퇴근·신청과 관리자의 승인·집계를 연결하는 웹 기반 멀티테넌트 SaaS를 지향한다.

- 주요 고객: 상시근로자 10~300명 사업장
- 서비스 지원 최소 규모: 5인 이상 사업장. 개별 법령의 적용 여부와는 별도로 판단한다.
- MVP 검토 대상: 고정된 근무 요일·시간을 운영하고 단순한 승인 흐름으로 핵심 업무를 검증할 수 있는 사업장
- 운영 방향: 동일 애플리케이션과 공유 DB, 고객사별 설정, 고객별 별도 코드 개발 지양
- 이용 환경: PC·모바일 반응형 웹. PWA의 세부 범위는 미정

파일럿 고객이나 특정 업종은 아직 선정하지 않았다. 다음은 고객 조사로 확인할 **문제 가설**이며 시장 조사 결과가 아니다.

| 문제 가설 | 제안하는 제품 가치 | 검증 방법 |
| --- | --- | --- |
| 출퇴근·신청·승인 정보가 분리되면 확인과 대조가 반복될 수 있음 | 원천 기록과 신청·승인·결과의 연결 | 고객 인터뷰와 실제 업무 흐름 비교 |
| 누락·정정·잔여 휴가를 확인할 때 담당자 문의가 반복될 수 있음 | 본인 조회와 처리 상태의 가시성 | 파일럿에서 문의·수작업 대조 사례 수집 |
| 집계 결과의 변경 근거를 추적하기 어려울 수 있음 | 적용 정책과 정정·승인 이력 추적 | 담당자가 결과에서 근거까지 확인하는 사용성 검증 |

경쟁 서비스 조사, 고객 인터뷰와 차별점 검증은 아직 수행하지 않았다. 특정 서비스보다 우수하거나 업무 시간이 일정 비율 줄어든다고 주장하지 않는다.

### 목표와 비목표

- 목표: 직원의 기록·신청부터 승인·확인·집계까지 하나의 흐름을 검증한다.
- 목표: 계산 근거, 미처리 항목과 오류 가능성을 사용자에게 드러낸다.
- 목표: 테넌트 격리와 최소 권한, 원천 기록 보존을 제품의 기본 조건으로 유지한다.
- 비목표: 모든 근무제·법정 휴가·사업장 예외를 한 번에 자동화하거나 급여 계산 시스템을 완성하는 것.
- 비목표: 법률 적합성을 자동 보증하거나 미확정 집계를 급여 확정 자료로 제공하는 것.

AI는 개발을 지원하는 도구이며 제품 내 AI 기능은 이번 범위에 제안하지 않는다.

## 3. MVP 대안과 권장안

아래 모든 대안에서 인증·권한, 테넌트 격리, 원천·정정·감사 이력과 계산 검증은 공통 필수 조건이다.

| 대안 | 범위 | 장점 | 제약·부담 |
| --- | --- | --- | --- |
| A. 핵심 업무 연결 — 권장 | 고정 근무, 출퇴근, 종일 연차·정정 신청, 단일 단계 승인, 휴가 잔여 이력, 일·주·월 현황 | kickoff의 핵심 흐름을 검증하면서 지원 규칙을 좁힐 수 있음 | 반차·추가 근무·마감 등 실제 고객의 필요 범위를 따로 확인해야 함 |
| B. 출퇴근 기록 우선 | 고정 근무, 출퇴근·정정과 내역 조회부터 검증 | 초기 기능과 계산 범위를 더 줄일 수 있음 | 휴가·승인·관리자 집계의 연결 가치를 충분히 검증하기 어려움 |
| C. 운영 업무 확대 | A에 반차·추가 근무 신청·Excel 출력·월 마감·연차 자동 발생 등을 추가 | 더 넓은 관리 업무를 검증할 수 있음 | 법령·상태 전이·정산·동시성 관련 선결정과 검증 부담 증가 |

**A안을 MVP의 검토 기준으로 제안한다.** 필요성이 확인된 조건부 후보만 추가하여 범위 확대를 통제한다. 채택 대안과 MVP/v1의 관계는 `D01`에서 결정하며 현재는 미정이다.

### 고정 근무의 제안 경계

- 기본안은 같은 날 시작·종료하는 고정 근무와 하루 하나의 근무 구간을 우선 검토한다. 모든 직원에게 같은 요일·시각을 강제하지 않는다.
- 사원별 적용 일정, 근무 요일, 시작·종료 시각, 휴게 구간, 휴일과 적용일을 식별할 수 있어야 한다.
- 구체적인 시각·근로시간·휴게 길이·반올림 단위는 정하지 않는다. 정책 근거와 법령 검증 후 명세한다.
- 소정 일정과 실제 근로 판단 자료를 구분한다. 체류시간 전체를 실근로시간으로 자동 간주하거나 예정 휴게를 실제 확인 없이 무조건 공제하는 정책은 확정하지 않는다.
- 자정 통과·야간·휴일·일정 외 기록은 예외 식별 대상으로 제안한다. 미지원이라는 이유로 기록을 버리거나 자정에 자동 퇴근시키지 않는다.
- 시차출퇴근, 선택적·탄력적 근로시간제, 교대, 간주·재량근로는 후속 검토 후보로 둔다. 기존 제품 후보 목록은 유지한다.

정식 지원 근무제와 위 경계의 채택은 `D01`·`D02`에서 결정한다. 주간·월간의 기간 경계와 근무일 귀속도 아직 미정이다.

## 4. 사용자 역할과 권한 제안

역할의 이름은 kickoff를 따르며 다음 책임·권한 범위는 검토안이다. 역할을 보유했다는 사실과 접근할 수 있는 고객사·사원·조직 범위를 함께 확인한다.

| 역할 | 주요 목적 | 권한 제안 | 자동 허용하지 않을 행위 |
| --- | --- | --- | --- |
| 직원 | 본인 기록과 신청·결과 확인 | 본인 출퇴근, 휴가·정정 신청, 신청 상태·휴가 잔여·일·주·월 현황 조회 | 타인 기록 조회·신청, 원천 기록 덮어쓰기, 본인 역할 변경 |
| 승인자 | 담당 범위의 신청 처리 | 지정된 대상의 신청 조회·승인·반려, 필요한 팀원 현황 확인 | 고객사 전체 접근, 자기 승인, 지정 범위 밖 승인 |
| 근태 담당자 | 소속 고객사의 설정과 검토 | 조직·사원·일정·휴일·승인 관계 설정, 휴가 기초 정보·조정 이력, 현황·정정 이력 확인 | 원천 기록 직접 변경, 승인 우회, 타 고객사 접근 |
| 서비스 운영자 | SaaS 고객사 이용 관리 | 고객사 등록·이용 상태, 최초 담당자 연결과 운영 감사 | 고객사 근태 일괄 열람, 대리 승인, 일반 요청에서 DB 관리 권한 사용 |

복수 역할, 권한 부여 주체, 담당 조직 범위, 대결·승인자 부재, 자기 승인 대안과 운영자 지원 접근은 `D04`·`D11`에서 결정한다. 고객사 업무 관리자와 서비스 운영자를 동일 권한으로 취급하지 않는다.

## 5. MVP 기능 범위 제안

### 기본안에 포함할 기능

아래 `F01`~`F12`는 모두 **포함 제안**이다. 법령·업무 정책이 미정인 기능은 결정표의 의존 항목을 해소한 뒤 명세와 구현으로 진행한다.

| ID | 기능 | 최소 제공 내용 | 선결정 항목 |
| --- | --- | --- | --- |
| F01 | 최소 고객사 온보딩 | 운영자의 고객사 등록·이용 상태 확인, 최초 근태 담당자 연결 | D11 |
| F02 | 계정·세션 관리 | 사용자 초대·수락·만료, 로그인·로그아웃, 비밀번호 재설정, 비활성·퇴사자 접근 차단 | D09, D11 |
| F03 | 조직·사원 관리 | 소속 고객사의 최소 조직·사원 정보, 재직 상태와 역할·승인 대상 연결 | D04, D11 |
| F04 | 고정 일정·휴일 관리 | 사원별 일정과 적용일, 휴게·휴일 캘린더 설정, 변경 근거 추적 | D02, D06 |
| F05 | 출퇴근 기록 | 선택한 인증 방식으로 본인 출퇴근 기록, 처리 결과 확인, 반복 요청의 중복 반영 방지 | D02, D03 |
| F06 | 본인 현황·신청 조회 | 일별 출퇴근·일정·휴가·예외·처리 상태와 주·월 현황 조회 | D02, D06 |
| F07 | 종일 연차·잔여 관리 | 검증된 기준일·기초 잔여 등록, 조정 사유·이력, 신청·승인·사용·취소 내역과 잔여 근거 조회 | D05, D06 |
| F08 | 출퇴근 정정 신청 | 누락·오입력의 정정 신청, 사유·기존 값·요청 값과 처리 이력 추적 | D04, D06, D07 |
| F09 | 신청 승인·반려 | 단일 단계 승인 관계, 처리 상태, 승인 전 철회·승인 후 취소 요청을 구분한 이력 | D04, D05, D07 |
| F10 | 기본 계산·집계 | 고정 일정·실제 기록·승인된 신청과 정책을 근거로 계산, 미해결 항목 표시, 일·주·월 집계 | D02, D06, D07 |
| F11 | 근태 담당자 검토 | 대상 사원의 누락·승인 대기·정정·휴가·집계 상태를 일별·월별로 확인 | D06, D07 |
| F12 | 감사·변경 근거 조회 | 권한·일정·기초 잔여·정정·승인·운영자 행위의 주체·시각·변경 근거 확인 | D11, D12 |

F07의 기초 잔여 등록은 법정 연차 발생 계산을 임의로 대체하는 기능이 아니다. 등록 근거와 정확성을 확인하고 변경 이력을 남기는 운영안을 제안하는 것이다. 자동 발생·소멸·이월·사용 촉진은 후속 후보이며, 실제 고객에게 제공할 휴가 범위와 대기 신청의 잔여 예약·차감 정책은 미정이다.

F09의 철회·취소·정정은 기존 신청·승인 이력을 삭제하는 기능이 아니다. 허용 시점, 처리 권한, 잔여량 복원과 집계 변경 규칙을 먼저 결정해야 한다.

| C04 | 월 마감 | 고객 운영에 필요한지 확인 후 판단 | 잠금 범위·권한, 승인 취소·정정, 재집계·재정산·재마감 정책 |
| C05 | PWA 설치·갱신 | 반응형 웹 이후 제공 범위 검토 | 캐시·로그아웃 후 정보 잔존, 브라우저 지원. 오프라인 출퇴근은 기본안에 포함하지 않는 제안 |

시간 단위 휴가, 연차 자동 발생·소멸·사용 촉진, 다양한 법정 휴가, 출장·외근·재택 신청, 복잡한 승인선·일괄 승인, Excel 업로드, 급여 연계 전용 출력, 요금제·과금·상세 사용량 콘솔은 후속 후보로 제안한다. 다양한 법정 휴가를 제품 후보에서 삭제하는 뜻은 아니며, 파일럿에서 필요한 미지원 업무 처리 범위를 확인해야 한다.

본인 현황은 목록 중심으로도 검증할 수 있다. 캘린더·대시보드 등 화면 표현의 세부 범위는 미정이며 핵심 업무 검증에 필요한 정도로 정한다.

### 기존 초기 제외 방향 유지

급여·급여세액 계산, 네이티브 모바일 앱, GPS 출퇴근, 생체인식·출입 장비 연동, 복잡한 교대근무 자동 편성, 외부 전자결재 연동, 고객사별 개별 코드 커스터마이징, 다국어 지원은 초기 제외 방향을 유지한다.

급여 연계용 근태 Excel 출력은 계산 기능과 구분하여 후속 후보로 남긴다. MSA·Kubernetes·React/Vue SPA는 기존 기술 범위에서 제외한 방향을 유지한다.

## 6. 핵심 사용자 시나리오와 수용 기준

아래 기준은 **제안하는 제품 검증 목표**다. 실행된 테스트 결과가 아니며 수치·상태 정책이 필요한 기대값은 관련 결정을 거쳐 Phase 2에서 구체화한다.

### S01. 고객사와 직원의 최초 이용 준비

- 역할·연결 기능: 서비스 운영자, 근태 담당자, 직원 / F01~F04
- 흐름: 고객사·최초 담당자 연결 → 최소 조직·사원 등록 → 일정·승인자 지정 → 초대 수락·로그인.
- 수용 기준: 검증된 고객사 소속만 업무에 접근한다. 만료·재사용된 초대는 허용하지 않으며 초대 대상과 다른 소속으로 등록되지 않는다.
- 예외 기준: 일정·승인자 등 필수 설정이 빠지면 필요한 항목을 안내한다. 값을 추정해 정상 이용 준비가 끝났다고 표시하지 않는다.

### S02. 정상 출퇴근과 기록 확인

- 역할·연결 기능: 직원 / F05, F06
- 흐름: 로그인 → 선택한 출퇴근 인증 → 출근 또는 퇴근 → 처리 결과와 본인 일별 내역 확인.
- 수용 기준: 다른 고객사·직원으로 기록할 수 없다. 실제 시각과 근무일을 구분하고 `Asia/Seoul` 기준으로 표시한다.
- 예외 기준: 연속 클릭·통신 재시도·동시 요청으로 유효 기록이 중복 반영되지 않는다. 통신 실패 시 성공 여부를 확인할 경로를 제공하고 미저장 기록을 저장 완료로 표시하지 않는다. 신뢰 시각과 재시도 식별 정책은 D02·D03에서 결정한다.

### S03. 퇴근 누락 또는 오입력 정정

- 역할·연결 기능: 직원, 승인자, 근태 담당자 / F08~F12
- 흐름: 본인 누락·오류 확인 → 정정 값·사유 제출 → 권한 있는 승인자 검토 → 결과·이력 확인.
- 수용 기준: 승인 전에는 유효 산정 입력이 바뀌지 않는다. 승인 후에는 원천 기록을 보존하고 승인된 정정과 결과의 연결을 확인할 수 있다.
- 예외 기준: 출근 없는 퇴근, 중복 정정, 이미 처리된 신청, 과거 기간 정정은 정책에 따라 안내·통제한다. 누락 시각을 임의 생성하지 않는다.

### S04. 종일 연차 신청과 잔여 확인

- 역할·연결 기능: 직원, 승인자, 근태 담당자 / F07, F09
- 흐름: 근거·기준일이 있는 잔여 조회 → 기간 선택·신청 → 승인·반려 → 상태·사용·잔여 내역 확인.
- 수용 기준: 신청 중·승인·취소 내역을 구분한다. 허용하지 않는 기간 중복과 잔여 초과를 확정 정책에 따라 검증하며 동시 신청도 중복 차감되지 않는다.
- 예외 기준: 기초 잔여나 적용 정책이 미확인인 경우 확정 잔여량처럼 표시하지 않는다. 휴일 포함, 재직 상태 변경, 신청 중 예약량의 처리 기준은 D05·D06에서 결정한다.

### S05. 승인·반려와 철회·취소

- 역할·연결 기능: 직원, 승인자 / F09
- 흐름: 담당 신청 조회 → 권한·현재 상태 확인 → 승인 또는 반려 → 신청자 확인. 승인 전 철회와 승인 후 취소 요청은 별도 흐름으로 검토한다.
- 수용 기준: 지정 범위 밖 승인과 자기 승인을 차단하는 안을 제안한다. 동시 처리 시 한 번만 유효하게 반영하고 뒤늦은 처리자에게 현재 결과를 안내한다.
- 예외 기준: 취소가 승인되는 경우 잔여량·집계는 정책에 따라 한 번만 반영하며 이전 승인 이력을 보존한다. 승인자 부재·퇴사·대결·자기 승인 대안과 취소 가능 시점은 D04·D07에서 결정한다.

### S06. 본인 주·월 현황과 담당자 검토

- 역할·연결 기능: 직원, 승인자, 근태 담당자 / F06, F10, F11
- 흐름: 대상 기간·접근 가능한 사원 선택 → 일별 상세와 합계 확인 → 누락·승인 대기·정정 필요 내역 확인.
- 수용 기준: 상세와 합계가 일치하고 적용한 일정·정책·기준 버전을 추적할 수 있다. 승인자는 허용된 대상만, 직원은 본인만 조회한다.
- 예외 기준: 미처리·범위 밖 근무·검증되지 않은 산정 항목이 남으면 잠정 결과와 확인 필요 이유를 표시한다. 월별 조회를 월 마감 또는 급여 확정으로 표현하지 않는다.

### S07. 일정 밖 근무·자정 통과 기록

- 역할·연결 기능: 직원, 근태 담당자 / F05, F08, F10, F11
- 흐름: 일정 외 시각이나 자정 통과 기록 발생 → 원천 보존 → 확인 필요 표시 → 정정·업무 검토.
- 수용 기준: 기록 전체와 발생 시각을 보존한다. 승인 신청이 없다는 이유로 실제 기록을 삭제하거나 추가 근로를 자동으로 0으로 만들지 않는다.
- 예외 기준: 자정·월말·연말 경계에서 임의 분할·자동 퇴근·정상 확정 처리를 하지 않는다. 근무일 귀속과 연장·야간·휴일 분류·실근로 판정은 D02·D06의 검증된 규칙을 따른다.

### S08. 권한 변경·퇴사 후 접근 차단

- 역할·연결 기능: 근태 담당자, 직원 / F02, F03, F12
- 흐름: 재직·역할·담당 범위 변경 → 이후 요청의 권한 재평가 → 허용된 정보만 조회.
- 수용 기준: 직원이 자신의 권한을 올릴 수 없다. 비활성 계정·퇴사자의 접근과 기존 세션·초대·재설정 수단의 사용을 확정 정책에 따라 차단한다.
- 예외 기준: 접근 차단이 과거 근태·승인 이력의 삭제로 이어지지 않는다. 적용 시각과 기존 세션 처리 기준은 D09·D11에서 정한다.

### S09. 고객사 간 접근과 운영자 접근 통제

- 역할·연결 기능: 모든 역할 / F01~F12, N01, N02
- 흐름: 요청의 고객사·사원 식별자 변조 또는 다른 고객사 요청과 연결 자원 재사용 상황을 검증한다.
- 수용 기준: 화면·조회·신청·승인·집계·이력과 향후 출력에서 다른 테넌트의 데이터에 접근하거나 영향을 줄 수 없다. 운영자에게 고객사 업무 데이터 접근이 자동 부여되지 않는다.
- 예외 기준: 테넌트가 확인되지 않거나 RLS 컨텍스트 설정에 실패하면 접근을 차단한다. 실패·종료 뒤 커넥션을 다른 테넌트가 재사용해도 이전 컨텍스트가 적용되지 않는다.

### S10. 과거 정책 변경과 기간 결과 재확인

- 역할·연결 기능: 근태 담당자 / F04, F07~F12
- 흐름: 일정·기준·승인 상태 변경 → 영향 기간 확인 → 과거 결과와 변경 근거 확인.
- 수용 기준: 과거 결과는 당시 입력·적용일·규칙 버전으로 설명할 수 있다. 기준 변경이 과거 기간 전체에 무분별하게 소급되지 않는다.
- 예외 기준: 변경 가능한 기간·재집계 권한·확정 결과 변경은 D07 결정 전 임의 처리하지 않는다. C04를 채택하면 마감 후 정정·재마감 시나리오를 별도로 추가한다.

## 7. 업무 상태와 계산의 제안 경계

### 신청 상태의 개념 초안

```text
제출 → 승인 또는 반려
제출 → 철회 (승인 전 허용 조건 미정)
승인 → 취소 요청 → 취소 승인 또는 취소 반려 (조건 미정)
```

이는 사용자에게 보일 흐름의 제안이며 확정된 상태 머신·코드·DB 스키마가 아니다. 임시 저장, 재상신, 정정과 취소의 우선순위, 취소 심사 중 원래 승인 효력, 승인자 변경 시 처리와 마감 이후 전이는 D04·D07에서 결정한다.

### 계산에서 지켜야 할 구분

- 근무 스케줄, 실제 출퇴근, 확인된 휴게, 승인된 휴가·정정, 적용 정책을 각각 구분한다.
- 추가 근무의 신청·승인 시간과 실제 근로 판단을 분리한다. 신청 승인만으로 실근로가 확정되거나 미승인만으로 실제 근로가 사라지지 않게 한다.
- 기본안에서 자동 계산할 수 없는 항목은 확인 필요 상태와 근거를 표시한다. 단순 체류시간·예정시간을 검증된 법정 근로시간으로 표기하지 않는다.
- 결과에는 대상 기간, 적용 기준·버전, 미해결 항목과 산정 근거를 연결한다. 재계산·과거 결과 보존 방식은 후속 설계에서 정의한다.
- 법정 기준값·일수·가산율·근무일 귀속·차감 단위·반올림을 추정하지 않는다. 공식 검증 후 입력·기대 결과·경계 사례로 명세한다.

휴가 취소·정정과 재집계의 처리 원칙이 확정되지 않았다면 실데이터에 대한 해당 변경 기능을 완성된 운영 기능으로 제공하지 않는다.

## 9. 화면과 업무 흐름의 후보

### D01 검토: MVP 기능 묶음과 v1 관계

**선택 상태: 미정 — 사용자 선택 전.** 아래 비교안을 문서에 기록하거나 커밋하는 것은 채택 승인이 아니다. D01~D05의 권장안은 기존 요구사항에 기반한 제품 설계 제안이며 법령·시장·기술의 외부 검증 결과가 아니다.

| 선택지 | 장점 | 단점·부담 | 적합한 검증 목적 |
| --- | --- | --- | --- |
| A. 핵심 업무 연결 | 출퇴근 → 종일 연차·정정 신청 → 단일 단계 승인 → 일·주·월 현황을 함께 검증 | 휴가 잔여·취소·정정·동시 처리의 기본 규칙 명세가 필요 | 근태관리의 핵심 업무 연결을 검증 |
| B. 출퇴근 기록 우선 | 기능·화면·휴가 계산 범위를 줄일 수 있음 | 휴가·승인·담당자 집계의 연결 가치를 충분히 확인하기 어려움 | 기록·누락·정정 흐름에 먼저 집중 |
| C. 운영 업무 확대 | 반차·추가 근무·출력·마감·자동 발생까지 폭넓게 검증 | 법령·승인 상태·정산·운영 예외와 회귀 검증 부담 증가 | 해당 업무가 반드시 필요한 파일럿 검증 |

**권장안: A.** F01~F12의 핵심 흐름을 검토 기준으로 삼고 C01~C05는 별도로 선택하는 방안을 권장한다. 고객사 온보딩·계정 관리와 테넌트 격리·이력·정확성은 함께 갖춰야 할 조건이다. 기능을 줄이더라도 보안 요구사항은 유예하지 않는다.

- 선택할 내용: MVP 기능 묶음을 A/B/C 중 어디까지로 좁힐지. 특정 조건부 기능만 추가하는 선택도 가능하다.
- 함께 제안하는 경계: MVP는 핵심 흐름 검증 범위로 두고, v1은 파일럿 결과와 운영 준비를 반영하여 별도로 결정한다.
- 선택 후에도 미정: C01~C05의 개별 포함 여부, 파일럿 적합성, v1 기능·출시 조건, D02~D07의 세부 정책.
- 사용자 선택 질문: **A 핵심 업무 연결안을 기준으로 삼고, 조건부 기능과 v1 범위는 별도로 결정할 것인가?**

### D02 검토: 고정 일정의 관리 수준

**선택 상태: 미정 — 사용자 선택 전.** 고정 근무라는 명칭만으로 모든 직원의 요일·시각이 같다고 가정하지 않는다.

| 선택지 | 장점 | 단점·부담 |
| --- | --- | --- |
| A. 회사 내 단일 고정 일정 | 설정·배정·검증 범위가 가장 작음 | 사원별 일정 차이가 있는 고객의 수용 범위가 좁아지고 기존 사원별 일정 제안을 축소 |
| B. 여러 고정 템플릿 + 사원별 적용일 배정 | 일정 차이를 수용하면서 매일 편성하는 기능을 줄일 수 있음 | 배정 누락·기간 중복·변경 적용일·과거 일정 추적의 검증 필요 |
| C. 일별·복수 구간·자정 통과·교대까지 정상 지원 | 다양한 근무 패턴 수용 가능 | 편성·구간 중첩·휴가 연계·근무일 귀속과 회귀 검증 부담 증가 |

**권장안: B.** 고객사별 고정 패턴을 사원에게 적용일로 배정하고, 정상 지원 경계는 당일 시작·종료와 하루 한 근무 구간으로 좁히는 안을 권장한다. 이 선택이 시차출퇴근·유연근무·교대근무 지원까지 의미하지 않도록 제품 범위를 명시한다.

- 휴게 검토안: 예정 휴게를 등록하되 실제 차이를 확인·정정할 경로를 두는 방식을 우선 검토한다. 예정 휴게의 일괄 자동 공제나 휴게 시작·종료의 별도 기록 채택은 미정이다.
- 기록 보존 경계: 정상 산정 범위 밖의 복수 기록·일정 외 근무·자정 통과도 보존하고 확인 필요로 표시한다. 미지원 기록 삭제·임의 날짜 분할·자동 퇴근으로 처리하지 않는다.
- 선택 후에도 미정: 실제 요일·시각·시간 수, 신뢰할 기록 시각, 휴게 확인·공제, 배정 누락·중복, 소급 변경, 주·월 경계, 근무일 귀속·반올림. 법령·계산 항목은 D06과 함께 검증한다.
- 사용자 선택 질문: **여러 고정 템플릿을 사원별 적용일로 배정하되, 당일 한 근무 구간을 정상 지원하는 B안으로 시작할 것인가?**

### D03 검토: 출퇴근 인증 방식

**선택 상태: 미정 — 사용자 선택 전.** 고정 근무 사업장이라는 사실만으로 고정된 공용망이 있다고 가정하지 않는다.

| 선택지 | 장점 | 단점·부담 |
| --- | --- | --- |
| A. 허용 IP 우선 | 직원의 기록 흐름이 단순하고 QR 게시·갱신 운영이 필요 없음 | 허용 대역 변경·프록시 신뢰 경로 관리 필요. 셀룰러·재택 등 정상 이용이 막힐 수 있고 공유망·VPN의 한계 존재 |
| B. 회전 QR 우선 | 사업장 공용망에 의존하지 않는 흐름으로 셀룰러 이용을 검토할 수 있음 | QR 게시 기기·담당자와 스캔·만료·재사용 처리가 필요. 사진·실시간 공유와 대리 기록 가능성을 제거하지 못함 |
| C. 고객사별 선택 또는 병행 | 고객사별 환경 차이를 수용할 여지가 큼 | 두 방식의 설정·보안·예외·테스트 부담 증가. OR 방식과 AND 방식도 별도 정책 결정 필요 |

**조건부 권장안: 안정적인 사업장 공용망을 이용할 수 있으면 A, 고정망이 없거나 셀룰러 기록이 필수이면 B.** MVP에서는 적합한 한 방식부터 검증하고 C는 후속으로 검토하는 방안을 권장한다. 파일럿 환경이 미확인인 현재 특정 방식을 채택하지 않는다.

- 선택 전 확인: 직원의 PC·Wi-Fi·셀룰러 이용, 공용망과 관리 담당자, QR 게시 기기 운영 가능 여부, 재택·외근·다중 사업장의 필요 범위.
- 공통 보안 조건: 로그인한 사용자·검증된 소속으로 기록 대상을 결정하고 중복 반영을 차단한다. IP·QR 어느 방식도 본인이나 실제 현장 존재를 보증한다고 표현하지 않는다.
- 세부 설계 경계: 클라이언트가 보낸 IP 헤더를 그대로 신뢰하지 않는다. 공용 QR을 여러 직원이 정상 사용하는 것과 동일 사용자 재사용을 구분하며 첫 사용으로 공용 토큰 전체를 소진하는 정책을 전제하지 않는다.
- 선택 후에도 미정: 허용 대역·변경 권한, 프록시 신뢰 정책, QR 만료·회전 주기·사용 단위, 재시도 식별, 인증 실패의 안내·정정 경로. 구체 보안 구성은 Phase 3~4에서 공식 자료로 검증한다.
- 사용자 선택 질문: **파일럿 환경을 기준으로 A/B 중 하나를 먼저 검증할 것인가, 환경 확인까지 방식 선택을 보류할 것인가?**

### D04 검토: 승인 단계와 권한 범위

**선택 상태: 미정 — 사용자 선택 전.** 승인 단계의 수와 승인 가능한 대상·행위를 구분해 선택한다.

| 선택지 | 장점 | 단점·부담 |
| --- | --- | --- |
| A. 1단계 지정 승인자 | 책임과 상태 흐름이 단순하고 핵심 신청 검증에 집중 가능 | 승인자 부재·퇴사·본인 신청을 처리할 다른 승인 경로 필요 |
| B. 고정 2단계 승인 | 팀의 확인과 담당자의 검토를 분리할 수 있음 | 처리 지연, 중간 반려·철회·승인자 변경의 상태 규칙 증가 |
| C. 고객사별 자유 승인선 | 다양한 조직의 순서·조건·대결 요구를 수용 가능 | 설정 화면·조직 변경·조건 분기·권한·회귀 검증 부담이 큼 |

**권장안: A.** 사원별 지정 승인자를 기반으로 시작하고, 직원·승인자 역할의 겸임은 허용하되 자기 신청은 다른 지정 승인자가 처리하도록 하는 안을 권장한다. 근태 담당자의 설정 권한이 승인 권한을 자동 포함하지 않도록 한다.

- 부재·자기 신청 검토안: 고객사 내부에서 명시적으로 지정한 대체 승인 경로를 둔다. 다른 승인자가 없으면 임의 자기 승인·운영자 대리 승인으로 해결하지 않고, 파일럿 적합성과 운영 절차를 먼저 확인한다.
- 상태 처리 검토안: 승인 전 철회와 승인 후 취소 요청을 구분하고, 승인·반려·철회·취소의 이력을 남긴다. 동시 처리로 중복 반영되지 않아야 한다.
- 선택 후에도 미정: 사원·조직별 대상 범위, 지정·대체 권한과 유효 기간, 권한 변경의 적용 시점, 부재·퇴사, 재신청, 취소 심사 중 원래 승인 효력, 과거·마감 기간 변경. 취소·정정·재집계는 D07과 함께 결정한다.
- 사용자 선택 질문: **1단계 지정 승인자와 자기 승인 차단을 기본안으로 삼을 것인가, 파일럿에 2단계 승인이 반드시 필요한가?**

### D05 검토: 휴가 단위·기초 잔여·반영 시점

**선택 상태: 미정 — 사용자 선택 전.** 휴가 종류·사용 단위, 잔여 부여 방식, 신청량 반영 시점은 독립된 선택이다. 종일·반차를 선택했다고 자동 발생·이월·소멸까지 채택한 것으로 해석하지 않는다.

| 휴가 단위 선택지 | 장점 | 단점·부담 |
| --- | --- | --- |
| A. 종일 연차 우선 | 기간·차감 단위를 좁혀 신청 → 승인 → 잔여 확인을 검증 가능 | 반차가 필수인 파일럿에는 부족 |
| B. 종일 연차 + 반차 | 부분 휴가의 실제 사용 흐름까지 검증 가능 | 오전·오후 구간, 일정·휴게와 차감량의 관계 명세 필요 |
| C. 시간 단위 휴가까지 지원 | 더 다양한 부분 휴가에 대응 가능 | 최소 단위·반올림·구간 중복·환산·집계와 동시성 검증 부담 증가 |

**휴가 단위 권장안: A.** 파일럿에서 반차가 필수임을 확인하면 B를 명시적으로 추가하는 안을 권장한다. 반차를 고정된 시간 수로 임의 정의하지 않는다. 다른 법정 휴가의 필요성과 미지원 업무 처리 경계도 별도로 확인한다.

| 잔여 부여 방식 | 장점 | 단점·부담 |
| --- | --- | --- |
| 검증된 기초 잔여 등록 + 조정 이력 — 권장 | 자동 발생 규칙의 범위를 늘리지 않고 근거·기준일·등록자·사용·조정 이력을 검증 가능 | 고객사 담당자의 기초 자료 검증과 등록 업무 필요. 자동화가 없다는 이유로 법적 적정성 검증이 생략되지 않음 |
| 법정 발생·이월·소멸 자동화 | 반복 등록을 줄일 여지가 있음 | 적용 대상·기간·입퇴사·기준일·예외·개정과 회귀 사례를 먼저 공식 검증해야 함 |

| 신청량 반영 방식 | 장점 | 단점·부담 |
| --- | --- | --- |
| 승인 시 차감 — 단순 운영 우선 권장 | 잔여 반영을 승인 시점에 집중할 수 있음 | 대기 신청끼리 잔여를 선점하지 않아 최종 승인 때 부족할 수 있음. 대기량 별도 표시와 승인 시 재검증·동시성 제어 필요 |
| 대기 신청량 예약 후 승인 시 사용 확정 | 이미 신청한 양을 반영한 가용량을 안내하고 초과 예약을 통제 가능 | 반려·철회 시 해제, 장기 대기, 승인자 부재, 취소·재처리의 상태 관리 부담 증가 |

**조합 권장안: 종일 연차 + 검증된 기초 잔여·조정 이력 + 승인 시 차감.** 신청 단계에서 가용량 선점이 반드시 필요한 파일럿이면 대기 예약을 선택하는 편이 적합하다. 승인 시 차감안에서도 대기 내역을 숨기거나 동시 승인으로 초과 차감되게 해서는 안 된다.

- 취소·변경 경계: 취소가 승인되는 경우 복원·집계 반영은 한 번만 수행하고 이력을 남긴다. 취소 요청만으로 즉시 잔여를 복원하거나 원래 승인 효력을 바꾸는 정책은 확정하지 않는다.
- 선택 후에도 미정: 휴가 종류·반차 구간, 기초 잔여 근거·이월·소멸, 중복·잔여 부족 처리, 휴일 포함·연도 경계·재직 변경, 취소 심사 중 효력. 마감 이후 변경과 재집계는 D07과 함께 결정한다.
- 사용자 선택 질문: **종일 연차부터 검증할 수 있는가, 반차가 필수인가? 기초 잔여 이력 등록과 승인 시 차감 조합을 채택할 것인가, 대기 예약이 필요한가?**

## 11. 검증 계획과 성공 판단

### 제품 가설과 사용성 검증

고객 인터뷰와 파일럿으로 실제 기록·신청·승인·대조 흐름, 발생하는 예외, 반차·추가 근무·마감의 필요성을 확인한다. 경쟁 분석에서는 지원 근무제, 승인·정정, 집계·출력, 대상 고객, 공개 가격과 운영 제약을 조사하되 결과와 출처 확인 전 차별점을 확정하지 않는다.

| 제안 지표 | 측정 의미 | 현재 상태 |
| --- | --- | --- |
| 핵심 시나리오 수행 결과 | 초대·출퇴근·신청·승인·조회 흐름의 완료·실패와 원인 | 시나리오·측정 대상 승인 필요 |
| 누락·정정·승인 대기와 대조 부담 | 미해결 건, 처리 경과 시간, 반복 확인이 필요한 이유 | 기준선·측정 기간·목표 미정 |
| 집계 대조 결과 | 검증된 사례와 산정 결과의 차이, 근거 추적 가능 여부 | 공식 규칙·기대값 확정 후 검증 |
| PC·모바일 핵심 사용성 | 상태 이해, 실패 후 복구, 본인·담당 범위 정보 확인 | 파일럿 대상·브라우저·평가 기준 미정 |

테넌트 간 접근 차단과 필수 계산·정합성 검증은 평균 성공률로 대체하지 않는 수용 조건이다. 검증하지 못한 항목은 통과로 간주하지 않는다.

### 후속 단계의 테스트 준비

- Phase 2: S01~S10에 연결된 상태 전이·계산 입력·기대 결과·경계 사례를 공식 근거와 함께 명세한다.
- Phase 3: 스키마·인터페이스, 권한 매트릭스, 테넌트 컨텍스트·RLS·계정·감사·시간 모델을 먼저 정의한다.
- 구현 단계: TDD로 단위·경계·회귀 테스트를 먼저 작성하고 PostgreSQL 통합·테넌트 격리·동시성 테스트를 진행한다.
- 품질 단계: 사용자 흐름, 성능·보안, 백업·복구를 검증한다. 이번 문서 작업에서는 이러한 테스트를 실행하지 않는다.

| 위험 | 영향 | 대응 제안 |
| --- | --- | --- |

| 일정 밖 근무나 자정 기록 누락 | 기록 유실·근무시간 오산정 | 원천 보존, 확인 필요 상태, 검증된 정정·귀속 규칙 |
| 승인 취소·마감·정정 충돌 | 휴가량·집계 중복 또는 과거 결과 불일치 | D04~D07 선결정, 동시성·재처리·회귀 시나리오 |
| 테넌트·권한·커넥션 오류 | 고객사 간 업무·개인정보 노출 | N01·N02 필수 검증과 운영자 권한 분리 |

다음 검토 순서를 제안한다.

1. A안과 고정 근무 경계를 검토하고 D01~D05의 선택지를 좁힌다.
2. 파일럿 고객 문제를 확인하고 조건부 후보·후속 후보의 우선순위를 검토한다.
3. 결정 근거와 미정 사항을 반영해 PRD를 갱신한다. 이후 별도 요청으로 Phase 2 업무 규칙 명세를 진행한다.

현재 단계에서는 PRD 초안 작성까지만 수행한다. 추가 문서, 구현 계획, 코드·스키마·SQL·실행 환경을 생성하거나 후속 단계를 자동으로 시작하지 않는다.
