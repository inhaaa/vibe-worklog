# 근로시간 결과·검토용 Excel 구현 계약

> 2026-10-29 조회 화면: 일 결과·연차 원장·신청·감사·원천/당시 출퇴근 표는 [WorklogSheet](../superpowers/specs/2026-10-29-common-sheet-design.md)를 사용한다. 계산·버전·감사·출력 API는 유지하며 미확정 null과 실제0, 서울 시각·숫자 ms 정렬값·상세 링크를 보존한다. 기존 서버 검토용 Excel 경로를 사용하고 그리드의 유료 Excel 기능은 추가하지 않는다.

2026-10-24 연속 MVP 구현 위임에 따라 [계산 명세](../rules/calculation.md)·[보안](security.md)·[신청 규칙](../rules/workflow.md)을 실행 흐름에 연결한다. 법률 적합성·급여 확정 자료가 아닌 검토 결과다.

## 입력·산정·최신성

- 조회 요청은 같은 고객사의 최대31일이다. 월 경계의 주를 평가할 때는 인접 월의 월요일~일요일 전체 결과를 조회한다. 재집계는 선택 기간을 포함한 온전한 주까지 확장하며 최대42일의 원천을 한 실행에서 고정한다.
- 직원은 본인만, 담당자는 자기 고객사 사원을 조회한다. 수동 재집계·법 적용 검토 등록·Excel·감사 조회는 현재 담당자 권한을 재확인한다.
- 실제 근로·휴게·유효 정정·현재 연차 효력·대기 정정·일정/휴일을 입력으로 순수 CALC-1 엔진을 실행한다. 근거 없는 일반 법 적용·월요일 주 기산점은 기본 미확인이다.
- 담당자는 민감한 보호 사유를 수집하지 않고 일반 규정 적용 검토 여부와 근거·유효기간을 등록한다. 회사의 월요일 주 기산점 일치도 별도 근거를 남긴다. 두 검토는 불변 revision으로 추가하며 같은 날짜에 새 검토 버전이 있으면 가장 높은 revision이 현재 적용 버전이다. 이전 결과는 당시 검토 ID로 재현한다.
- 계산 실행·일 결과는 추가만 한다. 원천 스냅샷과 정책·검토·효력 참조, 규칙 버전, 사실/검토 개정 쌍, source fingerprint를 저장한다. 재직기간은 잠금 뒤 읽고 source fingerprint에 포함한다. 현재 개정 또는 source fingerprint가 바뀌면 이전 값은 보존하면서 오래됨을 표시한다.
- 조회 GET은 재집계하지 않는다. 결과가 없으면 미산정, 오래되거나 미확정이면 null과 확인 필요로 다루며 직원 근로시간 화면은 이 값을 `-`로 보인다. 기간 합계는 현재 결과가 있는 날의 부분합과 확인 전 일수를 함께 보여주며(확인 전은 오늘 이전 또는 퇴근한 오늘 중 실근로가 표시되지 않는 날이고, 계산기가 기록 없이 0시간으로 확정하는 휴무일·승인 휴가일과 미래 날짜는 세지 않는다) 주 참고값은 전체 주와 검토가 확인된 경우만 제공한다.

## 검토용 Excel과 감사

일 결과 ID·필터·작성자·생성 시각·현재성 표시를 고정한 REVIEW 스냅샷을 만든 뒤 다운로드한다. 다운로드 직전에 현재 담당자와 생성자 권한을 재확인하고 열람 감사를 남긴다. 재집계가 진행되어도 이미 준비한 파일은 생성 당시 스냅샷과 일치하며 생성 시각·규칙/입력 버전·미확정/오래됨 표시를 유지한다.

XLSX는 JDK ZIP과 고정된 최소 OOXML만 사용하여 새 라이브러리를 추가하지 않는다. 사용자 문자열은 항상 inline string 셀로 기록하고 수식·외부 링크·매크로를 만들지 않는다. 자유 사유·이메일·IP는 출력하지 않는다. null은 미확정 문자열이며 0으로 바꾸지 않는다. 파일명과 시트명은 서버가 고정한다. 감사 목록 열람 자체도 기록하고 원천·신청·감사 행은 삭제하지 않는다.

원장·효력·업무 감사·재집계 필요 표시는 승인 트랜잭션에 속한다. 직원이 근무 확인을 저장하면 같은 요청의 별도 트랜잭션에서 그날이 속한 주(월~일)를 계산한다(감사 행위 `WORKTIME_AUTO_CALCULATE`, 계산 실행의 from·to는 그날·expanded는 그 주). 계산이 실패해도 확인은 유지하고 그날은 확인 전으로 남는다. 정정·휴가 승인 등 다른 사실 변경 자체는 계산을 시작하지 않으며, 담당자 수동 재집계나 같은 주의 다음 근무 확인 때 다시 계산된다. 계산·다운로드 실패에 정상 완료 표시를 하지 않는다. 실제 고객 적용·운영 성능·법적 검토는 별도 게이트다.

## 검토 출력과 상세 조회 범위

주간 화면 범위는 월요일부터 포함 일요일까지 ISO 날짜로 표시한다. 검토 XLSX에는 근무일 소속, 계산 당시 일정·휴일·정책·적용 검토 식별자와 유효 출퇴근·확인 휴게를 포함한다. 소속은 출력 시점에 확인한 근무일별 유효 소속이며 계산 당시 입력 근거와 구분한다. 정수 ms를 유지하며 HH:mm:ss.SSS를 병기하고24시간 이상 누적도 잘라내지 않는다. 원문 IP·이메일·자유 사유는 제외한다.

근로시간 화면은 실근로 합계·확인 전 일수·휴가 일수와 일 결과(근무일·실근로·휴게·8시간 초과·휴가), 주간 결과(실근로·확인 전·40시간 초과)를 보여주며 값은 현재 결과일 때만 표시하고 나머지는 `-`로 둔다. 결과 ID·개정·규칙 버전·상태 코드는 표시하지 않고 결과가 있는 근무일에서 계산 근거 상세로 연결한다. 선택한 결과의 입력·정책 근거는 후속 상세 화면에서 저장 당시 값으로 전개하며 현재성·최신 버전을 구분한다. 감사 화면은50건의 양방향 커서 탐색과 안전한 전후 상세·명령/요청 추적 ID 및 열람 감사를 제공한다. 기존 내부100건 조회 API는 보존한다. 안전한 업무 요약과 전체 원문의 재현은 구분하며 실제 고객 적용·운영 검증은 별도다.

## 상세 조회와 서울 시각 후속 계약

2026-10-24 후속 요청에 따라 아래 세 단위를 문서 → 실패 회귀 → 구현 → 검증 → 커밋·Push 순서로 진행한다. 기존 산정 규칙·불변 원천·권한을 유지한다.

### 계산 근거 상세

`GET /worktime/results/{id}`는 인증된 본인 결과 또는 현재 근태 담당자가 보는 같은 고객사 결과만 제공한다. 타인·타 고객사·없는 결과는404로 구분하지 않는다. 월 목록에서 저장된 결과 ID로 연결하며 과거 버전도 같은 ID로 재조회한다. 조회는 새 계산·새 결과를 만들지 않는다.

계산 당시 저장된 입력 근거에서 원천/유효 출퇴근, 실제 확인 휴게와 예정 휴게, 일정·휴일 버전, 정책·적용 검토의 ID/버전/기간/확인 여부, 당시 재직기간, 휴가 효력·대기 정정 참조, 실행 범위·시각과 규칙/결과/사실/검토 개정을 표시한다. 현재 원천의 일치 여부와 이후 결과 버전 존재 여부를 구분한다. 근거가 없으면 현재 입력을 대신 끼워 넣지 않고 확인 필요로 표시한다. 자유 검토 근거·이메일·IP·비밀값과 JSON 원문은 노출하지 않는다.

### 감사 상세와 페이지

`GET /admin/audit/{id}`와 목록은 현재 근태 담당자의 같은 고객사 범위로 제한하며 각각 열람 감사를 남긴다. 상세는 감사 ID·행위자·대상·시각·명령 ID·요청 추적 ID·사유와 안전한 전후 요약을 제공한다. 요약은 알려진 업무 필드의 타입을 검증하여 구성하고 비밀번호·토큰·이메일·IP·자유 근거·미등록 키를 제외한다. 자유 형식 이름·코드 등은 값 생략으로 표시하고 HTML로 실행하지 않는다.

목록은50건과 추가1건으로 다음 여부를 판단한다. `(occurred_at DESC, id DESC)` 순서와 같은 고객사의 감사 ID 커서 `before`/`after`를 사용하며 두 커서 동시 입력은400, 다른 고객사/없는 커서는404다. 이전·다음은 조회 시점 원장 기준이며 전체 원장의 고정 스냅샷을 보장하지 않는다. 새 Flyway V10에는 해당 고객사·시각·ID 정렬 인덱스만 추가하고 기존 마이그레이션·감사 행을 수정하지 않는다.

### 서울 시각 표시

서버 공통 표시 함수로 Instant를 `Asia/Seoul`의 `uuuu-MM-dd HH:mm:ss`, 일정 시각은 `HH:mm`(초나 초 미만이 있으면 `HH:mm:ss`), 시간량은 `H:mm:ss`, 날짜는 ISO 날짜, 알 수 없는 값은 `-`로 표시한다. 화면은 초 미만을 버리고 저장·계산·검토용 Excel은 밀리초를 유지한다. 화면과 새 XLSX의 생성/계산/효력 시각을 같은 기준으로 보며 입력값·DB Instant·기존 결과·다운로드 스냅샷의 바이트는 바꾸지 않는다. 실제 휴게 JSON은 허용된 구간만 날짜 포함 서울 시각으로 풀어 표시하고 손상된 근거는 원문 대신 확인 필요로 표시한다. 자정·연말·밀리초·로케일/서버 기본 시간대 독립성을 검증한다.

감사 요약에서 명시된 nullable 참조·날짜의 null은 `없음`으로 표시하여 승인자 해제 등 변경과 누락 필드를 구분한다. 해당 키 자체가 없으면 값을 추정하지 않고 표시하지 않으며 민감/미등록 키는 null이어도 제외한다. 연차 원장의 복원 종류는 실제 저장 값인 RESTORE를 사용한다.

후속 계약의 구현·검증을 완료했다. 사람용 화면은 서울 시각과 ISO 날짜, 새 XLSX 시각은 밀리초를 포함한 ISO `+09:00`으로 표시하며 기존 스냅샷은 그대로 다운로드한다. 로컬 전체 회귀368개와 실제 브라우저의 상세·페이지·권한·모바일·다운로드를 확인했다. 실행 근거는 개발 안내를 따른다.
