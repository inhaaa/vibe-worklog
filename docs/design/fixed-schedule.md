# 고정 근무 템플릿·사원별 적용일 배정 계약

2026-10-24 사용자는 최대2시간 동안 기존 MVP 설계를 순차 구현하고 단위마다 문서·검증·커밋·Push하도록 위임했다. 외부 서버·배포·실제 메일·실고객 자료는 범위 밖이다. [PRD](../prd.md), [논리 모델](data-model.md), [계산 규칙](../rules/calculation.md)을 따른다.

## 범위와 선택

고정 템플릿과 불변 주간 버전, 사원별 적용일 배정을 먼저 제공한다. 기존 관리 명령·감사·테넌트 격리를 재사용하는 안을 채택하며, 일정 엔진·고객별 스크립트·자동 교대 편성은 추가하지 않는다. 7요일별 당일 한 근무 구간과 여러 예정 휴게 구간을 정의한다. 예정 휴게는 실제 휴게 증거가 아니다.

- 템플릿 코드40자·이름120자·활성 상태, 버전 revision·사용 시작일·사유를 둔다. 코드는 불변이며 이미 등록한 버전 내용을 갱신하지 않는다. 변경은 새 버전 추가다.
- 각 버전에 월1~일7의 일곱 요일이 정확히 한 번씩 필요하다. 근로일은 같은 날 시작<종료, 비근로일은 근무·휴게 시각 없음이다. 최소 한 근로일을 요구한다.
- 예정 휴게는 시작<종료, 근무 구간 내부이며 서로 중첩할 수 없다. 인접 구간은 허용한다. `time(3)` 정밀도이며 더 세밀한 입력은 절삭하지 않고 거부한다. 법정 휴게·주간 한도의 적법성을 자동 인증하지 않는다.
- 사용 시작일은 서울 기준 오늘 이후다. 같은 템플릿의 새 revision은 기존 버전과 독립 식별자이며, 과거 배정의 버전을 바꾸지 않는다. 이전 버전은 종료일 NULL로 보존하여 명시적으로 배정된 기존 계약을 재현한다.
- 배정은 활성 사원과 활성 템플릿 버전에 한한다. 적용 시작일은 오늘 이후·재직 기간 안·버전 사용 시작일 이후이며 마지막 배정 시작일보다 늦어야 한다. 열린 이전 배정만 새 시작일로 닫고 새 구간을 추가한다. 날짜 구간은 [시작,종료)이며 중첩은 DB에서도 차단한다.
- 같은 날 배정 교체·예약 취소·소급 정정은 이번 첫 일정 단위에서 제공하지 않는다. 이후 사실 개정·재집계와 연결해 별도 구현한다. 오늘 이후 일정 도입은 기존 날짜의 기록을 정상값으로 소급 채우지 않는다.
- 담당자만 등록·버전 추가·배정할 수 있다. employee.version과 template.version, commandId·사유·감사를 검증한다. SQL tenant 조건·복합 FK·FORCE RLS를 유지하고 auth 역할에는 일정 권한을 추가하지 않는다.
- 휴일 캘린더는 다음 단위에서 근거와 함께 관리한다. 요일상 비근로일을 법정 휴일로 간주하지 않으며 일정만으로 연차·실근로를 확정하지 않는다.

## 인터페이스와 검증

`/admin/schedules` 목록·등록, `/admin/schedules/{id}` 버전 조회·추가, `/admin/employees/{id}/schedule` 배정·이력을 제공한다. 관리 POST는 CSRF·명령키·사유·낙관 버전을 받고303/400/403/404/409/422를 따른다. 시각은 ISO LocalTime 문자열이고 복수 휴게 입력은 요일별 `HH:mm[:ss[.SSS]]-HH:mm[:ss[.SSS]]`를 쉼표로 구분한다.

TDD는 누락 테이블·미구현 경로 실패부터 확인한다. 이후 버전 불변·정밀도·요일·휴게 경계·배정 중첩/복합FK·오래된 버전·명령 재시도·테넌트/권한·감사 롤백·웹 입력 보존을 검증한다. 단위별 실제 PostgreSQL 마이그레이션·전체 회귀를 거쳐 커밋·일반 Push한다. Docker 이미지·Compose는 연속 작업의 마지막 통합 검증에서 재확인한다.
