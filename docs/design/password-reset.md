# 로컬 비밀번호 재설정 계약

2026-10-24 MVP 연속 구현 위임에 따라 실제 메일 없이 `local` 모의 전달을 재사용한다. 요청은 회사코드·이메일을 본문으로 받고 존재 여부와 무관한 접수를 반환한다. RESET 목적의256bit 일회성 토큰은 SHA-256만 저장하고 요청 당시 auth_version에 결속하며30분 정각부터 만료한다. 재발급은 이전 RESET을 취소하지만 완료 전에는 비밀번호·세션을 변경하지 않는다. 완료는 활성·비밀번호 설정·현재 재직 계정을 재검증하고 토큰 소비·비밀번호 변경·auth_version 증가·감사를 원자적으로 저장한 뒤 수동 로그인한다. 원문 토큰·비밀번호는 URL·폼 재표시·로그·감사에 남기지 않는다. CSRF·속도 제한·목적/tenant/email/version 결속을 검증한다. 기존 V3를 수정하지 않고 V8에서 인증 역할의 RESET INSERT와 토큰 취소·자기 계정 재설정 감사만 확장한다. 행 정책은 INSERT 목적을 RESET으로 제한하며 기존 INVITE 소비를 함께 유지한다. 외부 전달·서버·배포는 수행하지 않는다.

인증 역할의 SELECT/UPDATE는 기존 INVITE 소비와 RESET 소비·취소를 함께 유지한다. RLS는 행 정책이므로 UPDATE(used_at,revoked_at)의 허용 열을 목적마다 다르게 제한하는 보장은 하지 않는다. INSERT만 RESET 목적에 한정하며, 각 서비스 SQL도 목적을 고정한다.

모의 전달을 사용할 수 없는 기본 프로필에서는 계정 존재 여부와 무관하게503으로 거부하며 토큰을 만들지 않는다. 개발 프로필에서도 실제 메일을 보내지 않고 완료 후에는 새 비밀번호로 직접 로그인해야 한다.
