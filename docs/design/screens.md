# 화면·HTTP 인터페이스 설계

## 1. 상태와 화면 원칙

기준일: 2026-10-24. [PRD](../prd.md)의 MVP를 화면·요청 계약으로 정의한다. 실제 화면·API·JSON 파일은 생성하지 않는다. [데이터 모델](data-model.md), [승인 규칙](../rules/workflow.md), [계산 규칙](../rules/calculation.md), [보안 설계](security.md)를 함께 따른다.

- PC·모바일 온라인 반응형 웹을 제공한다. PWA·오프라인 저장·앱 설치·다중 고객사 전환 UI는 후속이다.
- 기본은 서버 렌더링 HTML이며 htmx는 같은 화면의 목록·폼·처리 결과를 부분 갱신한다. 별도 공개 REST/JSON API는 MVP 범위가 아니다.
- 현재 고객사·본인·역할을 항상 확인할 수 있어야 한다. 역할 메뉴 숨김과 서버 권한 검증을 함께 적용한다.
- 시각에는 `Asia/Seoul`, 근무일에는 날짜를 표시한다. 자정 통과·월·연도 경계는 생략하지 않는다.
- 산정 불가 `null`은 `검토 필요`로 표시한다. 실제 0시간·미완료·대기·오래된 결과를 다른 문구로 구분한다.
- 소정 일정·원천 기록·승인 정정·실제 근로 판단·휴가·결과를 구분해 보여 주고 원천을 편집하는 버튼은 제공하지 않는다.
- 법정 적합·급여 확정 같은 보증 문구를 사용하지 않는다. 검토용 XLSX와 후속 급여 연계를 구분한다.

## 3. 핵심 화면의 정보 순서

### 오늘 출퇴근

현재 고객사·이름 → 근무일·시간대 → 적용 일정 → 마지막 서버 저장 결과 → 출근/퇴근 → 네트워크 상태·처리 메시지 → 내역/정정 연결 순으로 배치한다. 브라우저가 표시한 현재 시각은 참고이며 저장 시각은 서버 응답으로 교체한다. 요청 중 버튼을 잠가도 서버 중복 검증은 별도로 수행한다.

퇴근 후 현재 사실 개정의 출퇴근 구간과 예정 휴게를 보여 주고 실제 근로·휴게가 같은지 본인이 확인한다. 일치 확인은 검토 개정만 갱신하고 재집계 필요를 표시한다. 다르면 정정 신청으로 실제 구간을 제출하며, 확인 전 실근로를 정상 확정하지 않는다.

통신 실패면 `처리 여부 확인 필요`를 표시하고 기존 명령 키로 재확인한다. 저장 성공 응답을 받기 전 완료로 표시하지 않는다. IP 거부 때 우회 버튼·임의 시각 제출은 제공하지 않는다. 날짜 변경 후에도 이전 기록과 근무일을 명확히 표시한다.

### 신청·승인 상세

원신청 식별·종류 → 대상 날짜/사원 → 기존/요청 값 → 사유 → 기준 일정·잔여·입력 버전 → 현재 승인자 → 상태/결정 이력 → 업무 효과 → 취소/재신청 연결 순이다. 승인 시각·승인자의 당시 역할을 표시하되 비밀번호·IP 원문은 노출하지 않는다.

버튼은 PENDING에서 지정 승인자의 승인/반려, 작성자의 철회만 허용한다. APPROVED 연차는 예정 시작 전 별도 취소 요청을 제출하고 이미 시작·사용·퇴사한 건은 담당자 예외 경로로 심사한다. 취소 대기는 `원승인 유효·취소 심사 중`, 취소 승인은 `원승인 이력 유지·현재 효력 CANCELED`로 표시한다. 승인된 출퇴근 정정에는 취소 버튼이 없고 현재 유효 개정을 참조하는 새 정정으로 변경한다. 이전 정정은 APPROVED 이력·SUPERSEDED 효과로 남긴다. 반려 후 재신청은 새 ID이며 원문을 편집하지 않는다.

승인자 부재는 담당자의 대체 지정과 대기 건 재할당으로 해결한다. 화면에 자기 승인 예외나 운영자 강제 승인 동작을 제공하지 않는다. 최신 상태가 바뀌면 로컬 화면을 강제로 성공 처리하지 않고 다시 조회하게 한다.

### 현황·검토 출력

필터 → 기준 시각/시간대 → 완료·검토 필요·대기·오래됨 건수 → 일 결과와 주·월 요약 → 선택 결과의 입력·정책·규칙 버전 → 정정/재집계 → 검토용 XLSX 순이다. 주간 법정 판정에 월 밖 날짜가 필요하면 자료 부족을 표시한다. 예정 휴게와 확인된 실제 휴게를 분리한다. 퇴근 후 실제 근로·예정 휴게 일치 확인은 사실 개정에 결속하고 사실 입력이 바뀌면 재확인을 요구한다. 실제 근로·휴게에 영향을 주는 대기 정정은 현재 정상 확정을 보류하고 이전 산정값을 참고 이력으로 표시한다.

XLSX에는 고객사·필터·기간·생성 시각·시간대·단위·결과 버전·미확정/오래됨·검토용 표시를 포함한다. 기본 데이터 열은 사번·이름·소속·근무일·일정·유효 출퇴근·확인 휴게·근로량·휴가·예외·정책/규칙/결과 버전이다. 확인된 일8시간 초과량 `over_8h_millis`와 주40시간 초과 참고량 `over_40h_millis`를 각각 표시하고 법정 가산 최종값 `legal_overtime_millis`는 MVP 미지원 null로 남긴다. 야간·휴일 등 중첩 분류를 더해 총 실근로를 만들지 않는다. 자유 사유·이메일·IP·민감 감사 원문은 기본 열에 넣지 않는다. 근로량은 밀리초 정본 열과 사람이 읽는 표시를 제공하며 분 단위 절삭 합산을 하지 않는다.

## 4. 공통 입력·출력 계약

| 계약 | 정의 |
| --- | --- |
| 식별자 | UUID 문자열. 경로 ID는 현재 tenant·객체 범위에서 다시 조회 |
| 날짜 | ISO `YYYY-MM-DD`; 조회 범위 양 끝 날짜 포함, 내부 반개구간으로 변환 |
| 시각 | 오프셋 포함 ISO instant 또는 화면의 Asia/Seoul 날짜+시각. 밀리초 정밀도, 모호한 값 거부 |
| 출퇴근 시각 | 직접 기록 요청에는 입력하지 않음. 서버의 수신 시각만 원천으로 채택 |
| 기간·목록 | 시작≤종료, 페이지·정렬 허용 목록. 조회/출력 최대 범위는 Phase4 부하 검증 후 명시 |
| `commandId` | 브라우저가 동일 작업 재시도 때 보존하는 UUID. 같은 키·다른 입력은 충돌 |
| `expectedVersion` | 신청·설정의 현재 버전. 오래된 버전은 409, 묵시 덮어쓰기 없음 |
| `baseInputRevision` | 정정·근로/휴게 확인이 참조한 사실 입력 개정. 출퇴근·일정·승인효력 변경 때 충돌 검토 |
| `expectedReviewRevision` | 검토 증거의 동시 변경 방지용 개정. 정정 제출·확인 저장은 review_revision만 증가시키고 사실 개정은 유지 |
| 권한 필드 | tenant_id·행위자·신청자·승인 권한·차감량은 서버 결정. 고객사 설정의 대상 사원도 범위 검증 |
| 응답 형식 | `text/html` 전체/부분, XLSX MIME 바이너리. 공개 JSON 응답 계약 없음 |
| 공통 메타데이터 | requestTraceId, 저장 여부, 현재 버전, input_revision/review_revision, 재조회 경로. 개인정보 없는 식별값만 노출 |

## 5. 서버 렌더링 URL·명령 계약

아래 POST는 폼 인코딩을 기본으로 하고 CSRF·commandId를 포함한다. 성공은 일반 폼에서 303 후 GET, htmx에서는 200 부분 HTML과 최신 상태를 반환한다. 로그인·토큰 수락의 성공은 해당 인증 흐름의 안전한 화면으로 이동한다.

| 메서드·경로 | 입력 | 성공 결과·출력 | 주요 오류 |
| --- | --- | --- | --- |
| GET `/login`, POST `/login` | 회사 코드·이메일·비밀번호·CSRF | 인증 세션·본인 화면 이동 | 인증 실패·429 |
| POST `/logout` | CSRF | 세션 폐기·로그인 이동 | CSRF 실패 |
| POST `/invite/{companyCode}/accept` | 목적별 토큰·새 비밀번호 | 토큰 소비·계정 활성화·안전한 로그인 연결 | 만료·재사용·소속 불일치 |
| POST `/password-reset/request` | 회사 코드·이메일 | 존재 여부와 무관한 동일 접수 화면 | 429 |
| POST `/password-reset/complete` | 회사 코드·토큰·새 비밀번호 | 일회성 소비·기존 세션 폐기 | 만료·재사용·용도 불일치 |
| GET `/me/today`, `/me/attendance` | 기준일 또는 from/to·page | 본인 기록·일정·상태·버전 | 401·422 |

## 6. HTTP 오류·부분 갱신 계약

| HTTP | 의미·대표 코드 | 사용자 처리 |
| --- | --- | --- |
| 400 | MALFORMED_INPUT | 형식 오류, 서버 상세·SQL 비노출 |
| 401 | AUTH_REQUIRED / SESSION_EXPIRED | 업무 동작 미실행, 로그인 이동·재조회 |
| 403 | FORBIDDEN / CSRF_INVALID / IP_NOT_ALLOWED | 권한·CSRF·네트워크 안내, IP 실패는 정정 경로 |
| 404 | RESOURCE_NOT_FOUND | 존재와 범위 밖을 구분해 노출하지 않음 |
| 409 | VERSION_CONFLICT / ALREADY_PROCESSED / COMMAND_CONFLICT | 최신 상태·이력 재조회, 자동 덮어쓰기 없음 |
| 422 | VALIDATION_FAILED / BALANCE_INSUFFICIENT / REVIEW_REQUIRED | 필드·업무 사유와 해결 경로, 입력 보존 |
| 429 | RATE_LIMITED | 재시도 시점 안내, 우회 제공 없음 |
| 500·503 | INTERNAL_ERROR / TEMPORARILY_UNAVAILABLE | 요청 ID·처리 확인 경로, 중복 재시도 방지 |

전체 HTML과 부분 HTML의 상태 코드·업무 의미는 동일하다. htmx의 기본 4xx 처리에 의존하지 않고 폼 오류 fragment를 안전하게 표시하는 응답 처리 계약을 검증한다. 부분 요청의 세션 만료는 로그인 문서가 작은 영역에 삽입되지 않게 전체 화면 이동으로 처리한다. 부분 응답으로 권한 오류를 성공 상태로 바꾸지 않는다.

## 7. 모바일·접근성·수용 검증

핵심 버튼은 좁은 화면에서도 누를 수 있고 레이블·키보드·포커스·오류 연결을 제공한다. 긴 표는 필수 열 우선 카드 또는 가로 스크롤로 보여 주며 상태를 색만으로 구분하지 않는다. htmx 갱신은 처리 중·완료·오류를 보조기술에 전달한다. 파일 다운로드와 관리자 대량 목록도 모바일에서 상태를 확인할 수 있어야 한다.

화면 수용 검증은 JS 비활성 폼, 부분 오류 표시, 로그인 만료, 연속 클릭·동일 키 재시도, 타 고객사 ID·권한 회수, 취소 대기 표시, 미확정 null/0 구별, 날짜 경계·주 자료 부족, XLSX 필터·버전·단위 일치를 포함한다. 확인 저장·정정 제출이 스스로 사실개정 충돌을 만들지 않음, 사실변경 뒤 재확인, 검토개정만 바뀐 결과의 오래됨도 확인한다. 실제 브라우저·화면·HTTP·애플리케이션 테스트는 현재 실행하지 않았다.
