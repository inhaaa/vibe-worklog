## 선택할 디자인 방향

| 안 | 형태 | 장점·범위 |
| --- | --- | --- |
| **A. 밝은 워크스페이스 — 권장** | 옅은 회색 배경·흰 패널·블루 강조·짙은 네이비 타이포, 왼쪽 메뉴·상단 현재 고객사/역할·본문/상세 패널 | 개인 업무와 관리자 업무를 한 구조에서 명확히 구분. 기존 SSR 화면을 단계적으로 정돈하기 적합 |
| B. 개인 대시보드 | 오늘 일정·출퇴근·휴가를 크게 배치하고 관리 업무는 별도 영역으로 이동 | 직원의 일상 사용에 집중. 담당자의 표·필터·설정은 별도 화면으로 연결 |
| C. 달력 중심 | 주·월 달력과 선택 날짜의 우측 상세를 중심으로 구성 | 날짜별 이해가 쉬움. 기존 일정·휴일의 표현 범위와 모바일 상세 전환을 먼저 검토해야 함 |

A를 기준으로 B의 오늘 요약과 C의 일정 화면 구성을 조합하는 안을 제안한다. 여러 작업 탭·조직도·차트·새 집계/달력 API·새 승인 기능을 함께 추가하는 범위는 아니다.

## 소개 → 데모 진입과 인증 경계

1. 로컬 데모의 첫 주소 `/`에서 소개 화면(신규 경로안 `/demo`)으로 안내한다. 제품의 핵심 흐름과 합성 데모 표시를 보여 주고 **데모로 입장** 버튼을 제공한다. 아이디·비밀번호 입력 화면은 거치지 않는다.
2. 실제 기능 체험안은 버튼이 **기존 CSRF가 있는 정상 로그인 흐름**을 수행한 뒤 `/me/today`로 이동한다. 공개 합성 자격과 고정 데모 tenant를 사용하며 실제 DB 해시·활성/재직·현재 역할·세션 교체·속도 제한·RLS를 유지한다.
3. `local`+`local-demo`에서만 제공하고 일반 프로필의 회사코드·이메일 로그인은 유지한다. 데모 자료 부재·해시 불일치·비활성·역할 회수는 안내 후 실패하며 자동으로 복구하지 않는다. 고객사/역할 선택값으로 인증 범위를 바꾸지 않는다.

현재 데모 계정은 **EMPLOYEE·ATTENDANCE_ADMIN**이며 APPROVER·서비스 운영자 권한은 없다. 지정 승인함을 보여 주기 위해 새 역할을 주거나 자기 승인을 허용하지 않는다. 업무 경로 공개·가짜 principal·DB 검증 생략은 적용하지 않는다.

**대안은 읽기 시연 전용 `/demo`**다. 합성 view-model로 화면 이동과 역할별 모습을 보여 주고 실제 DB·인증 세션·업무 변경 API를 호출하지 않는다. 실제 동작 체험안과 읽기 시연안 중 어느 범위를 채택할지 승인받는다.

## 제안 메뉴와 현재 실제 경로

| 메뉴 묶음 | 화면·현재 경로 | 표시 권한 |
| --- | --- | --- |
| 내 업무 | 홈 `/me/today`, 날짜별 근태 `/me/attendance` | 본인 |
| 내 업무 | 휴가·신청 `/me/requests`, 정정 `/me/requests/correction`, 주·월 근로시간 `/me/worktime` | 본인 |
| 승인 업무 | 지정 승인함 `/approvals`, 신청 상세 `/requests/{id}` | 실제 APPROVER 및 상세의 허용 관계자 |
| 인사 관리 | 조직 `/admin/organizations`, 직원 `/admin/employees`, 계정·승인자 `/admin/employees/{id}/access` | ATTENDANCE_ADMIN |
| 근무 설정 | 템플릿 `/admin/schedules`, 사원 배정 `/admin/employees/{id}/schedule`, 휴일 `/admin/calendar`, 허용망 `/admin/networks` | ATTENDANCE_ADMIN |
| 휴가 관리 | 기초 연차 `/admin/leave-balances`, 고객사 신청 `/admin/requests` | ATTENDANCE_ADMIN |
| 현황·검토 | 근태·Excel `/admin/attendance`, 정책 검토 `/admin/work-policies`, 감사 `/admin/audit` | ATTENDANCE_ADMIN |
| 별도 운영 콘솔 | `/operator/login`, `/operator/tenants` | 서비스 운영자 별도 인증. 고객사 업무 메뉴와 분리 |

메뉴 숨김과 서버 권한 검증을 함께 유지한다. [화면 설계](screens.md)의 초기 경로와 다른 곳은 현재 controller 경로를 기준으로 연결한다. 직원/승인자/담당자 시연 전환을 제공한다면 합성 화면 표시 기능으로 구분하고 실제 권한 전환으로 사용하지 않는다.

## 공통 화면과 상태 원칙

- **레이아웃:** 현재 템플릿별 상단 메뉴를 공통 sidebar/header로 정돈하고 선택 메뉴·페이지 제목·고객사·역할을 일관되게 표시한다. 기존 Thymeleaf·htmx와 폼/목록 fragment·서울 시각 표시를 재사용한다.
- **홈:** 오늘 일정·출퇴근·휴가/신청 상태와 필요한 다음 행동을 우선한다. 기존 자료만 표시하고 시안의 예시 숫자는 합성 표본으로 명시한다.
- **일정·직원:** 달력/목록 선택과 상세의 연결, 검색·필터·표·폼을 일관되게 만든다. 새 근무 편성·조직도·대량 승인·집계 API는 추가하지 않는다.
- **빈 상태·오류:** 자료 없음·일정 미배정·권한 없음·저장 실패·세션 만료를 구분하고 해당 상태에서 가능한 다음 행동을 보여 준다. 자동 재시도·덮어쓰기로 상태를 숨기지 않는다.
- **계산 상태:** 미확정·대기·오래됨·실제 0·검토용을 서로 구분한다. 버전·단위·Asia/Seoul·원천/정정 구분과 CSRF·명령 ID·동시성 필드를 유지한다.
- **모바일·접근성:** 데스크톱/390px 화면을 검토하고 sidebar는 접근 가능한 접이식 메뉴, 상세는 독립 화면/영역으로 전환한다. 키보드·포커스·레이블·현재 메뉴·오류 연결·명도 대비를 확인하며 색만으로 상태를 구분하지 않는다. 소개 모션은 감소 설정을 존중한다.

## 승인과 진행 순서

1. 이 문서의 방향 A/B/C, 실제 체험/읽기 시연, 메뉴 구분을 검토한다.
2. **소개·홈·일정·직원 목록의 1차 시안**을 데스크톱/모바일과 정상·빈 상태 중심으로 먼저 제시해 승인받는다.
3. 승인 후 구현 계획을 세우고 공통 SSR shell → 개인 업무 → 관리자 목록/상세/설정으로 확장한다. 인증·권한·계산 정책은 유지하며 관련 회귀·실제 브라우저 수용을 확인한다.

이 문서는 구현 승인이나 완료 보고가 아니다. 제품 HTML/CSS·라우트·인증·DB 변경은 아직 수행하지 않았으며 실제 참고 자료와 제안 범위를 기록했다.
