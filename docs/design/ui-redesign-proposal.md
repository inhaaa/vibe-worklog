[PRD](../prd.md)·[화면 계약](screens.md)·[로컬 데모 계약](local-demo-login.md)의 업무·권한·DB 경계를 유지하며 실제 회귀·브라우저·실행 이미지 검증은 [워크스페이스 UI 품질 보고](../quality/workspace-ui.md)에 구분해 기록한다.

## 검토한 디자인 방향과 채택

| 안 | 형태 | 장점·범위 |
| --- | --- | --- |
| **A. 밝은 워크스페이스 — 채택** | 옅은 회색 배경·흰 패널·블루 강조·짙은 네이비 타이포, 왼쪽 메뉴·상단 현재 고객사/역할·본문/상세 패널 | 개인 업무와 관리자 업무를 한 구조에서 구분하고 기존 SSR에 연결 |
| B. 개인 대시보드 | 오늘 일정·출퇴근·휴가를 크게 배치하고 관리 업무는 별도 영역으로 이동 | 직원의 일상 사용에 집중. 담당자의 표·필터·설정은 별도 화면으로 연결 |
| C. 달력 중심 | 주·월 달력과 선택 날짜의 우측 상세를 중심으로 구성 | 날짜별 이해가 쉬움. 기존 일정·휴일의 표현 범위와 모바일 상세 전환을 먼저 검토해야 함 |

A를 기준으로 B의 오늘 요약과 C의 일정 구성을 조합했다. 승인 범위는 소개·홈·개인 달력·직원 목록과 기존 화면의 공통 shell 연결이다. 여러 작업 탭·조직도·차트·공개 집계/달력 API·새 승인 기능은 후속 검토 범위다.

## 소개 → 데모 진입과 인증 경계

1. 로컬 데모의 GET `/`·`/login`에서 소개 `/demo`로 안내한다. 합성 데모 표시와 **데모로 입장** 버튼을 제공한다. GET 소개만으로는 업무 인증이 생성되지 않는다.
2. 입장 버튼은 `email=admin`·`password=admin` hidden 필드와 Thymeleaf CSRF를 **기존 POST `/login`**에 제출해 성공 후 `/me/today`로 이동한다. 고정 데모 tenant와 실제 DB 해시·활성/재직·정확한 현재 역할·세션 교체·속도 제한·RLS를 유지한다.
3. `local`+`local-demo`에서만 제공하고 일반 프로필의 회사코드·이메일 로그인은 유지한다. 데모 자료 부재·해시 불일치·비활성·역할 회수는 안내 후 실패하며 자동으로 복구하지 않는다. 고객사/역할 선택값으로 인증 범위를 바꾸지 않는다.

현재 데모 계정은 **EMPLOYEE·ATTENDANCE_ADMIN**이며 APPROVER·서비스 운영자 권한은 없다. 지정 승인함을 보여 주기 위해 새 역할을 주거나 자기 승인을 허용하지 않는다. 업무 경로 공개·가짜 principal·DB 검증 생략은 적용하지 않는다.

기획 단계에서 검토한 **합성 view-model만 사용하는 읽기 시연안**은 대안 이력으로 보존한다. 채택한 흐름은 정상 인증 후 실제 저장 자료와 기존 업무 폼을 사용하는 로컬 데모다. 실패·로그아웃 목적지는 기존 `/login`을 유지하고 소개로 전달할 때 `error`·`logout` 플래그만 보존한다.

## 제안 메뉴와 현재 실제 경로

| 메뉴 묶음 | 화면·현재 경로 | 표시 권한 |
| --- | --- | --- |
| 내 업무 | 홈 `/me/today`, 개인 달력 `/me/schedule`, 날짜별 근태 `/me/attendance` | 본인 |
| 내 업무 | 휴가·신청 `/me/requests`, 정정 `/me/requests/correction`, 주·월 근로시간 `/me/worktime` | 본인 |
| 승인 업무 | 지정 승인함 `/approvals`, 신청 상세 `/requests/{id}` | 실제 APPROVER 및 상세의 허용 관계자 |
| 인사 관리 | 조직 `/admin/organizations`, 직원 `/admin/employees`, 계정·승인자 `/admin/employees/{id}/access` | ATTENDANCE_ADMIN |
| 근무 설정 | 템플릿 `/admin/schedules`, 사원 배정 `/admin/employees/{id}/schedule`, 휴일 `/admin/calendar`, 허용망 `/admin/networks` | ATTENDANCE_ADMIN |
| 휴가 관리 | 기초 연차 `/admin/leave-balances`, 고객사 신청 `/admin/requests` | ATTENDANCE_ADMIN |
| 현황·검토 | 근태·Excel `/admin/attendance`, 정책 검토 `/admin/work-policies`, 감사 `/admin/audit` | ATTENDANCE_ADMIN |
| 별도 운영 콘솔 | `/operator/login`, `/operator/tenants` | 서비스 운영자 별도 인증. 고객사 업무 메뉴와 분리 |

공통 sidebar는 실제 `EMPLOYEE`·`APPROVER`·`ATTENDANCE_ADMIN` 역할별 메뉴를 표시하고 서버 권한 검증을 함께 유지한다. 관리자만 가진 계정의 기존 관리 권한도 보존한다. [화면 설계](screens.md)의 초기 경로와 다른 곳은 현재 controller 경로를 기준으로 연결하며 화면에서 역할을 임의 전환하지 않는다.

## 공통 화면과 상태 원칙

- **레이아웃:** 공통 sidebar/header·접이식 모바일 메뉴에 실제 고객사·본인·역할을 표시한다. 본인 tenant로 조회하고 현재 인증을 재확인하며 공통 모델을 redirect query에 넣지 않는다. 기존 Thymeleaf·htmx·서울 시각 표시와 업무 폼의 CSRF·명령 ID·동시성 필드를 보존한다.
- **홈:** 기존 본인 일정 snapshot·유효 출퇴근·원장 잔여·대기/최근 신청·주간 날짜별 상태를 조합한다. 화면 시안의 인명·연차8일·32시간·출근 시각을 업무 값으로 하드코딩하지 않고 미등록·미배정·미확인을 표시한다.
- **개인 달력:** GET `/me/schedule?month=YYYY-MM&date=YYYY-MM-DD`의 본인 월/선택 날짜 SSR다. 둘 다 생략하면 서울 기준 오늘을 사용하고 선택 날짜는 조회 월 안에 있어야 한다. 일정·휴일·원천/정정·신청과 승인/취소 효력을 기존 읽기 경계로 조회하고 예정 시간을 실제 근로로 확정하지 않는다.
- **직원 목록:** GET `/admin/employees`의 `q`·0부터 시작하는 `page`·`organizationId`·`status=all|active|inactive`·`employeeId`로 검색·현재 소속·활성 상태·현재 페이지 안의 선택 상세를 연결한다. 목록은 최대50명이며 통계는 **필터를 적용한 현재 페이지**의 직원·활성·비활성 수다. 전체 고객사 인원·재직자 수로 표현하지 않는다. 원래 등록 폼·상세 수정·계정/역할/승인자·일정 배정 연결을 유지한다.
- **빈 상태·오류:** 자료 없음·일정 미배정·권한 없음·저장 실패·세션 만료를 구분하고 해당 상태에서 가능한 다음 행동을 보여 준다. 자동 재시도·덮어쓰기로 상태를 숨기지 않는다.
- **계산 상태:** 미확정·대기·오래됨·실제 0·검토용을 서로 구분한다. 버전·단위·Asia/Seoul·원천/정정 구분과 CSRF·명령 ID·동시성 필드를 유지한다.
- **모바일·접근성:** 데스크톱/390px 화면을 검토하고 sidebar는 접근 가능한 접이식 메뉴, 상세는 독립 화면/영역으로 전환한다. 키보드·포커스·레이블·현재 메뉴·오류 연결·명도 대비를 확인하며 색만으로 상태를 구분하지 않는다. 소개 모션은 감소 설정을 존중한다.

## 승인 이력과 검증 구분

1. 최초 제안에서 A/B/C와 실제 체험/읽기 시연을 비교했다.
2. 소개·홈·일정·직원 목록의 A안 시안을 제시한 뒤 사용자가 제품 적용과 입력 없는 정상 데모 진입을 승인했다.
3. [적용 계획](../superpowers/plans/2026-10-26-workspace-ui.md)에 따라 공통 SSR shell·본인 조회·관리자 목록을 구현했다. 업무 스키마·인증/인가·근태 계산 정책·기존 변경 폼은 유지한다.

이 문서는 제안 이력과 승인된 적용 계약이다. 전체 회귀·실제 브라우저·HTTP·이미지의 수행 범위, 통과 수와 화면 증거는 [품질 보고](../quality/workspace-ui.md)에 실제 결과대로 남긴다. 설계 반영을 검증 완료나 외부 운영 수용으로 확대하지 않는다.
