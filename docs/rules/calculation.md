# 근태 계산·종일 연차 업무 규칙

회사별 휴가의 사용량, 유급 인정시간과 실근로시간은 각각 집계한다. 유급·무급 모두 사용 휴가 일수에 포함하고, 유급휴가만 해당 근무일의 기준시간과 사용 단위에 따라 선택근무 정산에 반영한다. 휴가 승인으로 실근로를 생성하지 않는다. [회사별 휴가 운영](../superpowers/plans/2026-11-20-company-leave-operations.md)

2026-11-18 확장에서는 같은 날 유효한 반차를 0.5일씩 합산한다. 반차만 승인된 근로일은 남은 근무의 기록과 확인을 필요로 한다. [반차 계산·검증 기준](../superpowers/specs/2026-11-18-attendance-codes-half-day.md)

2026-11-20 확장에서는 선택근무조의 목표를 근로일별 표준분으로 계산한다. 직원과 담당자는 정산기간의 목표, 확인 실근로와 승인 휴가를 각각 조회하며, 하루 8시간 초과를 선택근무의 법정 연장으로 확정하지 않는다. [선택근무 계산과 수용 사례](../superpowers/specs/2026-11-20-selective-work.md)

## 1. 상태와 적용 범위

- 문서 버전: `CALC-1`, 작성·공식 자료 조회일: **2026-10-24, Asia/Seoul**.
- [PRD](../prd.md)의 D01~D05와 후속 범위 결정을 계산 입력·결과·검증 사례로 구체화한다.
- 정상 지원: 사원별 적용일이 있는 여러 고정 템플릿, 당일 시작·종료하는 하루 한 근무 구간, 종일 및 반일 연차.
- 시간 단위 휴가, 연차 자동 발생·이월·소멸, 급여 계산은 후속 범위다. 근태 마감 이후 계산은 [회사 근태 월 마감과 재개](../superpowers/specs/2026-11-19-attendance-month-close.md)를 따른다. 연장근무 사전승인 분은 실제 기록과 별도로 대조한다.
- 이 문서는 업무 명세다. 실행 가능한 테스트, Java·SQL·DB 객체·설정을 만들거나 실행하지 않는다.

아래의 **법령 확인**과 **제품 정책**을 구분한다. 법령 원문을 확인해도 개별 사업장·근로자에 대한 적용과 적법성이 자동 확정되지는 않는다. 미확인 대상·예외·사실관계는 `REVIEW_REQUIRED`로 표시한다.

표준 법정 기준의 정상 산정 검증 대상은 근로기준법 일반 규정이 적용되는 성인 통상근로자의 고정 근무다. 단시간·연소자·임신 및 출산 보호·제63조 적용 제외·특례업종·유연근무의 별도 기준은 검증 후 확장한다. 해당 직원의 기록을 버리거나 권리가 없다고 판정하지 않는다.

### 2.2 운영 전 법 적용 확인

- 근태 담당자는 적용 대상 구분·검토자·검토일·근거를 등록한다. 미확인 상태를 기본 법정 정상 판정으로 바꾸지 않는다.
- 회사 주 기산점·휴일·근로계약·취업규칙·휴게의 실제 운영은 고객별 근거 확인 대상이다.
- 법령 개정 또는 예외 판정은 새 규칙 버전과 적용일로 관리한다. 과거 소급 적용은 별도 근거가 필요하다.
- 본 문서는 2026-10-24에 조회한 범위의 기록이며 이후 현행성, 모든 부칙·판례·행정해석의 완전한 검토를 보장하지 않는다.

## 3. 계산 입력과 결과의 의미

### 3.1 입력 계약

| 입력 | 필수 의미·검증 |
| --- | --- |
| 테넌트·사원 | 인증된 소속에서 결정하며 다른 테넌트 자료를 참조하지 않음 |
| 기준 근무일 | `Asia/Seoul`의 날짜, 실제 시각과 분리 |
| 템플릿 배정 | 해당 날짜에 유효한 배정 한 건과 불변 버전, 소정 요일·시작·종료·예정 휴게 |
| 휴일 캘린더 | 해당 날짜의 근로일·비근로일·휴일 구분, 종류·출처·버전 |
| 원천 출퇴근 | 사건 ID·종류·실제 발생시각·서버 수신시각·기록 경로·재시도 식별자 |
| 유효 정정 | 승인된 변경값·사유·승인자·처리시각·원천 사건과의 관계 |
| 대기 정정·충돌 | 해당 날짜의 실제 근로 유무·시각·휴게에 영향을 주는 미처리 정정과 충돌 사유·`review_revision` |
| 실제 근로 확인 | 체류 중 실제 근로 구간·실제 휴게 구간·확인자·근거·대상 사실 개정 `confirmed_input_revision`·`review_revision` |
| 승인된 휴가 | 날짜별 종일 연차 효력과 원장 차감·복원 참조 |
| 규칙 선택 | 적용일에 맞는 `rule_version`, 법 적용 검토 결과 |

템플릿에는 예정 휴게를 포함하지만 실제 휴게로 단정하지 않는다. 퇴근 기록 후 직원은 예정 휴게와 실제가 같은지 확인하고, 차이가 있으면 정정 신청으로 실제 구간을 남긴다. 확인 전에는 체류시간만 산출하고 실제 근로를 확정하지 않는다.

`input_revision`은 출퇴근·일정·승인 정정 등 사실 입력 개정, `review_revision`은 대기 정정 상태·실제 근로 및 휴게 확인 증거의 개정이다. 정정 제출·철회·반려나 확인 증거 저장 자체는 사실 입력을 바꾸지 않고 검토 개정과 재집계 필요만 갱신한다. 정정 신청의 `base_input_revision`과 확인의 `confirmed_input_revision`은 사실 개정과 대조하므로 자체 제출·확인 때문에 즉시 불일치하지 않는다.

실제 근로·휴게 확인 증거는 대상으로 삼은 사실 입력 버전에만 유효하다. 출퇴근·일정·휴게 사실 입력이 바뀌면 이전의 예정 휴게 일치 확인을 자동 재사용하지 않고 `REVIEW_REQUIRED`로 재확인한다. 승인된 정정에 실제 구간 근거가 포함되면 승인으로 생성된 새 사실 입력 개정에 결속된 확인 증거로 사용할 수 있다.

직원 확인과 승인된 정정도 법률상 최종 증명으로 표시하지 않는다. 지휘·감독 아래의 대기, 호출 대응 등 의심되는 구간은 단순 휴게로 공제하지 않으며 근태 담당자가 근거를 검토한다. [실근로의 법적 출발점][L04]·[자유 이용 휴게][L06]

| `over_8h_millis` | 일반 기준의 일 실근로 8시간 초과량이라는 확인된 분류량 | 대상·실근로 미확인이면 `null` |
| `over_40h_millis` | 같은 주 실근로 합계의 40시간 초과량이라는 확인된 분류량 | 주 전체 자료 미확정이면 `null` |
| `night_work_millis` | 확인된 실제 근로와 야간 구간의 교집합 | 자정 등 미지원 귀속이면 `null` |
| `holiday_work_millis` | 확인된 휴일에 실제 근로한 시간 | 휴일 효력·실근로 미확인이면 `null` |
| `legal_overtime_millis` | 가산 대상 연장시간의 법적 최종 분류 | MVP 자동 확정 미지원으로 `null` |
| `leave_days` | 승인 처리에 사용할 종일 차감량, 정수 `DAY` | 일정·원장 요건 미충족 시 승인 차단 |

`over_8h_millis`·`over_40h_millis`는 확인된 실근로에서 기준을 초과한 정확한 양이며, 화면·xlsx에 각각 명시한다. 가산 지급 대상의 최종 법적 확정과 구분하는 참고 분류다. 야간·휴일과 서로 배타적이지 않으므로 모두 더해 총 실근로시간을 만들지 않는다. 소정 초과와 법정 연장, 제53조 한도 판단과 제56조 가산 판단을 같은 필드로 만들지 않는다. [근로시간][L04]·[한도][L05]·[가산 구분][L09]·[행정해석][L15]

### 3.3 결과 상태

| 상태 | 의미·제품 동작 |
| --- | --- |
| `CALCULATED` | 지원 범위의 필수 입력이 확인되어 해당 계산 값을 산출함. 법적 적합 인증은 아님 |
| `REVIEW_REQUIRED` | 미확인·충돌·미지원이 존재함. 사유 코드·원천·마지막 산정값을 함께 표시 |
| `NO_SCHEDULED_WORK` | 확정된 비근로일·휴일이며 실제 기록도 없음. 실근로 0의 근거를 표시 |

확인 필요 결과는 정상 확정·0으로 치환하지 않는다. 산출 가능한 체류시간 등은 별도 표시할 수 있지만, 총계에는 확인된 부분합·미확정 건수를 함께 제시한다. 월 전체 확정값처럼 보이는 무표시 부분합은 금지한다. 직원 근로시간 화면은 이 건수를 '확인 전' 일수로 보이며, 미래 날짜와 기록 없이 0시간으로 확정되는 날은 부분합에 더할 값이 없으므로 세지 않는다. 입사일 전·퇴사일 후는 근무 대상이 아니므로 세지 않고 화면에 값을 비워 둔다.

원천이 없는 비근로일·승인 연차일도 누락 근로 등을 다투는 정정이 대기 중이면 실근로 0을 현재 확정값으로 사용하지 않는다. 영향 일·주·월은 `REVIEW_REQUIRED`와 미확정 건수를 표시하고 해당 실근로는 `null`로 둔다. 기존 0 결과는 과거 이력으로 보존하며 승인된 정정 반영 후 새 입력 버전으로 재집계한다.

화면의 `CALCULATED` 표시는 **지원된 사실·시간 계산을 완료했다는 상태**다. 법률 전체 판정 상태가 아니다. `legal_overtime_millis`의 미지원·미확정 사유와 법 적용 검토 상태를 별도 표시하며, 이 값이 `null`인 결과를 법적 정상·급여 확정이라고 안내하지 않는다.

## 4. 고정 근무 기본 산정

### 4.1 정상 산정 순서

1. 근무일의 사원 재직·일정 배정·캘린더·규칙 버전을 선택한다. 배정 누락·중복은 확인 필요다.
2. 원천 사건과 승인된 정정으로 유효 출근 한 건·퇴근 한 건을 정한다. 원천을 덮어쓰지 않는다.
3. 출근 < 퇴근이고 같은 `Asia/Seoul` 날짜인지 확인한다. 구간은 시작 포함·종료 제외로 다룬다.
4. `presence_millis = 퇴근 시각 - 출근 시각`을 산출한다. 자동 퇴근·일정 시각 대체는 하지 않는다.
5. 실제 근로·휴게 확인이 끝난 구간만 계산한다. 확인된 휴게는 겹침을 합친 합집합으로 한 번 공제한다.
6. `actual_work_millis = 확인된 근로 대상 구간 길이 - 그 안의 확인된 실제 휴게 길이`로 산출한다.
7. 일정 밖·휴일·야간·누락·휴가 충돌 등 사유를 분류하고 일·주·월 집계를 새 버전으로 만든다.

출퇴근 사이를 전부 실제 근로로 기본 확정하지 않는다. 정상 흐름에서는 직원이 그 구간의 실제 근로와 예정 휴게 일치를 확인한다. 근무 중 사적 이탈·외출·대기 사실이 다르면 정정·검토 대상으로 남긴다.

### 4.2 휴게·지각·조퇴

- 실제 휴게는 출퇴근 구간 내부이며 시작 < 종료여야 한다. 구간 밖·역전·상충 자료는 오류 사유로 남긴다.
- 휴게가 일부 겹치면 중복 공제하지 않는다. 겹친 원래 입력과 합집합 결과를 모두 추적한다.
- 예정 휴게를 쉬지 못했다면 실제 확인·정정에 따라 실근로를 늘려야 한다. 일정에 있다는 이유로 공제하지 않는다.
- 법정 휴게 부족 우려를 경고해도 부족분을 임의 생성해 실근로에서 빼지 않는다. [법정 휴게][L06]
- 지각·조퇴의 일정 차이는 참고 값이다. 분 단위 유예·급여 공제·징계 자동 판단은 없다.
- 근로시간이 짧아도 예정 시간을 채워서 보여주지 않는다. 승인된 종일 연차는 실제 근로시간으로 더하지 않는다.
- 승인된 종일 연차일에 실제 기록이 없으면 실근로 0·휴가 1일을 구분해 산출한다. 일반 소정근로일의 무기록은 결근 0시간으로 자동 확정하지 않는다.

### 4.3 일정 밖·중복·미지원 기록

- 소정 구간 밖 기록도 원천 보존한다. 사전 신청이 없다는 이유로 추가 실제 근로를 0으로 만들지 않는다.
- 추가 근무 신청은 후속이므로 일정 밖 근로는 `EXTRA_WORK_REVIEW` 사유와 함께 담당자가 확인한다.
- 확인된 실제 근로량은 보존하되 가산 대상·당사자 합의·법정 한도 충족 여부는 자동 정상 판정하지 않는다.
- 동일 재시도 식별자의 같은 요청은 사건 한 건으로 반영한다. 서로 다른 출근 두 건은 임의로 첫 건만 채택하지 않는다.
- 여러 출퇴근 구간·퇴근 선행·미퇴근·자정 통과는 `REVIEW_REQUIRED`다. 자동 날짜 분할·임의 잘라내기를 하지 않는다.
- 2026-11-16부터 출퇴근 기록은 같은 근무일의 같은 구분 두 번째 기록을 409로 거절한다([홈 출퇴근 위젯 설계](../superpowers/specs/2026-11-16-home-clock-widget-design.md) W2). 위의 같은 구분 중복·여러 구간 규칙은 그 전에 저장된 기록에 적용한다.
- 종일 연차일의 실제 기록은 근로·휴가 충돌이다. 승인 휴가를 자동 취소하거나 실제 기록을 지우지 않는다.
- 승인된 출퇴근 정정의 취소는 MVP에서 지원하지 않는다. 변경이 필요하면 최신 유효 정정을 참조하는 새 정정 신청으로 심사하고 이력을 연결한다.

## 5. 날짜·주·월·정밀도

### 5.1 경계 정책

- 기준 시간대는 `Asia/Seoul`이다. 실제 시각은 절대시각과 오프셋을 보존하고 근무일은 별도 날짜다.
- 정상 근무일은 출근·퇴근의 같은 한국 날짜다. 자정 통과 근무의 근무일 귀속·휴일 분할은 후속 검증 대상이다.
- 제품 기본 주는 **월요일 00:00 이상~다음 월요일 00:00 미만**이다. 법률이 유일하게 월요일을 정했다는 의미는 아니다.
- MVP 고객은 회사의 실제 주 기산점과 제품 정책의 일치를 확인한다. 다르면 법정 주간 판정을 확정하지 않는다.
- 월 집계는 한국 날짜의 해당 월 근무일을 모은다. 월말에 주가 끊겨도 주간 계산은 같은 주의 인접 월 자료까지 포함한다.
- 월·연도가 바뀌었다는 이유로 원천 사건·주 누계·휴가 유효기간을 초기화하지 않는다.

주 한도 참고량은 확인된 주 실근로를 기준으로 `max(0, 주 실근로 - 40시간)`이다. 일 8시간 초과량을 더해서 제53조제1항의 12시간 한도량으로 대체하지 않는다. 12시간을 넘으면 확인 경고를 남기며, 그 이하라는 이유만으로 합의·휴게 등 모든 의무 준수를 표시하지 않는다. [공식 행정해석 변경][L15]

### 5.2 반올림·초 단위 정책

- 계산 정본은 **밀리초 정수 `duration_millis`**다. 입력 시각도 밀리초 정밀도로 유지한다.
- 밀리초보다 세밀한 신규 입력은 인터페이스 경계에서 오류로 거부한다. 지원 정밀도를 명시하고 조용히 반올림·절삭하지 않는다.
- 구간·일·주·월마다 분 또는 초를 버리거나 올리지 않는다. 합산은 언제나 정본 밀리초로 수행한다.
- 화면은 시·분·초로 표시하고 초 미만은 표시할 때만 버린다. 초 미만 값은 검토용 Excel(밀리초)에서 확인하며 저장·계산·합산은 밀리초를 유지한다.
- 소수 시간 표시가 필요하면 표시용 변환임을 밝히고 정본과 구분한다. 표시 값을 다시 더해 집계하지 않는다.
- 5분·10분·15분 단위 절삭·출퇴근 유예·급여용 반올림은 MVP에서 제공하지 않는다.
- 종일 연차는 정수 `DAY`로 계산한다. 소수 잔여를 올려 정수로 만들지 않는다.

## 6. 종일 연차 계산과 원장

### 6.1 기초 잔여 등록

기초 잔여는 법정 발생 계산 결과가 아니라 고객이 근거를 확인하여 등록하는 시작 자료다. 근로기준법 제60조의 법정 발생·출근 간주·행사기간 적정성은 따로 검증해야 한다. [제60조][L10]

| 자료 | 필수 항목·처리 |
| --- | --- |
| 기초 잔여 묶음 | 사원·`bucket_id`·정수 일수·기준일·사용 가능 시작/종료일·근거 문서 식별·등록자 |
| 검토 증거 | 검토자·검토일·검토 사유, 기준일 전 사용분 포함 여부, 재직·적용 대상 확인 |
| 사용 | 승인 신청 ID·휴가일·차감량·사용한 묶음·승인 처리 참조 |
| 조정 | 증감량·사유·근거·처리자, 기존 기초 자료를 덮어쓰지 않음 |
| 복원 | 원래 사용 행의 참조·취소 승인 참조·복원량, 동일 사용을 한 번만 복원 |

- 발생·기초·사용·조정·복원 이력을 구별한다. 기초 잔여를 실제 발생일 이력으로 위장하지 않는다.
- 기초 자료의 기준일 이전 사용은 그 잔여에 다시 차감하지 않는다. 해당 기간의 소급 신청은 확인 필요다.
- 음수·소수 기초 잔여는 등록하지 않는다. 소수 자료를 가진 고객은 검증된 단위·이관 방안이 정해질 때까지 자동 잔여 기능 대상에서 제외한다.
- 승인 이력이 있는 기초 자료를 수정하지 않는다. 근거가 있는 조정 행으로 차이를 남긴다.
- 담당자 본인의 기초 잔여 등록·증감은 다른 담당자가 수행한다. 이미 승인된 사용량보다 작아지는 감액은 차단한다.
- 일괄 자동 이월·발생·소멸은 없다. 사용 가능 종료일이 지난 묶음은 신규 사용 배정에서 제외하되 법적 소멸로 단정하거나 이력을 지우지 않는다.

### 6.2 신청 차감량

신청 시작일·종료일은 모두 포함한다. 날짜마다 그 날 유효한 사원 일정과 휴일 캘린더를 평가한다. 다음은 종일 연차 제품 단위이며 단시간근로자의 법정 비례 환산을 대신하지 않는다.

| 날짜 조건 | 종일 차감량·동작 |
| --- | --- |
| 재직 중·유효 일정의 소정근로일·휴일 아님 | `1 DAY`, 그 날의 예정 시간과 관계없이 종일 단위 |
| 소정 비근로일 또는 확인된 휴일 | `0 DAY`, 신청 명세에 비차감 사유 표시 |
| 단순 토요일·일요일 | 요일만으로 판단하지 않음. 그 사원의 일정·휴일 속성으로 결정 |
| 일정 배정 누락·중복·휴일 미확인·재직 밖 | 승인 차단, `REVIEW_REQUIRED` |
| 전체 요청 차감량이 0 | 신청 거부, 비근로일만 선택했다는 안내 |
| 기승인 연차와 같은 날짜가 겹침 | 중복 사용 승인 차단, 대기 요청끼리도 중복 신청 차단 |

승인된 휴가일에 일정·휴일을 소급 변경하면 차감량을 조용히 바꾸지 않는다. 영향 날짜·원장·집계에 확인 필요를 붙이고 승인된 정정 또는 취소·재신청 절차로 차이를 반영한다. [정정·취소 흐름](workflow.md)

### 6.3 잔여·연도 경계·동시성

- 잔여는 사용일에 유효한 묶음별 `기초 + 조정 + 복원 - 승인 사용`이다. 승인된 미래 휴가도 이미 차감한 양이며 대기 신청은 차감·예약하지 않는다.
- 화면은 기준일 현재 사용 가능 잔여·미래 승인 사용·대기 신청량을 구분한다. 미래 사용이 반영된 양을 현재 사용량으로 혼동하지 않는다.
- 미래 휴가도 승인 시 사용 행을 한 번 기록한다. 실제 휴가일 도래 시 다시 차감하지 않는다.
- 신청은 전체 기간에 유효한 단일 `bucket_id`를 명시한다. 여러 후보가 있으면 종료일이 이른 묶음을 우선 제안하되 하나의 신청에서 혼합 배분하지 않는다.
- 묶음 유효기간 경계를 넘으면 묶음별로 분리 신청한다. 연도가 바뀌어도 같은 묶음의 유효기간 안이면 기간 선택이 가능하며, 1월 1일에 새 잔여를 자동 생성·이월하지 않는다.
- 요청 전체의 차감량·중복·재직·일정·묶음 잔여를 승인 시 다시 확인한다. 일부 날짜만 성공하는 부분 승인은 없다.
- 신청 후 일정 변경으로 차감량이 달라지면 승인을 차단하고 철회·재신청한다. 변경량을 숨긴 채 승인하지 않는다.
- 동시 승인·조정에서 동일 사원·묶음의 잔여를 원자적으로 검증·반영한다. 잔여 부족이면 승인 효과와 원장 반영 모두 실패한다.
- 중복 승인 재시도는 같은 승인·사용 결과를 돌려주고 추가 차감하지 않는다. 잔여 부족으로 실패한 요청은 승인된 것으로 표시하지 않는다.

### 6.4 취소와 복원 계산

- 상태·권한·허용 시점은 [승인 업무 규칙](workflow.md)을 따른다. 이 문서는 별도 취소 상태 이름을 만들지 않는다.
- 취소 심사 중 원래 휴가 승인·사용 차감은 유효하다. 취소 요청만으로 잔여를 복원하지 않는다.
- 취소 승인 시 원래 날짜별 사용 행을 참조하여 **같은 묶음에 같은 양을 한 번만** 복원한다.
- 복원 시점에 묶음의 사용 가능 기간이 지났다면 그 이력은 복원하되 현재 가용 잔여로 다시 열지 않는다. 필요 시 별도 근거 조정이 필요하다.
- 원래 사용량을 현재 템플릿의 시간·일수로 다시 계산하여 복원하지 않는다.
- 취소·정정 후 관련 일·주·월 결과를 재집계한다. 원장 반영과 재집계 대상을 연결해 재처리 누락을 찾을 수 있어야 한다.

## 7. 정책 버전과 재집계 증거

- 템플릿·배정·휴일·계산 규칙은 유효 시작일·종료일과 불변 버전을 가진다. 같은 날짜의 유효 배정 중복은 허용하지 않는다.
- 승인 결과에는 제출 시 입력과 승인 시 재검증한 입력 버전을 남긴다. 차감량이 바뀌면 기존 요청을 승인하지 않는다.
- 계산 결과마다 대상 테넌트·사원·근무일, `calculation_run_id`, `rule_version`, `input_revision`, `review_revision`, 생성시각을 남긴다. 최신성은 사실·검토 개정 모두 현재 값과 일치할 때만 인정한다.
- 입력 증거에는 원천 사건 ID, 유효 정정 ID, 대기 정정 상태, 사실 개정에 결속된 실제 근로·휴게 확인, 일정·배정·휴일 버전, 휴가·원장 참조가 포함된다.
- 재집계는 과거 결과를 덮어쓰지 않고 새 결과와 이전 결과의 관계·변경 사유·처리자를 남긴다.
- 과거 정책으로 재현과 새 정책을 적용한 재산정을 구별한다. 소급 정책 변경의 법적 타당성을 자동 가정하지 않는다.
- 마감한 월의 최신 근태 결과는 재개 전까지 보존한다. 열린 날짜를 재집계할 때 같은 주에 포함된 마감 날짜는 다시 저장하지 않는다. 월 조회·검토용 xlsx는 집계 기준시각·버전·확인 필요 수를 포함한다.
- 같은 입력·규칙으로 재실행하면 같은 수치·사유를 반환한다. 실행 ID가 다르다고 사용·복원을 다시 반영하지 않는다.

- 일반 규정 외 대상의 근로시간·휴가 비례, 연장·야간·휴일 중첩, 특별연장·대체·보상휴가·장시간 휴게 해석은 검증 필요다.
- 주 기산점, 실제 근로 확인의 증거 수준, 공휴일·임시공휴일 변경 반영은 고객 적용 전에 재확인한다.
- 연차 발생·출근율·개근·사용촉진·사용자 귀책·입퇴사·소멸의 적법성은 기초 잔여 방식으로 해결된 것으로 취급하지 않는다.
- 법정 최종 판정 미지원 항목은 화면·xlsx·인터페이스 모두 같은 사유와 `null`을 유지한다. 빈 칸을 0으로 내보내지 않는다.
- 문서 완료 검증은 상대 링크·표 열 수·후행 공백·다른 명세와 단위·상태·범위 일치를 확인하는 것이다. 코드·DB·실행 테스트는 수행하지 않는다.
