# WorkLog

**출퇴근 기록에서 연차·정정 결재와 근로시간 집계까지 이어지는 근태관리 시스템**

WorkLog는 고정 근무를 운영하는 국내 중소기업을 대상으로 만든 멀티테넌트 웹 애플리케이션입니다. 직원이 남긴 기록, 승인자가 처리한 신청, 담당자가 검토하는 집계를 한곳에서 연결합니다. 집계 화면에서는 어떤 출퇴근 기록과 근무 정책이 결과에 반영됐는지 확인할 수 있습니다.

- **개발 시작** 2026년 10월 23일
- **프로젝트 형태** 1인 개발 포트폴리오 · Claude Code와 Codex를 활용한 AI 보조 개발
- **현재 상태** 고정 근무 MVP 구현 및 로컬 품질 검증 · 가상 데이터 공개 데모

[**WorkLog 공개 데모 열기**](https://worklog.inhaaa.com/demo)

## 데모 둘러보기

1. **WorkLog 시작하기**를 누르면 가상 근태 담당자 계정으로 입장합니다.
2. 홈에서 오늘의 근무 일정과 출퇴근, 연차 잔여, 최근 신청을 확인합니다. 담당자 메뉴에서는 조직·사원 관리와 회사 근무 현황을 볼 수 있습니다.
3. 상단 **사번 변경**에서 가상 직원이나 승인자로 전환합니다. 직원의 **근태 신청** 화면과 승인자의 **대기·처리 완료 결재** 화면을 비교해 볼 수 있습니다.

여러 방문자가 함께 쓰는 가상 업무 공간입니다. 체험 시 실제 이름, 연락처, 근무 사유는 입력하지 마세요. [데모 진입·사번 전환 검증](docs/design/worklog-landing.md)

개발본의 **휴가관리 → 신청·연차 → 연차 관리**에서 회사의 회계 시작월, 연간 부여 일수와 이월 한도를 정합니다. 담당자는 사원별 부여·이월·소멸량을 미리 보고 원장에 반영합니다. 직원은 **내 신청 이력 → 내 연차 원장**에서 오늘 사용 가능한 일수와 신청 승인·취소에 따른 변동을 확인합니다. [회사별 연차 운영 기준](docs/superpowers/plans/2026-11-21-annual-leave-ledger.md) · [PC·모바일 검증 결과](docs/quality/annual-leave-ledger-20261121.md)

개발본에서 담당자는 근무조별 선택 가능 시간대·코어타임·하루 표준시간을 정하고 적용일부터 사원을 배정할 수 있습니다. 직원과 담당자는 같은 주별 또는 월별 정산에서 확인 실근로와 승인 휴가를 대조할 수 있습니다. [선택근무제 업무 명세](docs/superpowers/specs/2026-11-20-selective-work.md) · [PC·모바일 검증 결과](docs/quality/selective-work-20261120.md)

### 직원 · 출퇴근과 내 근태 확인

- **출퇴근 기록** — 회사에서 허용한 네트워크에 접속한 직원이 홈에서 출근·퇴근을 누르면 서버가 수신 시각을 저장합니다. 출근과 퇴근은 근무일마다 각각 한 번 기록하며 화면에는 서울 시각으로 표시합니다. 빠진 기록은 정정을 신청할 수 있고, 자정을 넘긴 기록도 원천을 보존해 확인 대상으로 표시합니다.
- **오늘의 근무와 개인 현황** — 홈에서 오늘의 출퇴근 상태와 이번 주 일정을, 개인 캘린더와 근무현황에서 날짜별 일정·기록·근로시간을 확인합니다. 퇴근 후 실제 근로와 휴게를 확인하면 해당 날짜가 속한 주의 근로시간을 계산합니다. **내 정보**에서 기본 인사정보와 발령 이력 등을 조회할 수 있습니다.
- **종일 연차와 근태 정정 신청** — 연차는 사용할 기간을, 정정은 대상 날짜·요청할 시각이나 휴게 구간·사유를 입력합니다. 제출 전에 결재자와 예상 연차 차감량을 확인할 수 있습니다. 대기 중인 신청은 철회할 수 있고, 승인된 건은 별도로 취소를 요청할 수 있습니다. 연도별 신청 화면은 사용·예정·대기 연차와 현재 사용 가능 잔여를 구분해 보여 줍니다.

### 승인자 · 신청 검토와 처리

- **1단계 결재** — 담당 범위에서 대기 건을 열어 신청 기간, 사유, 정정 전후 내용을 검토하고 승인·반려합니다. 사원별 지정 또는 조직장 기준으로 결재자를 배정할 수 있습니다. 신청에 당시 결재 경로를 남기고 본인이 작성했거나 본인이 대상인 건의 승인을 차단합니다.
- **연차 잔여 반영** — 신청이 대기 중일 때는 잔여를 유지합니다. 승인 시 현재 잔여를 다시 확인해 차감하고, 이미 승인된 연차의 취소가 승인되면 차감분을 복원합니다. 등록·조정·차감·복원은 원장에 남습니다.
- **정정 이력 보존** — 예를 들어 퇴근을 누락한 직원이 실제 퇴근 시각과 사유를 제출하면, 승인자가 검토한 뒤 승인된 정정값을 집계에 사용할 수 있습니다. 원천 기록과 정정 신청·처리 내역을 함께 확인할 수 있습니다.

### 근태 담당자 · 회사 설정과 집계 검토

- **조직·사원·권한 관리** — 조직 계층과 소속, 조직장, 사원의 인사정보·재직 상태를 관리합니다. 소속과 조직장 변경은 적용일 기준으로 남깁니다. 계정 초대와 역할 배정, 결재선 설정을 통해 직원별 접근 범위를 정합니다. 대표는 회사 현황을 읽을 수 있고, 결재에는 별도 승인자 권한과 대상 배정이 필요합니다.
- **근무 기준 설정** — 근무 요일, 시작·종료 시각, 예정 휴게를 묶어 여러 고정 근무 템플릿을 만들고 사원별로 적용 시작일을 지정합니다. 회사 휴일, 출퇴근 허용 네트워크와 사용기간·등록 근거가 있는 기초 연차 잔여도 설정합니다.
- **공통코드와 근태코드 관리** — 업무 화면의 표시·분류에 쓰는 공통코드를 관리합니다. 연차·정정에 쓰는 근태코드는 적용일과 버전을 관리해 각 신청에 어떤 기준이 적용됐는지 확인할 수 있습니다.
- **일·주·월 근로시간과 Excel** — 적용 일정, 유효 출퇴근, 확인된 휴게와 승인된 신청을 바탕으로 집계합니다. 실제 휴게가 확인되지 않았거나 정정이 대기 중인 날은 확인이 필요한 항목으로 표시합니다. 담당자는 계산 당시 입력과 정책 버전을 열어 보고, 필요한 기간을 재집계하거나 생성 시점의 결과를 고정한 검토용 `.xlsx`를 내려받을 수 있습니다. 변경 이력에서는 처리 주체와 시각, 변경 전후를 확인합니다.

### 시스템 설계

1인 개발에서 배포와 운영을 단순하게 유지하기 위해 **모듈형 모놀리스**를 선택했습니다. React 빌드를 Spring Boot JAR에 포함해 하나의 앱에서 화면과 업무 API를 제공합니다. 앱 안에서는 조직·권한, 출퇴근, 신청·결재, 집계의 책임을 나눴습니다. Java 서비스에서 업무 규칙과 트랜잭션을 처리하고 MyBatis가 SQL을 실행합니다. [아키텍처](docs/design/architecture.md) · [React 전환 결정](docs/adr/0003-react-frontend.md)

- **회사별 데이터 격리** — 로그인한 계정의 회사·역할을 기준으로 범위를 정합니다. 업무 SQL의 `tenant_id` 조건과 PostgreSQL RLS를 함께 적용하고, 일반 업무·인증·마이그레이션용 DB 권한을 분리합니다. [보안 설계](docs/design/security.md)
- **과거 계산의 추적** — 기록이 발생한 실제 시각과 서울 기준 근무일을 별도로 관리합니다. 출퇴근 원천, 승인된 정정, 계산 결과를 구분해 보존하고 결과마다 당시 일정·정책·입력 버전을 연결합니다. [데이터 모델](docs/design/data-model.md) · [근로시간 계산 엔진](docs/design/worktime-engine.md)
- **동시 처리의 정합성** — 승인 상태와 그에 따른 연차 원장, 신청의 효력, 감사 이력, 재집계 필요 여부를 같은 트랜잭션에 기록합니다. 동일 명령 재시도와 동시 승인에서도 중복 기록·차감을 방지하는지 검증했습니다. [격리·동시성 검증](docs/quality/phase6-report.md)

## 로컬 실행

1. Docker와 Docker Compose를 준비합니다.
2. [로컬 개발 안내](docs/development/local.md#비밀값-설정)를 따라 `.env.example`의 항목을 로컬 전용 값으로 설정합니다.
3. 저장소 루트에서 앱을 빌드하고 실행합니다.

```powershell
docker compose up --build -d
docker compose ps -a
```

브라우저에서 `http://127.0.0.1:18080/`에 접속합니다. 첫 실행에서 가상 계정으로 체험하려면 로컬 데모 데이터 준비 절차를 따릅니다. Java 25와 Node.js 22.12 이상을 사용하는 Windows 개발 환경에서는 `.\mvnw.cmd verify`로 빌드와 통합 테스트를, 프런트 의존성 설치 후 `npm --prefix frontend test`로 화면 테스트를 실행할 수 있습니다. [로컬 개발 안내](docs/development/local.md)
